# S349：接球后的控制与学习窗口打通，旧权重仍未学会停球

结论：修复了可以验证的训练覆盖缺口，但没有取得合格停球或整场提升。
所有新控制默认关闭，仍保留旧候选。

## 控制边界

`post_receive_contact_control` 必须显式启用，并要求严格真实脚接收交接及
受限接触老师。第一次真实接球后记录该球员的方向与支撑关节姿态。
支撑基线和短暂的身体移动保持不变，但允许接收者继续使用原幅度/变化率内
的腿部残差；接触老师从随球后撤逐渐减慢脚部目标速度，不再直接切到踢球
穿越目标。它不修改球位置、速度、碰撞体或直接施加球力。

一脚射门的前锋分支不被改成停球分支；全身模型、独占动作、故障锁存等
原有互斥边界保留。学习仍需实际激活及探索掩码，不因新增上下文自动更新。

## 四组真实八体课程

蓝队同一旧权重 × 控制开关 × 支撑窗口 0.2/0.5 秒，各跑一次 20 秒。

| 接触继续控制 | 窗口 | 身体安全 | 机器人接触计数 | 可控停球 |
|---|---:|---|---:|---|
| 关闭 | 0.2 秒 | 是 | 0 | 否 |
| 关闭 | 0.5 秒 | 否 | 423 | 否 |
| 开启 | 0.2 秒 | 否 | 70 | 否 |
| 开启 | 0.5 秒 | 是 | 0 | 否 |

两项开启候选触球前逐数组与旧对照完全一致；没有提前修改接近或传球过程。
真实接球后分别出现 10/25 帧收球上下文，10/25 帧实际腿残差控制、
10/17 帧接触老师激活。原本被禁用的窗口已实际运行，不只是配置存在。
但是第一次擦球后没有新的接收者脚触球，球速仍约 1.34 m/s，接不稳。
0.5 秒开启候选虽安全，也没有停球收益，因此不能替换旧方案。

本阶段没有新梯度更新。它为后续学习提供可用控制窗口，不是小脑已经学会。
单靠延长冻结、改变脚偏移或开通控制都不足以解决，需要训练触球前的
正确拦截姿态及连续减速，并回到完整世界检验迁移和旧技能保留。

## 工程与验证

- 新增接触进度验证：必须是有真实接收事件的 receive 模式、有限 0…1
  进度，不能伪作 strike，也不能无接触启用。
- 收紧 committed 接收偏移到运行时可用的 0.12…0.24 m，避免 0.10 m
  参数在仿真中途才失败；前端实验配置同步提前拒绝。
- 默认世界固定哈希不变；两项新模块相关测试 28 项通过。
- 全量第一轮 1593 passed、29 skipped、11 failed（49.50 秒），失败仍是
  原历史外部证据绑定；随后另加一个数值溢出/配置类型测试并通过。
- ruff 通过；mypy 435 源文件通过。没有硬件操作或模型晋升。
