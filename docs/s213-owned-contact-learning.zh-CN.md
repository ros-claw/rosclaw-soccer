## 真正实施的训练是什么

复用 G1 神经网络步行基础模型与有界脚部接触教师；对上层触球站位策略做
**离线、有限候选、物理反馈驱动的参数搜索**。不是 PPO、在线 RL，也没有新训练
端到端小脑网络。没有修改球位置、给球额外射门冲量或扩大机器人力矩限制。

一个旧固定站位为球后 0.72 m。本轮将持球 PASS/SHOOT/DISTRIBUTE 的站位与朝向
变成可学习参数；由既有有界运动控制实现，不直接控制根姿态。
该入口是 opt-in，默认 `owned_contact_policy=None`，不替换默认策略。
接球稳定等待和既有分阶段踢球控制优先，参数策略不能绕过它们。

| baseline | 原有规则 | 原有规则 | 1.50 |

每个候选在红蓝两队相同训练配置中测量，排名由较差一侧决定。

## 为什么不能把球员间球转移直接当作成功传球

第一轮开发验证中，旧评估器给红方回合记了一次 pass：

- 4.32 s：中场脚部触球。
- 4.42 s：中场才提交传球意图。
- 后续前锋确有脚部触球，但先前触球不能由后来的意图追认成主动传球。

旧规则允许接触后短时间内补充意图，在当前任务下会夸大有目的的传球能力。
本轮新建 `pass_failure_feedback`，要求意图先于出脚，限定意图有效窗口，
检查真实接球、对手中途触球、接球队员脚部距离和球朝接收者方向的速度。
诊断结果不替代正式比赛门控，碰撞/非脚部控球也不能获得合格传球奖励。

`owned_contact_learning.reward` 不再因旧 assessment 中有 pass 标签而给奖励。
缺少新的因果证据时传球得分为零；只有事件标签、跑动或大量传球意图都不会加分。
新的审计器可从原始轨迹重新计算结果，将旧口径的 PASS 降级为严格口径 REJECTED。

## 实验和结果

第一轮：10 个训练回合 + 4 个开发验证回合，各执行 primary/replay，共 28 条轨迹。
随后进行了红蓝两组控制优先级修复复跑，共 4 条轨迹。
第二轮：相同预算重新按因果评分运行，共 28 条轨迹。
总计 **30 组配对实验、60 条 CPU MuJoCo 轨迹**；这是轨迹数，不是独立泛化样本数。

开发验证使用名义球位之外的 ±0.12 m 偏移。第二轮复用了这些位置，
所以它们是已消耗的开发回归集，**不再称为新的私有 Holdout 或独立泛化证据**。
程序保留的 `heldout_*` 字段表示选择后评估阶段，不能据此宣称未见测试集成功率。

| 最终开发案例 | 时长 | 身体门限 | 旧 pass 标签 | 严格主动传球 |
|---|---:|---|---:|---:|
| 红方 baseline | 12.60 s | 未通过 | 1 | 0 |
| 红方 candidate | 7.58 s | 通过 | 1 | 0 |
| 蓝方 baseline | 2.86 s | 通过 | 0 | 0 |
| 蓝方 candidate | 2.58 s | 通过 | 0 | 0 |

这些回合都以边线出界结束。红方候选的零碰撞出界回合比 baseline 短，
**不能因此声称相同时间预算的稳定性成功率提升**。
非脚部触球仍存在，未形成合格射门或扑救；视频不是宣传级成功比赛。

两轮均 `REJECTED_PASS_EXAM`、`promotion_eligible=false`。
