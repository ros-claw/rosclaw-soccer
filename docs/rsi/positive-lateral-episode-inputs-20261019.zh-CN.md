# 跨基础场景的物理采集入口与未来训练划分

## 为什么做这一步

旧 C6/C7 的两条成功轨迹来自同一基础场景，不能一条训练、一条
验证后声称泛化。要学出小脑，先要让可信教师在不同基础场景中
产生真实动作和完整物理后果，再做有隔离的监督初始化及学生自身
闭环评估。当前尚未完成跨场景物理采集，也没有新训练出的学生。

`positive_lateral_episode_inputs.py` 把已经封存的采样注册表转换成
现有 `qualified_episode` 所需的原公开计划、完整 manifest 和八个
planning context；不改父代，不修改原采样噪声，不裁剪来球条件。
原有生成 seed 绑定、原生身体执行、独立 CPU 和 Foundation 审计
仍必须在真正执行时完成，这个输入预检不会代替它们。

## 当前实际验证

固定 registry `f93c7b57`：八个派生课程、四个基础簇，96行只是
完整元数据注册，不是96条物理轨迹。只有group12/13/28/29/76/77/
92/93有声明的采样视图；其余填充行不能成为实验样本。group编号
必须结合新的 source_plan_hash，不能与旧计划的同编号混为一谈。

预先固定训练seed为20261077/20261078/20261093，验证seed为
20261096；每个簇的两种扰动和所有控制族必须同分区。以后归一化
参数只能来自训练分区。验证仍是公开开发集，不是Fresh，也未
证明整个历史谱系无泄漏。当前没有导出训练集或授权优化器更新。

course tuple与持久化JSON list直接比较不等。零NN、零物理、无

测试也增加真实JSON round-trip，再冻结新v2目录执行。24项相关
测试通过（包括旧课程与视图测试），全ruff通过。

## 下一项仍要实际完成

等当前六例材料点机制组合及全部诊断真正完成，先复盘整批成败，
再冻结跨簇采集方案、执行器和整批读取器。候选参数必须保持原
catalog2，不能事后按新课程结果调参。所有失败、删失和非足碰球
均保留，旧全局反例不因为缩到局部课程而消失。若跨簇教师依然
不稳定，不能把它直接蒸馏为“学会踢球”；若可用，再开展真实
GRU参考动作学习、学生自己的身体闭环和旧能力回归，最后才回到
接球、传射、门将及连续球队比赛。局部M0侧向位移不是射门精度。
