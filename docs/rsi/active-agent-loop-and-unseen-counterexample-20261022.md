# 持续实施机制与一次必须保留的泛化失败

## Agent loop 的真实边界

持续目标保持 active；“四对四连续自主比赛、可展示的真实物理视频”尚未完成，
不得把单项训练、服务在线、定时检查或测试通过设置成总目标完成。

实验执行与智能决策是两种循环。systemd 执行已冻结、已声明预算的仿真或审计，
即使当前交互结束也能继续；每分钟的 watcher 只观测 PID、进展与终态。
它不能唤醒语言模型、不能分析失败后创造新算法，也不是科学后继任务调度器。
Agent 的后续执行依赖宿主继续调度 active goal。不能承诺宿主退出、断电或调度
停止时仍能自主推理。恢复入口保存在外部 evidence 的 next.json 中。

每轮必须落实以下责任，而不以“仍在监控”代替实施：

1. 对账当前阶段：实际 PID/CPU、完整结果、失败文件、源码及模型身份。
2. 对已结束的生产执行核验独立审计；不能重新执行已收费或已关闭的实验冒充进展。
3. 写明成功、失败和证据上限；根据反例选择不同的下一项科学动作。
4. 先固定源码和全部预算，再启动下一项可检验工作；更新恢复入口与 watcher。
5. 未达到总目标则继续；异常保留证据、修复原因，不无限自动重试同一失效命令。

这不是另写一个“永不结束”的 shell while，也不是让 GPU 忙碌就算成长。

## 本轮反例

此前新动作记忆在已训练32场景达到26/32，对照4/32；旧52个上下文保持。
但预先锁定两个模型后生成的32个连续随机未见局部场景，学得模型与对照均为
**2/32**，成功场景均为16和27，配对新增成功0、损失0。

生产源码 ebaf2405699b94d0ac5b909edcade1b6342cc87c；两组各64条轨迹、
248960个2ms子步、24896行本体神经推理。两项独立原生重放审计已通过，
结果与生产逐案例相符；这里不把两次重复算成64个独立场景。

学得组没有身体失败，但17场出现禁止的非脚接触；其余失败包括球路侧偏。
不能调低质量阈值或删除膝部触球使成功率好看。这个结果拒绝“已形成可靠的
局部泛化”结论，尤其不支持完整小脑、无缝接球射门或连续球队比赛的声明。

独立 own-policy coverage 诊断将重构每一控制帧的真实神经历史、动作和新增记忆
激活情况，区分新状态没有覆盖与覆盖后控制失效。此诊断不制造新训练标签。

## 同时推进的动作能力测量

不让触球单项无限阻塞球队路线。增加冻结速度 prior 的原生 MuJoCo authority
测量：初始默认姿态和原始记录姿态各测试0.3、0.6、0.8、1.0米/秒，均在既有
部署命令范围内。每条完整300控制帧独立重复两次，最大48000原生子步和4800次
神经调用。记录真实速度、停止漂移、姿态、力矩和球体接触，不修改动力学、PD、
基础权重或命令限幅。原有四场低速协议默认行为不变。

这只是追球和技能衔接的能力边界测量，不是已训练出足球策略。
