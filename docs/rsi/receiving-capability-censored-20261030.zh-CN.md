# 球队接球能力证据：保留删失和尝试身份

在原有 `receiving_capability_table` 之外新增 `receiving_capability_censored_table`，不改变旧接口或把现有足球政策升级。新接口区分安全成功、已观察失败、安全否决和观察窗口未完成；纯删失组的已观察成功比例为 `None`，不能被当成 0%。它只提供对**已记录尝试**的极端补全上下界，不是总体概率、置信区间或风险保证。

每项输入绑定一个调用方提供的 episode hash 和 context hash；不同证据文件若声明同一 episode 会被拒绝，避免将重复回放或同一场次多个窗口冒充独立尝试。不同 context 不合并，但本接口不验证调用方是否把全部相关物理状态正确纳入 context，也不能独立认证轨迹、episode 独立性或来源。删失条目的 `safe=True` 只表示已观测窗口没有记录到安全否决，**不证明未观测的未来安全**；已知安全否决必须标记为 unsafe。

单次已消费的八人共享 MuJoCo 探索中，`red.finisher` 的一个窗口仅记录 3 帧、无受控接球且未观察完整；来源轨迹和重复记录此前经独立读回与数组比较。将该窗口作为单个演示输入，得到一条删失、零条完整观测，成功比例未知，可能补全范围为 `[0, 1]`。这是选择的一个例子，不是总体成功率，也不是比赛成绩：该场景为教练指定接球，课程初始速度和横向位置不是事件时刻状态。外部机读示例 `team-capability-censored-example-v2-20261030.json` 保留原回执与上下文边界。

此功能只为球队战术能力建模防止证据错误，不自动进入 2v1 决策、更不改变任何技能权重；未知上下文、持续时间和后续可行动性继续保持未知。SIM_ONLY，无真实硬件许可。
