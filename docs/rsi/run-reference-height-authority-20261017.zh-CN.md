# 跑步参考高度权限：先证实输入作用，再检验实际身体

## 参考实验完成，不等于身体改善

从已消费 group4/mode3 的独立重建中，取得冷启动及第 100 帧
暖参考上下文。每个上下文比较三个随机种子、固定的
`height=-1.0/0.7/0.75`，同一配对只改变高度输入。
完成原参考重建 15 次、反事实参考 18 次，共 33 次 CPU ONNX 调用。
没有新身体物理、Foundation encoder/decoder 调用或优化器更新。

外部报告 `rsi-run-reference-height-authority-probe-20261017.json`，
封印 `sha256:cfe3a43d22b5216c92baa12ba607576d81b91121befbe93cebf276f78d78d4f8`。

第 100 帧上下文，原种子 30305 的完整参考最低根部高度分别为
0.556827、0.610125、0.628916m。正高度的完整输出在三个种子之间
逐位相同，负值默认则不同。这符合参考关键帧选择的机制，但
不证明消除了所有随机性或可以任意控制根部笛卡尔位置。

冷启动反而不呈单调关系：原种子最低参考分别为
0.686008、0.688938、0.677987m。由此排除“输入 0.75 就保证全程
高于 0.75”或“增大输入总能抬高全轨迹”的说法。
参考高度也不是当前 legacy encoder 直接消费的根部 xyz 指令。

官方文档将 `height` 定义为支持变高度行为的关键帧选择输入，并未
承诺它是 run 的硬高度约束。本次在本地固定 ONNX 模型上实际证实
了 run 的输出变化，不从文档推断身体效果。
参见 [官方接口](https://nvlabs.github.io/GR00T-WholeBodyControl/references/planner_onnx.html)。

## 有界身体对照声明

下一步固定两个已消费初态 group0/group4，各运行一次纯 Foundation
mode3，唯一新增高层控制参数为参考高度 0.75m。对照使用此前
已独立审核的对应纯 Foundation/default-height 执行，不重复基线。
两次新执行，300 帧、原 0.65m/foot-only 评分、世界与硬力矩界限不变。
该试验既不是 Fresh，也不是神经训练。

代码中的 opt-in 参数接受 0.65–0.8m 有界浮点输入，但本协议只
授权这两个 0.75m 条件，不把输入范围当成已声明的参数扫描。
仅高速 run 请求使用正高度，idle/slow-walk 仍用原 -1.0 输入；
反馈状态发生分歧后，不能声称低速阶段的完整动作轨迹逐位相同。

原生接口只在捕获实际网络调用的 pure Foundation 接近消融中接受
高度参数，禁止与学习残差、IK 或 postcontact 干预混合。默认参数
为空，历史模式声明/事件字段和默认控制分支不变。

独立审核必须重建新高度请求、逐事件高度及参考哈希、完整 encoder
消费、300 次 Foundation 调用和 3,000 个物理子步。新声明采用
显式 v2 参考合同；不能用旧 mode-only 审核冒充高度干预资格。

发现：参考高度输入确有动作生成权限，但不是安全保证。
排除：单靠增大请求高度即可直接判身体安全。
值得投入：检验暖参考改变能否通过网络改善实际低姿态且不破坏触球。
证伪条件：身体仍违反原门或触球更差时，不作为教师，也不立即扩大
同类高度网格；回到参考/接触协调机制。未通过不得自动晋级。
