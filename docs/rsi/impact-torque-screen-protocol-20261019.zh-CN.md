# 局部触球力矩权限诊断与持续推进约束

## 为什么接这一阶段

C3 足部朝向实验的六条轨迹全部保留并独立回放，正式 M0 从 2/3 到 2/3，不能晋升教师。精确碰撞几何显示：脚面朝向改善并不保证实际接触法线或球速方向改善。继续扫同类朝向增益没有依据。本阶段改为直接检验受限关节力矩对实际冲量的局部影响。

## 固定协议

- 全部六条 C3 原轨迹，包含失败和退化结果，不按效果挑选。
- 原力矩 2ms 回放共 18,000 子步。每例在事后首触球所在控制帧，用同一完整状态独立复制预测至多 13 个受限力矩动作，每个 10 子步，再重复零动作。预测预算至多 840 子步，总预算 18,840。
- 仅在原因果摆腿侧等于实际首触脚时生成动作，否则保留该例及不适用原因，仍完成原轨迹回放。
- 不修改浮动根、球、支撑腿或上肢，不换世界、球尺寸或 PD 增益。只允许选定腿六个关节的附加力矩，单关节不超过 min(12Nm, 原硬限的20%)。
- 零动作预测必须在 1e-8 原容差内重现实际十个子步；所有候选之后重复零动作必须逐字段逐字节相等。预测不得写入原状态。
- 所有候选原始数组、评分、否决和失败必须落盘，物理步的 attempted/integrated 分开记录；不得隐式重试或延长预算。
- 20ms 球速、方向与骨盆高度只是诊断代理，不是完整 M0 成功、持续平衡、接球、射门或团队能力。事后选帧不是可部署的在线触发器。

## 下一步判定

若有局部可重复改善，下一阶段才能设计只依赖当前/过去状态的在线触发与滚动预测，再做原生全程、独立 CPU、保留集和扰动验证。没有全程增益不得训练为教师，不得将短预测成功写成策略成功。若局部动作没有有效权限，保留反例，重新分析触球时机与步态/动作接口，而非扩大同类力矩暴搜。

## agent loop 不能用心跳替代进展

持续目标负责接续 Agent 工作；有边界的一次性任务负责物理执行；观察器只报告状态，不能声称唤醒 Agent 或产生科学决策。旧任务的定时观察器仍运行，不能证明新实验在执行。

每个阶段都必须留下：源提交与输入、预算、实际进程、原始结果、判定、明确后继动作。结束后必须进入读回/判定/后继开发之一，不能将“没有运行进程”伪报为训练中。崩溃保留失败与已消耗预算，恢复时采用新声明，不热改运行源码或复用输出目录。只有用户要求停止、真正需要新授权，或明确报告外部阻塞时才中止推进；没有成绩不能标记目标完成。

此机制保证的是可恢复、有证据的阶段接续，不保证算法必然成功，也不能保证宿主平台断线、关闭或重启时 Agent 仍在思考。后台任务与恢复文件不能冒充这一保证。
