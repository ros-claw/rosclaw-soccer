# 真实共享身体上的神经力矩学习与约束修复

本阶段把已有 Core GRU 小脑接入 Soccer 的实际共享 MuJoCo 身体，并完成第一次
真实 BC 权重更新和完整物理复验。结果还不是突破：四例都保持完整恢复，但射门
只有三例改善、一例退步，0/4 达到 0.1 m；尚未在线更新 actor-critic。

## 学到了什么、没有学到什么

`SharedNativeTorqueLayer` 将真实 500 Hz 身体/球观测传给 Core，执行 29 维绝对
关节力矩，并把实际 actuator_force 写回模型历史。不能把模型提议当成真实执行。
身体、父控制器和数据哈希必须匹配；每个身体有独立模型/隐状态。

原 547 维踢球网络、98 维速度网络依然负责父技能。本阶段新模型是 Core 的
102 维观测 → GRU96 → 29 维力矩 actor，而不是三个高层速度命令。
四个真实父轨迹共 26,080 条 native 标签。固定 0/3 训练，1/2 验证。
30 epoch 共 **390 次真实 Adam 更新**；训练归一化力矩 MSE 从约 0.00882
到 0.000205，验证从 0.00713 到 0.000322。这不是米制精度，也不是任务成功率。
critic 更新为 0，SAC update_index 为 0。checkpoint 保存优化器、critics、RNG，
不能把保存了 critic 结构描述成 critic 已经学会。

## 实验发现并修复了 Core 缺陷

原安全投影依次裁剪幅度、父控制器偏离和变化率，后一次可以破坏前一约束；功率
缩放也可能离开非零区间。原实际 previous 还被错误裁剪到更小的候选幅度上限。
修复为先计算约束交集，无交集明确回退，功率缩放后重新检查，回执记录原因。

通用数值算法位于 Core `control.vector_envelope`，不是 Soccer 私有补丁。
Core PR：<https://github.com/ros-claw/rosclaw/pull/764>。
最新 main 基线 5744f44a 上的修复提交 3fd6e258；受控实验使用旧冻结基线
a5a21e5c + 同一修复，得到 4f846e6e，避免混入其他 Core 变化。

旧模型试验四例实际父偏离峰值占 hard torque 的 25.2%–29.3%，超过声明的 8%。
独立数值审计发现 41/33/41/44 个违规关节采样，共 159 个。保留旧结果但不晋升。
修复版四例父偏离不超过 8%，峰值实际变化 11.12 Nm，各项候选约束违规均为零。
父回退不承诺候选专属的变化率/功率上限：例如修复版一个父值采样功率约 3088 W，
不能声称所有执行采样都低于候选 2500 W 上限。所有执行仍在原 0.85 hard 力矩上限内。

## 后续学习不能踩的坑

1. BC 拟合父力矩不等于精准踢球。下一阶段需要以真实球路、完整恢复和动作变化
   为反馈，保留第 0 例退步，不能继续只追 MSE 或只选择改善的三例。
2. Core SAC 当前 critic 训练动作是实际力矩，而 actor/target 采样是未投影提议。
   若直接套用，会在投影经常介入时产生动作语义错配；先处理此问题再规模化。
3. 原 `online_replay` 的任务奖励在 13 秒末尾，不能把折扣衰减后的微弱信号误当
   触球处的有效学习。应采用真实时序对齐奖励或明确的多步回报，不能使用未来
   落点作为部署观测，也不能将未来动作标签伪装成因果观测。
4. 本轮只有四个几何，验证集不等于私人 Fresh。扩展课程和真实保留性验收后再
   讨论迁移到多球员；模型 body hash 当前保守绑定单体布局，不能绕过哈希硬塞
   给不同共享世界中的 B 或八个球员。
5. Goal 保持 active。只读 observer 观察真实单元和失败，不负责唤醒 Agent，
   不能把每分钟心跳或“全部任务完成”当成科学目标完成。宿主自动续行与外部
   可恢复状态负责跨轮接续；不保证不受服务/重启影响的无限在线。

全部 SIM_ONLY，不访问硬件，不自动晋升，不生成虚假宣传成果。资产宣传授权
仍未确立。还没有达到可宣传连续 4v4 比赛目标。
