# 不依赖聊天在线的持续实验机制（2026-10-15）

## 为什么需要改变

九场有界动作接口实验已于 08:51 完成，旧路径全部 28 个数组精确复现，
九场均完成独立 CPU / Foundation 验证；但结束后没有自动开始下一阶段。
原生任务高质量仍为 0，不能用九场工程资格通过掩盖运动能力不足。
结果封印：`sha256:efe45cc966db738ab94867ac2db481e812391e16ee179197658566824df47f0f`。

因此先在 Soccer 验证一个常驻的首次触球科研 Campaign，而不是再次手工
开一批任务。该机制是专用实验试点，不把足球流程塞入 Core；验证后再抽取
任务无关的恢复、调度与决策协议到 ROSClaw Core。

## 自动接续什么

```text
冻结来源与预算 → 全量旧路径控制复现
  → 16 个公开初态 × 4 个候选
  → 独立物理与 Foundation 重算
  → 保留全部成功/失败/删失，逐状态比较旧策略
  → 分析安全退化、旧能力损失、触球、球路和奖励
  → 据反馈生成下一代有界参数 → 自动继续下一代
```

固定 16 状态为四类来球各四个公开初态；不是相邻帧数量，也不是新的 Fresh。
第一代明确比较 B（接近）与 C（接近加显式任务空间接触）以及两个独立参数
初值。之后保留最佳提议，围绕反馈选出的参数分布做有界采样，并保留新的独立
搜索初值。完全相同的状态、参数和采样身份复用已验证的收据，不重复执行，
也不把复用记录当成新的独立实验。

本次批准的预算为 3 代、每代 64 个逻辑配对评估，加一场控制复现；另留有限
崩溃重试预算。每场最多 H300，独立回放 3000 子步，Foundation 重算 300 次。
资源不足暂停等待，恢复后自动接续，不删除历史证据。

这是物理参数搜索，不是 actor-critic 更新。失败候选可以作为未获资格的搜索
提议父本，帮助寻找更安全的参数；安全与旧成功退化优先排序。它们绝不因此
取得教师或晋升资格。教师合格还需扩展 40 状态和扰动复核；神经学习仍受
G3 前置条件约束，Fresh、Champion 和真机权限始终不自动开放。

## 如何避免“进程活着，但没有推进”

- `heartbeat.json` 每 15 秒记录 PID、时间、阶段、尝试数、已验证数和当前任务。
- `campaign.sqlite` 以 FULL 同步事务保存哈希链事件，包括代际决策与参数声明。
- 一个任务先记录 ATTEMPT_STARTED，再执行物理；完整独立证据落盘后才完成。
- 冷启动检查声明、来源及已完成证据哈希。声明变更须创建显式新 Campaign。
- 强制中断保留原尝试目录并消耗预算；重启只恢复未完成工作，另起尝试目录。
- 用户级 systemd 服务在异常退出后重启，并在用户服务管理器启动后恢复运行。
- 正常失败、未触球和右删失是学习数据，不触发基础设施崩溃。

心跳不等于物理成功；应同时看已验证数和当前阶段。完整模型初始化可能需要
约 20 分钟，此时心跳显示 INITIALIZING_FULL_FROZEN_MODEL，而不是虚报训练。

## 哪些情况必须停止

源文件或证据改变、合同违反：FATAL_CONTRACT_VIOLATION，服务退出 78，不自动
“解冻”；需要事故分析和显式新声明。三代无配对净收益：PLATEAU_RESEARCH_REQUIRED，
停止该实验族，保留失败与下一研究依据。达到尝试或墙钟预算也明确停止。

这不是一个可无限自行编写新代码的离线 AI；它能自动执行已声明的科研路径，
根据真实结果更新搜索参数，并持续保存可接管状态。新架构、权限变化和停止后的
新研究族仍需要审查，不用无限重试冒充自主成长。

## 本机操作与数据

服务名：`rosclaw-first-touch-campaign.service`。

```bash
systemctl --user status rosclaw-first-touch-campaign.service
journalctl --user -u rosclaw-first-touch-campaign.service -f
systemctl --user stop rosclaw-first-touch-campaign.service
systemctl --user start rosclaw-first-touch-campaign.service
```

数据与配置放在外部 evidence 目录，不进入 Git。服务安装后的实际路径和状态
另存同目录 `deployment.json`。临时暂停可在 Campaign 根目录建立 `PAUSE` 文件，
只影响下一场任务；移除后自动继续。暂停不会中断当前仿真，停止操作也先保存
当前场的完整证据；强杀时则按未完成尝试恢复。

本轮新增测试覆盖真实子进程 SIGKILL 后恢复、完成证据变更、声明漂移、重复
执行、预算、三代平台期、反馈改变下一代参数及相同实验复用。测试只证明监督
机制，不是 G1 技能增长的证明。

验证记录：相关回归 **87 passed**，定向 mypy 和全仓 Ruff 检查通过，新增文件
格式检查通过。全仓格式检查另发现 68 个既有文件需要格式化，本轮未修改这些
无关文件，不宣称全仓格式通过。实际 systemd 故障烟测日志记录 `status=9/KILL`
及一次自动重启，恢复脚本正常退出；物理执行数明确为 0，只有调度恢复证明。

## 用户撤销磁盘预留线后的显式接续

用户明确要求不再按剩余磁盘容量暂停。新增 `reserved_disk_gib=0` 选项：
完全跳过容量门控，不再需要 100/101GiB 预留；写入失败仍不能产生完成收据。
内存、物理安全、评分、三代止损、尝试总额和原墙钟期限保持不变。

旧服务在 WAITING_RESOURCES 且没有活动仿真时正常停止，不热改冻结源码。
新 Campaign 通过只读、哈希绑定的前驱账本继承 19 场已验证结果、尝试数及
已生成的参数。已完成任务不重跑，旧目录不复制、不删除、不覆盖。新账本记录
显式接续事件；重启接续操作幂等，不能覆盖已经开始的后续尝试。

接续预检要求原配置、完整账本哈希链、末端哈希与所有继承证据匹配，前驱必须
处于明确的正常停止状态。科学配置不许变化；除监督器、资源策略和入口错误
处理外，仿真与学习源码必须逐文件相同，动作执行与搜索函数还要求 AST 一致。
损坏、未停稳、Fatal 或 Plateau 状态不能利用这条路径自动解冻。

`rsi-first-touch-continuous-campaign-no-disk-reserve-20261015`；原目录保留历史状态。
同一 systemd 服务切换至新的冻结源码与新配置，仍独立于聊天运行。
