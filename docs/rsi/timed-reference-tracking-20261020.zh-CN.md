# 整体动作参考跟踪：阶段入口，不是踢球突破

## 持续实施的实际机制

产品 Goal 保持 active，终点仍是有证据的连续自主球队比赛，而不是某次
模型拟合变好。官方 Goals 文档说明：工具执行轮结束、线程空闲且没有
待处理输入/工作时，产品才检查自动续接。阶段轮结束不等于目标完成。
每一轮应执行实际开发、实验或分析工具，并持久化下一步，避免无工具
的状态汇报轮导致自动续接被抑制。

参考：<https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex>。

本地 systemd 观测器只读取进程、完成文件和依赖状态，不能唤醒模型、
自行开发或选择新的科研方向。有限实验服务可以独立完成已声明的队列，
但不能据此承诺断电、产品关闭或额度耗尽后仍会持续推理。

工程循环应为：声明可证伪的问题 → 固定代码/数据/预算 → 运行 → 独立复核
→ 接受或保留失败 → 明确下一实验。连续失败应更换方法，不能放宽验收。

## 为什么转向整体动作

触球后的短时力矩与速度响应模型已有局部诊断收益，但尚未证明球队运动
能力提升。下一步隔离验证：完整29关节动作参考能否由冻结 SONIC 在自己
的身体反馈下跟踪，而非继续只修补触球后的力矩。

新模块 `sonic_reference_preparation` 要求显式来源频率，线性重采样关节与
根部位置、SLERP 旋转，保留29个通道。根部位置和航向做明确参考重锚定，
并用一秒参考入场连接当前实测姿态。物理身体不重置/瞬移；根部XYZ不被
此 SONIC 编码器用于笛卡尔跟踪，重锚定也不是脚底/地面校准。

姿态入口、连续性、关节范围与四元数检查保留，源动作不裁剪、不静默
放慢，不自动修改既有编码布局。依赖现有 `training` 与 `diagnostics` extras。

## 首次真实数据入场发现

固定来源足球 `BGI_Shooting_00001.csv`，SHA256
`5d7f68046daa9159faa6f4ce0fc439ad58205325fe9aecd923a060600916db73`。
993帧，声明120Hz，完整重采样414帧，加50个入场间隔合计464帧。

全片段被现有连续性合同拒绝：重采样后最大根部位移约0.2782m/20ms，
最大关节跳变约0.5902rad/20ms。原始根部突变在982→983帧；关节突变
也存在于更早区域。不是物理失败，也不代表整个数据集无用；没有据此
平滑或放宽阈值。检查本身物理积分0、优化更新0。

## 独立的首四秒可行性协议

`scripts/rsi_probe_timed_reference.py` 预声明两臂：实测初始姿态保持、
原来源0..480帧首四秒。两臂都经过同一个冻结低延迟 SONIC 编码器/解码器，
使用各自实际身体的本体感历史和原PD/力矩限制，不播放qpos。

采用现有H300原生身体，每臂300×10个2ms积分，总6000；球静置10m处，
不是任务目标。动作臂含50个入场间隔、201帧源参考，然后显式终态保持。
首四秒是几何入场隔离窗口，不能代表完整片段或完整射门，不能给它贴
M0通过、进球成功或自然动作已解决的标签。

输出原生q/v、控制、实际力矩、接触和参考/神经动作，报告实际关节跟踪
误差与根部状态。数值/求解异常保留failure；跌倒的有效物理结果也保留。
后续独立记录目标重积分后，才能讨论跟踪结果；没有预先声称会成功。

代码与资产在导入前及完成后固定；不可热改运行源。模型没有优化更新，
因此即使跟踪成立，也只是接通已有神经小脑，不是新训练或在线强化学习。

MotionDecode 本地许可限制为非商业研究/原型并要求署名。本轮只做内部
研究，不复制动作到MIT仓库，不据此制作商业宣传或发布派生权重。
