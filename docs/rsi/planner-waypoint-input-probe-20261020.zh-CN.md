# 冻结规划器的世界站位目标输入：只读八次 NN 对照

前置：完整移动响应数据和预测模型审查已闭合，简单延迟模型在六条验证指令上均未通过，不能接管移动。当前转向官方规划器已有的位置目标接口，不是重新调该模型。

本地参考项目 `GR00T-WholeBodyControl` 的 `planner_onnx.md` 和 `full_agent.py` 给出 `has_specific_target`、四个世界根位置 waypoint 与绝对 yaw 输入。目前 Soccer 默认规划器始终传 flag0，只表达速度方向；不能仅凭文档就认定当前冻结 ONNX 已具备有效的精确定位能力。

固定使用历史 case21 校准站位实验 right-law0 的第60帧，读取该帧及过去100ms的实际状态，50Hz历史重采样成四帧30Hz规划上下文。四元数符号连续化和归一化只用于 NN 输入，不更改仿真状态、历史文件或真实动作。根目标由当前球状态和已冻结站位模型重算，必须与历史当帧请求一致；不是未来实测位置。

四种输入：

1. 原始 flag0，waypoint全零；
2. sham：同一输入，仅填写位置目标与yaw，仍flag0；
3. flag1：四个waypoint均为同一个已知目标，yaw0；
4. 负对照：相对当前根位置反射目标，flag1、yaw0，其余相同。

相同上下文、速度/方向、固定seed30300和其他模型输入；四组在一个新CPU ONNX session中执行，再用另一个新session完整重复，共最多八次 planner 推理。零编码器/解码器调用、零原生积分、零优化器更新，不创建物理身体。完整保存所有输入、输出、长度、哈希和参考项目源码身份。

复核：flag0 sham应与原始输出逐值一致；flag1应真实改变输出，且正负目标在目标方向有正确响应对比。检查有限值、单位四元数、原始29关节范围，越界只记录拒绝，不裁剪修复。反向输入只用于模型诊断，不执行身体。

只证明目标信号被 NN 消费不证明动态可行性；规划器参考输出不等于 G1 实际动作。任何原生试验仍须另行声明、默认路径历史数值资格、完整身体连续性、原交接距离/截止时间和原任务门。没有自动晋升或视频成功声明。
