# v308：真实物理反馈驱动的受保护 contextual actor-critic

## 结论与边界

第二次更新后的**同一个神经运动模型**在十二个已用训练场景达到 **11/12 高质量首次
触球**。此前九个神经成功场景全部保留，历史高质量、干净脚触球、出界和骨盆高度
门均无损失。发展门第一次通过，但 **RSI-M0 仍未 COMPLETE**：封存的新场景尚未
打开，CPU MuJoCo、完整连续链路和可宣传球队仍无资格。没有制作视频或晋升策略。

## 实际执行的闭环

1. 冻结父运动员 SONIC、late-swing、G1 资产及接近球的配置。
2. 十二场景父策略与旧神经模型共 24 次物理复现；旧模型身体/球轨迹逐字节复现。
3. 根据真实失败，固定三个困难训练场景；每代每场景采样十二个动作，共 36 次物理执行。
4. 用真实末端结果拟合状态价值 baseline，并更新优势加权神经 actor 的塑性读出层。
5. 每次更新重新执行全部十二个场景，逐帧复核本体状态、真实神经输出、实际关节目标、
   限位/变化率、首次接触及碰撞后的释放，不用候选平均成绩代替模型成绩。
6. 第一次更新为 9/12，仍有一例旧干净脚触球损失，拒绝；第二次为 11/12 且零损失，
   通过 consumed development gate 后按预注册协议结束本轮训练。

共 **120 个物理执行**：24 次复现 + 72 次探索 + 24 次更新后的神经复测。
回放包含旧 384 条反馈、十二次旧神经执行和 72 条新探索反馈，共 468 条记录。
这仍只有 **12 个独立场景**，不是 468 个不同任务，也不是新场景成功率。
一次 GPU 0 初始化 OOM 未开始物理执行，不计作动作失败或额外样本；失败日志保留，
恢复后重新审计已完成轨迹，只补缺失执行。没有删除失败数据、修改场景或杀其他进程。

## 通用 ROSClaw 能力与足球专属部分

Core PR [#615](https://github.com/ros-claw/rosclaw/pull/615) 的
`growth.anchor_plane` 是通用冻结编码器潜空间保护与加权读出学习数学，不含足球、
G1 点位或机器人 transport。九个成功潜变量保护后还有 24 个塑性维度；已知九点的
神经输出严格不变，但**不保证未见状态或整条轨迹安全**，物理复测不能省略。

足球仓库负责场景、失败课程、37 参数原语、实际物理反馈、学习器、只读独立复核，
以及把证据转为现有 Core `SkillGrowthSpec` 和 `ConsolidationManifest`。Core 的
Learning/Retention/Safety 为 PASS，Applicability/Darwin 为 MISSING，因此正式结果
是 `need_more_evidence`，而不是 promotion。Isaac 是 E2 加速仿真，不能单独提供晋升真值；
registry 写入数与硬件权限仍为零。

## 算法到底学了什么

13 个输入均来自触球前第 20/30 帧的实测本体和球状态。13→32 的编码器冻结，模型
学习一个 37×33 的受保护读出，以及一个 33 维 value 读出。37 个输出为三段×十二个
腿部关节原语系数和一项持续时间，实际控制仍有冻结底层运动员及限幅/限速。
它是 [AWR](https://arxiv.org/abs/1910.00177) 思路的**单次原语决策 episodic contextual
actor-critic 改造**，不是全轨迹 PPO、100Hz 在线梯度更新、直接力矩策略或完整小脑。
实际发生了先采物理反馈、更新 actor/critic、再采下一轮并更新的循环；不是只拟合
一个静态数据集。部署时不读 seed、课程编号、未来结果或“每场景挑一个成功教师”。

剩下一例 seed20261282/lane0 仍存在膝部触球；该失败继续保留，不能用球飞得远掩盖。

## 复盘：成功并不意味着学习器无需改进

第一代回放中，失败状态的 value 约 -8.48，近成功动作回报约 2.99，而高质量动作
回报约 13.07/13.27。原式 exp(clipped((R-V)/0.5,-8,8)) 把三者权重都变成约 2980.96，
抹掉质量排序。这解释了为什么平均后的动作仍可能偏过精度边界。

下一次 v309 是独立预注册的**离线回放校正与物理消融**：保持奖励、判据、编码器和
运行推理不变，在相同实测状态内先减去最大 advantage 再指数化，保留质量排序。
这改变了跨状态的加权，仍只称 AWR-inspired；不能声称复现原论文完整算法。
校正是否让物理效果更好，要看新物理执行，不能只凭 loss 或数学修正宣布成功。
