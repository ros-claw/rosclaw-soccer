# 持续实施机制：不把心跳当成学习

## 目标和职责

目标仍是有物理证据支持的连续 G1 球队比赛，目前远未完成。
会话 Goal 保持 active；只有目标验收通过才能标记 complete。
后台观察器不是 Agent，不会思考、训练或唤醒会话；它只是落盘下一步待办。
会话自动接续依赖产品运行环境。断电、会话关闭、服务限额不能靠 Python
心跳保证无条件继续，因此不承诺绝对不间断。

## 两层执行

1. Agent 负责：读证据 → 提出可检验假说 → 实施 → 测试 → 冻结实验 →
   运行 → 独立验收 → 根据成功和失败选择下一阶段。每次接续必须实际工作，
   不能只有承诺或重复状态文字。
2. systemd 负责：已声明的有限仿真在会话采样间隙继续运行；每分钟读取真实
   PID、进程启动时间、CPU ticks 和只读 SQLite 最新事件。
   两个 worker 都要观测，不能仅监控最早启动的那个。

观察器明确区分 CPU 活动与新的物理证据提交。20 分钟无新 ledger 事件
会提示检查阶段进展，即便 CPU 很忙；20 分钟无 CPU 变化则提示调查等待或
阻塞，不擅自杀进程或重新扣款执行。
读取 ledger 最新行不等于校验整条链，报告明确标记 integrity_verified=false。
