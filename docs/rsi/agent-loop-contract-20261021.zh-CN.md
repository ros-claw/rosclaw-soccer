# 持续实施：Agent Loop 与训练流水线的边界

本轮用户要求：未有实质突破，不因小阶段结束而结束整个任务。
运行范围始终是 SIM_ONLY，不触及真实机器人。

## 两层机制，不混淆

1. **Agent 层**：当前线程的持久 Goal 保持 active。每轮读取最近实验的实际退出状态、
   原始结果与失败证据，作出下一项开发、诊断或实验决定，再执行工具验证。
   小测试通过、训练进程存活、模型文件生成，都不构成最终目标完成。
2. **作业层**：systemd 保持已声明的有界安装、仿真与训练作业；每分钟的只读监督器
   保存进程、CPU、检查点变化、依赖状态及下一项 Agent 工作。
   监督器不调用模型，不会自主科研，也不自动重跑失败的物理实验。

官方说明：Goal 的续接是线程空闲时的事件驱动机制；会受到平台中断、暂停和预算等
条件限制，不能承诺平台关闭或断电时仍持续推理。
见 [Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)。
后台监督器不能取代平台续接；重启后必须核验进程和检查点再接续。

## 每一轮必须留下的交接

- 当前冻结源码版本、依赖、数据版本、作业名称与外置证据目录。
- 已完成的真实物理步数、神经推理次数、优化器更新次数；没有发生就明确记零。
- 已通过与未通过的指标，失败原始结果，尚未证明的能力。
- 下一步明确动作：等待有证据的前置作业、诊断具体失败、修改并测试新版本，
  或启动新的预声明试验。不能只留下“继续努力”。

有存活作业不代表本轮取得科学进展。安装依赖不是训练；PPO 参数变化也不是球技提高。
等待期间可推进不修改冻结作业源码的独立检查与开发。

## 结束一个作业后的决策

| 实际状态 | 下一步 | 禁止行为 |
| --- | --- | --- |
| 前置依赖仍在工作 | 检查真实进度，继续独立工作 | 因观察超时盲目重启 |
| 干净退出并产生结果 | 校验来源、原始轨迹和指标，再声明下一阶段 | 从 complete 文件名推断成功 |
| 实验失败 | 保留原始输出与计算计数，定位原因，冻结新修复后再测 | 热改运行源码、删失败记录 |
| 作业已结束但无后继 | Agent 必须选择并执行下一项有意义工作 | 把监督器心跳称作持续学习 |
| 平台中断或机器重启 | 从外置阶段记录恢复，先核实实际状态 | 假定旧 PID 或旧结果仍有效 |

## 当前学习链路与完成标准

现在的下一条链路是：合格动作数据 → 隔离训练依赖 → 32 环境 GPU 物理检查 →
两次 PPO 更新及 actor/critic 权重变化校验 → 检查点安全读回。
这是新神经策略的工程验收，**不是**足球技能验收。

工程链路通过后，仍需有界课程训练、独立动作与触球评价、原生 CPU 一致性检查、
未参与训练的情境验收，再逐步接入角色和球队。
最后目标仍是有证据的连续自主球队比赛视频，不是挑选几个好看的镜头。
未满足该目标时，不把 Goal 标记为 complete，也不把实验候选自动晋升。
