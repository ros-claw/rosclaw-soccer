# 为真正的同状态专家查询补齐路径

## 发现了什么

离线模仿学生的8个positive课程全部失败，包含原教师通过的4个
课程；旧保持课程4也从同接近策略的零参考成功变为学生不安全。
所以第二个去过去动作依赖模型虽然数值误差改善，必须继续接受
独立身体考试。原13体生产仍按原顺序完成，没有修改原结果。

下一步不能把“教师轨迹t时刻动作”贴到“学生轨迹t时刻身体”上。
两者已处于不同位置/速度/接触相位，同帧不代表同一状态。
本轮先实现诊断用途的`query_recorded_body`，从**这一条实际身体
轨迹**的测量状态和NAV，查询原bounded body-origin IK专家建议。

## 如何还原实际缓存时钟

原Euler 2ms积分后，qpos已推进，而xpos/J相关缓存还属于上一个
子步计算的位置。因此在50Hz帧t（t>0）中：

- 当前关节状态：原`canonical_qpos[t]`。
- 原缓存位置：密集回放的`qpos_before_substep[10*t-1]`。
- t=0直接用原初始位姿。
- 接触相位只消费已经完成的前一帧及更早六通道接触，不偷看
  当前帧将要发生的碰撞，更不读未来结果。

只在scratch MjData上调用运动学与CoM位置管线，再恢复原当前
广义状态但不刷新缓存，查询雅可比和原有连续有界IK。没有
`mj_step`、`mj_forward`、新Foundation、优化器或真实硬件调用。
[MuJoCo官方API](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html#mj-jac)
说明雅可比所需的最小位置管线是`mj_kinematics`后`mj_comPos`。
原积分、控制器、球质量/尺寸、世界与考试均未改动。

## 下一步与推翻条件

`rsi_query_student_body_expert.py`准备对原完整13体的**实际学生身体**
同样查询，要求完整生产、整批审计、39000子步密集诊断都正常
结束才读取。全13条及原失败保留，OFF还必须完整重现原专家。

这个后继还需要单独冻结配置/排队；没有称已执行。

已参考本地OpenTrack的`dagger_horizon.py`，提交
`cb9b751993a2483e5d1805a2565ddbfe950c04c9`：其核心是学生在当前
状态出动作、专家在同一状态给建议，然后实际执行学生动作。
借鉴的是同状态查询机制，不复制其G1运动跟踪资格到足球任务。

如果新去动作反馈学生仍不能完成身体任务，可在原来源级隔离下
将可信专家域中的学生自身状态加入一个有限DAgger消融；不能
跨身体轨迹造标签，不能用验证来源做梯度，不能删掉失败或保持
对照。专家建议没有从该状态向未来成功的证明，必须明确记录
这个限制，并用新的身体评估证实或推翻其学习价值。

如果查询器不能复现原teacher或当前身体缓存，则拒绝这批建议，
先解决时序/状态问题。如果查询可信但学生闭环仍退化，就需要
评估更充分的教师示范、接近策略适用域与闭环分布，而不是反复
增加同一个离线拟合的epoch。三个角色/4v4和宣传目标均未达成。
