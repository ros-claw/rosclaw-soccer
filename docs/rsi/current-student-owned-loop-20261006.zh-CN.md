# 当前学生自身数据的下一代接续

## 为什么不是再跑一遍旧训练

v771 已完成四卡、320 次实际联合更新，但它的输入仍是旧父策略
采集的 160 条轨迹。零输出头允许精确重构旧行为分布，却不能把
旧轨迹改称为新循环学生的实际探索。当前学生必须亲自执行，留下
完整状态、动作和概率，再让下一代继承其真实 actor 与 critic。

这轮采取一条有明确退出条件的有限实验链。所有阶段继续 SIM_ONLY；
失败有日志及部分证据，不自动晋升、不打开 Fresh，也不循环挑选
考试中最好的学生。机器有空闲不等于可以无门槛推进下一阶段。

## 如何保留真正的当前学生行为

每条轨迹先核对固定世界、来源、课程、采样视图和收据，随后使用
原始 MuJoCo 控制量进行完整独立动力学重放，重算实际 Foundation
历史。当前 GRU 隐状态、抽样均值、潜变量动作和 AR(1) 条件概率
也必须完整重构。仅有一个自报“通过”的 JSON 不构成资格。

再从实际编译世界读取规范腿关节的限位，使用新增序列提取器重算
因果 context、冻结 parent 均值、gate 与学习动作。终局 MC 标签
不能改变这些输入；所有失败的整段状态都保留。每条学习数组均
绑定实际轨迹、World、独立重放、Foundation 和当前行为模型哈希。

共享文件仅去除重复存储，不删除整个 parent、actor 或 critic。
恢复后必须是原来的完整逻辑模型。新证据放在有空余的独立本地
证据目录；仍要求系统保留 100 GiB，且完整试点容量预算先通过。
不会为了让任务开始而降低旧保留量或删掉失败轨迹。

## 学习算法及其边界

下一代继承 v771/student0 的真实 actor 和已拟合 critic。critic 不
重新随机初始化。四个学生各计划至多 80 次联合更新；学习率是
预声明的两组 0.00005 / 0.0001，主候选仍固定 index 0。

演员使用 clipped latent policy gradient；value 网络拟合完整原始
MC 回报。优势标签采用同一场景另外三次抽样回报的平均值作基线，
全量标准化，含正、负反馈。它不是 TD、GAE，也不是由 critic
实时指导的在线运动策略；critic 的质量须单独检验，不能因保存
了 value 权重就宣称已解决稳定性—可塑性矛盾。

GPU 分配前独立重算当前非零 GRU 的完整条件概率。每个优化步对
所有输入行检查边缘与条件均值 KL，超过原 0.02 上限时，演员、
critic 与优化器一起回滚。潜变量 likelihood 不冒充裁剪后的动作
likelihood，更不冒充直接关节力矩的控制策略。

v779 不重新执行物理轨迹：51,000 个物理重放子步和 5,100 次
Foundation 重算属于 v778，不能重复计数。数值拟合收据保持“不
认证物理来源”，外部编排单独绑定实际采集与审计证据。

## 必须正视当前未达标结果

v772 的模仿学习学生首条新探索已审计：脚接触干净，最低骨盆
约 0.708 m，但高质量踢球未达标。

v773 的梯度学生首条新探索也已审计：最低骨盆约 0.668 m，高质量
未达标，且接触不干净。两者并非同噪声对照，不能从这两条比较
算法优劣；也不能用一条轨迹断言全部考试通过或全部失败。

v773 的第二条也已完成全量审计，所有 native 数组与第一条精确
一致。整对工程资格完成，共 6,000 子步、600 次 Foundation 重算，
结果 `sha256:9cb506e10d0be03363b162108bb3a6cbab1bc0c47ce094b369776f7bb2d1c53b`。
两条都是同一课程的重复验证，不能把失败场景或课程数量翻倍。

这些结果说明，训练损失、实际参数更新与 native 资格都不是球技
成绩。下一步需要用自身失败反馈接续学习，同时让完整 52 场
考试裁决，而不是先拍一个剪辑掩盖问题。

## 保持原裁决，不偷换“成长”

原 M0 门槛继续要求高质量场景至少 20 个、旧高质量不丢、旧干净
触球不丢、不新增出界、全场最低骨盆不少于 0.65 m，并对 12 个
旧成功场景保持原共同轨迹逐帧精确一致。

即使更高平均回报，也不能替代这些约束。完整考试失败时保存并
分析失败，不宣称晋升、Fresh 通过、成熟小脑或全队自主比赛提升。
目前仍没有达到可宣传的连续球队比赛效果。

## 扩大训练前的吞吐工程

新增 `RecurrentSamplingViewBuilder` 仅构造独立 seed 的共享存储
视图。完整当前学生只在分配时校验、复制并缓存一次，后续 seed
仍把整个 mean 的规范 JSON 字节纳入逻辑哈希，并检查源码与缓存
完整性。它不提供快速运动 decoder 或任意工厂回调，不绕过正常
采样读取器，也不减少逐帧物理和 Foundation 审计。

3 项新 builder 测试与 2 项共享循环采样回归一起通过，共 5 passed。
覆盖 4 个不同 seed 的完整普通/缓存文档和正常读取器哈希一致、
caller 修改后的隔离、critic 完整保留、越界 seed、重封授权标志、
缓存内容篡改及源码漂移。局部 ruff、格式与 mypy 通过。

这只是经数值测试的持久化吞吐改进，尚未给出实际加速比例，更不
构成球技收益。运行中的 v778–v781 继续使用原冻结来源，不被此
改动替换；未来采集采用它之前，仍需独立 native 输运资格。

缓存构造器的完整 native 输运资格 v785 已排队：使用相同当前
学生与相同 seed，两个新对照分别与 v773 原始普通输入的全量
