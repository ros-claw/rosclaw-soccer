# 首触研究的吞吐瓶颈：先分清控制执行与证据准备

这是性能定位，不是球技增长或新训练成果。完整组合验证和运动模式
研究的固定参数、碰撞判据、旧证据与授权边界均未改变。

## 来源与方法

使用已独立认证的全部 16 个拟合初态重执行（包括两个删失结果），
不按耗时或成功筛选。核验该完整报告封印、当前研究记录链、每场
八个见证文件的字节身份和收据一致性，并检查读取前后文件哈希及
修改时间未变化。使用 `ATTEMPT_STARTED` / 完成事件的墙钟与文件
mtime 描述阶段跨度；每场的时间顺序均单调。

外部结果 `rsi-trained16-filesystem-stage-timing-20261017.json`，封印
`sha256:faba31ec8739342a2ddc46669a65725c1d4778b48ae41edb83a027d63b1e0904`。
这是文件阶段代理，**不是函数级 profiler 或单项 CPU 成本测量**。
没有新增身体物理、Foundation 调用或神经更新。

## 实测阶段中位数

| 墙钟/文件标记跨度 | 中位秒数 | 不能忽略的范围说明 |
| --- | ---: | --- |
| attempt 开始 → commitment 文件 | 129.84 | 含原生场景/模型准备、预览/绑定等；不能仅归因于某个函数 |
| commitment → trace 文件 | 8.37 | 控制循环、神经推理、物理及轨迹压缩混合 |
| trace → report 文件 | 39.19 | 报告构造、承诺计算、共享载荷与文件写入混合 |
| report → independent review 文件 | 55.57 | 包含 CPU 复核、Foundation 重算及其它验证，不只是 CPU 物理 |
| independent review → Foundation review 文件 | 0.008 | 只是两份审核文件的发布间隔，不是 Foundation 重算耗时 |
| Foundation review → ledger 完成事件 | 7.16 | 收据/见证处理与提交等混合 |
| 整个 attempt | 240.02 | 范围 226.61–339.64 秒 |

关键解释已核对执行顺序：`qualified_episode` 在写出两份审核文件
**之前**完成 CPU 审核、捕获验证和 `auditor.recompute(trace)`。
所以 0.008 秒不能用来宣称 300 次 Foundation 重算只用了 8ms；
前一跨度也不能全部算成 MuJoCo 重放成本。各阶段中位数不能直接
相加当作整场中位数。

首次 attempt 前的共享工厂初始化不在上述时间内。文件时间可能受
系统时钟影响，阶段还混有 I/O、压缩与验证；没有做 GPU 对照，不能
据此报告 GPU 加速倍率或未来优化收益。

## 决策与证伪条件

发现：该固定队列的控制循环与写出轨迹段约 8 秒，而整场约 240 秒，
证明不能把串行吞吐低默认归咎于身体物理或缺少 GPU。仍需定位准备、
模型/报告处理及审核中的具体开销，不能用此代理直接认定 JSON、
某个安全检查或某个神经网络函数就是唯一原因。

因此保留已排队的原工厂初始化 profiler；它只在组合 40 场正常结束、
完整账本和内存门通过后运行，不同时开启第三个完整工厂。该 profiler
只覆盖初始化，还不能替代每场预览/绑定与审核的进一步分项测量。

若后续优化私有不可变模型/报告处理，必须保留完整原模型（含 critic
与父代）身份和全部数值验证语义，通过同输入的采样、动作、物理和
评分逐项等价复试后才能采用。当前没有实施或证明加速，不删审核来
提高数字，也不热改正在运行的源码。若 profiler 不支持当前准备/报告
开销假设，就调整性能研究方向，不继续以猜测批量改写。

RSI 大范围回归另外在运行；它使用合成测试数据，不计入物理训练量，
尚未完成时不称全量通过。最终目标仍是实际技能增长和自主球队比赛。
