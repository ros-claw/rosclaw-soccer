# 三身体参考学生控制权验证（未训练模型）

## 为什么先做这个

过去的小幅力矩残差曾被父代反馈抵消，优化器更新不等于机器人真的
获得新技能。因此本阶段把参考学生放到父代运动策略之前，用其自己的
当前身体状态和历史隐藏状态推理，再让父代重新计算动作。先验证因果
链，再做教师蒸馏和在线更新，不重复在无效接口上扩大训练。

## 固定协议

只有三个新原生MuJoCo身体，每个各做一次独立CPU动力学、PD、父代
与Foundation捕获回放，共18000个身体积分子步。关闭新接口、数值零
GRU、仅左踝pitch输出头bias为0.2的GRU，依次运行。种子2026101901，
输入135、隐藏64、输出12；无优化器、无教师训练、无事后参数搜索。

三者使用旧plan18的C6/group76、原catalog2、相同初态、完整原父代和
采样种子。此group76与新plan19的同号group并不是同一课程。仅一个
派生课程、一个源场景簇，不能声称跨场景泛化。

关闭接口必须先复现旧C6的全部33数组、全部300帧原始字节，否则
立即终止，后两个身体不允许执行。零/非零学生各自前30帧必须复现
相同原始前缀。零输出只保留纯导航，不是原带接触IK教师的全程复现。

比较学生实际参考增量、父代前目标、父代后目标、实际关节位置四级
差异，四级均超过1e-8才记录观察到控制权。它不是稳定性、成功率、
自然性或射门精度改善的证据，任何失败均原样保留。

## 接续与审计

生产器 `rsi_reference_student_three_pilot.py` 启动前验证冻结源码、原始
证据、世界和56GiB可用内存；本项目最多两个完整原生NN工人。首次
启动标记与持久SQLite意图账本阻止隐式重试；失败不得自动改种子。

`rsi_read_reference_student_three.py` 只在实际生产服务正常退出后执行，
重新验证完整账本、三份原始收据、所有文件字节、共享父代payload、
实际采样种子、原始任务评分、CPU/Foundation审计、前缀/全程一致性、
四级物理差异。读取器不新增物理，也不会将数值模型晋升成训练策略。

这份文档是启动前协议，尚无真实三身体结果。mock编排测试不算
物理测试。所有教师/数据准入、训练、Fresh、运行晋级、硬件权限为false。

## 通过之后

只有控制权经真实身体与终态审计确认、跨来源教师整批独立检查完成后，
才从训练来源拟合归一化和GRU；验证来源不得进入梯度。然后做学生
自己的闭环物理评估、旧技能保留、失败归因，不能用教师轨迹回放代替
学生表现。未通过则按证据修接口或重新设计，不靠无限重启同一实验。
