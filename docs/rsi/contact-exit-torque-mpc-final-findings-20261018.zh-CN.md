## 新发现：不能只看“12Nm实际施加了”

对同一课程、同一时钟、相同增益的旧/新轨迹，在每20ms首个子步分解：

`ΔPD = Kp·Δtarget − Kp·Δq − Kd·Δvelocity`。

再将各项投影到当时请求修正方向，以该方向平方范数总和归一化。
context0的22个非零请求帧得到：

| 项 | 沿请求修正的归一化投影 |
| --- | ---: |
| 请求修正本身 | +1.000000 |
| 父控制目标变化 | −0.384543 |
| 位置反馈变化 | −0.308754 |
| 速度反馈变化 | −0.202307 |
| PD变化合计 | −0.895604 |
| 总请求/实际力矩差 | +0.104396 |

代数恒等式最大误差3.55e−14Nm。这是匹配时钟上的描述性分解，不是
独立组件因果消融；轨迹分叉后姿态与父目标都相互依赖。89.6%仅指
该投影，不是总力矩、能量或所有时刻的“抵消率”。

不过，它提出了比“残差根本没执行”更具体的假设：局部修正试图退出
接触，原位置跟踪及随后Foundation目标又在很大程度上拉回旧运动。
只在20ms内优化当前 held-target，无法充分观察后续这种反馈关系。
