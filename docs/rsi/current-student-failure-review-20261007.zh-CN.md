## 能解释什么，不能解释什么

已知事实是：自身数据接续没有增加高质量场景，新增出界反而
增多；训练覆盖仅有四个场景；训练输入上的 KL 不能认证未来
闭环观测分布的稳定性。覆盖不足是下一步可检验的假设，尚不能
断言扩大数据量必然解决失败，更不能承诺“多训就一定更好”。

value-only 基准已经表明更大的 critic 更新尺度能降低旧消费
数据预测误差，但 critic 目前不进入运动 decoder，也不提供
当前演员的优势标签。该数值收益不能被当作 v781 的球技收益。

## 降低证据处理开销，仍不减少物理验证

核验大模型共享报告时，普通读取器会重复解压、解析和序列化
同一完整 parent/actor/critic，可能成为批量训练吞吐瓶颈。新增
ROSClaw Core `CachedSharedPayload`，支持既有共享格式的 1–8 层
嵌套位置：完整 payload 复制成不可变规范 JSON 字节，一次编码，
每次仍校验其内容身份并将所有字节纳入原完整文档哈希。

同时支持在完整 envelope 验证之后，按原报告约定排除 root
`report_hash` 计算报告 seal；禁止排除包含整个模型的 root 分支。
它不读取物理状态、不加载运动 decoder、不提供执行回调，也不
认证外部来源。返回的紧凑字段仍含 marker，不是可执行策略；
调用方仍须验证实际文件、World、轨迹、动力学和 Foundation。
