# 门控提议数据与首轮真实 actor-critic 试验

## 结论

这轮不是突破，候选不晋升。完成了此前没有跑通的**原始提议 → 安全门 → 实际
力矩 → 真实足球回报 → critic/actor 更新 → 再执行**链路，但首个 RL 候选相对
BC 模型三例退步、一例改善，仍为 0/4 达到 0.1 m。不能说“RL 更新所以必然更好”。

## Core 通用能力

Core PR #765：<https://github.com/ros-claw/rosclaw/pull/765>。

- `control.guarded_action_trace` 是不依赖机器人型号/仿真器的数值证据记录器。
  分开记录原始提议、门控结果、父值和实际执行；有界连续时钟；显式缺失掩码。
- `G1NeuralTorquePolicy.pending_actor_proposal` 是只读拷贝，只在 command 与
  note_applied 之间可见。预热、状态保护、OOD 跳过推理时返回 None。真实推理后
  被门控拒绝的提议仍保留，不能与“未推理”混淆。
- replay 显式区分 APPLIED_TORQUE 与 ACTOR_PROPOSAL_THROUGH_GUARD，混合直接
  拒绝，哈希绑定动作语义。提议 Q 的 critic 不拿 BC anchor 的父值冒充提议；
  anchor 仍参与 actor 的模仿保留损失。
- 新 checkpoint 保存 critic 动作语义，禁止跨更新/重启悄悄切换。历史有更新、
  无字段的 checkpoint 按旧 APPLIED_TORQUE 解释，不猜测另一种语义。

Soccer 负责足球回报、共享场景和角色；没有把足球奖励放进 Core 通用记录器。

## 数据身份与因果边界

BC 模型增加采集而不改动作后，零/全介入各四个世界完成。独立时钟、身体观测、
PD、接触和神经重放核对：八个 proposal trace 字段、三个神经 episode 数组和
11 个物理/控制数组均逐元素相同。没有调用生产共享世界或力矩层来证明自己。
仍使用相同 Core 推理和相同 MuJoCo，不声称跨实现/物理引擎认证。

采集记录了真实 head 调用，不以零占位代替未推理动作。学习仅选当前/下一步均
有真实提议的样本。0/3 两个球位训练，1/2 两个球位只看验证，不以验证选训练
轮数。训练集为 1155 个抽样 transition，历史 anchor 为 1302 个模仿样本；
不是 1155 个独立场景，也不是大规模探索数据。GRU 仍为截断16步上下文，尚未
解决与运行时持续隐状态的全部偏差。

足球奖励只依赖真实相邻状态：触球后的球向目标推进、实际首次穿越 x=5 平面的
精度、实际身体姿态/关节运动/力矩成本，实际摔倒或非脚触球事件。不把未来落点
放入策略观测。Monte Carlo 回报可以使用未来奖励作训练标签，二者不可混淆。

原 gamma=.995 对2ms时钟的 e-fold 时间约0.4秒，不适合本轮球飞行。显式仅迁移
gamma 为 .9995（约4秒），保留模型、Adam、critics、RNG、Fisher 和保留锚。
迁移后、训练前重新导出的部署二进制与原 BC **逐字节一致**，防止“续训”实际上
重置或换了 actor。

## 实际优化器更新

先做128次 Monte Carlo critic 预热，actor 不变；再用同版本采集数据做两次 SAC
更新，policy lag 分别0和1，不在第三次继续冒充 fresh。

- 新 actor 更新2次，保留原 BC390次，actor Adam 全部状态 step=392。
- critic Adam step=130（128 MC + 2 SAC），alpha Adam step=2。
- 最大 actor 参数变化约0.000863，action_limits 不变，不是只改模型版本号。
- 真实权重与完整 checkpoint 均存外部，SAC update_index=2。

这里的两次更新不是“大规模在线强化学习已完成”。没有摔倒样本也不证明 fall
critic 已学会识别和处理摔倒；其接近零的损失可能只是全零标签。

## 再执行的结果

| 原四球位 | 父控制器误差 m | BC+修复约束 m | 首轮 RL m |
| --- | --- | --- | --- |
| 0（训练） | 0.2882 | 0.4850 | 0.5930 |
| 1（验证） | 0.5703 | 0.4470 | 0.5618 |
| 2（验证） | 0.3456 | 0.3153 | 0.3351 |
| 3（训练） | 0.8692 | 0.5198 | 0.3788 |

RL 四例均健康完成652周期，实际力矩确实介入，RMS约3.18–3.22 Nm；零介入仍
完整身份一致。全部候选均未达到0.1m，不能改评分点或把进步的第3例单独剪成
“强化学习成功”的宣传视频。

## 暴露出的真正问题与下一轮

1. 约束 critic 的 MC 标签是数百级累计回退次数，预热验证 MSE 从约178087
   只降至169710；奖励 critic 从60.5降至13.1，仍不支持可靠的细小精度改进。
   不能因 loss 有限或下降就认定 value 已校准。三类回报量纲、每物理时间的
   熵项、损失缩放与约束预算需要一致设计。gamma 改为长时域后熵的累计作用
   也放大了，原默认 alpha 不是自动合适的。
2. 单个确定性行为策略的两条训练轨迹，不能可靠识别反事实动作效果。需要在
   原力矩约束内、显式种子和行为身份下收集探索提议，并独立重放。优先探索
   模型提议，不给球加脚本力或跳过身体。保留全部种子和失败，不挑最好球位。
3. 必须先通过 value 校准及真实保留验证再扩训练量。不能继续重复同一批数据
   的多轮 SAC，把 stale lag 写成0；也不能重新从零训练步行/踢球网络。
4. 本 pilot 的冻结 Core 为146866f3，早于语义 checkpoint 字段加固，因此它的
   checkpoint 尚无 replay_action_semantics 字段。其提议语义由本次声明与源
   哈希证明；不能直接交给新 Core 按缺省 APPLIED_TORQUE 继续训练。下一轮应
   从原 BC 未更新 checkpoint 或显式审计迁移开始，不静默改标签。
