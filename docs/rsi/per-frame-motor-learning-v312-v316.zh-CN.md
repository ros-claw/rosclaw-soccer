# 逐帧小脑学习：v312–v316 实施记录

日期：2026-10-01。仅仿真研究，不授权真实机器人，不表示球队能力已达标。

## 为什么继续重构

此前在训练课程上 v308/v309 单次决策网络达到 11/12 高质量触球。
但 v310 首次未见课程考试只有 27/40，对照 21/40；虽然整种子聚类
bootstrap 增益区间为 +2.5 至 +27.5 个百分点，仍有旧干净触球退化和
新出界，安全/保留门拒绝晋升。不能把“平均进步”解释成可靠成长。
此考试池已永久消耗，不会重复冠名独立考试。

## CPU MuJoCo 迁移检查：发现真实缺口

下载 SONIC 参考项目独立工作树的原生 MuJoCo 网格，保留原参考树；
加载真实 MuJoCo 模型，以 50 Hz 决策、500 Hz PD 进行物理执行。
记录实际关节、速度、根姿态、球和接触，而非播放 Isaac 轨迹。

第一轮 CPU 参数与 Isaac 摆腿合同不一致（0.55/0.05 对 0.95/0.15），
只保留为诊断，不能作公平迁移成绩。修正后在一个已消耗课程：

| 策略 | 接触 | 最低骨盆高度 | 结论 |
|---|---|---:|---|
| SONIC 基础运动 | 不干净 | 约 0.706 m | 不达标 |
| 基础运动 + 任务空间摆腿 | 不干净 | 约 0.706 m | 不达标 |
| 固定全局学习修正 | 干净脚触球 | 约 0.706 m | 单课程通过接触检查 |
| v309 一次决策神经网络 | 不干净 | 约 0.099 m | 摔倒，拒绝 |

不能仅归咎于网格或仿真器：加入不同运动修正后的结果明显不同。
单课程结果不构成 CPU 全面资格；独立 CPU 门和逐帧网络迁移仍待完成。

## v314：真正的逐帧神经网络，但首先是模仿暖启动

134 维因果输入包含实际关节位置/速度、体坐标速度、球相对状态、
足/胫几何、当前基础目标、上一帧实际修正和上一已完成帧接触力。
没有种子、课程编号、未来轨迹和结果标签进入运行时网络。
Actor 为 134→128→128→12；critic 为 134→128→1。
12 个双腿关节修正幅度上限 0.16 rad，每帧变化上限 0.012 rad。
它叠加在基础运动策略上，**不是直接输出力矩的端到端策略**。

离线选择成功教师只发生在训练数据构建阶段，不是运行时结果路由。
52 条真实轨迹、15,600 帧：41 条成功轨迹提供动作模仿监督，
11 条失败轨迹仅提供终局结果监督。18 个训练种子簇、4 个验证簇。
200 epoch 的离线验证平均误差约 0.00196 rad，活跃修正误差约 0.00532 rad。
这是 teacher-forced 离线误差，不能称为在线 RL 或闭环成功率。

## v316：正在实际采集在线策略梯度数据

已启动 4 课程 × 8 次逐帧高斯探索，以及 4 次父基线、4 次确定性
网络复现。计划 40 次物理执行；本记录不把未完成实验写成完成。
抽样发生在 tanh、关节限制和 slew 之前，保存/重建的是潜在高斯动作
及其概率。不能对限制后的关节输出直接套高斯密度。

下一步是基于真实终局结果的 Monte Carlo PPO-Clip 原型，gamma/lambda=1，
更新 actor 和 critic，保留旧成功状态均值策略回放、精确高斯 KL 上限。
训练损失或 KL 通过不等于物理保留门通过，候选必须重新执行并复审。
参考 [PPO 原论文](https://arxiv.org/abs/1707.06347) 和
[Spinning Up 算法说明](https://spinningup.openai.com/en/latest/algorithms/ppo.html)。
未实现 AReaL 集成，没有宣称完整球队 PPO、持续力矩控制或硬件安全资格。

## v318：逐帧 CPU 迁移和独立动力学复审

新增 CPU 逐帧模型执行入口及独立复审器，重载编译后的 MuJoCo 模型，
从初始状态重新执行 3,000 个物理子步。每步核对 PD 力矩、实际执行力、
本体/球状态、接触力及骨盆高度，并重建每帧神经网络关节目标。
不是把保存的身体姿态逐帧写回去播放。

三个完成的 CPU 探针都已独立复审：

| 课程 | 模型 | 干净脚触球 | 最低骨盆 |
|---|---|---|---:|
| 20261177/0 | 固定全局冠军 | 是 | 0.70598 m |
| 20261177/0 | 逐帧模仿暖启动 | 否 | 0.68728 m |
| 20261282/0 | 逐帧模仿暖启动 | 是 | 0.69545 m |

暖启动不再像旧一次决策神经网络那样在第一个 CPU 探针摔倒；
第二个困难课程也干净触球。但第一个课程接触不合格，仍不得晋升。
这里的“干净”检查全程足/胫接触，不只是第一次碰球的那一帧。

## ROSClaw 与 Soccer 的边界

Core 提供通用锚点保护和稳定优势权重；足球环境、运动观测、接触任务、
课程及视频留在 Soccer 下游。Core PR #615 的 CI 已通过，尚未合并。
Soccer 已测试部分直接提交 main；原始数据、权重、完整视频不进入 Git。
成功与失败证据均保留，代码提交不代表学习模型晋升。

只有完成独立增益、技能保留、安全、CPU 迁移和重载门后，才继续
运动员→角色→团队→比赛。当前不生成新的宣传片掩盖基础缺口。
