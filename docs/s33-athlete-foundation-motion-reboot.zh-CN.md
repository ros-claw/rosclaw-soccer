# S33 Athlete Foundation 与全身门将动作重启实施报告

日期：2026-08-14
范围：仅仿真（`SIM_ONLY`），未连接 ROS 传输层，未向真实机器人发送命令。

## 1. 先说结论

讨论 3 对问题的判断是对的：前几轮继续扫手臂幅度、给固定动作叠加补丁，已经不能解决“像不像运动员”和“能不能在动作中保持平衡”这两个核心问题。本轮因此停止把 S31 的手臂特化策略当成全局进步，改成以下学习链路：

```text
人类/外部全身动作
  -> 统一 Motion Atlas
  -> Athlete Foundation 学习型全身跟踪器
  -> 统一物理 Shootout
  -> 足球任务残差 RL
  -> Growth 晋升 / Dream 回放巩固
```

这次得到一个重要但尚不完整的突破：

- 直接 PD 回放六段门将动作时，6/6 跌倒，恢复率为 0；
- 预训练的 Humanoid-GPT 全身跟踪器在四段动态动作上 4/4 完成，没有中途退出；
- 但它把跳跃和侧扑幅度明显“压小”了，所以只是“稳定性改善”，还没有解决“可塑性不足”；
- 因为缺少脚滑、力矩、骨盆高度、动作后恢复等同口径指标，本轮没有产生新的 Athlete Foundation champion，也没有声称足球效果已经变好。

换句话说：路线已经从“动作补丁”切换到“数据驱动全身小脑”，但当前学到的是先不摔倒，尚未学会既不摔倒又把动作做足。

## 2. 为什么旧路线会越调越僵

旧的 Humanoid-Goalkeeper 适配器只取原始 21 个关节中的上肢部分，并明确把前 12 个腿部关节清零；随后又裁剪成约 25 帧并做 0.55 的幅度限制。这会产生三个系统性问题：

1. 手臂在扑球，腿、腰和根节点却没有同步做支撑面转移；
2. 控制器只能在动作发生后用大力矩补救，表现为抖动、后退和抽搐；
3. 手臂专项指标可能提高，但全身足球能力并没有可继承的增长。

本轮重新建立的适配器保留六段动作的完整长度、根节点轨迹、全部 21 个可观测关节、17 个刚体状态，并显式标记 G1 上未被原数据观测的 8 个关节。没有裁帧，也没有隐式幅度裁剪。

## 3. ROSClaw Core 的通用能力改造

### 3.1 Canonical Champion Registry

新增 `CanonicalChampionRegistry`，把“谁是当前冠军”从各实验目录中的散落 JSON 提升为通用、只追加、可回放的晋升账本。它支持：

- 全局基线、全局替换、专项冠军、归档四种权限；
- 候选声明的父记录与父权重哈希必须同时匹配当前 head；
- 过期分支 fail-closed，不能覆盖新 head；
- 重启后从事件日志确定性恢复；
- 始终保持 `SIM_ONLY` 激活上限。

这不是 G1 专用模块，任何 ROSClaw 实践领域都可以复用这套冠军谱系和晋升权限。

### 3.2 LearnerBackendContract

新增后端中立的学习器契约，统一描述：

- 输入/输出模态；
- 是否支持推理、训练、在线更新和多 GPU；
- 模型、数据、配置和日志承诺哈希；
- 运行状态、退出码、硬件边界和证据文件。

这样 Growth 不需要知道后端是 SONIC、Humanoid-GPT、OpenTrack 还是 ProtoMotions，只依据能力和证据作编排与晋升。

## 6. 物理实验结果

### 6.1 实验 A：直接全身 PD 回放（失败基线）

在 CPU MuJoCo 和通过资产资格检查的 G1 场景中，六段动作全部运行，并在动作后进入恢复窗口。

| 指标 | 结果 |
|---|---:|
| 动作内关节 RMSE | 0.06709 rad |
| 平均脚滑 | 0.51074 m/s |
| 最低骨盆高度 | 0.06648 m |
| 峰值力矩占限幅 | 1.000 |
| 力矩饱和率 | 2.018% |
| 根节点角速度 P95 | 2.7193 rad/s |
| 关节 jerk RMS | 76,943.68 rad/s³ |
| 动作后恢复率 | 0/6 |

结论：角度 RMSE 看起来不大并不等于控制成功。机器人可以在跌倒过程中“跟对关节角”，但支撑面、根节点和接触动力学已经失败。该证据被明确标记为 `PHYSICS_UNQUALIFIED`。

### 6.2 实验 B：Humanoid-GPT 官方稳定步行

先用官方脚本和官方模型做 600 帧冒烟测试：

- 轨迹完成率 100%；
- 关键点位置误差 0.00810 m；
- 关节误差 0.04472 rad；
- jerk 158.81。

这证明本地模型、转换链路和 CPU MuJoCo 推理工作正常。

### 6.3 实验 C：四段动态门将动作

根节点先消除初始偏航，XY 轨迹旋转到规范坐标系，根高度以 0.80 m 重基准，四元数从 `xyzw` 显式转换为 `wxyz`。修复前 `leftjump` 只完成 2.84%，修复后四段均完成 100%。

| 动作 | 完成率 | 关键点误差 | 关节误差 | 根位置误差 | jerk |
|---|---:|---:|---:|---:|---:|
| leftjump | 100% | 0.06933 m | 0.08785 rad | 298.13 mm | 432.52 |
| rightjump | 100% | 0.04228 m | 0.11790 rad | 140.21 mm | 516.08 |
| leftstep | 100% | 0.02972 m | 0.08603 rad | 104.89 mm | 135.63 |
| rightstep | 100% | 0.06397 m | 0.10507 rad | 136.51 mm | 435.90 |

平均关键点误差 0.05133 m，平均根位置误差 169.93 mm。视频中的白色机器人是学习策略，粉色透明机器人是参考动作。白色机器人保持稳定，但没有充分追上粉色参考的跳跃幅度，这正是本阶段暴露出的 stability–plasticity dilemma。

由于官方输出没有脚滑、力矩、骨盆高度、根角速度和动作后恢复指标，这组结果是 `PARTIAL_PHYSICS_TRACKING_PASS`，不是完整 Shootout 胜利，也不能晋升 champion。

### 6.4 实验 D：OpenTrack 专项数据桥与训练

四段规范动作已经转换成 OpenTrack 原生轨迹：

- 36 维 `qpos`，35 维 `qvel`；
- `qvel` 使用 `mujoco.mj_differentiatePos`，避免对四元数做错误的普通差分；
- OpenTrack 自己完成 31 个刚体的前向运动学；
- 原始 30 Hz 动作统一重采样到 50 Hz；
- 自动生成平滑起止过渡后帧数为 522 / 432 / 422 / 427；
- 原始证据只读，预处理写入独立工作副本。

4×A6000 已被 JAX 识别，并完成一轮从零开始的 100,000-step PPO 闭环：

- JIT 编译 225.10 秒，实际训练 93.91 秒；
- 产出 Orbax checkpoint 与 2.33 MB ONNX；
- JAX / TensorFlow / ONNX 三路输出的平均绝对误差为 `7.74e-08`；
- 训练集为四段、共 1,803 帧的完整动作，不是手臂子集。

但独立 CPU MuJoCo 回放给出了明确否决：四个动作都在第 52 帧跌倒，也就是约 1.04 秒；跌倒前完成比例分别只有 10.00%、12.09%、12.38%、12.24%，平均关节 RMSE 约 0.362 rad，最低骨盆高度约 0.077 m。该 checkpoint 已封存为 `PHYSICS_UNQUALIFIED`，拒绝模型也随证据保留；证据哈希 `sha256:4fc872c2…`，不会成为 champion。

这说明“RL 应该越训越好”需要加限定：100k 步证明了软件和梯度闭环，远不足以从零学会全身动态控制；直接扩大随机 PPO 还会浪费样本。下一步应从已稳定的 foundation 做专项蒸馏/残差学习，并逐步解冻，而不是从随机策略重新学站立。

## 7. Foundation Shootout 为什么仍然没有冠军

统一 Shootout 的门槛同时检查：

- 动作完成率；
- 关键点与关节跟踪误差；
- 脚滑；
- 最低骨盆高度；
- 峰值力矩与饱和率；
- 根节点角速度；
- jerk；
- 动作后恢复；
- 技能切换。

当前 PD 基线有完整指标但物理失败；Humanoid-GPT 物理完成但缺少安全与恢复指标。因此 `foundation-shootout-pending-v1.json` 合法地返回 `PHYSICS_EVIDENCE_PENDING` 和空 winner，而不是挑一个“看起来最好”的模型强行晋升。

## 9. 下一步工程闭环

下一阶段不应回到手调幅度，而应按以下顺序推进：

1. 完成 OpenTrack 专项训练并用同一物理评测器补齐脚滑、力矩、骨盆、恢复和切换指标；
2. 把 SONIC、Humanoid-GPT、OpenTrack、ProtoMotions 放进同一个 Motion Atlas Shootout；
3. 冻结胜出的 Athlete Foundation，仅在其上训练足球任务残差；
4. 逐步解冻腰、腿和根节点，采用位置条件 motion prior / AMP，防止动作模式坍缩；
5. 用自适应难度把准备、侧步、扑救、落地、起身串成全身门将任务；
6. 只有同时通过物理安全门、足球成功门和旧技能保留门，Growth 才能晋升；失败轨迹进入 Dream 回放，而不是污染在线 champion。

真正的目标不是让某一条视频更夸张，而是让 G1 能在变化的球路下，选择自然动作、保持平衡、完成任务，并把新技能可靠地留在 ROSClaw 的可审计成长谱系里。
