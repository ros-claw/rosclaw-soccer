## 实际打通 Core Practice 的范围

将同一公开失败课程的原始与表面提案轨迹导入独立 Practice 目录，每条取
300 个真实控制时刻的目标、实际关节、误差、命令力矩和完成步支撑力，加一条
失败事件。导入前重新核验原始 NPZ 哈希并重算接球判决。

使用隔离 Core 分支的正式 CLI，两个 session 分别完成 `record`、`verify
--strict`、`distill`。输出各一条失败知识，候选、晋升、sim2real 记录均为零。
没有伪造改进措施或成功闭环；Practice 校验通过只表示数据链路完整。
数据的墙钟明确为**导入时间**，模拟时间单独保存，未虚构原仿真墙钟。
力矩字段是命令力矩，不冒充硬件传感器实测。

外置目录：`receiving-mechanism-reboot/practice-integration-v1/`，包含输入 JSON、
每条 CLI 的 stdout/stderr、目录数据库、知识文件和 `complete.json`。
没有调用机器人 Runtime、训练权重、访问设备或修改用户默认 ROSCLAW_HOME。
