# 从人类参考到反馈教师：当前的接触缺口

2026-09-21，SIM_ONLY；全部实验无权重更新、无晋升，不构成 E2 通过。

## 人类动作参考并未直接带来接球

从 OmniContact 的 TRAIN 部分、已审计减速窗口中筛选脚接近球、无手接触
标注的候选，选定两个不同源动作。90 Hz 重采样到 50 Hz，使用当前实测入口
姿态作 300 ms 过渡，经冻结 low-latency SONIC 跟踪。对两场已见课程，
分别比较零导航和两种参考，每种独立重放，共 12 次。全部身体安全、重放
一致，但全部未接住；四个人类参考条件甚至没有测得本球员脚球接触。

参考根平移不进入 G1 编码器，因此“离线身体和球看起来对齐”不意味着
执行时能跟到该世界坐标。私有 FK 诊断还显示姿态跟踪及实际根位置的偏差。
这不是数据无价值的证明，而是不能把动作回放直接称为闭环接球教师。
源数据仅限非商业研究，不进入宣传视频或 MIT 发布资产。

首版运行因缺少显式 SONIC 入口帧在物理开始前失败，原日志保留；修正入口
后在独立 v2 目录完成上述 12 次，不重写失败记录。

## 当前状态驱动的脚部参考仍未通过

另做八次执行：两场 × 固定入口姿态 / 当前状态脚部 IK × 独立重放。
反馈只读取当前球和身体值，在私有 MuJoCo 数据上计算运动学，预测使用
明确的恒速模型，不读取未来真实轨迹、不改实时球或机器人状态。
它改变的是 SONIC 参考，不是模型权重、PD 增益或足球残差。

所有执行身体安全、无 motor fault、重放一致，但新增安全接球 **0/2**。
蓝方组织者从零脚球接触变为四帧接触，连续控球仍为零；触球第一帧记录的
脚体原点横向速度约 1.47 m/s，而球横向速度约 0.45 m/s。后续球速下降时
球已离脚过远。该速度是 50 Hz 原点差分，不是碰撞接触点的微步速度，
只能用于诊断，不能单凭此值断言冲量成因。

按先行的零增益停止规则，不扩大本 IK 参考族的采样或调参。后续教师必须
同时控制接近、接触相对速度和卸力/跟随，并在物理中验证；“多碰几帧”
不能替代原接球考试，更不能据此启动 DAgger/PPO。

外置证据：`m0/human-contact-reference-v2/complete.json`、其
`kinematic-diagnostic.json`，以及 `m0/causal-foot-reference-v1/complete.json`。
实验脚本 `probe_causal_foot_reference.py` 的内容哈希写入协议与轨迹；
该外置原型没有修改默认控制路径。

## 支撑脚资格：抬高脚踝不等于离地

另做无球基础能力检查，固定站立、横向移重心 8 cm、移重心并让右脚参考
抬升 8 cm，各两次五秒执行，共六次。身体稳定且重放一致。第三种条件
右脚踝在固定保持窗口平均高约 0.093 m，但右脚仍承担约 88 N 法向负载。
从已完成 qpos 在私有数据上重新计算七个脚碰撞几何的表面距离，脚仍贴地。

再用四次执行隔离“只约束脚位置”和“同时保持脚姿态”的参考 IK。位置组
逐数组复现前次原件；姿态约束组仍约 90 N 右脚负载，没有真正获得离地窗口。
因此不能把遗漏姿态约束当作已解决的根因，也不继续盲目调足高/增益。
这些是基础跟踪和支撑诊断，不是接球分数或完整官方 SONIC 系统质量判断。

这一教训反馈到通用 Core `surface_snapshot`：从当前姿态的私有 FK 查询
具名碰撞几何间距，不用身体原点代替表面；截止距离/不支持的组合返回未知。
该接口在上述实际轨迹 100 帧、每帧七个几何对上与独立审计完全一致，未改
live pose/cache 或模型，未推进物理。Core 的相关 16 项测试及 sim 全组
338 项通过（一个既有模型 attach 警告）。代码进入 Core PR，不混入足球控制器。

证据：`sonic-support-transfer-v1/complete.json`、
`sonic-support-orientation-v1/complete.json`，各自 `surface-clearance-audit.json`，
以及 `core-surface-snapshot-v1.json`。

## 自然步态的正对照与接球干预审计

自然导航参考在同一足球资产上完成三个五秒条件及各自独立重放，共六次：
向前、侧移、向前后在两秒处刹停。全部身体安全、严格重放一致。向前进展
3.162 m，侧向进展 2.109 m；刹停条件末速度 0.0121 m/s。按真实脚碰撞
表面离地超过 2 cm 且法向负载低于 20 N 的联合条件，三组都至少有一只脚
连续满足 0.2 s。侧移右脚仅 0.18 s，不能声称双脚都通过该时长。
这证明当前底座存在自然换脚和刹停能力，不证明接球能力。

另在原始 29DoF 资产上保留明确的运行时关节参数，完成站立/全姿态移重心
各自重放共四次；全姿态组右脚仍约 93 N 负载，未支持静态参考卸载成功。
这不是完整官方 43DoF DDS 系统的验证，也没有修改足球考试资产。

两个 A3 已见成功解在新邻域的七个合法课程上未迁移成功：基线与候选各自
重放，共 28 次、全部安全、双方均 0/7。原协议第八课速度 0.475 m/s 超出
既有课程域，执行前报错；保留部分报告，不把它算作物理失败，也不补课
凑成完整协议。新增课程预检用于防止此类声明错误再次占用仿真资源。

随后保留自然导航参考与已有 A3 参数，只在实际脚表面离地时提出有界的
当前状态脚球参考修正。两个已知失败邻域课程 × 开关干预 × 重放，共八次，
全部安全、重放一致，新增成功 0/2。独立审计发现：

- 慢球例干预从未触发，编码 token 和球轨迹与对照完全相同，不能当作有效
  干预的失败证据。
- 快球例五个窗口生成修正；编码/执行 token 与球轨迹均改变，但仍未接住。
- 两例首个窗口都有脚触球后的非脚部接触，慢球还缺足半秒观察时间。
  后续球变慢并留在脚边，不会抹除先前违规或自动补成合格接球。

因此停止这个具体修正族的扩采，先定位非脚碰撞及动作时序，不增加 reward
或 PPO 轮数，不放宽现有标准。这是诊断性干预，不是教师训练或 E2 通过。

首版原型的私有窗口冒烟检查出现 `abs(list)` 错误，却因后续 lint 成功掩盖
退出状态而误启动；仅两次未启用干预的基线完成，两次重放中断，无干预
成绩。原日志和轨迹保留。修正后在独立 v2 目录先通过 200 个私有窗口检查，
再执行上述八次。后续启动须分别检查冒烟与 lint 的退出码。

证据：`sonic-navigation-support-v1/complete.json`、
`sonic-native-support-v1/complete.json`、
`m0/sonic-positive-neighbourhood-v1/recovered-partial-report.json`、
`m0/swing-surface-reference-v2/complete.json` 及 `intervention-audit.json`。
这些检查没有新增权重、晋升候选或打开 Sealed Bank。

### 命名关节的局部权限检查

`shin-contact-audit.json` 重建包含双侧球门的完整场景，并要求编译物理哈希
与原轨迹完全一致后才解释碰撞 ID。确认慢球例为右小腿、快球例为左小腿。
不能拿省略第二球门的场景解释数字 ID；几何插入顺序会改变这些编号。

后续局部探针固定 token、导航速度、时间和其他关节，只对相应腿的膝/踝
给出预声明的 3×3 组合，每坐标最大改变 0.025 rad 的未过滤名义残差。
原有裁剪、滤波、力矩门及考试不变。每案含零改动对照，各自重放，最多
36 次执行。无增益则停止该族；即使找到成功也只是局部可达性，非反馈教师。
结果以 `m0/shin-clearance-local-oracle-v1/complete.json` 为准，不能从协议
的预算数量推断完成数量。

可复用的 `training.receiving_oracle_local_probe.local_oracle_proposals` 使用
具名关节而非裸索引，保留原解为第一个候选，拒绝越界、重复坐标、重复
候选及完全饱和的无效修改。它与该探针两组各九个提案逐元素一致。
新增 18 项单测，连同嵌入、调度、课程预检共 54 项通过；目标模块 Ruff
和限定导入的 mypy 通过。跟随全依赖的 mypy 仍报三个其他模块错误，不能
称全仓类型检查通过。
