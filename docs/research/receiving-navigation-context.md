# 接球预测的只读场景上下文

2026-09-21，SIM_ONLY。此接口是 Soccer 研究工具，不是 Core 硬件控制接口，
也不自动授予教师、学生或晋升资格。

## 为什么加入

私有小脑预测已恢复 LSTM 和记忆时钟，但旧预测固定查询时的世界导航指令。
触球后的导航会跟随球调整，漏掉它会误判关节提案。加入原生导航后，还须
知道其他球员的位置和速度，才能估计避碰约束。

`training.receiving_scene` 提供冻结、无模拟器引用的数据：

- 当前帧、接球者、世界配置哈希、当前意图；
- 排序且不重复的其他球员 ID、当前平面位置及速度；
- 当前持球者、接球租约拥有者及激活状态；
- 当前导航保持状态、实际接球脚横向偏移；
- 特殊导航路径是否可能影响当前接球者的保守标记。

拥有者必须属于观察名单；帧、有限数值、长度、唯一性、严格布尔均检查。
这些数据不会声明未来租约、意图、邻居运动或控球状态保持不变。

## 集成与兼容

反馈提供者显式声明 `requires_navigation_context=True`，并同时要求
`requires_locomotion_memory=True`。世界在本帧导航计算处复制当前场景，放入
`ReceivingLocomotionContext.scene`，仍由原来的残差 cursor 限幅、滤波和执行。
提供者不能改物理状态、控制句柄或检查门。

记录 `receiving_feedback_scene_json` 和规范内容哈希。源观察与 LSTM 都是
当前步积分前，普通球员姿态轨迹则在积分后；检查当前邻居位置时，应对应
上一条积分后轨迹，而不能读取下一帧冒充当前观察。

默认不采集场景，无场景字段从观察哈希中排除，保留旧观察身份。声明在
提案前后改变、场景缺失、错帧、错接球者或输入变更均使实验边界锁定失败。
另修复反馈契约先于 team 包导入时的循环依赖，增加独立进程导入检查。
