# M0 接球 Oracle：四路执行器与共同运动前段

2026-09-20。以下是接口资格与实验协议，不是 M0 通过或球技提升声明。

## 这次接通的实际控制链

- A0：在现有 12 维腿部残差入口执行有界、可插值的搜索轨迹。
- A1：同一基础控制链，允许 29 维关节目标残差；没有修改身体、球、关节保护或力矩上限。
- A2：显式选择 low-latency SONIC，支持从指定控制帧接管。
- A3：同一 low-latency SONIC 加 29 维小残差，接管帧必须匹配。

搜索轨迹不是神经网络学生。幅度 0.1 rad、每控制帧变化不超过 0.02 rad、滤波系数 0.25；记录请求残差、最终 PD 目标及守卫后的实际关节力矩。
未提供 Oracle 参数时，旧比赛路径保持默认行为；未启用的 Oracle 不能改变基线轨迹。

## 重要的失败与修复

外部第一版 qualification 的场景 ID 不符合既有 `s199.` 契约，未通过入口。第二版运行虽可重复，但与历史 R0 不同：旧脚本的导入曾隐式改变 pacing、跟随导航、接触教师侧向偏置及 one-touch 开关。
该版本保留为失败证据，没有被用作 R0 比较。

现在 `training.receiving_classroom` 显式重建这些参数，并在物理执行前校验冻结的 world 与 teacher 哈希；不存在“只要能运行就接受新基线”。
`ReceivingPracticeCell` 将接球课程任务限定在目标实例，不再全局替换 `RosclawSoccerAgentCell.decide`；课程实例有独立的 cell 身份，其他角色仍是原实例。

延迟接管的第一次配置也被原有门控拒绝：未注册 motor 的分支不能启用 motor idle fallback。修复调用配置后重新执行，没有放宽门控。

## 实际资格结果

外部 `m0/interface-qualification-v3/verification.json`：

- 6 组（旧基线、未启用搜索、四个动作路径），每组独立执行两次；一例物理场景，不是 12 个独立任务。
- 四路无 motor fault；初始 integration state 和编译模型哈希相同；每组所有轨迹数组重复一致。
- 旧基线与冻结 R0 历史轨迹逐数组相同；未启用的 Oracle 也不改变基线。
- 该例 R0 有接球成功；未优化的四路探针没有新增接球成功。A1 非零上肢残差确实进入控制链，不能仅凭“29D”宣称更强。

外部 `m0/interface-qualification-v5/verification.json`：

- 改用实例级接球课程，在第 30 控制帧（0.6 秒）分支。
- 四路分支前的物理轨迹、分支处完整 integration state 与模型哈希相同；各路独立整段回放一致。
- control 仍与历史 R0 原始轨迹完全相同。
- SONIC 在实测分支状态 cold-start；没有声称已迁移旧网络的隐藏状态。

快照记录的是物理状态。控制器状态通过从同一初态执行已验证的共同前段重建；不是跨进程恢复整个 Python 对象，也不是 64 个代表性初态已经完成。

## 下一步的有界搜索

先做 8 个公开案例的 CEM pilot：0.75/1.25 m/s、左右来球、站立起点／共同运动前段；每个案例、每种动作空间最多 16 次执行，包括选中候选的独立回放。
保留原生 R0 作为 A0/A1 的合法 incumbent；不把“零残差替代原策略”当成它们的最优能力。
学习模型权重不更新，PPO 不启动，sealed 不访问。

该 pilot 不能替代总纲要求的 64 例 M0。任何“所有空间都不行”的结论都必须限定搜索预算、搜索族和初始化条件，不能推导物理不可能。
