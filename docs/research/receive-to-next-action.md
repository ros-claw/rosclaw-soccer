## 第一轮：Receive→Dribble 对照

只在同一球员连续干净控球至少半秒后尝试交接；角色仍须授权 CARRY/DRIBBLE，
不伪造球权，RECOVER 优先，其他球员保持原决策。三个条件各独立执行两次：

1. 继续原接球教师；
2. 任务仍接球，只将 residual 切回原神经网络输出；
3. residual 切回原神经网络，同时显式切到带球任务。

不重置身体、球、LSTM 或滤波历史；不重新开启被抑制的额外任务力矩。
期望 residual 仍为原 `0.1*tanh(actor raw)`，通过原 cursor 的限幅、滤波和
速率限制。交接并非训练：权重没有更新。

预声明的一秒带球探针要求：球朝进攻方向推进至少 0.2 m、再次有自己的脚
接触、期间球距最近脚不超过 0.55 m、球高不超过 0.2 m、末速不超过
0.8 m/s，没有接触中断，且整个记录期间原生身体安全通过。这是新的后继
动作测试，不修改原接球考试。所有几何来自同刻的球状态与私有 FK 足位置。

## 可复用的后继动作验收

`training.dribble_successor_exam` 将固定一秒、两秒标准从实验脚本提取为
有测试的值级验收器。必须提供入场帧及完整 50 Hz 连续序列、同刻球/足
几何、无回退或未来时间的接触历史。缺帧、重复、非有限值、历史遗忘等
属于无效证据并拒绝；有效但动作失败的记录返回明确失败原因。

它不验证上游文件签名、主体身份、几何来源和身体安全判定，也不证明
入场资格；这些仍由独立证据审计与 `ReceivingControlWitness` 负责。
所有结果固定 SIM_ONLY，READY 和训练授权始终为假。23 个新单元测试
通过；对以上八次真实执行的 16 个考题重审，与原结果及数值一致。
审计 `m0/dribble-successor-exam-audit-v3` 不新增物理场次，也不是事先注册。
第一次审计因重复创建进度文件停止，原证据和停止原因保留；第二次完成，
第三次在极大整数校验加固后重新绑定源代码并完成。
第四次审计扩展到 16 次执行、32 个固定考题，仍与原始结果和数值一致；
它没有增加独立课程或物理执行次数。

深度与朝向条件。因此不能把“已控球半秒”直接写成“可立刻切传球模型”。
这也没有证明经过主动准备后不可能传球。此处没有执行传球、改变球权、
放宽入场阈值或重新打开被抑制的任务力。

STANCE_DEPTH / LATERAL_ALIGNMENT / HEADING_ALIGNMENT；激活授权固定

## 原生传球实测与只读物理证据解耦

`m0/receive-to-pass-native-v2` 完成四次实际执行、1902 次私有预测。
不发起请求的对照精确复现原接球物理轨迹；传球分支两次均在 2 秒
形成请求，入场前缀和独立全数组复跑一致，身体安全，但原生踢球模型
没有激活，也没有新的传出脚触球。结果是失败，不是已学会传球。
v1 因缺少桥接参数在物理执行前停止，原失败协议仍保留。

`m0/native-pass-preparation-audit-v1` 对实际失败轨迹只读重审：请求时
站位深度约 0.203 m，朝向偏差约 1.001 rad；请求后仅十帧仍有原生
近期触球球权，没有任何帧同时满足几何条件与球权。后来调整朝向及
站位时已失去球权。下一机制应检验接球过程中的后继准备，而不是
放宽球权/入场条件，或继续增加同类微小 residual 搜索。

新增 `skills.team.physics_evidence` 和可选 `physics_evidence_consumers`：
每个消费者只接收不可变的 500 Hz 值，不注册电机、不提供动作、不占用
控制权。身份/时钟/完整性错误或消费者异常会锁存证据故障并否决该次
结果的 passed，但不改变身体安全事实或清除别的电机目标。它是可信
进程内接口，不是任意 Python 插件的安全沙箱。默认关闭时旧结果哈希
结构不变。

冻结源 `7360ce5` 的关闭/开启/故障注入各两次物理执行完成，共六次、
990 次私有预测。所有轨迹数组与旧失败传球对照逐值一致；开启组每次
完整采集 3000 个物理样本且独立复跑一致；故障组第 0.01 秒注入异常，
此前四个样本保留，故障被报告而球员动作不变。

无干扰与故障隔离，不证明传球成功、已激活踢球时的恢复或全局资格。

定向 mypy 通过。仍未启动 DAgger/PPO、更新权重或打开 Sealed。

### 完整触球链路重审

`training.pass_contact_chain.inspect_pass_contact_chain` 在完整 500 Hz
记录中检查请求后的传出脚触球、离脚间隔、目标接收脚触球，并拒绝
中途他人/身体/环境触球、同刻抢球、时钟缺口与身体不安全。它只返回
触球归属事实，不等同于传球质量、接稳、READY 或学习授权；来源认证
及接球控制考试仍必须由调用方完成。

`m0/pass-complete-contacts-audit-v1` 重审开启记录组两次完整执行，均为
`no_sender_foot_contact` 与 `no_clean_receiver_arrival`。这排除了只看
50 Hz 画面误把球的自然滚动算成传球的做法，没有增加物理执行或独立
课程数。新接口十项测试覆盖干净传递、外界干预、同时接触、无力触球、
时间缺口及到达后的不安全尾段；与观察接口共 29 项通过。

### 下一机制的廉价证伪

`m0/successor-direction-feasibility-v1` 检查同一接球对照的 19 个控球
探针合格帧，对三个同队接收目标分别计算原生入场几何。三个目标都
没有几何合格帧。因此“换一个传球对象就能直接启动”没有得到支持。

`m0/pass-control-geometry-overlap-v1` 用实际传球失败轨迹的 2001 个
请求后物理样本及独立 FK，检查一个刻意乐观的上界：暂不要求触球
新鲜度、控制持续时间等，只看身体安全、脚球距离不超过 0.35 m、
球速不超过 0.5 m/s。376 个样本满足这个上界，204 个样本满足踢球
几何，两者交集仍为零。接收目标用最新记录的 50 Hz 测量，属于诊断
近似，不是逐子步在线激活证明。

这否决了仅延长球权期限的静态解释，并不证明新的动作准备不可行。
下一候选必须改变接球到踢球之间的实际身体/球状态：在保持原始接稳
与安全考试的条件下，提前准备朝向和支撑站位，再产生新的脚球互动。
先验证这一段控制可达性；不可通过修改考试、重置电机历史、瞬移球、
恢复额外任务力或静默打开另一种球权估计器来解决。
