# 实验接续与 Agent Loop 的真实边界

当前目标仍未完成：没有新增合格的连续自主 G1 4v4 宣传片。
本说明区分“任务在跑”与“确实学会了”，不把监控心跳算作能力提升。

## 三个不同层次

- Agent 负责提出假设、审查证据、开发和选择下一轮实验。产品侧当前
  Goal 保持 active；本地监控脚本本身不会唤醒或调用语言模型。
- 有限实验链可以独立执行：上游通过后，已声明的后续任务开始；
  完整性失败则拒绝后续分配，不自动重跑覆盖旧证据。
- 只读监控负责观察进程、检查点和声明的依赖关系。CPU 活动、文件
  存在以及 systemd 成功退出，都不等于科学结果已独立验证。

因此不能承诺产品关闭、电脑断电后 Agent 仍然自主开发，也不能承诺
训练必然突破。应保存源代码版本、输入哈希、实验声明、完整失败记录
和恢复指针。重启后需要审查已收费的尝试，而非直接重新执行原命令。

## 当前有限链

1. 六场原始完整模型与存储适配器对照。
2. 六场独立记录控制的原生物理复核。
3. 四十个公共场景、每场两个预先指定的相反动作，共八十场新执行。
4. 八十场独立物理复核。
5. 事实配对数据入库，原保持集只评估、不进入梯度。
6. 固定预算的三种子响应模型拟合；分来源检查退步，不只看平均分。

另有修正存储子类识别的两场实验，等待第 3 步的完整构造器结束，
再分配另一个构造器，随后进行自己的独立物理复核。

这些任务已分别声明物理步数、预测步数、优化器更新预算与截止时间。
它们不是无限自启动训练器，也不会自动授予策略控制权或真实机器人权限。

## 监控不应把等待说成训练

`rsi_watch_research_loop.py --dependency-plan <JSON>` 支持一个精确匹配
当前 campaign 集合的有向无环依赖图。只接受固定里程碑：成功终态且有
完成文件，或当前研究专用的 `factory-contract.json` 构造器里程碑。

新增 `declared_work_role` 分别显示等待前置、依赖失败待审查、当前阶段
待核实执行、以及完成元数据待认证。保留原进程观察，不修改实验文件。
禁止未知节点、重复前置、循环依赖和任意里程碑路径。里程碑内容仍未
由这个监控器验证，不能拿它替代原始数组、物理和模型的独立复核。

本轮六场对照实际完成 18,000 原生子步和 2,800 预测子步，原数组与
任务判定逐位一致；独立复核另完成 18,000 原生子步，检查误差全部为 0。
但该版本转换的 guard 数量为 0，不能宣称存储加速。另有 216 个历史
动作配对通过新提取函数的实际数组重建检查，零物理步和优化器更新。
这些是下一阶段的工程证据，不是球技提升、在线 RL 成功或比赛突破。
