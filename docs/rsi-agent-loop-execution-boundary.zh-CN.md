# 实验接续与 Agent Loop 的真实边界

当前目标仍未完成：没有新增合格的连续自主 G1 4v4 宣传片。
本说明区分“任务在跑”与“确实学会了”，不把监控心跳算作能力提升。

## 三个不同层次

- Agent 负责提出假设、审查证据、开发和选择下一轮实验。产品侧当前
  Goal 保持 active；本地监控脚本本身不会唤醒或调用语言模型。
- 有限实验链可以独立执行：上游通过后，已声明的后续任务开始；
  完整性失败则拒绝后续分配，不自动重跑覆盖旧证据。
- 只读监控负责观察进程、检查点和声明的依赖关系。CPU 活动、文件
  存在以及 systemd 成功退出，都不等于科学结果已独立验证。

因此不能承诺产品关闭、电脑断电后 Agent 仍然自主开发，也不能承诺
训练必然突破。应保存源代码版本、输入哈希、实验声明、完整失败记录
和恢复指针。重启后需要审查已收费的尝试，而非直接重新执行原命令。

## 2026-10-20：当前续接机制与实际阶段

产品 Goal 实际状态为 active，完成条件仍为证据充分的连续自主 G1 球队比赛展示，而非某个命令成功退出。根据 [OpenAI Docs 的 Goals 说明](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)，续接在一轮结束、线程空闲、没有其他待处理工作或用户输入、Goal 仍活跃且未耗尽预算时发生。纯计划或没有工具调用的续接不会形成无限空转。

执行约束是：每轮须产生可核实的开发、实验、分析或排障；保存当前源码/输入身份、原始结果、失败原因、下一项可执行工作；未达到目标不标记完成。观察器每 60 秒观察明确声明的实验及其依赖，但不能选择新科学假设或启动 LLM。产品退出、用户中断、预算限制等边界仍然存在，不能承诺绝对不停机或必然突破。

最新阶段是[预测式球入口八实例对照](rsi/predictive-ball-entry-20261020.zh-CN.md)：实际和独立记录控制回放均已闭合，合计 110,400 新原生步，0 优化器更新。结果是**拒绝**，干净脚触球 2/4→1/4，不是突破。当前不应重复相同短视导航试验，而应从同一本体/神经历史预测至原任务 H300 终点，覆盖接触参考、触球及后续身体，保留逐帧名义反馈候选。这个后继仍需实际开发和验证，并未由监控器自动产生；阶段切换不等于全部目标完成。

## 早期已声明的有限链（不是当前运行状态）

## 2026-10-21：续接必须包含真实后继工作

Goal 保持 active，完成条件没有降低。Agent 每次续接先读取不可变实验
结果和恢复指针，再选择可执行的开发、诊断或训练任务；不是重复输出
“继续训练”。正在执行的任务固定源码和输入哈希，终态后验证原数组、
独立物理复核和失败原因，再声明新阶段。进程退出成功不是策略晋升。

当前阻塞训练扩量的是 GPU 接触力可靠性，而非显存：六次诊断
（Graph/eager 各三次，共 480 GPU world steps + 480 原生步）均未通过
既定传感器误差门限。关闭 Graph 未解决问题，传感器与历史缓冲读数
一致。保留失败，不剪裁尖峰、不降低 10 N 触球阈值、不扩大量学习
这个未可靠验证的奖励信号。

非零球感知候选另完成 18,360 原生步、1,836 次神经网络调用和八次完整
执行（两个案例 × 两臂 × 两次独立重复），重复完全一致。但左脚案例
初始臂用左脚首次触球，候选变为右脚；右脚案例两臂都先由左脚触球。
因此候选不晋升，不能把球移动更远称作踢球能力突破。当前后继是基于
上游 tile-sort 配置差异的独立进程内对照诊断，而非重复同一 PPO 预算。

这里的系统监控只观察已声明任务。它不启动模型，也不保证产品退出、
断电、用户中断或平台预算限制时继续运行。恢复指针必须记载这一边界，
不得将 systemd timer 描述成无限自主 Agent Loop。

## 历史有限链明细

1. 六场原始完整模型与存储适配器对照。
2. 六场独立记录控制的原生物理复核。
3. 四十个公共场景、每场两个预先指定的相反动作，共八十场新执行。
4. 八十场独立物理复核。
5. 事实配对数据入库，原保持集只评估、不进入梯度。
6. 固定预算的三种子响应模型拟合；分来源检查退步，不只看平均分。

另有修正存储子类识别的两场实验，等待第 3 步的完整构造器结束，
再分配另一个构造器，随后进行自己的独立物理复核。

这些任务已分别声明物理步数、预测步数、优化器更新预算与截止时间。
它们不是无限自启动训练器，也不会自动授予策略控制权或真实机器人权限。

## 监控不应把等待说成训练

`rsi_watch_research_loop.py --dependency-plan <JSON>` 支持一个精确匹配
当前 campaign 集合的有向无环依赖图。只接受固定里程碑：成功终态且有
完成文件，或当前研究专用的 `factory-contract.json` 构造器里程碑。

新增 `declared_work_role` 分别显示等待前置、依赖失败待审查、当前阶段
待核实执行、以及完成元数据待认证。保留原进程观察，不修改实验文件。
禁止未知节点、重复前置、循环依赖和任意里程碑路径。里程碑内容仍未
由这个监控器验证，不能拿它替代原始数组、物理和模型的独立复核。

本轮六场对照实际完成 18,000 原生子步和 2,800 预测子步，原数组与
任务判定逐位一致；独立复核另完成 18,000 原生子步，检查误差全部为 0。
但该版本转换的 guard 数量为 0，不能宣称存储加速。另有 216 个历史
动作配对通过新提取函数的实际数组重建检查，零物理步和优化器更新。
这些是下一阶段的工程证据，不是球技提升、在线 RL 成功或比赛突破。
