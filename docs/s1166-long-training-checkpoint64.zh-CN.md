# S1166：长训练到第 64 代的结论与下一轮

## 结论

没有达到宣传要求，不晋升这个模型。更多训练没有在本次固定 CPU 配对考试中带来更好的精确首传：

| seed 114864，32 个训练过的身体上下文 | 原始第 8 代对照 | 第 64 代候选 |
|---|---:|---:|
| 身体安全 | 31 | 32 |
| 受控出球 | 5 | 4 |
| 严格精确首传（≤0.1 m，且其余原生门控通过） | 2 | 0 |
| 非脚接触 | 2 | 0 |
| 后续本体重触球 | 0 | 1 |

两组初始身体、球和基础控制器状态匹配。CPU 配对审计重算了记录中 2 ms 的目标平面交叉与触球信用窗口，误差复算最大差为 0。它没有重新执行完整物理轨迹，不是新的身体上下文泛化考试，也不是 4v4 比赛。

第 32 代的另一随机种子曾显示 1/32 到 2/32，不能与本次不同种子当作同一连续测试曲线。第 64 代固定 GPU 开发评估为 256 身体安全、8 精确首传，但 8 个副本只代表 1 个独特身体上下文的成功；不能拿 8 个副本当作 8 种球技。

## 实际完成的工作量

从已审计的第 8 代继续，实际完成第 9–64 代共 56 次 rollout/update：14,336 个训练 episode、3,584,000 个控制步、13,343 次 Adam step。不是原计划的 128 代，也不是新的 14,336 个独立身体上下文。

其中第 9–56 代为 S1146：12,087 次 Adam step，随后第 57 代 reset 显存不足退出。S1161 对所有 48 次已完成更新进行精确复算并通过。S1162 从模型、Adam、Torch/CUDA 与 NumPy RNG 一致的第 56 代状态，在新证据目录完成第 57–64 代，共 1,256 次 Adam step。S1163 对恢复起点与这 8 次更新的复算通过。

S1166 依次执行训练审计、CPU 对照、CPU 候选和 CPU 配对审计，四项均正常结束。这里的“审计通过”只表示证据与计算一致，不表示球技通过。

## 调整下一轮，而不是宣称长跑成功

综合此前小幅且不稳定的收益、第 64 代考试未改善，以及训练窗口的显著不均衡，降低继续同一条 128 代长跑的优先级；保留未完成计划和 OOM 记录，不修改目标来包装通过。这是工程资源分配决定，不是统计上证明该算法永远无效。

S1167/S1171 开始另一组预先限定的配对实验：两组都重新从原始父模型和零修正头开始，各训练 16 代。只改变 actor 损失是否按每次尝试等权；其他奖励、GAE、critic、动作与安全约束相同。两组都保留失败，使用固定最后一代考试，不挑最佳中间代。共同 CPU 球扰动种子为 116901，不用考试数据训练。

本轮使用已提交的静态 contact-storage 校验优化和默认关闭的等权选项。该优化已做同状态接触查询等价检查，默认 PPO 路径也已精确复算旧更新；仍不声称跨进程 GPU 物理逐位一致。运行工作树已安全快进到 `e997430`，新实验开始后再次冻结源文件。GPU 训练与审计通过共享互斥锁串行；不触碰真实机器人。
