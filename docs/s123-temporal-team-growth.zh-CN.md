## 1. 结论先行

本阶段把 S122 的“单帧反应式跑位”推进为有短期记忆、保守继承父策略、能从失败中修正接球与制动行为的三 G1 共享物理闭环。

最终 v8 密封考试结果：

- 时序候选：8/8 合格，安全率 100%；
- S122 父策略：5/8 合格，安全率 100%；
- PASS/SHOOT：各 4 个未见案例；
- 精确复跑：8/8；
- 机器人之间的物理碰撞：0 步；
- 路线命令变化 RMS：`0.004573 m/s/step`，父策略为 `0.006818 m/s/step`，降低约 32.9%；
- 预测接球反射在 4 个传球案例中实际触发，关节残差峰值受限于 20 N·m；
- 连续置信度制动在 2 个困难对角跑位中实际触发，峰值 `0.1674 m/s`，低于 `0.18 m/s` 上限。

阶段独立验证结果为 `VALIDATED_TEMPORAL_MULTI_AGENT_STAGE`，错误列表为空。

这不是“完整比赛已经学会”的结论。当前 PASS 和 SHOOT 仍是不同战术回合，尚未证明同一接球队员在一次不重置的物理时间线内完成“移动接球—调整—射门—门将扑救”。本阶段也没有训练端到端关节力矩策略，更没有真实机器人证据。

## 2. 这次真正开发了什么

### 2.1 时序神经路线 actor

新增 `growth/temporal_route_actor.py`：

- 输入由 14 维当前观察、14 维指数移动平均和 2 维上一时刻命令组成，共 30 维；
- 训练端使用 PyTorch 小型 MLP，四张 GPU 分别训练独立候选；
- 发布物是纯 JSON 数值，运行时只依赖 NumPy，不加载 pickle 或可执行模型代码；
- 网络只输出平面速度请求，不能直接输出姿态、关节、力矩、球状态或硬件命令；
- S122 ridge actor 是冻结主干，时序网络只提供有界残差；
- 使用父策略衰减上限、残差/父命令比例上限、PASS 近目标父策略锚定和 OOD 支持门，控制可塑性，避免为了新样本遗忘旧能力；
- 每个 episode 都重置时序记忆，禁止跨考试样本泄漏状态。

四卡训练实际设备为 `cuda:0`、`cuda:1`、`cuda:2`、`cuda:3`。最终 seed 为 1231，模型哈希为：

`sha256:ab788a2a353d178594ffb92f6588298937d0afbe6272b76d2df82b7c5ea1f7ee`

训练/验证序列共 16 条、5600 帧。相对父策略：

- RMSE：`0.065174 → 0.056575 m/s`，降低约 13.2%；
- 命令加速度 RMS：`0.016588 → 0.014768 m/s/step`，降低约 11.0%；
- 支持域接受率：100%。

### 2.2 通用的反应式运动执行加固

`shared_world.py` 与全身 2v1 桥接新增了以下闭环组件：

1. 弱侧镜像执行：RoboNaldo locomotion 在局部负 y 半空间明显较弱，复用已经验证的镜像本体感知/动作路径，修复“命令向左、身体却向右漂”的执行错误。
2. 角色碰撞盾：根据实时角色间距生成有界速度修正；最终 v8 有 4 个案例实际触发，机器人互撞保持为 0。
3. 接球后随动：接触锁存后继续向进攻方向运动 0.35 m，避免触球后立刻木桩式停住。
4. 全动作关节守卫：之前只保护 PASS 接球队员，v6 暴露 SHOOT 无球队员越界后，扩展为所有反应式跑位。
5. 预测接球反射：用实时球位置、球速度、脚位置和 MuJoCo 关节雅可比，把 0.10 秒后高速来球的脚部误差转成受安全投影约束的有限力矩；没有放大脚或球的碰撞体。
6. 连续置信度制动：根据首帧前向/横向误差连续计算困难对角接近置信度，再用本体速度生成有界制动。普通样本修正接近零，困难样本平滑增加，消除了 0.499/0.500 m 硬阈值导致的策略跳变。

其中第 5、6 项是失败驱动形成的运动反射与稳定器，目前是可解释的工程模块，不应冒充“网络自己学出的肌肉记忆”。下一阶段应把它们的输入、激活置信度和成功/失败标签蒸馏回通用 growth actor。

### 2.3 证据与验证能力

新增 `training/temporal_route_growth.py` 和 `training/temporal_route_validation.py`：

- 从已发布 S122 物理轨迹提取有顺序的训练序列；
- 四卡独立候选训练、CPU 汇总、稳定性/可塑性门控；
- 开发样本与密封样本 ID 强隔离；
- 每个最终案例运行时序主策略、时序精确复跑、S122 父策略，共 24 次 CPU MuJoCo；
- 每条 NPZ 同时绑定文件哈希和语义轨迹摘要；
- stage-summary 绑定模型、训练报告、开发报告、最终考试、7 轮拒绝历史、当前实现哈希和 Git 基线；
- 独立验证器不调用训练代码，重算全部提交并 fail closed。

## 3. 失败是怎样推动成长的

没有删除或改写失败结果。正式历史如下：

| 密封代次 | 时序候选 | 父策略 | 候选安全率 | 结果与主要发现 |
|---|---:|---:|---:|---|
| v1 | 未完成 | 未完成 | — | 冻结战术 actor 对一个案例 OOD，考试中止并记录 |
| v2 | 7/8 | 7/8 | 100% | 弱侧执行错误仍存在 |
| v3 | 6/8 | 4/8 | 87.5% | 镜像改善任务，但暴露碰撞和稳定性问题 |
| v4 | 7/8 | 5/8 | 100% | 碰撞盾有效，出现时序候选对父策略的单例退化 |
| v5 | 7/8 | 5/8 | 100% | 父策略锚定修复退化，仍有高速接球近失误 |
| v6 | 6/8 | 2/8 | 87.5% | 接球反射仍弱；SHOOT 无球队员缺少关节守卫 |
| v7 | 7/8 | 4/8 | 100% | 唯一失败初始横向误差为 0.499464 m，揭示硬阈值不连续 |
| v8 | 8/8 | 5/8 | 100% | 连续置信度制动首次通过全部门槛 |

典型闭环：

1. v5 困难样本的脚—球最近距离约 17.6 cm，但没有物理接触；
2. 固定目标平移和简单追球命令均没有改善，试验被撤回；
3. 轨迹显示问题是全身横向过冲和摆腿相位，而非碰撞体积；
4. 雅可比预测接球反射把 v5 样本转为真实接触；
5. v6 又暴露更大的全身过冲，于是加入本体速度制动；
6. 全局制动破坏普通跑位，因此被撤回；
7. 硬分类在 v7 的 0.499464 m 边界失败；
8. 连续置信度既保留普通样本，也修复困难样本；全新 v8 首次 8/8。

这就是本阶段“自进化”的实际含义：保留失败、定位可观测失效模式、提出有界候选、在已揭示样本回归、换新密封集考试，只有新集通过才晋升。

## 6. 仍然不足的地方

1. 最终候选的 teammate root jerk 为 `30.2661 m/s³`，父策略为 `30.0224 m/s³`，约高 0.8%。命令更平滑，但全身根部 jerk 没有同步改善，不能宣称身体已经更自然。
2. 预测接球反射和制动置信度仍是可解释工程模块，不是端到端学习策略。
3. PASS 只证明传球与移动接球；SHOOT 只证明射门回合中的团队跑位。没有连续的一脚传射链。
4. 门将在同一共享求解器内活动，但本阶段没有重新训练门将扑救策略。
5. 所有证据都是 CPU MuJoCo；没有真实 G1 迁移和 sim-to-real 结论。
6. 模型没有任何自我授权、真实电机权限或“意识”证明。这里的本体记忆只是数值状态，不应与主观意识混淆。

## 7. 下一阶段建议（S124）

优先顺序：

1. 建立一次不重置的“前锋传球—接球队员移动接球—一脚射门—门将扑救/二次反应”共享世界考试；
2. 将接球反射、制动置信度、碰撞盾激活和全身安全状态写入通用 growth transition schema，而不是留在足球专用训练器；
3. 用 v1–v7 失败及相邻开发样本训练小型 gating network，蒸馏目前的手工连续制动，保留硬安全上限；
4. 奖励同时加入接球成功、接触前相对速度、根部 jerk、足滑、接触冲量和接球后可射门姿态，避免只追任务成功；
5. 在四卡并行训练后，仍用 CPU MuJoCo 新密封集做唯一晋升真值；
6. 为旧阶段单独排期重新跑物理证据，不能仅更新 implementation hash。

S123 的突破不是“已经像顶级球星”，而是把一个长期 7/8、对临界初值敏感的路线系统，变成了在新密封集上 8/8、安全、可复现、失败历史完整的时序团队闭环。下一步应把这套成长机制从案例模块进一步上提为 ROSClaw 的通用自进化能力。
