# S2076–S2082：持续动作学习与真实传接失败链

## 结论

没有达到连续自主比赛宣传片标准，未晋升任何学习候选。
已取得一个工程上的明确改进：在保持传接前段完全不变的对照中，依据正在执行
运动技能的邻居实测速度做提前避让，消除了射门后的机器人碰撞。
但后续射门仍有非脚部接触和偏出边线，不能把身体安全误报为足球表现合格。

## S2076：0.2 秒导航决策学习

冻结接球和所有关节策略，蓝方中场仅学习三个导航潜变量。一次决策维持 10 个
物理控制帧，帧内奖励折扣求和，块间折扣使用 `0.997**10`，末尾不足 10 帧的块
明确为终止块。没有把一段持续动作重复算作十次独立决策。

三轮各四个探索世界及独立重放，实际决策块数 327、373、356，共 1056；
优化器各 36 步，共 108 步。训练世界身体安全 12/12，固定考试父子均为身体安全
4/4、严格接球 2/4、中场合格传接 0/4。新触球未转化为可靠传球，不晋升。

全部三轮优化器更新逐位重放通过；另外逐帧核对全部 20 个世界的双份轨迹、
动作保持、块奖励、实际作用掩码，并验证首轮两个案例与 S2074 原始对照逐位一致。

实验之后对块索引增加无符号整数越界回归检查。实验所用原始模块保存在
`source_snapshot/navigation_blocks.py`，可结合 Git `7cf0a34` 重建当时源码树；
后续加固没有重写原始实验记录或将其冒充新版本采样。

## S2078：换用已经发生第二次触球的课程

S2072 的一个父代球位 `(4.92,-0.49)` 能依次发生后卫传球、中场接球及出脚、
前锋较晚射门。因此使用该物理链作为新的开发课程，仅训练中场近球关节头，
不再只在完全没有第二次触球的球位探索。此球位属于已见开发数据。

四轮各四个世界和重放；中场有效更新样本为 379、525、546、109，共 1559。
训练身体安全 13/16。出现一条 `physical_receive_confirmed=True` 的诊断记录，
但该轨迹有机器人碰撞；进一步检查也发现前锋接球先碰到非脚部，因此不能视为
干净、合格的完整传接。这说明单一诊断标签不足以作为晋升门。

固定考试父代身体安全 4/4，候选 3/4，二者严格接球 2/4、传接诊断成功 0/4。
四轮优化器精确重放通过，候选拒绝。

## S2082：保住前段，消除射门后的机器人碰撞

选用 S2078 `train-001-1` 的冻结模型和探索种子。前 611 帧公共物理轨迹必须
逐位不变；这覆盖原来的传接行为。只在实际滚动射门技能已启动后，对其邻居
增加基于实测速度的短时预测避碰平面，原有位置净空约束仍然保留。

| 预测时长 | 机器人接触计数 | 世界身体安全 | 实际射门 |
| --- | --- | --- | --- |
| 关闭 | 57 | 否 | 有 |
| 0.20 秒 | 0 | 是 | 有 |
| 0.35 秒 | 0 | 是 | 有 |
| 0.50 秒 | 0 | 是 | 有 |

四例均有完全一致的独立重放；关闭对照与旧轨迹全部列逐位一致。
三种预测均消除该案例的机器人碰撞，但只是单个已见失败案例的工程对照，
尚未证明广泛泛化，也不是更换足球尺寸、改碰撞体或修改球状态的结果。

进一步核对：前锋在 5.76/5.78 秒先发生非脚部接球，5.82 秒才有脚部接触；
13.24 秒射门同时有自身非脚部触球，随后球又碰到对手，偏向边线。球没有成为
到达球门的威胁，不能据此认定守门员“不愿扑救”。完整比赛门保持不通过。
后续学习只可选取干净的局部出脚窗口，不能把污染片段标为合格接球或精彩进球。
