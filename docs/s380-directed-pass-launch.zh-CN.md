# S380：准备触球不等于传球已经发出

## 结果

修正了接球窗口过早计时的问题，前锋由漏接变成实际脚部接触球，但随后仍有非脚部碰球，完整接传链路未通过。

证据：`/code/rosclaw/phase8_evidence/s380-directed-launch-shared-world-v1/assessment.json`。

| 同一 20 秒八人场景 | 原触球计时 | 有方向出球计时 |
|---|---:|---:|
| 八台身体安全 | 是 | 是 |
| 机器人碰撞 / motor fault | 0 / 0 | 0 / 0 |
| 16.82 秒仍在接应 | 否 | 是 |
| 后段球到前锋最近脚距离 | 0.423 m | 0.141 m |
| 前锋实际脚部接触 | 无 | 17.40、17.42 秒所在控制帧 |
| 随后非脚部接触 | 无 | 有，故不合格 |

关闭新功能的完整 trajectory 与 S377 directed 精确相同。开启后保留了此前前锋传中场、中场神经接球及目标条件化出球控制；两组都运行 100 帧接球网络和 250 帧出球网络。并未将安全 smoke 的 `passed=True` 当作整场比赛成功。

## 原因与修改

原接球窗口以任意源球员脚部触球启动，12.728 秒的准备触球被视为已发球，约 15.8 秒窗口过期；实际明显出球更晚，前锋在球接近时切回其他任务。

`PassHandoff` 新增可选、创建时固定的 `launch_target_xy` 与 `observe_directed_launch`。新模式下：

- 普通准备触球不填写发球时刻。
- 必须是约定传球者的真实脚部接触，力大于 1 N，球向约定目标的速度投影至少 0.4 m/s。
- 目标不能在观测时任意替换；无脚接触、弱接触、反向/纯横向运动或对方干预不能变成发球。
- 原准备期与飞行期上限均保留；重复触球不能不断续期，过期承诺不能复活。

世界配置 `directed_pass_launch` 默认关闭，开启要求严格物理握手。关闭时原固定配置哈希及轨迹不变。新模式的实测发球时刻约 15.332 秒，前锋可以持续接应。它只改进事件识别，不授予控球、硬件动作或晋升权限。

## 尚未解决

前锋在 17.40 秒脚部碰到球后，球被弹起，下一控制帧有非脚接触。因此当前需要训练前锋自己的干净减速接球，不能仅复制传球者的收益曲线，也不能以第一下脚部碰球判定成功。

现有 `diagnose_passes` 仍是按战术承诺边沿和 50 Hz 峰值触球推断的诊断工具；本次多次准备承诺与实际发球时刻不完全一致，其 `NO_POST_COMMITMENT_FOOT_CONTACT` 不能替代明确的物理事件链。同样，实际脚接触也不能绕过非脚接触的拒绝条件。后续报告应绑定握手身份、真实发球事件和接球窗口。

20 项新增测试通过；Ruff、mypy 440 文件通过。全量 **1683 passed、29 skipped、11 既有历史证据绑定失败**。未改写历史证据、未降低安全阈值、未采用新比赛冠军。所有试验 SIM_ONLY。
