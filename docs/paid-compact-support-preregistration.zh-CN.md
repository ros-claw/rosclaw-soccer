# 首脚学习死梯度复盘与连续紧支撑对照

这是 SIM_ONLY 研究协议，不是模型晋升、实机授权或球队比赛成果。

## 已证实的失败

`full-entry-contact.trajectory-support.v2` 的三个固定种子各执行了 512 次门训练和
1024 次动作头优化，但逐张量对照发现：三个动作头的参数变化均为 **0**，末层权重和
偏置仍全零。所有 3228 个教师状态均被校准后的保护门拒绝。

因此优化器步数只能证明计算发生，不能证明有效学习。几何诊断检查了 3228×18694
对自身观测，14 条教师轨迹均无与受保护状态完全相同的特征；这不能证明全局 MLP 门
可泛化，却排除了这批缓存上的精确标签冲突。失败记录保留，不追加同类盲目训练。

## 新假设与固定对照

输入仍为自身标准化 160 维观测与自身 R2 的 128 维隐状态。父模型、R2、原动作尺度、
最终相对 R2 的每关节 0.2 rad 权限、同一 TRAIN 数据、三种子均不变。没有案例编号、
成功标签或教师 IK 进入推理。新增连续紧支撑：

- 每个成功教师特征是一个中心，半径为其最近受保护特征欧氏距离的 0.45 倍。
- 距离采用 float64 直接相减，不用平方范数相减，以避免近邻消减误差。
- 增益为所有中心 `max(clamp(1-distance/radius, 0, 1))`。
- 教师中心增益恰为 1；所有受保护锚点在每个支撑球之外，增益为 0，保留父动作。
- 新动作是 `clamp(parent + gain * 0.4*tanh(MLP), -.2, .2)`；增益为 0 时直接返回父动作。

这是由数据构建的连续局部记忆，不是精确状态哈希或按案例开关。它只保护已登记状态，
不保证未观测状态安全，也不保证机器人自身闭环轨迹始终处于支撑区域。

神经动作头仍是 288→128→64→29，种子仍为 2026102800/2801/2802，Adam 0.0003，
1024 步，正负各 512 行。保持 v1/v2 动作头完全相同的 PCG 抽样流与活跃样本权重。
不再训练全局二分类门，故总预算不与 v2 相同：不虚称等算力比较。

## 分级验收和证伪

1. 单元测试：连续邻域、所有旧锚点严格拒绝、教师梯度非零、一次实际更新后参数变化、
   碰撞与非有限输入拒绝、无输入张量别名。
2. 有限离线拟合：1024 步均有非零梯度，动作头确有更新；CPU 完整检查 3228 个中心
   与 18694 个保护状态。报告活跃动作 MSE 与零修正 MSE，并记录支撑查询耗时。
3. 当前产物使用 **OFFLINE_FIT_ONLY_NOT_ADMITTED** 状态，不能被现有运行时加载。
   16 行批次证书不代替 CPU batch1；下一阶段必须补严格加载、种子/优化器/父模型/
   训练归属/支撑半径重算校验及 batch1 动作一致性、延迟测试。
4. 随后才允许完整首脚接管考试：新 TRAIN20、原 TRAIN16、原 DEV16，三种子，
   原有全阶段自身 NN 和 MuJoCo 独立审计；首脚案例 4/5 必须真正成功，已获得能力
   不得下降。闭环离开支撑导致失败时，收集自身策略分布上的 TRAIN 反例，不用
   已消费 Fresh 的动作或标签调整模型。
5. 真正通过后才能声明新的未使用 Fresh。再通过球队接口、连续移动接球/传球/射门/
   扑救与整场比赛检验，才考虑宣传片。

失败后自动重跑同一输入、只看进程活跃或只看梯度次数都不是成长闭环。Agent 必须消费
每个终态结果、归因、声明下一科学步骤；观察器只负责发现无进展，不替代研发决策。
