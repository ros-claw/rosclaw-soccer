# S344：绕球回传恢复安全，接球尚未完成

本阶段把回传的接近路径从“穿过球去最终站位”改为“先侧移、从球侧面绕到
可踢的一侧，再接近站位”。这是可复用的 `OwnedBallContactPolicy.approach_waypoint`
和共享世界默认关闭的 `pass_stance_bypass`，不是移动物理球或机器人位置。
最终命令仍受原有速度、加速度、球员避碰和关节力矩约束。

## 实验与结论

六次实际 CPU 八体、每次 20 秒：红/蓝各对照一次，候选各运行并独立重复一次。
候选全部精确复现；禁用旁路的两个控制组也与 S343 数值轨迹一致。

| 条件 | 红队安全/接触计数 | 蓝队安全/接触计数 | 真实接球 |
|---|---|---|---|
| S343 直接去回传站位 | 否 / 281 | 否 / 231 | 0 |
| S344 绕球就位 | 是 / 0 | 是 / 0 | 0 |

候选均无运动接口故障。红队在 4.78 秒产生脚触球，朝接应者的峰值球速
0.803 m/s，最近球脚距离 0.644 m；蓝队第二次传球在 8.10 秒触球，
朝队友峰值速度 2.021 m/s，最近球脚距离 0.219 m。原来的相反方向回传
得到纠正，但两边均未完成接球。蓝队最初承诺没有在诊断窗口内产生脚触球。
不能把第二次的改善抹成第一次成功，也不能把最近距离当成真实接球。

全队合格门控仍失败，默认战术未改，冠军模型未替换，本阶段没有新增强化学习。
这是修复失败动作链的一个进步，不是成熟的全队比赛成绩。

## 后续诊断

真实轨迹显示接球方在源球员的约 0.6 秒接触记忆持有期内仍执行 SUPPORT，
球已运动但接收租约尚未激活；随后球近脚时又因为统一刹停而没有横向补位。
下一轮将区分“来源仍有记忆控球标签”“球实际向队友运动”“接球已经发生”，
测试提前跟踪来球和近距离横向补位，不能虚构接球或放宽真实触球门控。
