# 接球运动模型：完整MLP可塑性与精确先验锚定

## 为什么新增这项工作

完整96场角色对照的source及独立own现已匹配。受控传球从39增至53，功能接球
从40增至55，但严格到点成功仍只有已知的第6、24条；第60条功能接球退化，
所以此角色方案没有晋升，也没有满足广泛学习/保持门。

真实轨迹的诊断说明第60条不是没碰球：新方案第161控制步附近碰球后，相对
球速很快超过0.6m/s，球越过身体并在正式期限末离身体约2.18m；原追球方案
能形成长期稳定控球。诊断不修改原评分，也不能把碰球等同接球。

下一步需要接球过程的运动学习，不能只继续调上层位置目标。已有
`VelocityPriorActor` 已把相同速度ONNX转换为可训练Torch MLP，优先复用。

## 这是什么、还不是什么

`AnchoredReceivingMotor` 拷贝原98→512→256→128→29运动网络，并加入14个
因果输入。完整MLP的8个权重/偏置张量可训练，不只是新增一个输出head。
另保存独立冻结的初始化拷贝，避免训练时改写先验。

输出为当前同一状态的真实ONNX参考动作，加上“可训练完整网络−冻结拷贝”
经有界映射得到的修正。初始化两个网络完全相同，修正精确为0；这避免把
ONNX与Torch的微小数值差异冒充训练效果或身体动作变化。修正上限为声明的
参考相对0.2rad，并限制到原有浮点可表示动作盒内。该B控制接口是**新实验
域**，不能继承A或旧B的物理资格。

它仍是29关节**位置目标**，后面仍有原PD，不是直接力矩策略。也还没有训练
出接球模型、证明动作变好或部署到比赛：目前只有原型、软件测试与初始化
资格流程，优化器更新数为0。

## 因果14维输入

在当前动作前的真实机器人坐标系中表达：球相对位置3、球相对平移速度3、
沟通锚点相对位置3、自身线速度3、过去是否有足部/其它身体接触2。速度是
世界平移差转换到身体坐标，不能误称旋转坐标下位置的导数。

没有案例编号、随机种子、A的动作/隐藏状态、未来接触时间、最后成功标签。
接触标志来自此前实际物理步的接触分类，不从本轮将来的合法/成功结果倒推。

## 初始化资格与后续边界

1. 用已认证96条真实接球轨迹的全部动作前状态重构112维输入；只做离线NN
   核对，不执行保存的动作，不产生新的物理成绩。
2. 所有记录上的锚定输出必须精确等于原ONNX输出；转换后的Torch先验与
   原记录的误差单独检查。安全张量保存/重载保持同一初始化。
3. 反向传播探针检查所有8个MLP张量可获梯度，冻结拷贝无梯度；该探针不
   调优化器，不是奖励学习或一次RL更新。
4. 下一阶段还需真正的共享世界控制器、实际执行动作反馈、独立native复跑、
   随机动作密度和新checkpoint/data协议，才允许做运动策略优化。当前有接球
   退化的角色方案不能凭这个原型绕过保持门；新候选需使用明确父代和目标。

最终目标仍是有证据的自主连续4v4，不是这个初始化检查。没有全链路物理
净改善、历史保持和隔离Fresh，就不能声称自进化完成。
