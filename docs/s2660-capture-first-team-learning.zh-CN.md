# S2660：从触球计数转向接稳球的训练

## 本轮目标和边界

根据用户反馈停止制作视频，集中于接球、控球和接球后的动作衔接。
所有工作均为 SIM_ONLY。没有操作硬件，没有修改足球状态来制造接球，
没有将场外教练回球记作球员传球，没有发布新的冠军策略。

基础代码从 main `204b8f7` 开始；工作前 fetch 后与 origin/main 一致。
足球实现留在下游 soccer，继续复用 ROSClaw Core 的学习权限和冻结策略契约。

## 复盘发现

上轮 S2656 的录像看起来有运动和触球，但重新检查自由球阶段：

- 21.18、26.36、38.34、43.50 秒的出界之前，对应本次回球入场后没有球员接触。
  不能把这些问题全部解释成射门过猛。
- 红方中场 28.60 秒用脚触球并减速，28.66 秒已切换为 PASS。
  当时没有进入接球后的稳定控制阶段。
- 原稳定阶段只由已有接球租约触发；自由球接触不能触发。
- 在固定姿态的稳定阶段，腿部残差被屏蔽。仅修改该残差的训练奖励，
  不能保证真正训练到需要改善的动作阶段。

## 实现

### 接球训练窗口

`training/team_capture_curriculum.py` 根据实际 RECEIVE/PRESS/INTERCEPT
任务及实测脚球距离不超过 1 m 准入，每位球员使用不重叠的 100 帧窗口。
准入不依赖未来是否触球，因此漏接同样进入失败数据。
任务中途变为 PASS 不会擦除已经开始的接球考试。

复用既有 `receiving_window` 和 `capture_retention_window`：真实脚部接触、
接触后至少半秒观察、安全身体/关节/碰撞、没有后续非法接触，以及窗口
末端连续 10 帧低速、近脚、低球。不是要求全部两秒都静止，也不是触球
即成功。末尾不完整窗口明确标记 censored，不能作为完整成功。
带回球事件的输入必须先分割为实际入场到下一次出界的 live epoch，
不能跨教练投球或死球间隔计算奖励。

新增显式 `team_capture_v1` 奖励模式；保留旧模式、身体/关节/碰撞惩罚、
真实动作激活及探索掩码、任务学习掩码。该模式不是默认奖励，也不是
通用比赛成功判据：需要快速一脚传球的任务不能只按接稳留球课程评价。

### 自由球接触后的控制衔接

新增默认关闭的 `loose_ball_capture_hold`：要求严格接触处理，真实新脚部
接触力大于 1 N，实际接球/拦截任务，无已有接球租约、活跃运动选项或
正在运行的稳定阶段。持续接触不反复刷新计时。保留已有一脚射门路径。

只复用已有稳定控制，记录 `loose_capture_agent_code`，不授予硬件权限，
不伪造传球完成或控球成功。默认配置哈希保持逐字节身份不变。

## S2660 新数据与 S2662 对照训练

采集五个 45 秒课程，每个独立运行 primary 和 replay。
一个慢速无噪声对照，四个全新探索课程，种子 266000–266003；
教练来球速度混合 1.25 和原来的 2.0 m/s。
慢速只是训练课程，最后仍在原 2.0 m/s 环境考试。

四个探索课程有 9000 个控制帧，分割后 20 个 live epoch、4976 帧。
train-0 全队安全失败，未删除，也未将其列为通过样本。
所有课程的 primary/replay 一致；初始既有进攻前缀保持。

使用同一父模型、同一批数据、同一 250 系数行为锚点、各四轮 PPO，
比较 `contact_safety_v1` 和 `team_capture_v1`。两组都实际更新：

| 球员 | 有效学习样本 |
|---|---:|
| 蓝方中场 | 501 |
| 红方后卫 | 1066 |
| 红方中场 | 508 |

其余球员没有足够的实际激活/探索/任务交集，不虚报更新。
学习的是私人 12 关节腿部残差 actor-critic；不是八个端到端小脑，
不是重新训练行走底座或守门网络。两组优化器结果、权重和 Core 学习
权限记录可精确重放。

原速无噪声考试两组全队安全，但自由球阶段合格接球均为 0。
增加接球奖励没有在这个对照中解决控球。两组均不晋升。

## S2664 控制衔接消融

对 S2624 父模型和 S2650 旧候选分别只开启自由球稳定衔接，仍使用原
0.2 秒固定姿态阶段，不做新的梯度更新。两组各两次物理运行，全队安全，
但合格自由球接球仍为 0。

父模型在 28.64 秒触发，脚球距离 0.148 m；0.5 秒后为 0.254 m，
1 秒后为 0.407 m。旧候选触发后球速度从约 0.213 m/s 增至 0.549 m/s，
恢复出球后进一步失控。因此不将短暂固定姿态当作已解决控球。

## S2666–S2672：先纠正控制范围和学习范围

全局打开主动接球控制（S2666）破坏了已有第一轮进攻，三条课程均不安全。
原始 primary/replay 保留；外层收集器还因没有任何射门样本时访问
`samples[0]` 而退出。这三条不能列作成功完成的数据管线，也未用于训练。

因此新增独立的 `loose_ball_capture_control` 和
`loose_ball_capture_hold_sec`，仅作用于新准入的自由球接触，不改变已有
约定接球的时长和控制方式。S2668 使用 0.6 秒；首轮前缀保持，两个
探索课程全队安全，但无噪声对照不安全，合格自由球接球仍为 0。

S2670 在这些新探索数据上更新了五名球员的腿部策略，但核查发现
`capture_active_frames=0`：探索改变了早期路径，真正触球时已经是
PASS 而非 RECEIVE。因此这不是接球稳定阶段的学习成果。
无噪声候选仍不安全、合格自由球接球为 0，拒绝晋升。

S2672 改为只在实测稳定阶段施加探索。没有事后重新标记旧动作，
原接近路线和未准入角色保持无噪声。首版观察包装器传错了 keyword-only
参数，三个调用在首个运动计算处退出；保留 v1 失败目录，修正后使用 v2。

v2 三个课程实际探索角色帧数为 60/30/30，与真实控制激活及接球上下文
相交后为 48/18/18，共 84 帧。红方中场 54 帧，蓝方中场 30 帧；
后者不足既有 32 样本门槛，没有降低门槛强行更新。
三条轨迹都因红方中场失衡而不安全，不是成功示范。

S2674 的 PPO 只学习实测执行上下文中的真实激活、真实探索样本；
不再用上层 PASS/SUPPORT 标签替代实际正在执行的接球阶段。
测试部署也限定到同一阶段，其他时刻复用冻结父策略，逐帧记录并重算
所选模型的动作、log probability 和 value。它不是一个未经范围限制的
新通用运动模型。

## S2674–S2676：学习闭环与基础平衡对照

S2674 更新了红方中场的残差网络，四次优化器更新，6750 个原始动作帧的
采样、log probability、value 重新计算一致；权重与 Core 学习权限记录
重复训练一致。蓝方中场 30 样本未越过 32 样本准入线，仍保持冻结。
新网络仅在实际接球稳定阶段使用，其他阶段使用冻结父模型；部署选择
逐帧记录并重新计算。该候选仍跌倒、接稳为 0，拒绝晋升。

进一步检查发现，主动缓冲阶段仍用触球瞬间的关节位置覆盖了基础运动
策略的实时输出。触球可能发生在任意步态相位，固定这组姿态并不等于
持续闭环平衡。这是待验证原因，而非仅凭源码判定性能。

新增默认关闭的 `loose_ball_capture_live_foundation`，必须同时明确开启
自由球主动缓冲。此时基础运动网络继续提供实时 PD 目标，接球残差和
有界脚部缓冲叠加其上；基础网络权重不变。原有约定接球、一脚射门及
未启用该选项的路径不变。记录逐帧 `capture_live_foundation_active`。

S2676 与 S2668 的无噪声父模型、来球速度、缓冲时长相同，只增加该
实时基础运动输出选项。两次物理执行均完成、重放相同，原进攻前缀保持。

| 指标 | S2668 固定触球姿态 | S2676 实时基础运动输出 |
|---|---:|---:|
| 全队安全 | 否 | 是 |
| 红方中场最低骨盆高度 | 0.07084 m | 0.71467 m |
| 红方中场最大倾斜 | 2.57325 rad | 0.27412 rad |
| 红方中场关节越界 | 是 | 否 |
| 合格自由球接球 | 0 | 0 |

这支持该场景下基础平衡输出被覆盖是重要失衡原因，但只有一个公开
无噪声场景，不是泛化证明。S2676 没有新的梯度更新；改善归因于控制
衔接修正，不归因于新网络已经学会控球。全部实验配置仍默认关闭。

## 下一步方向

先在保留实时平衡的控制方式上重新采集接球阶段数据，不能直接将
失败的固定姿态控制数据当作新控制方式的 on-policy 数据。
训练效率也需要改造：45 秒全场课程只提供少量接球帧，不能继续单纯
增加这类长课程的轮数。应建立包含完整物理状态和策略循环记忆的
接球前状态恢复/局部课程；截取一段 npz 不等于可恢复的仿真状态。

局部接稳通过后，再做接稳→带球→传给队友→队友接稳的完整事件链与
独立场景验证。不能拿触球帧数、运动速度或教练回球次数替代，也不能
将本轮一个公开场景的平衡改善推广成整个球队已经成长。

原始数据、候选权重和机器可读审计位于外部证据目录，未进入 Git。
本轮不制作宣传视频。
