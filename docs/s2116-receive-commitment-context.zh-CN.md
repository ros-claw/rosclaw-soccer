# S2116：为重复接球提供独立约定身份

SIM_ONLY。本阶段只新增只读上下文，没有实现自动重启、连续接球或完整比赛。

## 问题与实现

当前接球后退役是单向的。单独一个 `committed_receiver` 布尔值不足以证明
后来的请求属于新一次传球，而不是旧约定持续存在或重复观察。

新增 `TeamReceiveCommitment`，包含发送者、接收者、单场递增代数、接受帧、
接受时间和原始 handshake 内容哈希。世界只在实际创建新的接球租约时递增，
不是每次战术决策都生成新身份。身份只交给匹配的接收者；无接球租约时传入
`None`。观察入口拒绝外来接收者、未来约定、非有限时间及损坏身份。

世界选项 `motor_receive_commitment_context` 默认关闭；关闭时保留既有
配置哈希。它不授予关节控制权，不证明脚球接触，也不解除任何故障锁存。
旧 actor 输入保持不变，不把新增身份塞进神经网络特征。

## 物理验证

同一已知开发场景，开/关两组，各独立重复一次，共四次 CPU MuJoCo 八体世界。
前锋保留冻结接球网络与零均值协同策略，中场及其他球员不变。

- 四次均身体安全、干净接球；前锋后续原生射门帧仍为零。
- 开/关组所有物理数组逐值相同；各组独立回放相同。
- 开启组实际接球调用观察到了同一租约代数；关闭组全为 `None`。
- 此实验只覆盖一次租约；不能据此宣称重复接球已经在世界中完成。

## 后续必须实现的边界

新约定身份只是前提。循环技能还须同时验证：旧技能正常完成、旧原生射门
控制已释放、新约定未消费、当前球确实朝接收者运动、基础神经历史连续。
故障不应因收到新约定自动解除，旧约定也不能反复触发。没有这些检查，不能
简单把 `completed=False` 当作持续比赛能力。
