# Learning reception navigation without rewriting motor memory

`training.reception_navigation` introduces an explicit **136 observation / 3 action**
contract for offline anticipatory navigation learning. It is not a joint policy,
a compatible replacement for a receiving actor, or a promoted match controller.

The integration order is intentional:

1. Observe current body/ball state, previous joint residual, **previous** foundation
   target, and normalized previous navigation residual (133 + 3 features).
2. Sample the navigation actor; smooth and bound XY/yaw residuals using the existing
   navigation envelope. Compose with nominal navigation and apply current neighbor
   and pitch clearance in the caller.
3. Advance the frozen recurrent foundation **once** using that command.
4. Evaluate the frozen 133/29 receiving actor using the **current** foundation
   target, retaining its existing residual history and joint/torque safeguards.
5. Observe actual physics. Train only the navigation actor/critic with the archived
   navigation observation, sampled action, log probability, and reward.

Using a foundation target generated by the sampled navigation action as an input
to that same navigation action's likelihood would make the update inconsistent.
Separating the two inference stages avoids that feedback error. Neither stage may
reset the LSTM or the body's physical state during a receiving episode.

This experiment responds to observed failures: a receiver can reach the ball but
sweep it sideways with a moving foot; joint-only adaptation can instead learn to
avoid contact. The new policy can learn braking, alignment, and approach timing
while preserving the motor expert. It does **not** establish that these behaviors
have already been learned. A training score or safe body alone cannot establish
controlled reception, multi-agent coordination, or complete-match success.

The PPO update's existing math is unchanged; its explicit shape allowlist gains
only `(136, 3)`. Tests cover zero navigation initialization, exact equivalence to
the existing navigation envelope, detached valid history, invalid-input rejection,
and an on-policy update. Existing 139/32 and 133/29 optimizer replays remain exact.

All components are simulation-only. They expose no simulator stepping, actuator,
hardware, activation, or permit authority. The caller must retain physical foot
contact, incoming-ball timing, nonfoot/body/ball-boundary checks, stable control
windows, frozen-policy audits, and independent shared-world qualification.
