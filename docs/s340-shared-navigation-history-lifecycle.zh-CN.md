# S340：同一球员的神经历史交接进入共享八身体世界

S340 完成八次真实 CPU 仿真：红/蓝两个镜像场景 × 保持旧初始化/启用交接 × 两次重复。使用既有慢速域的 S286024 模型和参考 29，未将单机快跑候选强行替换到多人场景，也没有扩大共享世界速度上限。

四种条件都身体安全、零机器人间接触、无 motor fault；每对完整数值轨迹摘要一致。开启交接后，两队前锋都生成了绑定实际球员、控制帧和历史的回执。定向球速由约 3.990 变为 3.931 m/s，仍满足原强前向射门检查；这是接口接通与保持能力的结果，不是多人射门球速突破。

没有实际接球成功，完整比赛检查仍失败。不能把成功的状态交接、意图数量或者 `all_roles_autonomous` 字段当成已经会有效协作。

## 蓝队坐标与生命周期约束

在原有平移推理副本基础上，增加显式 `allow_planar_yaw_rotation`。启用时严格验证同一平面刚体变换：身体与球的位姿一起变换、世界系线速度一起旋转，自由关节的局部角速度不能跟着转；关节状态不变。不是允许任意修改姿态或反射身体。该选项写入交接绑定，默认关闭，保持此前默认绑定路径。

`G1SonicNavigation.handoff_to()` 只接受当前球员下一帧实测状态：先补录最后一个导航控制后的观察，再传给新选项，并终止旧导航实例。错误时锁定旧选项，不允许因重试而重复写入历史。

后续增加的 `start_from_history()` 用于显式新建的导航段，从已有动作历史返回导航。全局控制帧不归零，只有新参考使用局部帧零；第一次 propose 不再次 reset 或重复写入刚导入的状态。它仍需要后续完整的动作—导航往返实测，不能仅凭单元测试宣称多人循环已经解决。

相关测试覆盖错误球员、错帧/时间、旧历史、参数不匹配、重复交接、部分航向变换、启动后重复初始化、全局帧与局部参考帧的衔接。S340 全量测试记录为 1510 passed、29 skipped、11 个既有历史外部证据绑定失败；后续新增往返生命周期测试单独通过。

外部证据：`s340-shared-team-history-retention-v1/assessment.json` 及配对轨迹。八个身体均处于同一物理时钟，不重置人体或球，不以视频打分；保持 `SIM_ONLY`。
