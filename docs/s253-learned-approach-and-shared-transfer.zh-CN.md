# S246–S254：从固定接近动作到数据驱动选择，再到八机共享场地

## 当前取得的局部进展

修复 GPU 球阻尼后，训练出的接近动作选择网络在 **32 个未用于训练的
CPU MuJoCo 情境**中，干净稳定触球为 **31/32**，固定参考为 **14/32**。
两组均 32/32 身体安全。这里的“合格”要求每 2 ms 检查身体、真实正
法向脚球接触、无先前小腿等非脚接触，并在首脚后 0.2 秒干净窗口内
获得朝目标方向超过 1 m/s 的球速。

这是近球接近技能的成绩，不是整场 4v4 胜率，也不是球门高死角精度。
同一判据下，球心干净穿过球门范围由固定参考的 8/32 到选择网络的
21/32；仍以地面球为主，1.5 m 高目标和 0.1 m 精度没有通过。

随后在实际含 **8 台 G1 的同一 MuJoCo 场地**中，红、蓝前锋各完成
4 个静止/滚动球迁移测试，共 8/8 干净稳定触球，8/8 全体身体安全。
两侧对应案例的球速几乎相同，验证的是刚体坐标旋转而非错误的左右关节
镜像。其余七台有各自独立的平衡控制器，但没有参加争抢、接应或守门；
因此不能把此测试称作自主比赛，也没有据此制作完整比赛宣传视频。

## 实际模型及训练方式

系统目前是分层学习，不是端到端关节力矩策略：

1. 冻结 SONIC 神经运动基础，参考轨迹只作为输入，从不直接覆盖世界姿态。
2. 133 维身体/球状态输入的 actor-critic，对 29 个关节目标输出残差。
   残差幅值 0.25 rad、每控制 tick 最大变化 0.025 rad、平滑系数 0.2。
   50 Hz 更新目标、500 Hz 真实 PD 与关节/力矩保护。
3. 新增 4 → 64 → 64 → 6 的接近参考效用网络。输入为声明课程中的
   球位置偏移与平面速度，输出六种参考的预估效用，物理开始前选择一次。
   这个网络是从真实试验结果进行离线回归学习，不是把 if/else 路线规则
   改名叫神经网络；它也不是在线 RL，不能和下层 PPO 混称。
4. 之后由全身模型根据每一步实测本体和球状态闭环执行。参考选择不是
   瞬移、加速球、冻结身体或把成功轨迹当成仿真结果回放。

六个参考来自之前冻结规划器生成的运动库，不是本轮新训练出的六个
独立运动大模型。选择器当前只覆盖限定默认站姿、地面来球课程，不覆盖
任意跑姿、空中球、任意距离、全部角色和比赛对抗。

## 失败和修正同样保留

| S246 旧口径 CPU | 触球计数从 10/16 到 13/16 | 该口径只从首脚后关闭非脚接触窗口，未排除之前小腿擦球；不能当作干净完整链路成绩 |
| S247 | 尝试非脚接触罚分，完成 1 次更新后发现会误罚球门框 | 主动中断、保留日志和已有 checkpoint，不采用；未在进程存活时改源码 |
| S248 | 增加身体接触独立组，球门框不再被当成小腿罚分；32 次 PPO、3072 个 episode，默认站姿训练占 2/3 | 严格开发集合格仅 64/96 → 68/96，32 个身体接触情境仍在；不把增加训练量当成突破 |
| S249 | 在修正物理中重验 120 个参考组合 | 发现固定斜向参考适合部分滚远球，而更直的参考对静止球更合适 |
| S250–S251 | 相同 128 个开发情境 × 6 个固定参考，合计 768 次真实仿真 | 保存每个成功和失败，不把重复参考试验算成 768 个独立情境 |
| S252 | 离线效用回归 512 步，Core 前置 lease 与结束审计 | 开发数据选择 122/128，与该有限动作库可达到的 122/128 相同；不能据此声称泛化 |
| S253 | 另一个固定种子生成 32 个新情境，CPU/ONNX 独立执行固定/学习方案各一次 | 干净触球 14/32 → 31/32，未根据这些结果重训或挑选网络；仍仅是窄课程验证 |
| S254 | 红蓝双侧、实际八机模型、静止/滚动与两种偏移 | 8/8 局部迁移通过，全体安全；其他球员只保持平衡，尚非比赛 |

S253 两组未过滤的球门范围穿越分别为 14 与 21；上文使用更严格的
“射门前无非脚接触且穿越前无其他几何碰撞”归因后，固定组只有 8 个。
穿越测量仍为球心平面插值，并非完整足球竞赛规则的全球过线裁决。

## 可复用实现与边界

新增 `providers/g1/approach_router.py`：

- 纯数值加载，不依赖 Torch 推理，不加载 pickle；绑定全身残差 checkpoint
  与参考库的内容哈希。共享 SONIC 基础、身体姿态和世界仍需调用方另行资格检查。
- 有界 manifest/ZIP/NPY 读取，读取数组前校验头部形状，防止小文件声明
  超大数组；拒绝重复/额外张量、非 float32、非有限参数和权重篡改。
- 越出学习域即拒绝，不把超界观测截断后伪装成合格输入。
- 仅返回参考提案，效用不是概率，不写机器人状态，不自动晋升、激活或授权。
- 128 个训练情境和 32 个独立试验情境，共 160 次提案，与原 Torch 网络
  的参考选择完全一致。11 项新增模块测试通过，ruff 全仓与 mypy 425 文件通过。

原始轨迹、模型、训练数据、冻结/可塑参数审计、日志在外部
`phase8_evidence/s246-*` 至 `s254-*`。原始报告仍保留旧定义和失败，不做
追溯性“修绿”。测试世界记录了八台模型和初始编队：为避免课程初始姿态
与原对方前锋重叠，双方前锋在初始化时采用对称、分离的位置；之后没有
把身体/球强制写回参考轨迹。

## 已开始的后续闭环

S255 把冻结的学习选择器接入全身 PPO：在每次显式 episode 初始化后，
读取实际球状态选择参考，再更新全身 actor-critic；同时冻结 SONIC 与
选择器并前置绑定 Core PlasticityLease。仍保留旧参考回放，不自动把新
身体权重声明为与旧选择器兼容，必须重新做独立身体/参考兼容验收。

后续需要：连续跑动状态迁移而非只从默认站姿开始、传球目标和射门目标
条件化、在共享场地中接回各角色自己的意图与反馈，以及真实对抗验收。
这些未完成项不能被上述 31/32 或八机局部测试替代。
