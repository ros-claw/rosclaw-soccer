# 从可复现失败到完整小跳恢复：S1844–S1868

## 目前确实完成了什么

在单 G1 MuJoCo 仿真中，从一次真实落地后的失败状态学习反馈参数，
再放回不含中途状态重置的完整起跳过程，得到可持续站稳的小跳。
冻结参数和切换条件后，四个新的参数组合均通过 16 秒检查。
这不是足球扑救成功，也不是自主 4v4，更不是已经具备通用肌肉记忆。

证据目录：`/home/dell/rosclaw_soccer_evidence`。实验脚本目录：
`/code/rosclaw/phase8_evidence/s532-delayed-handoff-cpu-v1`。

## 先排除不成立的解释

S1844 对全部七个手臂关节做离线几何搜索，8,486 次评估只找到毫米级
手套中心高度改善。优化器未收敛，不能据此声称全局运动学极限。
S1846 加深下蹲后出现真实离地，腾空 34–150 ms、骨盆升高约 24–55 mm，
但八个案例随后全部恢复失败。S1848 预设屈膝缓冲、S1850 改用实际脚位
作为参考支撑点，也都没有解决问题。

S1852 的 16 秒零动作对照则能稳定站立。带预测关节保护与不带该保护
的诊断分支轨迹逐元素相同；关闭保护仅用于隔离原因，没有用于晋升或
球队运行。问题是扰动后的恢复能力不足，不能归结为名义站姿本身站不住。

这些实验仍保留原生关节限位验收和电机硬力矩上限。没有给球或机器人
根节点添加起跳推力，没有通过运动学播放制造腾空。

## 数据与算法

S1854 保存了一个失败案例在仿真 3 秒时的完整 `mjSTATE_INTEGRATION` 状态。
采集没有改变原始运动轨迹。S1856 从该状态重放后续 5 秒，所有比较的
原生轨迹数值精确相等，最大误差 **0**。

快照 SHA-256：
`9381da480891bcc6e3f567d96c580f067057839a99ff5f174b6a7f0209a248af`。

S1858 使用交叉熵方法（CEM）学习四组线性反馈增益的比例：根部位置、
关节位置、根部速度、关节速度。每代 24 个候选，共 6 代、144 次原生仿真，
四个 CPU 工作线程。所有候选的状态、速度、控制量与分数均保留。
比例约束在 `[0.2, 5]`；预测关节保护与电机硬上限没有改变。

这是**基于失败数据的模型控制器参数学习**，不是神经网络 PPO、在线
actor-critic 或端到端力矩网络。基础反馈矩阵来自局部动力学线性化，
本轮学习的是其四组列缩放系数：

`[2.3031375584, 1.7236174973, 0.9243812853, 1.0568061456]`

每代通过同一恢复检查的候选数为 4、5、14、21、22、23。这只说明搜索
在同一训练状态上收敛，**不是泛化成功率**。
最终训练状态续跑的最低骨盆高度约 0.7707 m，无关节越限，末段速度接近零。
结果文件 SHA-256：
`3be69c8946fac36944a9c1e794ea6a3b421358dcea30fef657a1450908101f40`。

## 如何回到完整物理过程

S1860 从起跳前重新运行，在 3 秒切换到冻结的学习参数，不修改中途根姿态
或速度。切换前 1,500 个原生步骤与原失败实验精确相等。八个开发案例中
三个通过完整小跳恢复门槛。较深下蹲仍触及既定最低高度门槛，另有小跳
高度不足等失败，没有修改阈值将它们算作通过。

S1862 更换下蹲、蹬地和发力时长后，固定 3 秒切换只通过四个新组合之一。
这暴露了切换时机的脆弱性。

S1864 改为在参考动作完成后，结合实际腾空记录、机器人自身支撑力、
根部高度、直立程度和低运动速度决定何时接入学习后的反馈。
八个开发案例均不再出现关节越限和跌倒，但严格完整小跳门槛仍只有三个
通过，不能把“恢复稳定”与“全部动作要求通过”混为一谈。
S1866 在已经测试过的四个邻近条件上全部通过；它们不再是未见数据。

S1868 再冻结策略，使用新的下蹲/蹬地组合，延长至 16 秒：

| 下蹲膝角 / 每脚蹬地力提议 | 骨盆上升 | 腾空时间 | 原生关节越限 | 完整小跳恢复 |
|---|---:|---:|---:|---|
| 1.295 rad / 325 N | 34.51 mm | 90 ms | 0 | 通过 |
| 1.325 rad / 325 N | 37.41 mm | 98 ms | 0 | 通过 |
| 1.295 rad / 475 N | 44.86 mm | 138 ms | 0 | 通过 |
| 1.325 rad / 475 N | 49.15 mm | 144 ms | 0 | 通过 |

实际关节力矩仍经原保护与硬上限处理；上表 N 值是雅可比映射前的力提议，
不是测得的脚底力，更不是施加在根节点上的外力。
这些结果只证明此初始化协议附近的局部能力，不支持任意来球或扰动的成功率。

## 对 ROSClaw 的工程启示

有用的闭环是：保存可复现失败 → 在同一状态比较候选 → 保留失败和成功
证据 → 冻结参数 → 返回完整物理过程 → 在新条件与更长时间上复查。
训练状态通过不能直接授权新的使用阶段；阶段切换条件本身也必须验证。

G1 的举臂、下蹲与踢球时序属于 Soccer 的机器人提供者实现，不应塞进
通用 Growth 引擎。通用层应提供状态快照、证据绑定、策略适用范围、
候选评估、回归保护和受控切换机制。

当前小跳测试从优化的举臂平衡姿态初始化。下一项必须验证的是从准备
姿态进入小跳，然后再连接真实传球、射门与手套扑救。不能把单人小跳
视频当作用户要求的球队宣传片。
