# S37 灵活门将、连续二扑与高难射门闭环报告

日期：2026-08-15
状态：开发完成，候选未晋级，全部能力上限保持 `SIM_ONLY`

## 1. 本轮结论

本轮不是一次“调大动作”的补丁，而是把门将学习目标从单次扑救改造成了三个可分离、可追责的阶段：首扑、首扑后的回中恢复、第二次来球。工程闭环已经贯通到 4 卡训练、确定性训练内选择、独立 CPU MuJoCo 配对考场、elite 压力测试和结果绑定视频。

取得的真实进展：

- 修复了旧奖励只在“首扑成功且恢复成功”时才承认第二次扑救的结构性盲点。现在任何第二次来球的真实扑救都会进入 `second_attempt_save`，严格连续二扑仍单独记为 `second_save`，不会再丢掉可学习信号。
- 给第二次来球增加更强但有界的手臂可达奖励，advanced 为 1.6 倍、elite 为 2.0 倍；第二次来球的手臂残差上限从 0.25 提到 0.30，但横移动作安全上限仍保持 0.35。
- 加入基于拦截误差与身体横向速度的因果教师动作：扑救阶段加速，越过目标后制动，恢复阶段只允许上限 0.25 的回中横移并关闭上肢残差，减少无意义挥臂和左右振荡。
- 4×A6000 训练可在每轮对 128 个环境进行确定性选择，并使用父策略蒸馏防止首扑遗忘。训练内最佳迭代达到首扑 35.94%、第二次来球 35.16%、严格连续二扑 13.28%，零跌倒，最大根部角速度 2.35 rad/s。
- 发现并封堵了难度证据陷阱：仅写 `difficulty_profile="elite"` 不等于加载 elite 物理参数。CPU 考场现在要求世界配置与公开难度工厂生成的完整哈希一致，否则 fail-closed 拒绝运行。

没有取得的部分同样明确：训练内提升没有在新的 CPU 物理种子上稳定复现，v5 因最大根部角速度 3.537 rad/s 超过 3.5 上限且出现关节越界而被拒绝；elite 射门仍未攻克。因此没有把本轮候选晋级为冠军。

## 2. 架构改造

### 2.1 从“单次命中”改为阶段化门将记忆

`goalkeeper_multistep.py` 和 Torch 等价实现现在同时输出：

- `first_save` / `first_hand_save`：第一次来球；
- `recovered`：首扑后是否安全恢复；
- `second_attempt_save` / `second_attempt_hand_save`：不依赖首扑结果的第二次真实扑救；
- `second_save` / `second_hand_save`：首扑成功、恢复成功、二扑成功的严格组合技能。

这种拆分解决了原来最严重的稀疏奖励问题：首扑偶然失败时，后续正确二扑不再被当成零贡献；同时严格组合技能仍保留，防止用两个互不连贯的动作冒充连续扑救。

NumPy CPU 评分器和 GPU Torch 评分器已保持数值与语义同构。

### 2.2 小脑动作包络与回中制动

动作形状器采用按阶段不同的权限：

| 阶段 | 横向残差 | 上肢残差 | 目的 |
|---|---:|---:|---|
| 活跃扑救 | 0.35 | 首扑 0.25 / 二扑 0.30 | 快速覆盖来球并提高二扑手部可达性 |
| 首扑后恢复 | 0.25 | 0 | 用位置和速度预测制动，只做安全回中 |
| 其他等待 | 0 | 0 | 避免无来球时抽搐 |

恢复控制使用 `y + 0.35 * vy` 作为短时捕获点误差；已经越过球门中心时会主动反向刹车，而不是继续沿原方向滑动。曾测试横向上限 0.40：CPU 考场未增加扑救数，却把最大角速度推到 3.776 rad/s，因此回退到 0.35。

### 2.3 选择函数与独立晋级门

GPU 训练选择现在同时考虑首扑用手、第二次来球、二扑用手、严格连续二扑、手部可达、回中误差和角速度。训练内指标只负责选择 checkpoint，不负责晋级。

晋级必须通过同种子的父策略/候选策略 CPU MuJoCo 配对考场，检查：

- 扑救率与用手率不退化；
- 第二次来球与严格连续二扑达到预设最小增益；
- 奖励提高；
- 无跌倒、无非有限状态、无关节/力矩越界；
- 骨盆高度、根部速度、角速度、动作步长和手速满足自然性上限。

阈值为 0 的动作幅度项现在表示“不作为晋级目标”，不再错误解释成“必须不退化”。这避免了用更大横移/挥臂来冒充更灵活。

## 3. 实验结果

### 3.1 正确 advanced 配对考场：二次来球覆盖开发候选 v4 对冠军 v3

64 个同种子双来球，飞行时间 0.38–0.60 秒，目标横向 ±1.06 米、高度 0.16–1.48 米：

| 指标 | 父策略 v3 | v4 | 变化 |
|---|---:|---:|---:|
| 首扑 | 28.13% | 28.13% | 0 |
| 首扑用手 | 7.81% | 7.81% | 0 |
| 第二次来球扑救 | 23.44% | 25.00% | +1.56 pp（+1/64） |
| 第二次来球用手 | 6.25% | 6.25% | 0 |
| 严格连续二扑 | 9.38% | 9.38% | 0 |
| 平均回报 | 200.558 | 200.076 | -0.482 |
| 最大根部角速度 | 2.790 | 2.618 rad/s | 更稳定 |

它显示了一个小但真实的第二次来球覆盖增益，同时角速度下降；但增益低于 2 pp 门槛、严格连续二扑和总回报未提高，因此 v4 仍只是开发候选，正式冠军继续保留 v3。

### 3.2 连续二扑专项 v5 对 v4

4 卡共执行 2,560,000 个物理世界步（1,280,000 训练步与 1,280,000 确定性选择步），自动选择第 2 轮而不是最后一轮。独立 advanced CPU 考场结果：

| 指标 | 父策略 v4 | 候选 v5 |
|---|---:|---:|
| 首扑 | 21.88% | 21.88% |
| 第二次来球扑救 | 17.19% | 17.19% |
| 严格连续二扑 | 3.13% | 3.13% |
| 平均回报 | 176.911 | 177.449 |
| 最大根部角速度 | 2.774 | 3.537 rad/s |

扑救数没有提升，角速度越过自然性上限，并出现关节边界违规。因此状态为 `REJECTED_BY_CPU_MUJOCO_EXAM`，v5 不进入候选档案，更不能替换正式冠军 v3。

### 3.3 elite 压力考

elite 使用 0.30–0.50 秒飞行时间，来球起点更靠近门将，目标扩大到横向 ±1.10 米和 1.65 米高。32 个同种子双来球：

| 指标 | 父策略 v3 | v4 |
|---|---:|---:|
| 首扑 | 15.63% | 15.63% |
| 第二次来球扑救 | 9.38% | 6.25% |
| 严格连续二扑 | 0% | 0% |
| 最大根部角速度 | 2.137 | 2.243 rad/s |

机器人保持站立，但高速高角度覆盖显著不足，且 v4 动作步长超过该考场上限。elite 只是本轮挑战暴露器，不是成果宣称。

## 5. 为什么训练内变好，独立考场却没过

强化学习不是“训练越久必然越好”。本轮主要有四个原因：

1. 连续二扑仍是组合稀疏事件。首扑、制动、回中、识别第二球、再次跨步、用手接触必须连续成立，任一环节失败都会让严格指标归零。
2. 训练内 128 个环境仍来自同一个分布与选择循环；即使是确定性复测，也可能选中对这些种子特别合适的 checkpoint。新 CPU 种子正是用来揭露这种过拟合。
3. 外部冻结教师偏向单次扑救，不具备本项目的回中后二扑行为；它能提供运动先验，却不能替代组合技能学习。
4. 当前低层 locomotion prior 主要是稳定站立/横移，不是专为门将训练的落地、侧扑、跪撑和快速起身技能。上层残差在安全包络内已经接近能力边界。

## 6. 下一阶段突破路线

下一轮不应继续盲目提高奖励权重或动作上限，而应模块化补齐底层技能：

1. 建立门将专用 option：预判跨步、低位侧扑、高位伸手、落地支撑、快速回中，各 option 先单独达到 CPU 物理成功标准。
2. 为第二球引入显式剩余时间与可达域估计，让策略在首扑接触前就规划落脚和回中方向，而不是首球结束后才反应。
3. 用 prioritized replay 提高“首扑成功但二扑失败”轨迹采样率，并分别训练 value head，避免大量普通失败淹没组合技能信号。
4. 把 elite 拆成速度、高度、横向三个独立课程，只有单轴过门后才组合，防止一次扩大所有维度导致学习信号消失。
5. 增加接触后的恢复模型和脚底支持多边形约束；门将真正的灵活不是手臂挥得大，而是扑出后还能把质心带回下一次可行动区域。

本轮最重要的工程成果，是 ROSClaw Soccer 已能诚实地区分“训练内看起来进步”“独立物理考场确有进步”和“高难度泛化失败”。这为后续真正训练出更帅、更灵活、更高成功率的门将建立了可信闭环，但当前结果还没有达到最终目标。
