# S215：八人场景中的私有近球残差 PPO

## 结论

已实现并实际运行在线物理采样 → 私有 actor-critic 更新 → 新球位对照 →
原始轨迹审计。网络发生了真实梯度更新，但本轮没有提高合格传球数，
**没有整体比赛突破，也没有晋升默认控制策略**。

外部证据位于 `$ROSCLAW_SOCCER_EVIDENCE/s215-private-residual-ppo-v1`。
`training.json`、`learning-audit.json`、各回合 `probe.json`、主/重放 NPZ、
每代网络 NPZ 均保留。证据不进入 Git。

## 实现边界

- 八个独立参数集合：56 维本地观测、32 维隐藏层、12 维腿部残差及独立 critic。
- 基础 RoboNaldo 步行 ONNX 冻结；上肢不由本次残差调整。
- 输出是关节位置目标残差，不是端到端力矩控制。幅度上限 0.10 rad，
  低通过滤 0.25，单控制帧变化上限 0.02 rad；既有关节/力矩约束继续执行。
- 仅显式注入候选时启用；默认 `None`。触球附近获得控制权的球员才有有效样本。
- 每次采样冻结权重；一轮红蓝回合后更新。PPO 每代重建 Adam，权重与 critic
  连续继承；**不是持久化 Adam 状态的训练恢复服务**。
- 运行时仅 NumPy；训练时显式加载可选 PyTorch。CPU MuJoCo 采样和小网络更新，
  不宣称使用四卡大规模训练；现场 GPU 正有其他工作负载。
- checkpoint 禁止 pickle、限制大小/张量形状/有限值，内存权重不可写，绑定
  body、球员标识、代次和父策略哈希。具体基础网络/控制实现由回合 fixture 和
  implementation 哈希记录；本版本 checkpoint 尚没有单独的 foundation 字段，
  不应脱离回合证据跨基础网络使用，更不具备晋升权限。

## 实验

4 轮更新，每轮红蓝各一条 12 秒任务，各自执行第二次严格重放。
训练球位偏移 ±0.04 m；评估偏移 ±0.08 m，红蓝各两场。
评估使用确定性均值动作，不选择噪声样本作为展示结果。

| 球员 | 有效训练帧 | actor/critic 是否更新 |
|---|---:|---|
| 蓝前锋 | 859 | 是 |
| 蓝中场 | 1043 | 是 |
| 红前锋 | 976 | 是 |
| 红中场 | 1093 | 是 |
| 两名后卫、两名门将 | 各 0 | 否，逐元素保持不变 |

共 3971 个有效角色控制帧。8 对训练回合、8 对评估回合，共 32 条物理轨迹。
旧策略概率、critic 数值、随机种子采样、checkpoint 父链和角色样本数均重新计算核验。

| 新球位评估 | 零残差 | 第 4 代 |
|---|---:|---:|
| 世界安全通过 | 3/4 | 3/4 |
| 合格传球 | 0 | 0 |
| 整体比赛验收 | 0/4 | 0/4 |

奖励包括脚靠球的势差、真实脚球接触时的目标方向速度、倾斜/低身高/碰撞/非脚
接触和残差代价。宣布 PASS 不给奖励。该密集奖励并不等价于传球成功，当前结果
也表明不能据此宣称足球技巧进步。

## 验证与反思

- 额外两对 5 秒验证：零残差和禁用模块的全部共同轨迹字段逐元素完全一致。
- 8 个新单元测试通过；包含实际 PPO actor 更新、无样本角色冻结、错误旧策略
  概率拒绝、随机重放、滤波边界和 checkpoint 非有限值/浮点代次拒绝。
- 全量执行当时：1094 passed、13 skipped、11 failed；随后补充的 3 个测试也通过。
  11 个失败仍是 S78/S79/S80/S94/S104/S105/S107/S108/S113/S114 的历史外部证据
  内容绑定问题，未跳过或改写它们来获得全绿。
- ruff、mypy（400 文件）、compileall 和 diff whitespace 检查通过。

下一步不是把这 3971 帧说成“大规模训练”。需要解除预先传球决策与 FreeKick
网络选项的耦合，让步行/残差控制也能在触球前建立真实的传接球承诺；用可完成
的物理传球课程增加有效样本，再回到原始对抗阵形验证迁移。失败策略仍保留，
不晋升、不替换默认策略。守门和后卫需要自己的有效课程，不能用中场的数据冒充。
