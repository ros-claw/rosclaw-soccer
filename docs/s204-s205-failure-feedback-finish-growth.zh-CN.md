# S204–S205：失败反馈驱动的稳定射门成长闭环

## 结论先行

本阶段打通了一个真实、可复演的成长闭环：S204 先在多上下文射门组合中暴露出一个
`0.289709 m` 的隔离评测失败；S205 不删除失败，也不放宽安全阈值，而是将失败绑定为
训练输入，在 CPU MuJoCo 中对四个高层动作参数执行两阶段主动搜索，最终把同一上下文的
落点误差降低到 `0.059552 m`，改善 `0.230157 m`（约 `79.4%`）。学习后动作没有摔倒，
最低骨盆高度为 `0.652785 m`，触球后支撑脚滑移为 `0.097480 m`，通过独立严格复演。

这证明的是“ROSClaw 能从一个已确认失败的动作盆地中学习出更稳定、精确的局部肌肉记忆”，
不是“射门策略已经跨场景泛化”，也不是“已获得真实机器人执行资格”。S204 的通用角色后端
仍被正确拒绝；S205 的通过范围明确限定为一个失败上下文点修复。

## 为什么需要这一步

S203 已证明固定上下文下能够通过搜索找到精确射门，但一个样本不构成可用策略。S204 把
上下文扩展到不同接球相位和横向跑位后，发现冻结全身踢球先验的高层目标映射高度不连续：
相邻上下文只发生毫米级变化，原动作的落点误差也可能突然增大。

如果只在成功样本之间平滑插值，会有两个问题：

1. 插值可能穿过已经实测失败的动作盆地；
2. 单纯追求落点误差，可能选择支撑脚滑移更大的动作，让机器人更不稳定。

因此本阶段把“会不会踢中”和“踢完能不能稳住”同时放进成长门控，并把失败作为一等数据，
而不是作为需要隐藏的坏结果。

## 架构变化

### 1. 通用的有界主动搜索能力

新增 `BoundedActiveSearchPlan`、`BoundedSearchDimension` 和
`BoundedSearchCandidate`。该模块只负责产生确定性、内容绑定、可审计的 Halton 候选，
不包含足球、G1 或 MuJoCo 语义，因此可以被其他 ROSClaw Growth 任务复用。

所有候选固定为 `SIM_ONLY`，禁止硬件授权和直接关节力矩输出；计划哈希、候选哈希和搜索预算
都进入证据，避免运行时静默扩大搜索空间或替换候选。

### 2. 成功记忆与失败盆地并存

`G1ContextualFinishTargetActor` 从 v1 升级到 v2，新增
`FinishTargetFailureMemory`。决策顺序为：

1. 先计算查询上下文到已确认失败盆地的归一化距离；
2. 落入失败排除半径时，返回 `KNOWN_FINISH_FAILURE_BASIN_FALLBACK`；
3. 未进入失败盆地时，才允许从已验证成功局部专家中选动作；
4. 超出成功支持域时仍然 fail closed。

这避免了“明知中间失败，仍在两端成功样本之间盲目插值”。

### 3. S204 多上下文组合与角色后端门控

S204 使用 6 个成功发现上下文、2 个失败发现上下文、2 个成功隔离评测上下文和 2 个失败
隔离评测上下文。每个发现上下文执行有界候选搜索，选择结果还需独立复演。成功记忆、失败
记忆、Actor、角色后端候选和路由决定逐层绑定。

只有成功隔离评测、失败 veto、稳定性、严格复演和角色资格全部成立时，后端才能被路由接纳。
本轮成功隔离评测没有通过，因此后端保持拒绝，没有为了得到绿色结果而绕过门控。

### 4. S205 两阶段失败修复

S205 从 S204 的 `basin-a-sealed` 失败点开始，搜索四个可解释的高层参数：

- 策略目标横向位置；
- 脚面偏航；
- 射门站位横向偏移；
- 脚面俯仰。

第一阶段在诊断热启动周围执行 33 个候选。第一阶段发现：最精确动作误差仅 `0.018152 m`，
但支撑脚滑移 `0.141688 m`，超过相对稳定门控；另一个稳定动作误差为 `0.102048 m`，距离
精度门槛只差约 2 mm。

第二阶段没有放宽滑移门槛，而是自动选择“安全、稳定且越过门线”的第一阶段候选作为中心，
再执行 33 个更小信赖域候选。最终从 66 个候选中得到 2 个同时满足精度、传球链和稳定性的
动作，选择其中落点误差最小者并独立复演。

学习结果被保存为 `extended-finish-intent-memory.json`，它绑定源失败上下文、源失败轨迹、
两个搜索计划、选中候选、选中轨迹、四维动作和观测结果，但明确禁止自动推广。

## 失败迭代记录

本阶段保留了每一轮拒绝结果：

- S205 v1：找到了 `0.022953 m` 精确动作，但发现物理目标高度与策略内部目标高度混用，
  基线无法复演，且选中动作稳定性未通过；
- S205 v2：坐标系修正后得到 `0.018152 m`，但支撑脚相对滑移仍超限，没有放宽门控；
- S205 v3：两阶段搜索首次找到稳定精确动作，但 JSON 中 tuple/list 类型差异导致内容相同的
  基线被误判为不一致；
- S205 v4：改用规范化内容哈希后，物理结果、基线复演、候选选择、学习记忆和独立复演全部
  闭合通过。

这些失败分别推动了坐标语义、候选资格、主动精修和证据规范化的工程修复。

## 安全和能力边界

本阶段只使用 CPU MuJoCo。没有发布 ROS topic，没有访问 DDS、串口、CAN、厂商 SDK 或真实
机器人，没有发出硬件命令。主动搜索器和学习记忆都永久标记为 `SIM_ONLY`，不能直接输出
关节力矩，不能自行热更新运行策略，不能获得推广资格。

当前动作仍依赖冻结的全身踢球先验；S205 只是在高层意图层学习局部修复，并不是端到端神经
小脑，也不是持续在线 actor-critic。

## 下一阶段建议

1. 把 S205 的四维成功记忆与失败记忆扩展到多个相邻上下文，训练可查询的四维局部专家 Actor；
2. 使用新的、真正未参与搜索的相位与横向位置隔离评测，验证单点修复能否形成局部泛化；
3. 把“不稳定但精准”和“稳定但差 2 mm”的候选对作为 Stability–Plasticity 训练样本，学习
   带稳定约束的候选价值模型，减少盲搜次数；
4. 只有多上下文 Actor 通过隔离评测后，才重新申请角色后端接纳；
5. 再将同一种通用主动搜索、失败记忆和严格复演能力迁移到传球与守门角色，而不是在 Growth
   通用模块中写入 G1 足球专用逻辑。
