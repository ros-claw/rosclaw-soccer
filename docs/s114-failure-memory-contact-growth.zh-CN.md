## 结论先行

S114 第一次让第二前锋的新候选策略在完整连续物理链路中真正接管、真实失败、从失败中更新，然后在同一标准场景中独立通过。它不再是父策略兜底，也不是球炮或轨迹回放：候选在两次 23 秒严格重放中各接管 2 个接触控制帧，冻结父策略接管 0 帧，第二颗实体球经右脚接触后在 1.475 m 高度被门将手套真实扑出，最终门将恢复 ready，全场安全门通过。

## 这轮到底学了什么

### 1. 修正了完整链路中的目标语义

S113 虽然把球和目标送进了目标条件 actor，但第二脚仍错误复用了第一脚的草地高度目标 `z=0.115 m`，并以球门线 `x=7.5 m` 作为弹道终点。第二次考试实际要求门将在球门前约 0.83 m、约 1.44 m 高处完成高位扑救，旧目标与任务物理相互矛盾。

现在 `G1PhysicalSecondStrikerConfig` 单独声明：

- 目标深度：球门线前 0.83 m；
- 目标横向位置：0.19 m；
- 目标高度：1.44 m；
- 配置 schema 升级到 v3，低至球半径的错误目标 fail closed。

由此目标条件从旧的约 `vy=-0.143, vz=3.147 m/s` 修正为约 `vy=-0.152, vz=5.160 m/s`，并落在本轮真实测量的出球速度凸包内部。

### 2. 修复了多 G1 教师的自由度投影错误

原 loft teacher 默认把雅可比固定切片 `6:35` 当作执行器自由度。这在单 G1 模型成立，但在四 G1 合成世界中只对应第一台机器人。将同一个教师用于第四台第二前锋时，会把力投影到错误角色。

现在教师显式接收该角色自己的 29 个 DoF 索引，并验证数量、唯一性、范围。共享世界把第二前锋自己的 `joint_qvel` 索引传给教师。教师和塑性候选互斥，不会叠加两个控制权；采集时父策略仅保留诊断上下文，不施加接触力矩。

### 3. 在完整世界采集成功和失败，而非单独踢一颗球

新增 `role_isolated_contact_actor_growth.py`，在每个样本中都运行完整的：

```text
传球 → 第一前锋高球 → 第一次飞身扑救 → 恢复/rearm
     → 第二前锋实体脚触球 → 第二次高位扑救 → 最终 ready
```

教师课程包含 8 个横向/竖直脚速目标，每个完全相同地重放 2 次，共 16 条 23 秒轨迹。样本必须保留第一次扑救、全场有限状态、真实第二脚接触和所有非部署型物理门；成功与失败轨迹一起进入局部模型。最终局部拟合使用 5 个邻近安全探针，含成功与拒绝样本：

- 局部正向接触模型 RMSE：0.02865 m/s；
- 正向响应条件数：3.217；
- 最近成功教师：`lat7-up7`；
- 教师峰值任务空间力：`[182.366, 180.0] N`；
- 教师峰值脚速：`[0.921, 0.630] m/s`。

actor 不是一个手写动作序列。它是从测得的“任务空间力 → 实际出球速度”数据拟合出的局部逆模型，输入期望横/竖出球速度和自身脚部横/竖速度，输出有限幅的横/竖接触力；随后用当前 MuJoCo 测得的脚部雅可比转成该腿 29 关节的直接力矩残差。运行时只有目标落在训练支持域内才能接管，否则回退冻结父策略。

它也还不是端到端神经小脑或在线 actor-critic：当前是可解释、低样本、局部线性的接触小脑。这样可以先证明失败数据、支持域、直接关节力矩和完整任务结果真的连在同一个可审计闭环里。

## 第一次候选为什么失败

初始逆模型使用 0.25 的局部可塑步长。候选的支持域和选择门都通过，两次重放均真实接管，但球最终越过门线：

| 指标 | 初始失败候选 |
| --- | ---: |
| 候选接管 / 父策略帧 | 2 / 0 |
| 第二脚接触 | 16.948 s |
| 第二次手套触球 | 17.538 s / 1.457 m |
| 第二颗球进门 | 是 |
| 失败门 | `outward_physical_save`、`final_goalkeeper_ready` |
| 报告哈希 | `sha256:939937e5…35e3` |

原因不是“没有学到”，而是学得太猛：弹道解析目标与最近成功教师只差约 0.066 m/s，但 0.25 逆模型修正已经足以把轨迹推过门将接触结果的非连续边界。与此同时，脚部速度在第一个接触子步后变化，固定输出会发生分布漂移。

## 失败如何变成下一版肌肉记忆

新增 `role_isolated_contact_failure_update.py`。它读取并重新验证：

- 8 组教师证据和 16 个无 pickle 轨迹；
- 初始失败候选的 2 条轨迹；
- 所有轨迹文件哈希和语义摘要；
- 教师成功/失败标签、候选支持和真实接管；
- 当前 Soccer 与 ROSClaw Core 源码、依赖和输入 artifact 闭包。

只有“证据可信、候选在支持域内真实接管、完整任务确实失败”时才允许更新。失败响应是：

- 局部逆模型步长从 0.25 收缩到 0.05；
- 加入 6 N/(m/s) 的本体脚速负反馈；
- 保留最近成功教师为行为锚；
- 新 actor 仍标为 `UNQUALIFIED_SIM_ONLY_FAILURE_UPDATED_CANDIDATE`，不能热更新或触达硬件。

## 对 ROSClaw 自进化架构的价值

S114 在足球案例中验证的是可迁移的通用闭环，而不是“给 G1 多写一个踢球补丁”：

```text
角色隔离的探索教师
  → 成功/失败轨迹与本体状态
  → 局部数据模型与置信支持域
  → 候选真实接管
  → 完整任务失败
  → 失败记忆触发小步稳定更新
  → 控制考试
  → 封闭留出
  → 组合晋升或拒绝
  → 下一轮困难课程
```

ROSClaw Core 提供通用的源码/artifact/进程可复现闭包；Soccer 只提供角色、足球物理和任务门。稳定性通过冻结前缀、父策略回退、力/支持域裁剪和封闭留出保护；可塑性通过目标条件逆模型、本体反馈与失败触发更新获得。任何其他机器人技能都可以替换“第二前锋接触”和“手套扑救”评分器，复用相同的证据—失败—更新—资格结构。

## 尚未突破与下一轮

1. 当前 actor 在接触前看不到球质量/地面摩擦，静止球的瞬时状态不足以区分标准球和重球；下一轮应加入显式动力学上下文或由安全试探辨识出的 latent context。
2. 应只用新的重球训练分区采集教师数据，保留另一组质量、摩擦、目标高度和横向角度作为全新封闭留出，不能继续对同一留出手调。
3. 线性局部小脑证明了闭环，但还需将同一数据合同升级为带不确定度的神经接触 actor/critic；神经策略仍必须经支持域路由和直接力矩安全投影。
4. 控制证据是同进程双重放，不是 S112 的三个新鲜进程冠军资格；通过困难组合后还需做跨进程资格。
5. 当前只验证右脚第二前锋和 left-inner 单通道，双脚、多角度、高低球、不同传球方与门将行为都未被本阶段授权。

这轮的突破不是“所有球都能扑”，而是系统第一次把一次真实失败变成了可审计的新肌肉记忆，并且在成功之后仍能对没学会的困难条件说“不”。
