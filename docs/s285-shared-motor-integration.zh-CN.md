# S283–S285：把身体模型变成可复用的每球员模块

## 独立检查没有证明突破

S283 使用训练后才生成的 seed28301，共 32 个实际跑动到射门的完整场景，
固定双方相同的第 28 条参考，比较 S269 分支 0 actor032 与 S282 actor008。
两者均为 32/32 身体安全、24/32 干净触球；严格连续强射门分别 11/32 与
12/32，球门开口穿越分别 6/32 与 7/32。改善只有一个场景，不能称为显著提升，
不自动采用新权重，也不能拿训练开发集的较高比例代替这个成绩。

## 已落地的公共模块

`providers/g1/ball_motor.py` 提供 `G1FrozenBallMotor` 和 133 维观测构造函数。
它把实验中的 NumPy/Torch 推理和残差平滑逻辑变成可复用、只返回提案的接口。

- 检查数值 NPZ 的完整内容哈希、成员名、张量形状、类型和有限性，不允许 pickle。
- 合同绑定身体模型、声明的冻结基础模型、参考库、默认关节角和原训练残差边界。
  调用者仍必须核验实际加载的基础模型与参考库；声明哈希本身不是物理资格证明。
- 每个实例有自己的上一帧残差和控制帧号。必须显式开始新 episode，连续调用
  0–199 帧；重复、跳帧或无效观测锁定失败，不能悄悄推进“肌肉记忆”。
- 只返回关节目标和残差提案，不写球或机器人状态、不调用驱动、不更新权重。
  实际控制器仍负责冻结教师历史、坐标转换、PD、关节限位和力矩上限。
- 没有目标位置输入，不声称任意朝向、任意球位或身体形态泛化。观测裁剪是
  训练预处理，不是域外动作的通过判定。此接口没有把候选升级为球队策略。

## 不只做导入测试

数值核验使用 S282 真实权重及记录的姿态，连续比较 200 次提案与原 Torch
计算：133 维观测误差为 0，最大残差差异约 2.23e-8 rad。这组姿态是数值探针，
不是连续物理轨迹。

S285 又把公共模块接入真正的八人 MuJoCo 世界，用预先指定的 case0/4/7/9
分别从红、蓝两侧跑动接球射门。两侧各 4/4 全身安全、4/4 干净触球、1/4
严格连续强射门、1/4 球门开口穿越。每段使用 500 Hz 公共接触证据模块。
两侧是同组场景的半转对称检查，不是八个独立随机测试。其余七人保持平衡，
依然不能称为 4v4 自主比赛。

原始脚本、world.mjb、轨迹、逐物理步接触记录、数值核验均在外部
`s283-expanded-body-continuous-exam-v1`、
`s285-public-motor-continuous-integration-v1` 目录。
物理运行后仅给观测数组补充静态类型标注以通过 mypy，没有改计算逻辑。
