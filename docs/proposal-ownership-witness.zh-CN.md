# 单帧学习控制权证据

`diagnostics.proposal_ownership` 是不依赖 G1、Core、Torch、MuJoCo 的只读校验模块，来自 S931 暴露的实际控制接续问题。它不是机器人执行器、许可系统或候选晋升门。

## 实践中的缺口

S931 接球外层已标记结束，中层的 210 帧 memory adapter 却继续调用接球模型。结果记录了 890 帧导航和 210 帧接球，总数超过整场 1000 帧。部分导航只是计算了候选，随后被接球输出覆盖。“已经结束”和“导航调用增加”不能证明控制交接。

S933 同时检查中层终态、readiness 和捕球后的坐标镜像路径，并记录每帧实际返回的 target hash。S934 独立复核：

- 第 424 帧按五条连续实测稳定离球状态退出，前 425 个控制前状态与对照一致。
- 接球实际调用 106 帧，导航 890 帧，其余 4 帧没有学习选项返回目标，由原有世界回退路径处理。
- 全部 1000 帧至多一个学习控制器提出目标，终止后无接球输出；八个身体安全、无控制器故障。
- 射门仍被后卫拦截，之后出现自身非脚触球；没有任务晋升或宣传资格。

## 组件契约

`ProposalActivity` 描述某个 owner 在本帧的 0/1 次提案及终态；终止后不能继续提案。

`ProposalOwnershipSnapshot` 绑定 subject、frame、上下文哈希、已声明活动和实际返回目标哈希。拒绝重复 owner、多个提案、终态提案、无声明却返回目标、已有提案却没有返回目标，以及不合法类型/标识/哈希。活动顺序不影响规范化绑定哈希。

零提案意味着该独占路由没有返回目标，不代表机器人停了，也不证明回退路径执行。内部 ensemble 可以由一个独立合格 owner 管理，但不能把外层互相覆盖的两个控制器伪装成一个结果。

这是调用方提供的路由证据，不能发现未上报的调用、验证哈希对应的真实观测、认证记录作者、检查跨帧时钟或决定技能何时重启。它没有任何执行权限。使用者仍负责完整记录实际分支、控制周期、物理约束和生命周期。

## 验证及后续回归

41 项定向测试通过，覆盖重叠提案、终态、输出与活动不一致、非法输入、不可变记录、上下文绑定和无需加载训练/仿真/Core 的独立导入。定向 ruff/format/mypy 通过。

S936 将组件放入 S933 原有“返回提案”路径：上下文绑定实际当前 `TeamMotorObservation`，记录组件快照、选中的 owner 与目标哈希。它不改变动作或阈值。必须再检查完整物理轨迹与 S933 一致，并重建每帧快照哈希，才能声称在真实共享仿真路径中接通。

已完成 S936/S937 回归：1000 个组件快照全部重建，106 帧接球、890 帧导航、4 帧无学习提案；整场六名场上球员的 q/v，以及全部八名球员姿态/关节和球的数组与 S933 逐字节相同。接入模块没有改变物理结果。完整观测未单独序列化，审计验证的是快照哈希一致性，不是逐字段重建所有原始观测。证据：`/code/rosclaw/phase8_evidence/s937-runtime-proposal-witness-audit-v1/result.json`。
