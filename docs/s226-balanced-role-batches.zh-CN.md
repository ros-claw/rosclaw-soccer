# S226：固定父策略下的五球位平衡批次

S224 的四次小批更新没有提升球技，而且稳定性从 16/16 退至 15/16。
因此本轮不继承第 52 代、不放松指标，也不仅增加相同的小批更新次数。

## 已实施的训练能力

- `--role-batch-rounds 1..5`：一个冻结父策略采集最多五轮课程后才更新一次。
  五轮为双方四角色 × 五种训练球位，共 40 场；每场仍有独立 CPU MuJoCo 重放。
- 每场种子由批次和样本序号固定，不依赖 worker 的完成顺序；每批使用同一
  checkpoint。轮数为 1 时保留原课程序列和种子。
- 训练球位仍为 −0.12、0、+0.12、+0.04、−0.04 m；±0.10 m 验收球位不参与更新。
- 学习审计验证每批实际报告数量、角色、侧别、物理初始球位、编队和种子；
  不是仅看文件夹名，也不接受把验收球位放进训练。
- 不更改 PPO 学习率、物理控制器、接触几何、奖励阈值及晋升门。

## 预注册实验

从 S221 第 48 代出发，8 个 CPU worker，5 轮/批，2 次更新，12 秒上限。
预计 80 组训练 + 父子各 16 组验收 = 112 组 / 224 条轨迹。
每个角色会接触更多球位，但有效动作样本数由真实激活情况决定，不按总帧数冒充。

证据目录：`$ROSCLAW_SOCCER_EVIDENCE/s226-balanced-batch-private-ppo-v1/`。
当前状态：训练进行中，结果待最终审计。研究假设是降低单球位采样导致的
更新偏移；未证明它能提高成功率，也未进行策略晋升。

±0.10 m 是已被多轮查看的开发验收集，虽然未进入优化器采样，也不能称为
从未见过的最终盲测。若出现开发集改善，还必须在预先冻结的新场景上验证，
不能以本轮开发集数据推断泛化成功率。

S221/S224/S225 的旧数据，未改写它们的原始报告。
