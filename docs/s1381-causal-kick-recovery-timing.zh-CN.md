# S1381：实测触球后的恢复时序提取

新增 `providers/g1/kick_recovery_timing.py`，把足球实验中的恢复时序从一次性实验脚本提取为可测试组件。它只提出随摆结束、恢复开始及混合进度，不执行动作、不检测触球、不判断进球，也不授予底层控制权。

配置显式绑定踢球起始控制帧、最长等待帧、随摆帧数、混合帧数和物理采样与控制帧的比例。调用方只能提供已发生的、踢球开始后的首个足端接触采样；后续不能重写首触球。未触球时存在有限等待上限。新回合必须新建状态对象。

输入检查包括整数/有限范围、严格递增控制时钟、接触不能来自未来或起脚前，以及异常输入不改变内部状态。异常会抛出 `ValueError`，不是宿主运行时的自动 fallback。接触本身不代表干净射门，非足触球、跌倒、目标误差等仍须独立检查。

## 验证

- 23 项新单元测试通过。
- 与实际已录制的 S1377、S1380 共 42 个物理回合逐控制帧对照，恢复混合值、首触球观察帧、恢复起始帧完全一致。报告位于外部证据根目录 `s1381-recovery-timing-adapter-parity-v1/result.json`。
- 联同已施加动作编码与 held-action 聚合回归，共 56 项通过；新增模块的 ruff 与 mypy 检查通过。
- 全量回归：2932 passed、29 skipped、11 failed。11 项均为既有外部证据绑定失败；与 S1361 的 JUnit 失败测试标识集合逐项相同，没有新增失败。完整结果在外部证据根目录 `s1381-full-regression.xml`，不能称为全量全绿。

这只证明模块提取未改变相应时序。没有把该组件自动接入默认多人比赛，也没有晋升动作策略；同一时序在不同运动状态下可能成功或失败。S1376 和 S1377 的高角目标实验都没有取得合格高角进球，不能用时序验证通过替代球技成绩。

后续 S1383 是另一项实验：在冻结完整踢球、走路底座与参考运动的条件下，从零初始化新的 136/29 残差 actor-critic，固定 8 代 PPO，以独立种子复考真实高角目标。虚拟策略条件点、真实球门目标、弹道预测引导和真实越线证据分别记录；学习完成与模型晋升是不同步骤。本文不预告其成功。
