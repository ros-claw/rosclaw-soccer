## 已启动的自动后续流程

`finish_s2686_campaign.py` 正在等待完整采集结果，之后按顺序执行：

1. 要求全部 48 个课程完成，不静默删除失败课程。
2. 核对计划、源码、父模型、文件和报告哈希；核对主运行和重放的逐数组一致性。
3. 按原随机数顺序重建全部采样动作、logp、value。
4. 用实际探索、控制生效、接球阶段的交集确定逐角色训练资格。
5. 使用同一批新数据执行 **16 个 PPO epoch**，保留旧行为约束系数 25。
   样本不足的角色冻结，不降低现有样本门槛。
6. 重新计算模型更新，要求权重和 Core 更新租约记录完全一致。
7. 三档速度分别执行父模型／候选模型无探索噪声对照，共六个课程，各带重放。
8. 保存结果供复查，**不自动晋升模型、不替换默认球队**。

当前不能声称步骤 2–8 已完成。数据校验、训练或复测失败会保存失败状态并停止
后续阶段；不会把不完整课程集当成完整成功结果。

## 资源和恢复边界

- 启动时 32 个 CPU 线程、约 98 GiB 可用内存。
- GPU 0/1 大部分被其他工作占用，不干预；2/3 有余量。本批沿用经过重放校验
  的 CPU MuJoCo 队伍链路，**不是 4 GPU 或 GPU 向量化训练**。
- 根盘启动时约 7.8 GiB 空闲。预算每课程 80 MiB，并保留 3 GiB；启动检查
  按所有尚未完成课程计算，不是只按一个工作进程计算。每个采集器再次检查余量。
- 临时仿真放在 `/dev/shm`，完成后持久化。不是磁盘空间的实际预留；外部任务
  继续写盘仍可能使采集失败，失败不能伪装为通过。不删除历史证据。
- 每完成一个课程原子更新进度。重启后仅复用哈希有效且与计划一致的完整课程；
  不完整目录／日志不覆盖，标记为需要复查。
- 后续自动流程等待采集有三小时上限，不永久空转。
- **批次和后续复测结束前，不修改 source tree、父模型或采样脚本**。源码校验
  可拒绝混入不同版本；它不能替代运行期间的版本冻结。
