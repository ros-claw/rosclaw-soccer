# S334–S338：学习结果与跨技能神经历史交接

## 已经做成的组件

新增 `providers/g1/sonic_history_handoff.py`，把导航控制器的十帧实测本体历史传给刚初始化参考的射门控制器。接续的是神经网络输入历史与上一动作，不是拼接录像，也不改写人体或足球状态。

交接检查同一球员标识、同一控制时刻、相同 SONIC 资格与动作归一化参数、相同实测状态；允许仅用于推理副本的身体/球一致 XY 平移。检查源控制器确实记录了当前控制后的本体状态，目标控制器仍处于刚 reset 的状态。校验完成后才复制数组，避免源控制器后续修改污染目标。每次显式 reset 后最多交接一次，包括全零动作的重复交接也拒绝。

球员身份与时钟的外部真实性仍由共享仿真调用方负责；该模块验证传入声明与数值一致性，不是硬件权限凭证。它不允许任意航向旋转或跨机器人交接，也不负责修改参考轨迹。

## 为什么需要这个改动

之前的“物理不停步”链路，射门控制器仍把当前姿态重复十次作为初始历史，丢掉了助跑时真实的关节速度和动作变化。这次明确区分：身体运动连续、神经历史连续，是两个不同的条件。

原 S325 相关报告中“Proprioceptive history never reset”的表述已用追加勘误澄清；原始证据哈希保持不变。

## 训练与实战复测

S334 在修正且提前校验的物理坐标下，从 S332004 恢复模型、Adam 和 RNG，继续 16 轮真实 PPO。SONIC 与参考库冻结，192 个世界来自三个实测入口的扰动副本。首轮 304 步精确重放，所有权重误差为零；每轮 Core 可塑性审计只允许残差学习器变化。

固定 GPU 开发考试的强射门数量：初始 128/192，第 8 轮 192/192，第 12 轮回落到 160/192，第 16 轮 192/192。六个不同固定开发状态的副本不算独立统计样本，训练过程也不是单调进步。

S335/S336 分别对中间与最终检查点运行完整 CPU 考试，仍发现新球位 4.125 m 的关节超限等问题，没有全局采用。S337 才发现真实历史交接可以改善这类切换行为；随后 S338 改用公共校验模块，再完成 32 次 CPU 运行：两个模型 × 八个物理课程 × 两次精确重复。交接历史摘要、时间、球员与原始数值轨迹均检查。

| 摩擦 0.6 的五个球位 x / m | 原模型 + 历史交接球速 / m/s | 训练模型 + 历史交接球速 / m/s |
|---|---:|---:|
| 4.000 | 3.131 | 3.736 |
| 4.125 | 3.007 | 3.463 |
| 4.250 | 3.258 | 3.485 |
| 4.375 | 3.100 | 3.501 |
| 4.500 | 3.357 | 3.733 |

两种模型在这五个球位均身体安全、强前向触球并穿过球门内部。训练模型的球速提高不是纯调参：它来自真实的 29 关节残差 actor-critic 更新，但基础 SONIC 仍冻结，也不是直接力矩端到端策略。

**仍不能宣布完整晋升**：训练模型在摩擦 0.6、球位 4.0 m 的严格滚动检查失败（滑移比 p95=0.310）；同条件原模型通过。在摩擦 0.4 的三个旧球位，训练模型身体、强射门、球门与滚动检查均通过，原模型有一个滚动失败。不同物理域不能合并成一句“全部变强”。

## 验证和后续边界

与导航、残差小脑一起的聚焦测试 50 项通过。全库 1504 passed、29 skipped、11 failed；11 项仍为既有外部历史证据绑定失败。ruff、mypy 433 源文件通过。

这证明了单机组件的连续交接与学习效果，还不是 4v4 比赛通过。保持旧默认模型；进一步在更多球位检查滚动、身体恢复和传接球兼容性，再考虑绑定明确场景的候选应用。没有改变多人世界速度上限，没有硬件授权。
