# S532–S538：目标条件衔接学习与物理诊断

日期：2026-09-11。执行范围为 CPU MuJoCo 仿真。

本轮把目标条件导航 actor-critic 接入真实物理 rollout 和公共 PPO 更新器。
已训练、已保存 checkpoint，不等于已经学会比赛。当前完成的验收没有合格的新
衔接策略，现役策略没有被替换；没有生成新的宣传视频。

## 公共工程修正

`training.handoff_policy` 上一版只是特征函数和限幅函数。其“egocentric”
说明与实际世界坐标输入不一致；`residual_norm` 也不是残差历史。
本轮把目标位移旋转到身体坐标系，拒绝零距离目标与非法限幅参数，明确限幅不
保证平衡、连续性或实际执行。旧特征语义变化须重新生成训练输入，不应直接
复用按旧语义训练的权重。

新增可选 Torch 后端 `build_handoff_actor_critic()`：输入 143 维，包括
133 维运动状态（含完整 29 维上一关节残差）、3 维上一导航动作、7 维目标
特征。输出 3 维原始导航动作及 critic；沿用现有导航动作包络与场景投影。
观测使用上一步基础策略目标，随后才推进基础策略，避免动作反过来污染本次
策略观测。基础运动策略和电机 actor 保持冻结。

公共 PPO 只新增显式 `(143, 3)` 合同；既有输入形状和默认探索下界不变。
此模型是目标条件导航学习器，不是直接输出关节力矩的端到端小脑，也不是
已上线的多智能体自我进化系统。

## 实验与失败证据

所有小规模配对评估都从 **同一个实测身体初态的四种扰动**开始。32 世界的
控制器扫描是八个方案乘四扰动；PPO 评估则把四扰动各重复八次，不能把它
解释成 32 个独立身体场景或泛化成功率。训练另加球位、球速扰动。

| 实验 | 改动 | 观察 |
|---|---|---|
| S532 | 八种转身启动时刻，32 次 CPU 回放 | 连续控球 0，出球姿态 0，身体安全 19/32 |
| S533 | 两种启动时刻 × 四种接球残差衰减 | 连续控球 0，出球姿态 0，身体安全 25/32 |
| S534 | 目标条件 PPO，8 次 rollout/update，9 次评估 | 160 优化步，所有评估出球姿态为 0；基线/最终安全均为 24/32 |
| S535 | 绕球移动的站位目标及切向速度补偿 | 连续控球 0，出球姿态 0，身体安全 6/32 |
| S536 | 只对参与控制的片段做 PPO，16 次更新 | 192 优化步，所有评估出球姿态为 0；安全由基线 24/32 降到最终 16/32，拒绝候选 |
| S537 | 转身阶段保持 recurrent 镜像坐标系 | 连续控球 0，出球姿态 0，身体安全 7/32 |
| S538 | 在 C15/24 基础上加入实测球速补偿 | 零补偿基线 1/4 控球；其余方案均为 0/4，所有方案出球姿态为 0 |

S534 的动作均值参数最大变化约 0.00182，critic 最大变化约 0.00484。
保存真实 rollout、更新前模型、Adam 状态与随机状态，再独立重放首次更新，
所有参数最大误差为 0。这证明优化器确实消费了真实仿真数据；不证明球技提高。

S536 随后排除导航尚未实际参与控制的前 80 帧，增加到 16 次更新；最终仍
失败，首次更新也通过独立精确重放（最大参数误差 0）。两批合计 24 次
rollout/update、352 个优化步骤。它们仍是冻结低层电机模型的导航学习实验，
没有获得可用的新球技。所有训练进程已正常退出，模型与训练数据已保存。

这些实验暂不支持“只是延迟一下转身就能解决”“球速补偿即可解决”或
“固定坐标系即可解决”。当前证据指向动作组合与接球末态分布的问题；尚不能
凭这些小样本确定唯一原因。完整衔接需要在不同接球末态、目标方向及后续动作
上训练和验收，低层适配也应纳入候选，而不是仅凭导航奖励上涨认定改善。
