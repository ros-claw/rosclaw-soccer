# S84：三台 G1 连续传射与双手高球扑救

日期：2026-08-25
状态：`FROZEN_SIM_DEMO` / `SIM_ONLY`
物理权威：CPU MuJoCo 严格回放；视频像素不参与评分

## 结论先行

本轮打通了同一物理世界、同一颗球、不中断重置的三角色闭环：第一台 G1
传球，第二台 G1 将来球踢成高速高球，第三台 G1 双手举起并由解剖手套发生真实
接触，把球扑到球门外。最终候选连续执行 11 秒，并通过两次逐状态一致的 CPU
MuJoCo 严格回放。

这不是三段成功动画的剪辑。宣传片由已经冻结的 `trajectory.npz` 下游渲染；
传球、射门、手套接触、球门判定、关节与力矩安全均由物理状态评分，画面没有反向
参与候选选择。

| 事件 | 仿真时间 | 结果 |
|---|---:|---|
| 传球触球 | 5.602 s | 球进入前锋击球口袋 |
| 前锋触球 | 7.390 s | 形成高速高球 |
| 门将手套触球 | 8.020 s | 右手套真实接触，双手均已举起 |

关键量化结果：

- 传球三维误差 `0.004634 m`（4.6 mm），横向误差 `0.002251 m`。
- 射门峰值球速 `10.270 m/s`；门将前入射速度 `8.701 m/s`。
- 射门飞行最高点 `1.459 m`；手套接触高度 `1.409 m`。
- 接触时左右手高度分别为 `1.242 m`、`1.239 m`，均超过本轮提高后的
  `1.20 m` 双手门槛。
- 扑后球速度 `8.742 m/s`，低于新增的 `10.0 m/s` 上限，没有不自然的增能。
- 球最终在 `y=5.009 m, z=1.141 m` 处穿过球门平面；标准球门半宽只有
  `3.66 m`，所以球从门柱外侧飞出，判定为 `NO GOAL`。
- 11 秒内传球者、射手、门将最低骨盆高度分别为 `0.681 m`、`0.646 m`、
  `0.727 m`；无关节越界、无力矩越界、无执行器饱和。

## 本轮开发

### 1. 通用双臂高球协同

在 `G1GoalkeeperConfig` 中加入有界的辅助手高举偏置。高球的主到达点仍由可见球
历史 actor 估计，双臂动作仍通过任务空间/Jacobian、关节投影、力矩限制和 CPU
物理执行；新增偏置只让非接触手保持在肩头以上的接球准备位，不绕过控制链直接
改写画面。

门将真实接触后会锁存事件并退出高球专项路由，回到站立小脑，避免扑后继续追逐
已经离开的球而发生抽搐或晚倒。

### 2. 失败驱动选择，不以“看起来成功”为准

本轮窄区间扫描暴露了三个不同失败族：

- 双臂偏置过小：球被扑出，但辅助手停留在胸肩附近，宣传画面不可信。
- 双臂偏置过大：出现关节越界、尾段失稳，或手套改变接触点后漏球。
- 接触阻尼过低：双手姿态和扑救都成功，但扑后速度达到约 `15.45 m/s`，存在
  非自然增能。

最终保留 `0.26 rad` 辅助手高举偏置和 `0.15` 手套接触阻尼，并新增扑后总速度
上限门控。旧的“能挡住即可”被升级为“真实接触、双手到位、确实不进、扑出速度
合理、三人尾段稳定”联合验收。

### 3. 更严格的证据与媒体绑定

新增独立 S84 证据入口和下游媒体渲染器：

- 两次 CPU MuJoCo 结果字典与轨迹摘要必须一致；
- `request.json`、`trajectory.npz`、实现文件和模型资产均以 SHA-256 绑定；
- 视频渲染前重新校验冻结证据、Body hash、请求 hash 与轨迹 hash；
- 输出清单明确写入 `visualization_only=true`、`pixels_used_for_scoring=false`、
  `activation_ceiling=SIM_ONLY`。

### 4. Fail-closed 加固

高强度失败扫描曾产生提前终止的非有限轨迹。评估器现在会先拒绝非有限 rollout，
并验证触球时间必须落在实际轨迹范围内，避免截断数组或错误接触时间造成异常或
误通过。

## 诚实边界与下一步

这证明的是一个确定性、标准球门条件下的高质量三角色连续样例，不等于不同落点、
不同速度和不同随机种子下已经达到 80% 扑救率，也不等于真实 G1 获得了硬件授权。
下一步应把这一成功轨迹加入课程学习与 replay buffer，训练覆盖左右高角、速度扰动、
传球误差和门将横移的 actor population，再用独立 holdout 统计三角色联合成功率。
