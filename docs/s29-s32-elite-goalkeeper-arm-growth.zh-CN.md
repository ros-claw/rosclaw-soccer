# S29–S32 G1 门将上肢成长与精英发球闭环报告

日期：2026-08-14
边界：`SIM_ONLY`；GPU 训练使用 MuJoCo Warp，终审使用单线程 CPU MuJoCo；没有打开 ROS、DDS、串口、CAN 或真实机器人接口。

## 1. 先说结论

这一轮不是简单把手臂动作放大，而是完成了“增加上肢可塑性—提高发球难度—独立物理终审—失败回写”的闭环。

- S31 保守策略通过 4×A6000 独立留出集和 160 回合 CPU MuJoCo 终审。CPU 上平均最大手部位移由 **5.05 cm 提高到 13.36 cm（2.65 倍）**；95 分位根部角速度由 **1.385 降到 1.289 rad/s**，没有跌倒、关节越界或力矩越界。
- 新的 `elite` 发球分布覆盖球门左右 `±1.10 m`、高度 `0.10–1.65 m`、飞行时间 `0.30–0.50 s`。在终审的固定种子上，284 次实际发球速度为 **7.41–14.94 m/s**，均值 **10.46 m/s**，95 分位 **13.42 m/s**；124/160 个回合包含第二发。
- 继续增强的 S32 高球伸臂策略把训练时手部位移推到约 **19.9–21.0 cm**，但所有 8 个迭代都超过稳定门，峰值根部角速度为 **4.99–11.26 rad/s**，部分迭代出现 `0.39%–0.78%` 失败率。因此它被正式记为 `REJECTED_NO_SAFE_CANDIDATE`，没有生成 checkpoint，也没有替换 S31。
- 当前视频能如实展示低球手套扑救和二次扑救；两个高球片段仍是身体封堵，不是成熟的飞身手扑。S31 是一个更好的稳定上肢专家，但尚不能称为真人级门将或新的全局 Champion。

## 2. 用户反馈被转成了哪些工程指标

“手臂挥动还差远了”被拆成了四个可测量量，而不是只看视频：

1. 手相对骨盆 ready pose 的最大位移；
2. 手速度及其 95 分位，防止抽搐式刷位移；
3. 手部真实接触后的扑救率，而不是身体接触冒充手扑；
4. 手臂动作引入的根部角速度、横向漂移、跌倒、关节/力矩越界。

“提高发球难度”则被固化为不可变 world config：更近的发球点、更短飞行时间、更宽/更高目标范围、双发概率以及固定种子速度审计。视频像素不参与任何评分。

## 3. 主要开发内容

### 3.1 独立的上肢可塑性通道

`GoalkeeperMJWarpConfig` 将躯干和手臂的滤波、最大动作步长及 residual scale 分开。这样可以在不解冻 29-DoF 下肢小脑的情况下提高肩、肘、腕学习能力。GPU 环境和 CPU 考试实现完全同构，并报告滤波后的真实最大动作步长。

第二发单独设置手臂 authority，避免首扑后的残余动作在第二球到来时继续扭动身体。最终 S31 的最大施加动作步长为 `0.072`，低于终审上限 `0.08`。

### 3.2 只训练手臂的 PPO 与教师蒸馏

`arm_only_online_update` 做了两层硬冻结：

- 教师预训练时，trunk 参数和 actor 的前 4 个输出行逐元素保持不变；
- PPO 探索、log-probability、entropy 和梯度只作用于 14 个手臂通道。此前即使声称 arm-only，随机探索仍会扰动横移/腰部通道，这个隐蔽问题已经修复并由测试锁定。

任务空间教师使用编译后的真实 G1 左右手 Jacobian，生成肩—肘—腕一致的镜像动作，而不是凭视觉写动作补丁。教师只作为训练目标，不能直接控制 MuJoCo，更没有硬件权限。

### 3.3 更重视真实手扑的密集物理奖励

精英课表提高了 hand contact、hand save、second hand save、单手 reach 和双手协同 reach 奖励，同时增加根部角速度与动作幅值惩罚。候选选择分数同时考虑手扑、二扑、手位移和根部角速度，不允许只靠大幅摆臂获胜。

### 3.4 CPU/GPU 一致的非劣终审

CPU 终审默认仍要求 `maximum_save_rate_regression = 0`。精英专项考试显式声明 1% 的统计非劣界限，相当于 160 回合最多容忍 1 个离散扑救差异；它不是全局默认放宽。终审同时要求：

- 零跌倒、零关节越界、零力矩越界；
- 平均手位移至少增加 5 cm；
- 95 分位根部角速度不超过 2.0 rad/s；
- 瞬时根部角速度不超过 4.0 rad/s；
- 最大施加动作步长不超过 0.08。

### 3.5 失败也进入 Growth 记忆

S32 暴露了训练器的闭环缺口：如果所有迭代都未通过安全选择门，旧实现会抛异常，导致失败经验无法落盘。现在训练器写出 schema v3 报告：

- `promotion_status = REJECTED_NO_SAFE_CANDIDATE`；
- `candidate_available = false`；
- checkpoint 名为 `null`、字节数为 `0`；
- 最佳分数使用 JSON `null`，不写入 `Infinity/NaN`；
- 写明拒绝原因，并保留教师、每轮指标、四卡同步差异和训练量。

因此失败分支不能被误用为候选，又能成为下一轮训练的反例数据。

## 7. 为什么还不像真人门将

目前的结构冻结了下肢 locomotion prior，只允许横移意图、腰部和手臂 residual。它适合验证 ROSClaw 的安全持续成长，但天生限制了真正高球扑救所需的蹬地、降重心、跨步、侧倒和落地恢复。S32 已经用数据证明：在下肢不配合时继续放大手臂，会把反作用角动量传给躯干，表现为横漂和旋转，而不会自然变成飞身扑救。

因此下一步不能再只是“提高手臂系数”，需要模块化增加：

1. **角动量补偿器**：根据肩臂动作速度预测躯干反作用，用腰部、支撑脚和横移 prior 做前馈补偿；
2. **全身扑救技能 option**：仅在高球/远角且安全域允许时解冻受限的髋、膝、踝动作，学习蹬地—触球—缓冲—起身完整时序；
3. **真人动作模仿**：把 SONIC/MotionDecode 中许可和 Body 对齐合格的门将片段只用于姿态/相位先验，再由物理 RL 决定接触与恢复；
4. **课程化对抗发球器**：自动寻找当前策略最弱的高度、横向和速度区域，但保持独立留出种子不参与训练；
5. **Stability–Plasticity 双记忆**：S31 作为稳定专家，新的全身 option 作为可塑专家；只有多课表配对考试全通过才更新路由或 Champion。

这条路线的目标不是让一个危险的大动作通过门控，而是让 G1 学会“手伸得更远，同时脚下和躯干知道怎样配合”。
