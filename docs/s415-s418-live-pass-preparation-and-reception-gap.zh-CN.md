# S415–S418：把学到的出球接回角色协作

新出球策略已经在真实八人共享 MuJoCo 世界里运行，出现了正确方向的脚出球；新传球准备流程也实际唤起了接球技能。但接球者先碰小腿再碰脚，仍不合格，没有发布新的宣传视频。所有工作均为 SIM_ONLY。

## 两阶段动作桥接

实验性 139/32 适配器先根据当前身体、上一帧步态目标、上一帧残差和固定队友目标提出导航修正；场内/邻居约束由共享世界重新投影。随后只运行一次原有 LSTM 步态基础，再将同一帧缓存的关节残差叠加到该基础目标。

适配器不拥有仿真器或 LSTM，不推进第二次隐藏状态，不修改球和机器人姿态。重复导航、错帧消费、缺少当前球员资格或错误基础模型绑定都会拒绝。首次实际定向脚出球后，可以继续同一个有界恢复技能，不要求继续占有已经传出去的球，也不因此获得新传球资格。

目前使用显式第 220 帧的开发触发点，并非自主技能入场策略。桥接实现仍在外部实验目录，不能将它写成已经发布的通用导航插件。

S415 v1 错将“已确认持球”作为准备接近自由球的必要条件，候选未运行；两个候选的所有轨迹数组都与旧基线一致。v2 修正准备资格后，又在球权转移时错误中止恢复，完整物理轨迹保留，但旧的稠密动作观测打包断言失败。v3 区分出球前资格与出球后有界恢复，完成了 250 个控制帧、2500 个物理观测；实际脚接触 6 个采样，非脚接触为 0，最大沿目标方向球速约 0.798 m/s，八个身体安全、无机器人碰撞或电机候选故障。未形成有效接球。

## 为什么球传出了，队友却没进入技能

旧约定约在 1.82 秒建立，3 秒准备期到 4.82 秒结束。新动作的定向脚接触出现在稍后，因此该约定没有获得有效的飞行记录。单纯修改机器人动作并不能自动修好角色协议。

已经新增 `growth.pass_preparation`：

- 电机技能只提交不可变的准备请求，不自行创建或批准传球约定。
- 共享世界要求同一帧的双方认可、相同传球目标、当前有效电机提案、稳定且就绪的双方，以及尚未发出的有效旧约定。
- 形成一份新的、显式绑定的准备记录，仍保留原来的 3 秒准备期与 3 秒飞行窗口。旧约定和新约定哈希、角色协议哈希、动作目标哈希、请求及仿真范围均进入记录。
- 同一个请求、已经准备过的旧/新约定、过期约定、已发出的球均不能再次绑定。它不是悄悄延长既有飞行窗口。
- 完整记录作为普通 JSON 字符串进入轨迹，不依赖 pickle；未启用新协议的旧场景逐数组完全复现原轨迹。

这是 Soccer 的角色—技能协作能力，不是 G1 专用的关节补丁，也没有任何真实硬件权限。账本只覆盖单次仿真回合，不冒充持久化硬件控制账本。

## S418 实际结果与下一个失败点

八人仿真在 4.400 秒实际生成唯一的新准备记录，准备截止 7.400 秒；4.874 秒的真实定向脚接触建立飞行记录。接球者在第 326 帧、6.520 秒进入学习过的接球技能。

然而 7.570 秒先发生接球者的非脚接触，7.608 秒才碰到脚。1000 个接球物理采样里有 9 个非脚接触、6 个脚接触，末段球速约 1.648 m/s。因此不是干净停球。八个身体仍安全，无机器人碰撞；全局非脚触球导致出球候选按原有保护锁定退出，后续球出界。

旧的动作提供者观测打包假定“所有提供者永不退出”，在这种真实故障下断言失败。S418 已在断言前保存完整仿真诊断、轨迹、LSTM 状态、源出球和接球的物理观测，故障没有被删除或改为通过。下一轮将独立记录每帧实际身体状态，使故障后的真实数据仍可用于分析，而不是填补虚构观测。

接球身体入场时朝向与来球方向不一致，而旧接球导航固定为零转向。下一轮同时检查面向实际来球的有界导航与神经网络接球动作；该导航提示必须标为解析控制，不冒充新训练模型。

## 持续学习复查

S416 从 S413 完整检查点继续训练四种身体相位，16 轮共 3440 步优化。新 128 种不同开发起点的合格出球从 20 提高到 50，其中高目标球速组出现 7 次成功；CPU 相邻相位从 1/16 提高到 6/16，身体全安全、球全在场内、无非脚接触。但旧相同起点基准从 16/32 下降到 15/32。

S417 将旧成功起点逐个声明为关键保持任务，实际调用未修改的 ROSClaw Core 门控。完整比赛范围仍判定缺少验证；另对已经完成的 CPU 子任务单独评估，历史保持和关键技能检查均失败，结果 REJECT。没有因平均分增加而替换旧模型，也没有补造回放、SelfCore 或其他缺失证明。
