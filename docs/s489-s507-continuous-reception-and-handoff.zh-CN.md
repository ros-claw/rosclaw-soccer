## 可复现的实际进展

S489 将原来成功动作的完整 100 个控制帧重新在 CPU 物理仿真中执行并采集。
S490 通过公共 `training.success_distillation` 把 100 帧学入同一个 133/29
神经网络。5000 步模型在原始成功初态下闭环通过，无 40 帧冻结前缀、无技能内
切换；1000 和 10000 步模型没有通过。它仍是冻结 LSTM 行走基础上的有界关节
目标残差，不能称作端到端直接输出力矩的全身模型。

S495、S496 用物理结果搜索神经网络末层的 29 个偏置，并保留原网络其余参数。
这是 CEM 参数学习，不是 PPO。S496 在四个开发扰动中选择最差情况仍较好的
候选，得到 `s496-robust-whole-skill-weight-search-v1/actor-007.npz`：


第一脚传球由前锋真实踢出。中场在 6.4 s 入场接球、7.232 s 首次脚触球，
8.4 s 完成接球并触发下一脚传球准入。触球后 0.3 s 至接球技能结束的整个区间，
球速最大 0.359430 m/s，球到最近脚踝距离最大 0.308961 m，均满足持续控球

但下一脚没有完成发射，球最终出界。**准入不是发射，发射不是传球成功，
接稳一次更不是比赛成功。** 当前仍未达到值得宣传的连续比赛效果。

## 修正了什么衡量问题

旧判据分别检查触球后 0.3–0.5 s 与结束前 0.2 s，中间有空档。
S495 的现场候选恰好两个窗口通过，但中间球到脚踝距离达到 0.391839 m；
之后第一次机器人碰撞发生在 8.6 s。不能将这个案例记作持续接稳。

S497 增加独立的 2 ms 连续审计。使用上一物理子步的 qpos 重算脚踝位置，
匹配 MuJoCo 已缓存的位置语义，再与当前球位置计算距离；不重写旧结果。
S496 的上述现场案例也通过了这个更严格的连续审计，因此进展不依赖测量空档。

S506 没有脚触球，旧审计对 `None + 0.3` 抛错。另存 `audit_v2.py`，不覆盖已
绑定哈希的旧脚本：无接触和空接触窗口明确返回失败，峰值为 null，不把空数组
的 `all()` 作为成功。球末速较低但发生非脚触球，仍不是合法接球。

S496 的 18/32、15/32 采用历史两个窗口标准；S498/S501 与父模型比较采用
更严格的连续标准。不能跨标准直接比较百分比。所有 CPU 扰动都只是同一个
捕获身体状态附近：球 XY ±0.015 m、速度 XY ±0.03 m/s、关节 ±0.002 rad。
32 次试验也不足以证明跨场景、跨角色、跨对手泛化。

## 稳定性与可塑性：保住成功不是提高泛化

S493 从 S490 成功模型继续 PPO，16 次更新、1186 个真实优化步；原成功初态
后来失败。S494 每轮 PPO 后，再对旧成功记忆做 8 步正优势加权的 actor-only
监督保持，共 1356 个 PPO 步和 128 个保持步。旧成功初态仍通过，但名义来球
开发组仍为 0/32，最终非脚触球增多，不能称作整体优于纯 PPO。

两组随机种子不同，这不是严格配对的因果消融。S494 的保持更新不修改 critic，
不把旧样本冒充 PPO 新鲜样本；它只是部分借鉴成功经验保持，不是完整复现
Self-Imitation Learning 的离策略 actor-critic 算法。

独立审计验证 S493 第一轮 PPO 参数精确重放；S494 第一轮 PPO、优势权重
重算、8 步保持都精确重放，最大参数误差 0。S503 也通过首轮重放，共 944
真实优化步、1024 个训练 rollout、256000 个控制帧。**更新确实发生不等于
运动成绩合格。**

## 接住以后为什么仍传不出

S496 现场在下一传球入场时，身体 yaw 约 −1.004 rad，下一目标方向约
−2.88 rad，相差约 1.88 rad；球在身体侧后方，速度约 0.35 m/s。旧传球导航
确实在追球和转身，并非命令一直为零，但还在转身时球已离开合适的触球范围。

此外，接球残差结束时最大约 0.129566 rad，旧转传适配器从残差零开始。
S502 按实际观测和同帧 foundation target 重放 100 次公共接球推理，提取该
残差历史；S503 训练时继承这份历史以及原 LSTM 状态。这个交接尚未在完整
现场部署，不能说实际换策略突变已经修好；并且它单独没有使转传成功。

因此下一阶段不继续用“接球计时结束”代替“下一技能可用”：需要把球相对脚的
位置、速度、身体朝向、剩余运动状态一起作为衔接任务，而不是分别把两个技能
在各自初态训练好后直接拼接。

## 数据驱动的技能选择：目前只有上限分析

S507 检查 S501 的 256 个已搜索候选与相同 16 个训练状态：最好单一候选覆盖
9/16，四个互补候选的联合覆盖可达 15/16。但这里根据已知结果选动作，是
oracle 覆盖分析，不是可部署策略，也不是新考试。它只说明不必强求一个固定
偏置覆盖所有上下文；后续可训练仅看当前本体/来球状态的选择器，并在新种子
和真实现场验证。不得把 15/16 写成当前系统成功率。
