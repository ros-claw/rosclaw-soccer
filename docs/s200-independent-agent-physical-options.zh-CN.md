# S200：独立 ROSClaw 智能体的物理技能路由闭环

## 结论先行

S199 已经证明 6 台 G1 可以各自拥有独立的 ROSClaw Agent Cell，并在同一个 MuJoCo
球场里持续观测、决策、协商和行走；但当时 `PASS`、`SHOOT`、`SAVE` 仍只是高层意图，
没有证据证明这些意图真正触发了脚与球的物理接触。

S200 补上了第一段执行闭环：组织者的 `PASS` 和终结者的 `SHOOT`，必须由当前 Agent
Cell 的决策产生，经内容寻址的物理 option 请求授权，再由冻结的全身接触策略执行，
最后用 MuJoCo 的接触、球速、姿态、安全和恢复状态关闭请求。另 5 台 G1 在同一时钟中
继续运行各自的策略，并没有被替换成动画或静态道具。

最终候选通过了如下事实门：

- 传球和射门都观察到真实的右脚—球碰撞；
- 接触后球速相对接触前有显著增益；
- 两种 option 都完成了接触事件门控的运动策略→行走策略恢复交接；
- 6 个 Agent Cell 在每一个团队决策帧都给出了自己的当前决策；
- 6 台全身 G1 同时存在于一个 174 actuator 的 CPU MuJoCo 世界；
- 没有机器人互撞、关节越界、球状态瞬移、根位姿回写或硬件命令；
- 主跑与独立重放的结果和轨迹完全一致。

这还不是完整比赛闭环。当前阶段只证明独立 Agent 的 `PASS`/`SHOOT` 意图能够安全、
因果地进入真实接触技能；尚未宣称一次传球后由接球队员连续完成接球、射门和门将扑救，
也尚未达到 0.1 m 射门精度。

## 为什么原来的角色“不知道自己要干什么”

过去的成熟三角色仿真把很多能力集中在一个共享世界控制器里。它可以展示传、射、扑，
却不能证明每个身体后面都有独立的 ROSClaw：谁拥有观测、谁做决定、谁能学习、谁承担
失败，都不够清楚。

S199 把心智拆开后，又出现了另一层断点：Agent Cell 会说“我要传球”，但冻结的行走
策略只接受速度命令，并不会因此摆腿触球。S200 的工作就是把这个断点变成显式协议：

```text
独立本体/角色模型
  → 私有观测与 Champion 策略
  → 当前 PASS/SHOOT 承诺
  → 团队协调帧/接球握手
  → 独占球权的 PhysicalOptionRequest
  → 冻结全身接触策略
  → MuJoCo 接触、球速、安全、恢复测量
  → PhysicalOptionOutcome
  → 后续个人失败记忆与 Growth 更新
```

这个协议的重要性不在于多了一个函数，而在于禁止了几种“看起来会踢球”的捷径：

- 不能拿旧帧决策触发当前动作；
- 不能把 A 球员的策略或观测换给 B 球员；
- 传球没有接球队员的时序握手就不能启动；
- 高层意图、目标、球状态、接触策略必须在同一请求哈希中；
- 请求没有直接关节力矩或硬件权限；
- 未触球的 option 到期后必须立即平滑交权，不能在租约外继续摆腿；
- 成功不能靠视频像素判断，必须有物理接触、球速增益、安全和恢复交接；
- 仿真开始后不能写球状态或机器人根位姿来制造结果。

## 新增的通用模块

### `physical_option_router.py`

这是任务层到身体技能层的权限桥，不负责生成关节动作。它定义：

- `PhysicalSoccerOption`：`PASS`、`SHOOT`、`SAVE`、`DISTRIBUTE`；
- `PhysicalOptionRequest`：绑定 Agent Cell、Champion 策略、当前决策、协调帧、球状态、
  接触策略、目标、超时和可选接球握手；
- `PhysicalOptionOutcome`：记录接触时间/身体部位、接触前后球速、交付距离、进球/扑救
  接触、安全状态、恢复交接和越权写入；
- `build_physical_option_request`：验证上述身份和因果关系后才签发 SIM_ONLY 请求。

该模块不依赖 G1、MuJoCo、RoboNaldo 或 ROS，因此后续可以作为 ROSClaw 通用 Physical
AI option 协议的足球适配层继续抽象。

### `independent_option_world.py`

这是 S200 的 CPU MuJoCo 物理真值 runner：

- 在同一个球场实例化 6 台 29-DoF G1；
- 每台身体绑定自己的 Agent Cell 与冻结行走网络；
- option 所有者额外运行冻结的全身触球策略；
- 控制环为 50 Hz，PD/物理环为 500 Hz，团队决策为 10 Hz；
- 其他 5 台 G1 在 option 执行期间仍然自主移动和更新意图；
- 触球后只有在“真实接触已经发生”且“最低动作相位已经完成”时，才平滑交回行走策略；
- 每次物理接触和每台机器人的姿态、关节、力矩、脚位、意图、目标都写入外置轨迹。

### `independent_option_growth.py`

这是可重放的 Growth 证据程序。它分别运行组织者传球和终结者定向射门，并对每个情形
重新创建世界做一次独立重放。证据目录必须为空，原始 NPZ 和视频只写到仓库外部；报告
绑定源代码、输入、轨迹和每个结果哈希。

### `independent_option_video.py`

视频只从通过硬门并完成严格重放的 NPZ 轨迹生成。它不参与评分，清楚标记
`CPU MUJOCO · SIM ONLY`、`visualization_only=true`、`promotion_eligible=false`，并绑定
源报告和轨迹文件哈希。

## 三次失败如何推动了修复

### v1：按时间切换恢复，射手倒地

初版在固定策略帧切换到行走恢复，没有等待脚—球接触。射门在 6.878 s 才接触，但恢复
已经开始，造成最低骨盆高度 0.072 m、最大倾角 1.510 rad 和关节越界。总门正确拒绝。

修复：恢复交接改为两个条件同时满足——真实物理接触已经发生，且最低触球动作相位已经
完成。修复后射门接触提前到 5.538 s，最低骨盆恢复到 0.677 m。

### v2：把射门偏航参数复制给传球，传球擦球

射门参数 `foot_yaw_offset=0.085` 用于传球后完全没有脚—球接触。说明“共享小脑”不能
被误解成所有角色共享相同末端技能参数。

### v3：只恢复偏航，没有恢复摆腿幅度，仍然擦球

传球不仅依赖脚尖偏航，也依赖 `swing_amplitude=0.88` 的完整技能头。仅恢复偏航仍失败。

最终保留“共享、冻结、合格的基础运动模型 + 角色专属可学习技能头”。这正是
Stability–Plasticity 的工程化分层：基础稳定性不随一次传球失败被破坏，失败只更新拥有
该技能的 Agent Cell 与其 PASS 头。

## 下一阶段 S201

下一阶段不应继续做两个孤立触球片段，而应打通一个不重置球状态的连续链：

1. 组织者自主发现传球窗口并发起 PASS；
2. 终结者接受握手、跑位、FIRST_TOUCH 接球；
3. 同一个球继续进入 SHOOT；
4. 对方门将根据自己的观测选择 SAVE 并真实扑球；
5. 门将成功后选择 DISTRIBUTE，失败则把责任分到视野、站位、起跳、手型或恢复；
6. Growth 只给责任角色签发 Plasticity Lease，另外 5 个 Agent 和共享基础模型冻结；
7. 新候选必须同时通过个人保持集、团队保持集和困难对抗集，才能替换各自 Champion。

S201 的通过门至少应加入传球交付误差、接球真实接触、射门入框/目标误差、门将触球率、
连续球身份、角色信用分配和无重置恢复。之后再扩成更多球员和红蓝自博弈，才不会把“人多
了、都在动”误当成真正的团队自主性。
