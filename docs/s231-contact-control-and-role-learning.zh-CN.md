# S231：传射控制冲突、模块接续与角色学习（开发中）

## 结论与边界

目前仍没有达到完整 4v4 宣传比赛的效果。局部门将动作选择已经产生学习权重并回到物理世界复验；完整球队的问题主要仍在近球控制、真实传接与后续射门，不能用扑救发球器实验代替球队成绩。

本阶段只在 CPU MuJoCo 共享八 G1、单足球世界中运行。冻结走路策略仍是底层基础，角色决策仍含规则，新增训练不是全身端到端力矩小脑。无硬件操作、模型自动晋升或默认策略替换。视频没有用成功片段掩盖整场失败。

## 做了哪些工程改动

1. 增加只读力矩分解：每个 50 Hz 帧保存最后一个 2 ms 控制子步的原跟踪力矩、触球残差、跟踪调整、保护后实际力矩、任务力及脚踝位置。有效标记区分未调用教师与真实采样，不能把活跃帧数写成传球数。
2. 增加默认关闭的触球腿刚度对照：只降低所选腿六个关节的比例跟踪项，保留其阻尼、对侧支撑腿和下游力矩/关节保护。范围 0.4–1.0，默认 1.0 不改变原控制。
3. 允许显式提前介入关节保护：安全余量仅允许从原 0.04 rad 增至最多 0.10 rad，不降低位置、倾斜或力矩合格阈值。默认配置哈希保留历史身份。
4. 新增 `ContactControlProfile`，将同一实验控制配置传入既有角色课程、PPO 采集与考试。复用已有近球站位、预判接触与严格接球交接，不为训练和考试分别偷偷设置不同环境。
5. 增加实测 50 Hz 关节余量轨迹及 `contact_safety_v1` 奖励：在有限回合势能塑形基础上增加本智能体的关节限位风险惩罚。它不是安全证明，也不代替物理保护。旧奖励模式不变；新模式缺少余量证据就不能计算。

相关实现集中在 Soccer 的 `growth/locomotion_contact_teacher.py`、共享世界控制循环、`training/team_contact_diagnostic.py`、`training/contact_control_profile.py` 和既有私有 PPO/角色课程中。足球实现没有继续塞入 Core；Core 复用的是通用可塑性边界审计。

## 实际诊断与受限对照

证据根：`/code/rosclaw/phase8_evidence`。

`s231-torque-attribution-v1/red` 中 965 个有效采样，约 94.2% 原跟踪力矩在触球残差方向上相反，原跟踪投影中位数约 -17.81 Nm，残差向量范数中位数约 26.57 Nm，保护后投影约 8.11 Nm。反向力矩可能承担平衡职责，不能直接认为全部应该去掉。逐时段检查也显示后半段脚踝目标误差较大。

随后 `s231-stiffness-ablation-v1` 固定其他条件，对红/蓝开球各运行 1.0、0.8、0.6、0.4 四档、每回合 25 秒：

| 刚度比例 | 红开球峰值球速 m/s | 红身体安全 | 蓝开球峰值球速 m/s | 蓝身体安全 |
|---|---:|---|---:|---|
| 1.0 | 0.566 | 否 | 0.319 | 是 |
| 0.8 | 1.391 | 否 | 2.676 | 否 |
| 0.6 | 0.834 | 否 | 0.983 | 否 |
| 0.4 | 1.255 | 否 | 0.832 | 是 |

没有一档在两侧同时通过，不能选最高球速当冠军。部分球运动来自小腿接触，甚至存在足球移动但没有合格脚接触帧的回合。对照是固定开发初态，不是随机成功率估计。

`s231-stiffness-guard-v1` 在 0.8 档上考查 0.08/0.10 rad 提前保护，两侧四次均通过身体检查，但仍未形成合格比赛。0.08 档红/蓝峰值球速为 1.981/0.579 m/s，0.10 档为 0.771/0.098 m/s；保护过早也会妨碍触球。0.08 档的接触回放明确查到中场小腿先碰球，未把它改分类成脚。

上述旧诊断结果用 `asdict(result)` 保存全部原始字段，未包含计算属性 `safe`；初次批处理的打印因此中止，但该次轨迹和结果已经完整落盘，余下候选另行完成。安全结论由原始逐角色字段重建并调用原结果类计算，没有改写历史 JSON。新诊断已改用正式 `to_dict()`，直接包含这些属性。

## 复用既有模块后的完整接续

前一组诊断没有启用已有近球站位策略，默认传射站位离球约 0.72 m，不能作为训练版本的最终组合。

`s231-integrated-contact-v1` 接入既有 `OwnedBallContactPolicy`、预判接触、基础接传角色绑定、严格接球交接，使用新控制配置；红/蓝各运行两次 25 秒精确回放：

- 两侧均精确复现；红侧身体安全，蓝侧前锋出现踝关节限位失败，无机器人之间碰撞。
- 红侧评估器记录一次传球事件，但严格交接诊断发现中间非脚部接触，拒绝认定合格传接。
- 蓝侧出现争球和带球事件，仍没有合格传球。
- 两侧均没有高质量射门和扑救链，不能录成完成的宣传比赛。

这说明解除一个模块瓶颈之后还必须检查接续，不能把单模块参数改进直接写成球队成长。
