# S229：共享 4v4 门将运动控制接入（实施中）

本阶段不是完成报告，也不是宣传视频的通过证明。目标是把此前独立/三人实验的运动能力接入真正的共享球场，而不是把 `SAVE` 意图或手套碰撞体当作已具备扑救能力。

## 已经执行的工作

- 基于 S228 的刚体坐标投影，为红、蓝门将各自建立独立的观察历史、MOSAIC GMT 跟踪历史、伸手记忆和触球恢复状态。共享比赛仍只有一颗物理足球。
- 复用既有双手雅可比伸手、支撑手镜像和关节力矩迎球解码器。影子 MuJoCo 数据只计算关节目标/Jacobian；禁止回写球位置、速度、根部姿态或放大手套。
- 将 GMT 动作及其对应的手臂阻抗一起迁移。默认不启用这些实验控制，不晋升旧候选模型。
- 新增明确可选的走路模型手臂观测隔离。它仅改变冻结走路网络的输入：腿部、重力方向、角速度保持实测；完整本体感仍供独立智能体和上肢模型使用。推理发生异常也必须恢复输入副本。
- 触球后进入由真实、正接触力触发的短时连续控制阶段，不读取计划射门时钟。
- 增加独立契约的空中速度估计修正：历史位置差商是窗口中点速度，空中球当前竖直速度需要扣除 `g × 窗口长度 / 2`。整个窗口离地才应用；滚地球不产生虚假向下速度。旧观察器默认行为和原有演员契约不变。
- 共享主循环已真实跑过基线/候选两组 5 秒、8 机器人实验；不是仅做接口 mock。8 个角色均有决策和移动，候选出现手套接触；两组整体安全条件都未通过，不能据此宣布比赛突破。

## 已暴露、不能掩盖的问题

1. 仅接伸手残差时，手举得不足，可能实际是头部挡球。
2. 直接组合 GMT 上肢与冻结走路模型时，若上肢动作完整输入走路网络，会出现明显失稳。观测隔离对照改善了站立稳定性，但这不是重新训练出通用小脑。
3. 即使第一次有效接触来自手套，也可能球继续进门。另有球被缓冲、没有进门，但没有快速向场内清出。必须分开报告。
4. 同一物理步中原始手部碰撞体与手套可能同时接触。不能由 MuJoCo 的接触枚举顺序决定是手套扑救还是其他身体挡球。应检查首次身体接触集合，并排除同一步的头、肘等非手部接触。
5. 检查发现测试发球器早期版本球心高度为 0.110 m，而球半径是 0.115 m。新版本按真实半径初始化；此前有初始地面穿透的开发数据不能与修正后的正式考试直接混用。
6. 早期探索时有源码修改与实验重叠的问题。因此早期结果只作诊断，不作为可复现晋升证据。新考试绑定导入时完整 Soccer Python 源码树；工作进程发现代码变化拒绝启动下一案例，并记录结束时源码完整性。

## 分开的验收指标

- `hand_contact`：检测到了手套接触，不等于扑救成功。
- `first_robot_contact_glove`：首个身体接触物理步包含手套，且只涉及该门将的手部/手套；头、肘或其他球员先碰球不合格。
- `completed_hand_save`：上述条件成立、观察窗口内不进门、门将高度和倾斜通过。允许缓冲式扑救。
- `stable_save`：保留更严格的快速清球条件，在首次手套触球后 30–200 ms 内向场内速度大于 1 m/s，且完成扑救并稳定。不能用较宽的指标覆盖这个失败。
- `source_integrity_verified`：执行源码和导入时内容一致；还需重复回放一致性与未参与调参的考试。

模型的关节目标和迎球关节力矩仍通过原有 500 Hz 关节安全投影与硬力矩限幅。运动目标是 50 Hz。全部为 CPU MuJoCo、SIM_ONLY，沒有硬件动作授权。

## 数据位置与复现边界

本地开发证据位于外部证据根的 `s229-shared-keeper-v*`；共享主循环数据位于 `s229-live-roster-v1`。原始轨迹、模型和视频不进入 Git。

较新考试保存压缩仿真模型、模型哈希、完整物理轨迹、2 ms 手套接触力、所有球接触物体、观察窗口结果、GMT 权重/模仿技能绑定哈希。删除的仅是该次程序刚生成、已压缩并验证无损的中间 `world.mjb`，可由 `world.mjb.gz` 恢复。

这里的训练资产复用包括冻结 GMT 神经跟踪器及其已绑定的 MOSAIC 模仿技能。参数对照、参考动作跟踪和模型接入不能写成“新 PPO 模型训练成功”。新训练权重的产生、私有学习证明及球队晋升需要后续单独闭环。

## 尚未完成

### 环境对照新增事项

旧 S88 runner 显式使用 `solref=(0.0075, 0.15)`、手套接触优先级 1，以及腕部限位约束的 margin/solref；原共享球场没有应用这一套配置。因此新增独立的 `GoalkeeperGloveMaterial` 环境契约，统一施加给两队门将，尺寸、位置、质量和球状态不变。旧默认环境保留。

该项是**仿真环境假设对齐/敏感性实验**，不是新学习权重，也不是实测乳胶材料。每组基线与候选必须使用相同环境模型哈希，不能跨材料配置归因学习收益。MuJoCo 的 `solref`/`solimp` 描述约束刚度、阻尼和阻抗；详见[官方建模文档](https://mujoco.readthedocs.io/en/stable/modeling.html#solver-parameters)。

一次后续全量验证记录为 1180 passed / 13 skipped / 11 个既有外部证据绑定失败；这不是最终提交后的永久保证，后续修改仍需重跑。

提交前再次全量验证：**1182 passed / 13 skipped / 11 个相同的既有外部证据绑定失败**；ruff 全仓通过，mypy 409 个源文件通过。日志为外部证据根下 `s229-validation/full-pytest-v4.log`。

`s229-shared-keeper-v26` 的固定候选在 8 个红蓝/球位组合中，仅红、蓝中路 1.5 m 球各通过一次 `completed_hand_save`，快速清球全部未通过。两个方向的案例不能充当 8 次独立随机泛化考试；侧向失败也没有从分母删除。后续 v27 开发对照得到一个中路高球通过案例，快速清球速度约 0.762 m/s，仍未达到原有 1 m/s 门槛。**没有候选晋升，也没有新宣传视频。**
