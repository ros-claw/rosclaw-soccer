# S171–S175：连续射门计划、失败修复与诚实闭环报告

日期：2026-04-06

范围：三台 Unitree G1 的传球—接球—射门—守门共享世界链路

执行边界：CPU MuJoCo、`SIM_ONLY`，没有 ROS/DDS 发布，没有硬件命令

## 1. 本轮结论

本轮完成了“连续高层动作提案 + 多任务 critic + 物理失败修复 + 失败记忆回灌”的闭环工程。它把 S170 同一组已消费开发场景的严格成功数，从基础目标 actor 的 **1/6**、S169 actor 的 **2/6** 提高到 S174 actor 的 **4/6**；候选保持 **6/6 安全、6/6 确定性重放**，并产生 3 个进球、1 次真实物理扑救。其中一个严格进球的目标误差为 **0.0866495 m**，首次进入 0.10 m 精度半径。

但这不是新鲜泛化突破。S175 使用的是已经看过的 S170 开发上下文，作用是证明“失败经验被吸收并可重放”，不是证明未知场景已经学会。连续 critic 在初始 213 条轨迹上通过了校准门，但连续提案的第一次物理回放退化到 1/6；吸收反馈后它会安全回退，却没有产生净收益。在扩展到 298 条轨迹时，样本集中于少数失败上下文且只有一个不安全样本，多任务 critic 的安全和触脚头不再满足上下文隔离校准门。因此本轮**没有发起新的密封考试，也没有晋升连续策略**。

当前最优运行时 actor 仍是失败感知的离散高层计划记忆。连续策略是已实现、可序列化、可审计、可回退的候选层，还不是冠军。

## 2. 问题与设计选择

S169 的最近邻计划能够复用成功动作，却不能在动作空间内细调。射门误差由多个强耦合量共同造成：接球站位、到达提前量、触球帧、脚尖朝向和足端目标速度。单独修改其中一个量容易破坏触脚、平衡或时序。

本轮把状态和动作组成 critic 输入：

- 9 维赛前共享意图：接球队员通道、接球点、传球者局部球位、草地摩擦、传球者朝向/站位和摆腿速度；
- 10 维有界高层动作：到达提前量、对齐容差、接球站位、触球帧、脚的 yaw/pitch 和三维足端目标速度；
- 6 个监督目标：安全、预期脚触球、明确结果、严格链路成功、精度价值、触球后稳定价值。

连续 actor 只在多个成功记忆之间做凸插值；它不输出关节力矩。每个候选必须同时通过四个上下文隔离 critic 的安全下限、方差上限、严格成功优势、精度优势、稳定性退化和触脚退化门。任一条件不满足，立即回退到内容哈希绑定的父 actor。已观察到失败的连续状态—动作对还会进入显式排除集。

这形成了如下安全链：

```text
共享赛前意图
    │
    ▼
不可变父 actor ──────► 安全回退动作
    │
    ▼
成功记忆凸插值候选
    │
    ▼
四折多任务 critic 门 ──拒绝──► 父动作
    │通过
    ▼
有界站位/相位/足端目标
    │
    ▼
冻结且哈希绑定的神经触球 actor（唯一关节力矩拥有者）
```

## 3. 实现内容

### 3.1 连续高层计划与 critic

`runtime_finish_plan_actor.py` 新增：

- `RuntimeFinishPlanCriticHead`：只含归一化输入和核回归系数，不含可执行代码；
- `RuntimeFinishPlanContinuousPolicy`：父 actor、训练快照、反馈证据和失败输入均做 SHA-256 承诺；
- 动作向量编解码：解码时重新施加所有 `SIM_ONLY` 数值包络；
- 四头集成决策、分歧门、父策略比较和失败近邻排除；
- 旧 actor 的 JSON 序列化保持不变，S169 actor 哈希仍为 `sha256:a164982...`。

### 3.2 连续 critic 训练

`continuous_finish_plan_growth.py`：

- 验证所有训练报告、请求、轨迹文件和轨迹摘要；
- 要求训练数据完整覆盖父 actor 的每条成功/失败记忆；
- 以 `context_hash` 为分组单位做四折 out-of-fold 校准，避免同一上下文泄漏；
- 训练加权 RBF 核多任务 critic；
- 可消费连续策略物理反馈，并把失败连续动作写入排除记忆；
- `clear_outcome` 头在 S171 的 AUROC 为 0.4489，明确降级为诊断头，不能控制运行时选择。

### 3.3 物理失败修复

`continuous_finish_plan_repair.py`：

- 对 4 个已消费失败上下文进行完整三 G1、单一足球、单一求解器的 CPU MuJoCo 物理探测；
- 第一阶段在父动作周围做有界局部搜索；
- 第二阶段以严格成功/高精度种子做半步长微调；
- 神经足端目标支持域在仿真前过滤；
- 所有轨迹及配置均绑定哈希，修复数据永远 `promotion_eligible=false`。

### 3.4 证据和视频

`continuous_finish_plan_development_video.py` 只接受通过所有开发门的 S175 报告，并重新校验报告、请求、轨迹、视频和渲染器哈希。视频明确覆盖以下提示：

- `CONSUMED CPU MUJOCO DEVELOPMENT`；
- `SIM ONLY`；
- `PIXELS NEVER SCORE`；
- `FRESH EXAM PENDING`。

因此视频不能被误用为密封泛化或真机证据。

## 6. 失败分析

连续策略“理论可插值”不等于“物理会变好”。目前的主要瓶颈不是 GPU 数量，而是有效数据几何：

1. 298 条轨迹中新增 85 条主要聚集在 4 个困难上下文，不能代表完整状态空间；
2. 不安全样本只有 1 条，安全分类器容易出现方向反转，AUROC 门会正确拒绝；
3. 严格成功、目标精度、触脚和平衡并非同一个目标，单一标量奖励会掩盖失败方式；
4. 局部搜索找到的 8.66 cm 解能被记住，但不能据此推断相邻未知上下文同样有效；
5. 高层 actor 无权直接修复全身动态；触球后自然度仍受冻结神经小脑的动作分布和恢复策略覆盖限制。

这也解释了为什么“加大规模 RL”此刻未必自动解决问题：若继续在高度相关的 4 个上下文上采样，GPU 只会更快地产生相似数据和过拟合 critic。

## 7. 下一阶段：满足条件才开 S176

下一轮优先建立平衡、主动的数据采集，而不是立刻跑新鲜考试：

1. 在未用于最终 S176 的开发分区中，按 `context × outcome` 分层采样；每个上下文都要包含成功、触脚失败、方向失败、稳定性失败和安全硬负样本；
2. 用 critic 集成分歧和决策边界做主动采样，补足稀缺硬负样本；
3. 把动作评价改为多目标 Pareto/约束排序，安全和预期脚是硬约束，严格成功是首要目标，精度与稳定性做条件优化；
4. 对左右脚、不同来球速度、不同摩擦和球门左右上角做成组镜像采样，避免只会一条轨迹；
5. 连续 actor 必须先在新的已消费开发集上同时超过 S174，且保持 6/6 安全、6/6 重放；
6. 只有上述条件成立，才预注册并冻结新的 S176 请求、actor、实现哈希和特征新鲜性承诺，然后运行一次密封考试；
7. 低层神经小脑继续冻结。若后续训练低层 actor，应另开安全闭环：模仿初始化、动力学随机化、恢复课程、critic 约束、影子执行和独立密封考试，绝不能用本轮高层结果代替低层验证。

- S174 已通过新鲜泛化或可晋升门；
