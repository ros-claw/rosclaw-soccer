# S208：接球—转身—支撑—射门—恢复相位闭环

## 结论先行

S208 首次在同一条、不可拼接的六台 G1 CPU MuJoCo 轨迹中通过了以下物理链：

1. 红方组织者以脚传球；
2. 红方终结者以脚接球；
3. 终结者依次通过 `CAPTURE → ORIENT → PLANT → STRIKE → RECOVER → COMPLETE`；
4. 终结者以右脚产生峰值 `7.0438 m/s` 的射门，触球 `0.10 s` 后仍为 `6.6074 m/s`；
5. 门将触球前的无阻挡弹道投影为 `y=-1.3785 m, z=0.4593 m`，整颗直径 23 cm 的球仍在 3 m × 2 m 球门内；
6. 蓝方门将左手套真实接触足球，使速度向量改变 `3.7082 m/s`；
7. 射手在触球后 `0.72 s` 完成恢复；六机均安全，机器人互撞为零；
8. primary/replay 的世界结果、评测结果与轨迹摘要完全相同。

正式状态是 `PASS_PHASE_CONDITIONED_STRIKE_SAVE`。这是一脚被扑出的射门，**不声称进球**；它也只证明 SIM_ONLY，不产生任何真实机器人权限。

## 为什么 S207 看不出激烈射门

S207 已有传球、接球、抢断、带球和冲刺，但终结者接球后直接进入通用追球逻辑。接球时足球仍在滚，机器人会从球的一侧绕向另一侧；站姿横向误差快速放大，射门 option 一直不能获得支撑脚条件。结果是策略“想射门”，身体却没有进入能射门的状态。

S208 把这个隐式切换改为有测量门槛的技能图：

```text
脚部接球
  ↓
CAPTURE（短时保留接球关系）
  ↓
ORIENT（跟随来球并调整朝向）
  ↓
PLANT（收敛预测触球时刻的站姿）
  ↓
STRIKE（才允许整身射门 option 接管）
  ↓
RECOVER（球离开是正常事件，等待身体稳定）
  ↓
COMPLETE
```

状态只能单调前进；非有限输入、身体失稳、球在触球前逃逸、各阶段超时都会 fail closed。相位控制器没有 MuJoCo、ROS 或执行器入口，可复用于其它“移动技能 → 接触技能 → 恢复技能”的 rosclaw 任务。

## 本轮真实修复

### 1. 预测站姿，而不是追球当前位置

站姿使用足球当前速度和 `0.36 s` 触球时域预测。终结者跟踪未来触球点，减少 locomotion 与 kick option 交接时的空间跳变。

### 2. 镜像 locomotion 的 yaw 符号修正

原有 sagittal mirror 会翻转横向速度，但没有在新射门相位翻转 yaw，导致局部策略与世界转向相反。S208 只在新相位链中修正 yaw，保留已经冻结的旧接球分布，避免回归污染。

### 3. 把合法门将防守与作弊身体触球分开

旧的 `foot_only_ball_control` 会把任何非脚碰球都判失败，包括合法的门将身体防守。S208 的专用评测器要求：

- 射手的接球和射门来源必须是脚；
- 射门前不得有非脚触球；
- 射门后的非脚触球只能来自对方门将；
- 正式扑救仍必须由手套 geom 接触并产生足够速度变化。

### 4. 修复恢复相位的错误失败条件

早期实现会在足球射出 2.4 m 后报 `BALL_ESCAPED`。这在触球前是失败，在触球后却是预期结果。现在 `RECOVER` 不再追踪球距，而是等待身体稳定达到保持时间；超过恢复超时才失败。

### 5. 明确误差补偿的真实身份

`+0.65 m` 横向瞄准补偿来自本轮失败轨迹插值。它是可审计的 `parameter` adapter，不是新训练出的 neural actor；代码不会把它标成 `learned_adapter`，后者必须绑定数据集快照哈希。

## 失败驱动实验记录

以下候选都真实运行过，但没有写成 PASS 证据：

| 候选 | 观察 | 决策 |
|---|---|---|
| 预测数组原地加法 | 会修改 MuJoCo `qpos` view，导致足球假位移 | 立即修复；增加“不修改 qpos”回归测试 |
| 高瞄准目标 `y=1.35` | 横向站姿不能在时限内收敛，`PLANT_TIMEOUT` | 拒绝 |
| 站姿横向偏置 `-0.30/0/+0.30` | `-0.30` 产生最干净右脚触球；其余持续速度或身体接触更差 | 保留 `-0.30` |
| 降低摆腿幅度 | 峰值速度与持续速度都下降，没有解决偏航 | 拒绝 |
| 无抬升协同 | 球路低，容易被防守身体挡下 | 拒绝 |
| 抬升 `0.30`、脚踝 pitch `0.14` | 峰值仅 `3.79 m/s` 且世界不安全 | 拒绝 |
| 抬升 `0.15`、pitch `0.08` | 安全，轨迹最高约 `0.59 m`，可形成真实门将干预 | 保留 |
| 瞄准补偿 `+0.55` | 手套触球，但球门投影仍偏外 | 拒绝 |
| 瞄准补偿 `+0.75` | 球路入框，但变为门将身体挡球 | 作为失败样本保留，不用于正式证据 |
| 瞄准补偿 `+0.65` | 入框投影与手套扑救同时成立 | 正式候选 |
| 接球角偏置 `-0.30` | 球更慢，但终结者倒退找站姿并触发关节限位 | 拒绝并撤回 |
| “朝球门转、同时站位”试验 | 在当前对手几何下仍被横向约束卡住，随后被抢断 | 撤回，留作下一轮结构优化 |

这里的原则是：失败结果可以指导下一次搜索，但不能进入正式 PASS 报告，更不能进入宣传视频的成功统计。

### 手套碰撞体复核

可见手套椭球半轴是 `9.5 × 5.0 × 3.25 cm`，小于可见手套外形，并非球半径级“隐形球拍”。保存的触球帧重建结果：

- 足球中心：`(6.8815, -1.4814, 0.5529) m`；
- 左手套中心：`(6.9888, -1.3664, 0.6232) m`；
- 两中心距离：`0.1723 m`；
- 足球半径加手套最大半轴：`0.2100 m`。

因此该接触在几何上可实现。画面中球心与手腕不会重合，是因为足球本身半径已达 11.5 cm，手套又从手腕沿掌心方向偏置 9 cm。

## 尚未解决的问题

1. `4.70 s` 的接球到射门仍太慢，视觉上不是顶级球员的一脚流；
2. 射门高度仍只有约 0.6 m，不是上角高球；
3. 门将这次是站立左手扑救，不是飞身双手扑救；
4. 参数补偿仍是小规模物理搜索，不是 MotionDecode/SONIC 驱动的端到端技能模型；
5. 当前只证明一个固定场景的精确复现，不代表分布外成功率；
6. 本轮通过的是“被扑出的有效射门”，不是进球或完整长局比赛。

## S209 建议

下一阶段不应继续堆动作补丁，而应把 S208 变成可训练问题：

1. 将站姿误差、球速、对手到球时间、身体稳定性作为相位观测；
2. 用 MotionDecode/SONIC 动作先验训练低层 residual actor，同时保留相位安全门；
3. reward 同时约束接球到触球时间、弹道目标误差、支撑脚滑移、触球后稳定；
4. 对组织者、终结者、门将分别维护 replay buffer，再用团队结果做集中训练、分散执行；
5. 先把接球到射门从 `4.70 s` 降至 `≤ 2.5 s`，随后训练 0.3–1.6 m 高度、多角度、左右脚分布；
6. 以跨 seed / 跨位置 / 跨球速的通过率作为成长门，不再用单视频决定晋升。

这一步的真正突破不是“多了一个好看的动作”，而是 rosclaw 已能把一次复杂接触技能拆成可观测、可失败、可恢复、可复跑、可审计的闭环。下一轮才有可靠基础把这些相位从人工参数逐步替换为数据驱动的肌肉记忆。
