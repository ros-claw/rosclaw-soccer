# S207：连续 3v3 物理比赛、接触技能证据与失败驱动成长

## 结论先行

S207 不再把“六台 G1 同时走动”当成足球比赛，而是建立了一个必须在**同一条连续 MuJoCo
物理轨迹**中完成的资格考试：抢球、带球、传球、冲刺、射门和扑救都只能由真实脚/手套接触、
球状态变化和事先存在的角色承诺共同证明。

当前最佳稳定证据 `s207-continuous-match-v7` 已在 10 秒连续 3v3 中完成：

- 红方组织者两次触球并向红方前锋完成物理传球；
- 红方前锋在跑动接应中完成第一次脚部触球；
- 蓝方组织者逼抢、夺回球权，再次触球形成带球反击；
- 红方前锋出现持续冲刺；
- 六台 G1 都由各自独立 ROSClaw Agent Cell 决策；
- 双次运行轨迹摘要完全一致，机器人之间零碰撞，基础世界安全门通过。

但是，它没有在同一条轨迹中完成合格射门和扑救，蓝方组织者还有 2 帧右小腿擦球。因此正式
结果是 `REJECTED_CONTINUOUS_MATCH_CHAIN`，而不是一个被包装过的“比赛成功”。这是一个明显
强于上一轮站位演示的课程台阶，但还不是完整比赛能力。

## 本轮纠正了什么

旧 3v3 演示的主要问题不是画面不够热闹，而是证据语义太弱：机器人在动、决策中出现了
`PASS`/`SHOOT` 字样，并不说明脚碰到了球，更不说明球传给了约定队友。S207 把判断权从意图
日志移到物理轨迹。

| 过去容易误判的现象 | S207 的处理 |
|---|---|
| 机器人从球旁走过也算控球 | 接触教师开启时，球权只能来自实际接触并在短时间内保持 |
| 两名队员先后碰球就算传球 | 必须先有 source→target 握手，再出现同队不同球员的脚部接触和足够位移 |
| 前锋做出踢腿动作就算射门 | 必须是前锋、脚部触球、有效射门租约且球速达到 3 m/s |
| 球靠近门将就算扑救 | 必须是门将手套接触，并形成足够大的来球速度变化 |
| 身体撞球仍算有效控球 | 脚/手套与非脚触球分开记录；小腿擦球会使纯净接触门失败 |
| 录像看起来成功就算成功 | 视频像素不参与评分；视频必须绑定报告和 NPZ 哈希 |

## 模块化实现

### 1. 独立 Agent Cell 的唯一追球权

`growth/independent_agent_cell.py` 和共享世界现在为每个智能体提供私有观察、角色自我模型、
策略身份和记忆命名空间，但每个决策周期只允许：

- 无人控球时，全场恰好一名外场球员获得追球权；
- 对手控球时，每队恰好一名球员获得逼抢权；
- 其他球员执行接应、拉开、保护空间或守门，而不是六个人一起挤向球。

追球权有最短租约和切换优势门槛，避免两台机器人在每个 100 ms 决策周期反复争抢同一任务。

### 2. 传球—接球因果租约

传球队员选定目标后，世界保存 source、target 和球的起始位置。目标队员先等待传球启动，再
根据球速与进度进入动态接球租约。接球点由球速预测，临近球时主动刹车，避免脚越过球后把球
反向弹回。

接球后的短时全身目标保持和“一脚出球”窗口是两个不同状态。S207 还修复了证据字段：前锋
处于一脚出球窗口时不会再被错误标记为“停球保持中”。

当接球租约已经被球速/位移激活，且接球队员的主角色是前锋时，世界会记录一个单独的第一脚
射门预授权。v7 中该授权从 `2.02 s` 持续到 `3.04 s`，并与实际第一次触球同帧绑定；但授权
只允许评估器检查候选射门，不能替代 3 m/s 总球速和 1.5 m/s 朝球门速度门。

### 3. 有界脚端接触教师

`growth/locomotion_contact_teacher.py` 是训练阶段使用的任务空间教师：

1. 从球位置、球速、目标方向和左右脚语义生成踝部目标；
2. 使用 MuJoCo 实测 Jacobian 将任务空间力转换为关节残差力矩；
3. 对任务力、单关节残差、脚球距离和越球状态设硬门；
4. 最终仍经过关节边界预测与 G1 硬力矩上限。

它不会写机器人根状态，不会写球状态，没有 ROS、DDS 或真实硬件路径，权限上限固定为
`SIM_ONLY`。它是发现接触数据的教师，不是已经训练完成的端到端小脑。

### 4. 冻结神经运动策略与射门 Option 桥

六台 G1 的基础行走继续使用冻结的 RoboNaldo 神经运动策略。高层世界速度先转换到机器人
当前身体坐标系，再由 50 Hz 神经策略产生目标，500 Hz PD 环闭合。射门 Option 只有在纵向
深度、横向误差、身体朝向和射门租约同时满足时才能激活；仅出现 `SHOOT` 意图不会激活。

### 5. 物理技能评估器

`growth/competitive_match_assessment.py` 将不可变轨迹转换成保守技能事件：

- `BALL_WIN`：相邻有效脚部触球来自对立球队；
- `DRIBBLE`：同一智能体两次脚部触球之间有足够球位移；
- `PASS`：显式传球握手、同队不同智能体触球和足够位移同时成立；
- `SPRINT`：骨盆水平速度连续超过阈值；
- `SHOT`：前锋脚部接触、射门租约和 3 m/s 球速同时成立；
- `SAVE`：合格射门后，门将手套真实接触并改变球速。

安全门和足球纯净度门被刻意分开。小腿擦球会拒绝技能晋升，但不会被错误描述为“机器人世界
不安全”；机器人互撞、非有限状态、关节/力矩越界等才属于安全失败。

### 6. 双跑、原子证据与视频绑定

`training/continuous_competitive_match_growth.py` 使用同一冻结配置执行 primary 和 replay，保存
两份压缩 NPZ，再比较结果、轨迹摘要和评估事件。报告使用原子写入并绑定：场景、世界配置、
教师配置、Option 配置、阈值、实现文件和轨迹文件哈希。

`media/continuous_competitive_match_video.py` 只接受安全、严格复现、但因射门阶段未通过而被拒绝
的这一级证据。视频包含实况广播机位、传接球慢动作和抢断反击慢动作；黄色球迹仅是可视化，
已在清单中声明，不能用于评分。

## 失败驱动实验记录

本轮没有把失败的调参留在默认配置中。

1. **仅解除一脚射门站姿门**：脚端教师开始工作，但 0.3 秒窗口内没有第二次有效接触；增大
   通用残差又破坏了上游传球并造成失稳，因此撤回。
2. **放松踢球腿刚度**：踝部移动增加，但全身稳定门失败，球速仍未达到射门阈值，因此撤回。
3. **延长一脚出球窗口**：前锋长时间冻结支撑姿态，最终失稳，仍无射门接触，因此撤回。
4. **全局加快转向**：它在传球发生前就改变接球队员姿态，导致传球链断裂，因此撤回。
5. **缩短绕球距离并只加快射门转向**：横向误差有所变化，但产生大量机器人碰撞，撤回。

这些反例说明持续成长不能靠把同一组增益不断放大。上游传球、接球、身体稳定和下游射门是
耦合系统；每次修改必须重新跑完整链，而不是只看某个脚端瞬间。

## 对 ROSClaw 的通用价值

足球只是压力测试。可以迁移到 ROSClaw Core 的能力是：

```text
私有 Agent Cell
  → 稀缺任务租约
  → 具身承诺/接管握手
  → 真实接触与状态变化
  → 因果信用分配
  → 失败类型拆分
  → primary/replay 严格复现
  → 候选晋升或拒绝
```

同一模式可用于双臂交接、多人搬运、移动抓取、工具递送和协作装配。领域插件定义角色、接触体、
任务事件和阈值；ROSClaw Growth 负责租约、记忆、证据绑定、回放、拒绝和晋升。

## 仍未完成与下一阶段

当前实现不是完整在线 actor-critic，也不是直接输出全身关节力矩的端到端小脑。MotionDecode
可作为动作先验和模仿数据来源，但本轮没有声称它已直接控制比赛中的六台 G1。

下一阶段不应继续无结构调增益，而应实现：

1. 把接球后状态拆成 `capture → orient → plant → strike → recover`，每段都有超时、可达性和
   失败原因；
2. 训练一个只在安全包络内选择接球落点、支撑脚和射门 Option 的残差 Actor，而不是先让
   Actor 直接接管 29 路力矩；
3. 用当前成功/失败轨迹建立相位条件经验池，保留上游传球成功作为不可退化锚点，解决
   stability–plasticity dilemma；
4. 完成前锋物理射门后，再激活门将预测、移动和手套扑救课程；
5. 在随机球速、摩擦、延迟、来球方向与双方阵型留出上达到稳定通过后，才允许形成新的
   “完整比赛”宣传片。
