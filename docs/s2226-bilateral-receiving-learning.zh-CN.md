# S2226：从单边球技回到双方球队能力

## 目标与结论边界

重新对照《rosclaw_soccer想法1.md》的主线：接球、连续控球、下一次决策和团队成长，而不是无限追加孤立射门参数。当前仍未达到连续自主 4v4 宣传片标准。本轮首先检验已有接球与出球模型能否用于对面球队，随后针对失败角色收集自己的物理学习数据。

## 显式坐标契约，不静默修改旧模型

旧接球输入的 135 个字段混合了关节/本体量与世界坐标量。新增可选契约 `recurrent_receiver_canonical_heading_135_float32.v4`，必须明确指定 `canonical_half_turn`：

- 转半圈时，仅反转世界根部线速度 XY（61–62）、球相对根部世界偏移 XY（67–68）、球世界速度 XY（70–71）和朝向 sin/cos（133–134）。
- 保留重力、本地角速度、关节位置/速度、残差历史和基础 PD 目标；不镜像关节，不改物理姿态，不移动球。
- 不是任意角度转换，不是把全部字段改成本体坐标；旧 v1/v2/v3 不接受该选项。
- 开关进入内容哈希，冻结执行器和训练采样器使用同一转换；训练保留转换后的实际输入、原始采样和对应概率。
- `False` 不改变旧 v2 的数值行为，但新契约明确区分来源。

近球策略本来使用本体相对字段。本轮另建候选，把 8 个私有角色权重的两队行对换，保留父哈希和旧检查点。固定随机探索的行也显式对换，让红方对应角色使用蓝方同角色的随机序列。此操作是结构复用，**不是优化器学习**。

## S2226：8 次真实物理执行

四种条件各进行 primary/replay 两次独立 MuJoCo 模拟，8 秒共享 4v4 场地，双方角色与原场地尺寸不变；每个接球执行器保留独立状态。蓝方球位 `(4.92,-0.49,0.115)`，红方半场对称球位 `(1.08,0.49,0.115)`。红蓝近球随机种子均为 207811，冻结接球网络取均值；不能把整个回合称为无探索均值策略。

| 条件 | 全体身体安全 | 中场接球 | 前锋接球 |
| --- | --- | --- | --- |
| 蓝方旧契约 | 通过 | 通过 | 通过 |
| 蓝方新契约、不转换 | 通过 | 通过 | 通过 |
| 红方新契约、不转换 | 通过 | 无脚触球 | 无脚触球 |
| 红方新契约、半圈转换 | 通过 | 无脚触球 | 无脚触球 |

蓝方两条件整段物理数组完全相等。红方转换后中场最小足球距离从约 0.181 m 降到 0.164 m，但没有实际脚接触，不能算接住。红方前锋也没有接球成功。因此坐标兼容性并不等于物理技能泛化，不晋升候选。

## 后续学习边界

S2228 针对红方中场单独收集 on-policy 接球轨迹，冻结基础小脑、近球策略和前锋接球模型；只允许红方中场候选权重在 Core 学习租约内更新。先测试同一初态下能否学会接球，再考虑扰动泛化和连续串联。固定初态上的探索样本不能称为任务分布泛化；训练样本中的一次成功不能替代冻结候选的独立考试。

### S2230：增加接球时间并不足够

对父模型和第一代分别把中场接球窗口从 100 帧扩为 125/150 帧，保留 100 帧振荡周期，成功标准仍要求实际脚接触、至少 0.5 秒接触后持续观察及近脚低速稳定尾段。四组各双重放，共 8 次。全体身体安全，但四组均未接球；延长窗口也影响了前锋后续准入，不能当作免费改善。

### S2234：发现模型之外的朝向不一致

场地、球位和角色按半圈旋转对应，但旧的接球侧身角对红队取负、蓝队取正，改变了身体的侧身方向。独立重算与实际第一帧命令精确一致：蓝中场 yaw 命令 -0.8 rad/s，红中场 +0.4785642977 rad/s；旋转对应的两者本应有相同的相对转向命令。这说明 S2226 的模型坐标转换并没有给红队建立同样的基础运动条件。

反例只证明初始指令不满足旋转等变，不能单独证明修复后能接球。反例文件 `/data/rosclaw_overflow/s2234-receiving-heading-counterexample-v1/counterexample.json`，哈希 `sha256:cb1412bae12cd8afbd1ee499c3db07410da61445198bf72603e1d18c6441fe7f`。后续用默认关闭、明确绑定配置的选项做实际物理对照。

### S2236：朝向修正恢复红队中场接球

新增 `rotation_equivariant_receive_heading`，仅能显式用于双边场地；默认 False 不进入旧配置哈希。开启时，双方承诺接球均按同一身体侧身方向朝向来球；不改变保持停止、非承诺移动、关节执行器或成功门限。它只修正这一条接球朝向规则，不宣称整个战术系统已经具有旋转等变性。

蓝红双方各开关两种条件，共 8 次物理执行。关闭选项时两队均与 S2226 原轨迹逐数组精确一致；蓝队开启/关闭也精确一致。红队开启后：

- 中场开始帧从 73 变为 69，与蓝队一致；真实脚接触 2.86 秒，最终球速约 0.28647 m/s，**受控接球通过**。
- 对应中场窗口内，旋转后的蓝红球轨迹最大差约 3.86 微米；这不是放宽误差门限，而是诊断一致性。

- 全部身体/相互碰撞门限通过，没有优化器更新。改善是上层意图与已有模型条件一致性修正，不能冒充新的 RL 成绩。
