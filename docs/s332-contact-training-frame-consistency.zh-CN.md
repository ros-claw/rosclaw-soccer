# S329–S333：把物理训练目标与完整演示场景对齐

## 找到了什么问题

S329 的新快跑触球课程沿用了旧参考的坐标标准化：身体和球一起平移到参考起点，但是物理球门和奖励目标没有跟着平移。它可以作为另一种明确声明的射门任务，却不应被当成完整 CPU 助跑任务的等价训练初始化。

三个真实 CPU 入口被横向移动了 -1.491、-1.470、-1.429 m，纵向移动了 +0.060、-0.212、-0.452 m。静态球门仍在原处。只验证“球相对身体的位置没变”不足以证明足球任务不变。

这个问题在本轮新建的 S329/S331 研究课程中得到实证；不能据此推断此前所有研究都犯了相同错误。只用于神经网络输入、没有写入物理世界的标准化副本也不是这个问题。

## 修复和工程化

新增 `training/contact_course_frame.py`，在创建 GPU 世界前检查：

- G1 身体和球的初始位姿形状、有限性、单位四元数。
- 如果课程只做平面平移，关节、朝向和高度不得暗中变化。
- 身体、足球、物理球门、奖励目标必须具有相同的平移量。
- 输入和坐标变换进入不可变绑定摘要；不会改写输入或创建机器人执行权限。

它只验证初始坐标的一致性，不证明 CPU/GPU 动力学等价，也不包含模型晋升。S332 的 `frame-audit.json` 从三个绑定的实测入口重建旧变换：三个都被拒绝；保持原始世界坐标的三个都通过。后续 S334 训练在创建仿真前实际调用该模块，并将绑定纳入 Core 学习上下文。

## 如实保留错误支线

S329 进行了四次真实 on-policy PPO 更新，192 个 GPU 世界来自三个实测身体状态，每个状态 64 个扰动副本。不是 192 个独立动作样本来源。更新恢复原 S286024 的模型、Adam 和 Torch RNG，SONIC 和参考冻结；第一轮 304 次优化步骤精确重放，全部权重误差为零。

S330 的 32 次完整 CPU 配对考试显示退化，没有新强射门课程。S331 继续支线在发现坐标问题后被 SIGINT 停止，已完成检查点、优化器、采集数据和 Core 审计均保留，未完成的迭代不计为完成。没有用这些模型替换原模型。

## 修正后的训练，仍须接受物理考试

S332 从原 S286024 重新开始，保留相同采样种子和其余设置，仅保留原始世界坐标，不再平移身体/球而留下球门。四轮真实 PPO 更新，第一轮 304 步再次精确重放。

固定 GPU 开发测试：身体安全 192/192 保持，强前向射门从 96/192 到 128/192，进球门 192/192 保持。实际只有三个起点 × 两个固定侧向偏移，即六个不同开发状态，重复副本不能提高统计置信度。

S333 随后实际运行 32 次 CPU 连续助跑考试：父/候选 × 八个物理课程 × 两次精确重复。八课程包括摩擦 0.4 的三个旧球位，以及摩擦 0.6 的五个球位（其中两个新球位未用于该候选梯度更新）。

候选仍不合格：

- 旧摩擦、4.00 m 球位强射门退化。
- 新摩擦、4.125 m 新球位身体关节超限 0.025314 rad，超过原 0.025 rad 门槛；没有放宽容差，安全失败。
- 没有增加新的强射门课程，尽管部分原有课程球速有所提高。

因此，修正坐标是必要的工程修复，但四轮训练的 GPU 进步不能当成完整实战的成功。继续训练与考试使用分离的候选，旧模型保留。
