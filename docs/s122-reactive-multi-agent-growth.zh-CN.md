# S122：三 G1 观测闭环跑位与失败驱动成长报告

## 1. 结论先行

S122 已把 S121 的“按时间播放固定路点”升级为真正读取现场状态的跑位 actor。队友和防守者每个控制周期都读取自身位置/速度、球、持球队员、另一角色以及 PASS/SHOOT 任务，再输出有界二维速度；速度随后进入冻结的 RoboNaldo 神经运动策略。route actor 无权写根姿态、关节、力矩、足球、ROS 或硬件。

最终第二代 champion 在全新封存的 8 个大扰动场景中取得：

| 指标 | 结果 |
|---|---:|
| 任务成功 | 8/8（100%） |
| PASS / SHOOT 覆盖 | 4 / 4 |
| 安全通过 | 8/8（100%） |
| 运动质量通过 | 8/8（100%） |
| actor 支持域接受 | 8/8（100%） |
| 独立精确重放 | 8/8（100%） |
| 队友平均位移 | 1.204 m |
| 防守者平均位移 | 0.695 m |
| 队友平均停滞占比 | 0.21% |
| 防守者平均停滞占比 | 6.71% |

第一代 champion 的封存考试只有 7/8，已明确拒绝，没有修改成功标准或把失败藏掉。随后仅使用另建的开发课程采集失败、学习并做遗忘回归；第一套封存轨迹没有进入训练。第二代模型再参加场景哈希完全不同的封存考试，取得 8/8。

## 2. 为什么 S121 还不够

S121 虽然让三台完整 G1 都动起来，但队友与防守者的目标是随时间插值的路点。若机器人被扰动、步态产生相位偏差、球或其他角色的位置改变，控制器仍沿原时间表走。这能验证底层神经步态，却不能证明多智能体理解了“现场发生了什么”。

S122 的闭环如下：

```text
当前物理状态
  ├─ 自身目标误差、根速度
  ├─ 球相对位置
  ├─ 持球队员相对位置
  ├─ 另一角色相对位置
  └─ PASS/SHOOT + 队友/防守者身份
            ↓
14 维 observation-conditioned route actor
            ↓
OOD 拒绝 + 世界速度限幅 + 加速度限幅
            ↓
世界坐标→机器人局部坐标
            ↓
冻结 RoboNaldo 神经运动策略
            ↓
29-DoF G1 + 共享足球 + CPU MuJoCo
            ↓
成功/失败、接触、稳定性、运动质量、可重放证据
            └──────── failure replay / DAgger ────────┘
```

## 3. 数据是否真的有用

训练源是 S121 已发布且逐文件复核哈希的 8 场物理轨迹，共 5,600 个角色控制帧。以整场比赛为组做 leave-one-match-out，避免同一轨迹的相邻帧同时进入训练和验证。

| 特征 | 平均 RMSE | 最大 RMSE | 平均相关性 |
|---|---:|---:|---:|
| 只看最终目标 | 0.1035 m/s | 0.1188 m/s | 0.8858 |
| 目标 + 本体速度 + 任务/角色 | 0.0792 m/s | 0.0864 m/s | 0.9310 |
| 完整球队上下文 | **0.0624 m/s** | **0.0763 m/s** | **0.9656** |

完整上下文相对“只追目标”降低约 39.8% 的平均误差。因此球、持球队员和另一名角色不是装饰字段。

对最终 champion 做 0.25 m 反事实扰动，速度输出变化范数为：球 0.0061 m/s、持球队员 0.0794 m/s、另一角色 0.0378 m/s；全部非零且低于安全上限。目标误差仍是主要信号（0.2394 m/s），符合“上下文修正目标追踪”而非无目的追球。

## 4. 失败是怎样变成能力的

仅做离线行为克隆并没有成功。第一次物理烟测中 actor 在历史轨迹上预测准确，但进入自己造成的新状态后发生分布漂移：队友只移动 0.442 m，错过真实接球。

闭环没有调低门槛，而是对 on-policy 失败状态调用有界恢复专家重新标注，再把困难帧以更高权重加入训练：

| 里程碑 | 结果 |
|---|---|
| 初始离线 actor | 安全、100% 支持域接受，但 PASS 失败；队友位移 0.442 m |
| 第一次失败重放 | 位移升至 1.499 m，运动质量通过，但仍错过接触 |
| 第二次失败重放 | 同一病例形成真实接触，PASS 成功；队友位移 1.182 m |
| 开发集检查 | 7/8，发现另一传球 hard example |
| 第三次失败重放 | 开发集 8/8 |
| 第一套封存考试 | 7/8，champion **REJECTED** |
| 新建 ±0.14 m 开发边界课程 | 最近足-球距离 0.351→0.225→0.185→0.152 m，最终真实接触成功 |
| 防遗忘回归 | 原 8 场 + 4 场边界课程 = 12/12 |
| 全新第二套封存考试 | 8/8，champion 通过 |

这体现的是 ROSClaw growth 应有的纪律：失败进入开发记忆；封存集只裁决，不做梯度；学习新 hard example 后必须回归旧能力；通过新的未知考试才宣布成长。

## 7. 诚实边界

- 这是 CPU MuJoCo、SIM_ONLY 结果，不是实体 G1 证据。
- route actor 是数据驱动的线性观测策略与 DAgger 纠偏，不是端到端神经网络、在线 actor-critic 或直接关节力矩策略。
- 29-DoF 身体动作由冻结的 RoboNaldo 神经策略执行；S122 学的是多智能体跑位命令，不是新的全身肌肉记忆。
- PASS 的任务定义仍在真实足部接球处结束，尚未组成接球后不停顿的一脚射门。
- 视频看起来比木头人更有持续移动，但还不能声称具备真人顶级球员的风格、扫视、假动作、对抗或队形理解。
- 当前模块位于 Soccer 工程；其“证据→失败记忆→候选→遗忘回归→新封存考试”方法可上提为通用 ROSClaw growth primitive，但本阶段没有虚构已经完成该上提。

## 8. 建议的 S123

下一步不应继续堆固定脚本，而应：

1. 把线性 route actor 升级为小型时序网络，显式记忆速度趋势、控球权和角色切换，并保留相同 OOD/限幅外壳；
2. 在 2v2/3v3 联赛中让传球者、接球队员、防守者和门将都拥有独立但共享参数的 actor，做 centralized-training / decentralized-execution；
3. 用 MotionDecode/SONIC 等合规数据只做步态、转身、上肢摆臂与足球姿态风格教师，不把数据轨迹当接触真值直接播放；
4. 把 PASS 接球扩展为“移动接球→一脚射门→门将扑救”的连续物理链，并对每段以及整链分别计分；
5. 将本阶段可复用的证据隔离、失败记忆、反遗忘与封存晋升协议上提到 ROSClaw 通用 growth engine，让足球只是一个适配器和高难度验收场。
