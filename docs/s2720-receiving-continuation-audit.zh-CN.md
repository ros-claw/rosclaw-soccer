# S2704–S2720：加量接球训练、延迟奖励与失败闭环

日期：2026-09-18。仅 SIM_ONLY；本轮没有达到可宣传突破，没有晋升权重。

## 实际执行

本轮不是只修改参数或制作视频：完成两批新的八人分角色 PPO 数据采集与更新、配对物理考试、三个控制消融、低速先修课诊断及历史全身策略 GPU 复验。

CPU 部分共 164 个课程执行配置，每个均另跑一次独立物理回放：328 次执行。两批训练各 32 课，新增有效角色学习样本共 11,193（5,419 + 5,774）；回放不重复计作学习数据。GPU 部分另有 128 个世界执行，但每种策略只有 8 个独特场景，不能宣称 128 个独立测试场景。

课程使用八人世界、指定一名真实球员接球，四个进程并行。是显式教练接球任务，不是自主比赛，也不是在同一场地放多颗球。其余角色不计为这堂课的受训者。保存的策略均为研究候选，不覆盖历史资产。

## 发现与否定的假设

1. **触球不等于接住。** 两批训练都能频繁形成真实足部接触，但球继续离开身体，持续控球仍稀少。
2. **教师任务存在冲突。** 默认一脚射门会抢占前锋的接球保持阶段；关掉后能够进入该阶段，却丢失原有慢球成功。因此不能将“修复阶段覆盖”冒充“学会接球”。
3. **保持期导航停住值得继续研究，但直接解除停止不够。** S2710 实际物理验证未产生成功，不能将该补丁部署给所有角色。
4. **训练加量和更长奖励回溯不自动改善。** 第二代研究候选没有净增益，第一代还出现安全回退。不得用训练损失下降替代物理考试。
5. **历史资产不能凭名字复用。** 历史全身模型与 GPU 学生均未在当前筛选场景通过；仍需任务匹配、观测契约和 CPU 迁移复验。

## 工程闭环

新增 `training/receiving_curriculum_progress.py`，对单个冻结策略按八名球员×显式球速分别检查课程覆盖。默认每层至少四课、至少 80% 安全控球，所有课身体安全，才标记可继续课程；少数角色成功不能掩盖门将或后卫缺失。重复课程、混合权重和伪布尔结果被拒绝。

该模块仅汇总**调用方已审计的数据**，不是证据鉴真器、统计显著性证明或晋升服务；始终 `promotion_eligible=False`。当前候选每层只有一堂确定性开发考试，覆盖也不够，不能毕业。已将两组真实审计课程接入该诊断，而非只测试构造样例。

两次 PPO 更新均独立重复并得到相同权重和审计结果；各角色 Core Plasticity 审计通过。另一次独立审计重算全部 CPU 控球结果、验证文件哈希和逐数组回放一致性。部分新数据采用“独立再仿真、验证完全相等后硬链接存储”，不是跳过回放，也不是独立备份。

本轮代码验证：接球课程、进度、残差 PPO、Plasticity、行为锚点、策略归档、接触奖励与导航坐标相关测试 **148 passed**；新模块 mypy、全仓 Ruff lint、compileall 通过。新增两个 Python 文件格式检查通过；全仓格式检查仍报告 70 个未修改历史文件，不在本轮批量重排。本轮未重跑全量测试，不能将上一轮的全量结果当作本轮通过证明。

## 下一轮优先级

先验证观测和执行权限是否足以完成“接近—卸力—随球控制”，再扩量：只扩大无法控制根部追随的腿部残差训练，可能继续重复失败。候选方向是使用已有受限导航策略接口，联合足部实际位置和接触后的随球速度学习；不得伪造接球租约、附着球体、直接修改球速或取消碰撞保护。已有学到的拦截选择器只能作为待验证起点，不代表已迁移成功。

只有在每名球员上都形成可复现的接球保持成功，再扩大随机来球与球速、接后传带射及多人课程，最后回到单球 4v4 比赛验证。不用更多世界数、轨迹帧数或剪辑代替技能改善。
