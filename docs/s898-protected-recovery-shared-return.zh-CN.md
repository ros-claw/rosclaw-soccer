# S898–S915：保护射门、改善射后恢复，但还不是合格比赛宣传片

## 当前判断

本阶段的有效进展是：把触球前的策略保护起来，并找到一个明显更稳定的射后恢复起点，再在原八人世界验证。不能把它说成已经学会流畅比赛：射门仍被后卫挡住，触球前仍有短暂后退，队伍的持续争球和配合还不够好。

所有结果为 SIM_ONLY，未运行硬件。训练网络输出为关节目标残差和参考朝向，不是直接力矩策略。

## 射门方向探索

S898 将 S886 开发扫描中的偏侧目标 y=0.25 m、参考中心 -0.3 rad 固定后复考：32 个样本中，31 个速度成功、15 个精度成功、32 个安全。S899 运行用数值实现的标签一致。

S900 回到八人世界，助跑前 441 个控制帧的 q/v 与 S884 完全一致。首次脚接触 0.206 秒，朝球门速度 3.498926 m/s，但在 0.506 秒被同一后卫身体挡住。瞄准点修改被明确记录为执行层假设，不冒充战术智能体自主选出的新球路。

S903 随后扩展为 y=-1/+1 m 两个侧向目标，各扫描 16 个参考中心，范围 -0.55 至 -0.1 rad。32 项配置中精度成功为 0、速度成功 18、安全 30。它扩大了 S886 原先过窄的朝向搜索，但并没有解决远侧球路；不能用无脚接触时球原本滚过目标平面的现象当射门成功。

## 受保护的 PPO 学习

S901/S902 将一个冻结动作网络与一个可学习后续网络分开，额外二元特征由已经发生的脚接触、时间和间距产生。完整做完 4 次原生 CPU MuJoCo / CPU ONNX PPO 更新，中间因系统盘空间保护停止一次，随后在 `/code` 精确续训。

四次优化器更新均精确重放；九条训练/评估轨迹的 2 ms 标签复算、历史递推和恢复代价复算通过；五代评估在事件前的物理轨迹完全一致，23/32 精度成功、28/32 速度成功均保持。

## 恢复起点：不再持续叠加踢球残差

S908 只把后续分支的关节输出层初始化为零，冻结前缀、参考朝向网络和基础 SONIC 运控均保留。原残差平滑器在事件后逐渐卸掉踢球残差，没有把身体位置、速度或姿态直接设成站立状态。

**这是明确的分析性初始化，不是新 RL 训练成果。** 它验证一个假设：射门之后继续使用针对踢球优化的关节残差，可能在妨碍基础运控恢复。

S909 在同组 32 个状态上保留全部射门标签和安全标签，平均恢复代价从 3.201294 降至 0.787608，32 个样本均改善。world0 的晚段角速度 p95 从 1.117984 降至 0.602587 rad/s，平面速度 p95 从 0.344511 降至 0.233595 m/s。这些仍是孤立的 4 秒实验。

S911 用运行侧 NumPy provider 驱动全部关节目标和下一步参考朝向，不让 Torch 输出控制命令。32 个样本的事件与成功标签一致，最大平面误差差 6.37e-6 m，前 0.2 秒最大 q/v 差约 2.93e-7 / 1.97e-5，原门槛未改。

## 可复用代码和验收边界

- 通用训练模块 `training/event_protected_actor.py`：冻结前缀、独立可学习后续分支、冻结探索方差，非 G1 特定的数据结构。
- G1 适配器 `providers/g1/event_protected_motor.py`：有界、哈希绑定的完整数值检查点；不依赖 Torch，不运行优化器；两个分支共享真实的同一份动作历史，而不是各自虚构历史。
- 原 `goal_reference_motor.py` 只抽出参数加载与选择接口，原模型数值行为通过回归测试。
- 二元事件是调用方提供的数据，不是已验证物理证据或运动授权。多人实验另行绑定真实接触、时钟与物理记录；运行边界与仿真安全保护仍独立负责。

相关适配器测试 40 项通过；全量测试为 2397 passed、29 skipped、11 failed，失败项仍为此前的旧外部证据绑定问题，未放宽断言。记录位于 `/code/rosclaw/phase8_evidence/s912-repository-tests.xml`。
