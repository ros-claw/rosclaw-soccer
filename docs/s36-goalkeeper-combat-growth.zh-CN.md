# S36 G1 门将实战自进化实施报告

日期：2026-08-15
状态：**开发闭环完成，候选被 CPU MuJoCo 晋升门拒绝，未成为 Champion**
安全边界：**SIM_ONLY；没有发送任何真实机器人命令**

## 1. 本轮结论

本轮不是给旧门将动画再加一段挥臂，而是把 G1 门将正式接入可学习、可回退、可审计的物理训练闭环。最终候选在 64 个全新 advanced 双球 CPU MuJoCo 回合中：

- 零跌倒、零关节越界、零力矩越界；
- 平均回报从 `166.1801` 提高到 `170.0362`（`+3.8561`）；
- 首次扑救从 `21.875%` 提高到 `23.4375%`（多救 1 球）；
- 平均手部覆盖从 `0.0451 m` 提高到 `0.1790 m`；
- 平均侧移峰值速度从 `0.0964 m/s` 提高到 `0.3146 m/s`；
- 但二次扑救仍为 `6.25%`，没有达到至少 `+2 pp` 的增长门槛；
- 一个极端回合的根部角速度为 `3.5893 rad/s`，略高于 `3.5 rad/s` 自然性上限。

因此候选被明确标为 `REJECTED_BY_CPU_MUJOCO_EXAM`。这轮取得了真实的运动能力增益，但不能宣称已经训练出合格 Champion。

## 2. 为什么旧路线不能直接用

Humanoid-Goalkeeper 官方 checkpoint 是很有价值的动作教师，但不能直接接管当前 G1：

- 它的 29 DoF、10×96 历史观测和 checkpoint 都已逐项校验；
- checkout 固定到 commit `976a81ff19b7306bafbe923d2890066b68a85271`；
- checkpoint 固定为 `sha256:7ecdedff5de6e30a0a4d11742561a9be6c94d8faeefc4701f3e8788381b67b14`；
- 许可证是 `CC-BY-NC-SA-4.0`，所以只能作为研究教师，不能成为可商用 Champion；
- 将官方动作直接作为当前 MuJoCo G1 的 29 关节目标时，18/18 回合跌倒。

直接迁移失败并不等于数据无用。正确做法是把它降级成“建议动作的冻结教师”，由 ROSClaw 决定何时、以多大权限采用，并让已经合格的稳定步态小脑始终掌握主要身体控制权。

## 3. 新的小脑—教师—肌肉记忆架构

每个 20 ms 控制周期按以下顺序工作：

1. 冻结步态小脑根据带方向的侧移意图生成稳定 29 DoF 基础目标；
2. 外部门将教师读取真实球位置、身体角速度、重力、本体关节和 10 帧因果历史，生成自然的全身守门动作建议；
3. 学习 actor 的第 0 通道同时表达方向和强度：符号决定左右侧移，绝对值决定外部教师介入程度；
4. G1 手腕 Jacobian 教师把三维落点误差转换成肩—肘—腕的精确纠偏标签；
5. 学习 actor 的其余通道输出腰部和双臂残差；
6. 动作经过低通滤波、单步变化上限、角速度降权、关节范围投影、预测式关节保护和力矩硬限后才进入仿真。

这相当于：稳定小脑负责“不倒”，自然动作教师负责“像门将”，任务空间教师负责“手套到球”，在线 actor 负责把三者压缩成可持续学习的肌肉记忆。

### Stability–Plasticity 的硬边界

- 带方向侧移/教师门控：`[-0.35, 0.35]`；
- 腰部学习残差：`[-0.20, 0.20]`；
- 手臂学习残差：`[-0.25, 0.25]`；
- 外部教师总融合上限：`0.25`；
- 教师关节组比例：腿 `0.25`、腰 `0.60`、双臂 `2.0`，且最终关节融合不超过 `0.50`；
- 学习动作只在来球阶段有权限，收势阶段自动回到稳定小脑；
- 角速度上升时连续缩小动作权限；
- 零动作严格等价于冻结稳定基线，可直接回退。

## 4. 数据闭环与持续成长

### 4.1 配对反事实课程

同一批射门分别用 `0 / 0.15 / 0.25 / 0.35` 四档动作权限完整执行，按真实物理结果评分，而不是按动画好不好看评分。评分包含：

- 第一次扑救和手扑；
- 扑救后恢复；
- 第二次扑救和手扑；
- 手部覆盖；
- 根部角速度；
- 跌倒失败惩罚。

第一球与第二球分别归因并分别产生标签，解决“整场只选一个动作幅度”无法学习恢复后再扑的问题。失败回合不是被丢弃，而是参与反事实排序，成为 failure replay。

正式课程产生：

- `256` 个配对课程回合；
- `4,554` 条因果监督观测；
- `640,000` 个课程物理世界步；
- 模仿损失从 `0.07021` 降到 `0.04677`；
- 父策略保持损失 `0.00664`，用于抑制灾难性遗忘。

### 4.2 四卡持续 PPO

- 4×NVIDIA RTX A6000；
- 每卡 32 个 MuJoCo/MJWarp 世界；
- 4 个 PPO iteration；
- 训练与选择总物理世界步 `3,200,000`；
- 四卡最终参数最大差异 `0.0`。

在线父策略蒸馏系数为 `0.35`。这允许新策略学习新球路，同时持续约束它不要偏离已经安全的父策略。

### 4.3 选择证据不再混用探索噪声

旧选择逻辑用随机 PPO rollout 的指标选择一个最终执行时不带噪声的均值策略，二者不是同一行为。S36 将每轮拆成：

- 无探索噪声的确定性候选 rollout：唯一允许绑定 checkpoint 和晋升指标；
- 有探索噪声的 PPO rollout：只负责采样和更新。

正式候选来自 iteration 2。其 128 个跨卡确定性回合指标为：

- 零跌倒；
- 首次扑救 `28.125%`；
- 二次扑救 `10.15625%`；
- 二次手扑 `2.34375%`；
- 最大根部角速度 `3.3080 rad/s`；
- 平均回报 `172.7653`。

## 5. 开发过程中的诚实回退

本轮并非一路“越训越好”，而是多次由证据拒绝错误方向：

- 直接 29 DoF 外部策略：18/18 跌倒；
- 教师门控过大：`0.75` 档出现跌倒，`1.0` 档跌倒率 `4.6875%`、峰值角速度 `7.67 rad/s`；
- 任务空间纠偏 `0.85`：跌倒率 `20.3125%`、峰值角速度 `10.83 rad/s`；
- 任务空间纠偏 `0.25` 但没有动作信封：确定性跌倒率 `1.5625%`、峰值 `8.09 rad/s`；
- 加第一版动作信封：零跌倒，但峰值仍为 `4.28 rad/s`；
- 收缩信封和教师融合后：确定性训练选择峰值降到 `3.31 rad/s`，才允许产生候选。

这正是自进化应有的样子：失败改变课程、权限和选择契约，而不是只挑最好看的随机片段。
