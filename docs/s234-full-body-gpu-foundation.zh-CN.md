# S233–S234：全身学习底座，不是球队晋升

日期：2026-09-09。边界：SIM_ONLY。当前完整 4v4 尚未达到展示标准，不发布新的突破宣传片。

## 为什么换路线

S231–S232 的 12 关节小残差 PPO 出现遗忘：扩大训练后，新的通过项不能补偿旧课程失效。保留原候选，拒绝晋升。冻结 SONIC 能保持局部身体稳定，但给它一段关节参考并不等于它知道如何追球。现有 G1 编码接口没有足球任务目标，不能把姿态跟踪称为自主足球。

## 工程实现

- `providers/g1/vector_motor.py`：独立 G1 批量 MuJoCo Warp 电机环境；显式重置、每 2 ms 的关节保护、29 路有界力矩入口，与教师 PD 入口分开；非有限状态和求解器容量溢出阻断后续执行，保留失败状态。可选 CUDA physics graph 仅允许在第一次回合前预热，不暗中重置回合。
- `providers/g1/sonic_torch.py`：从原始 ONNX 数值张量重建冻结 G1 分支，拒绝外部权重引用、非有限输入和超限批量；加载时核对原 ONNX 输出及文件哈希。不支持的分支不能冒充支持。
- `providers/g1/sonic_vector.py`：每个身体独立的历史与 update/observe 顺序；参考只作为策略输入，不写入物理状态；保留原参考求导约定，原生 50 Hz 求导为显式选项。

这些模块属于下游 Soccer 的 G1 provider，没有向 Core 塞足球奖励或角色逻辑。也没有宣称已有学成的直接力矩神经网络：直接力矩入口已经存在，当前稳定教师仍输出关节目标。

## 已完成实验

证据目录均位于本机 `/code/rosclaw/phase8_evidence/`，不把模型、轨迹或视频提交 Git。

| 证据目录 | 检查 | 结果与限制 |
|---|---|---|
| `s233-vector-motor-smoke-v1` | 32 世界、0.5 s 站立，对比同版本 CPU | 最大关节差 7.99e-7 rad；根位置差 1.48e-7 m。仅短时 PD 一致性 |
| `s233-torque-teacher-v1` | 记录力矩加 4 档关节反馈 | 全部失稳；不是正示范，不能晋升 |
| `s234-sonic-vector-physics-v1` | 冻结 SONIC 批量跟踪与 CPU ONNX | 静态编码样本误差 0，GPU 解码最大误差 1.67e-6；动态最大关节差 0.10694 rad、根位置差 0.00894 m，不能称轨迹完全一致；CPU 没有踢到球 |
| `s234-graph-parity-v1` | 256 世界、250 个物理步，graph 开关对比 | 5.061 s → 0.363 s；最大 qpos 差 8.94e-7；**非逐位相等**，不是球技指标 |

静态网络数值相近不证明长时间接触动力学完全相同。动态差异原因仍需定位，不把“可能量化分岔”当作已证实的结论。32/256 份相同初态也不是 32/256 个独立泛化样本。

## 版本与隔离

GPU：Torch 2.11.0+cu128，MuJoCo 3.10.0，MuJoCo Warp 3.10.0.2，Warp 1.15.0.dev20260626。CPU 验收环境：MuJoCo 3.12.0。因此上表的“同版本 CPU”不等于已经通过最终 3.12 验收。

借用已有 Python 环境和隔离依赖目录，没有启动 Isaac Gym、Isaac Lab、ROS 或任何硬件。只使用 cuda:0，不停止其他 GPU 任务。

CUDA graph 使用同一 Torch/Warp stream 执行共享数组操作，参考 [Warp 的 PyTorch 互操作说明](https://nvidia.github.io/warp/latest/user_guide/interoperability/pytorch.html)；预热状态不计入回合证据。

## 下一步的可证伪目标

1. 球状态进入全身残差 actor，在线物理 rollout 更新 actor–critic；明确仍是关节目标残差，不包装成端到端力矩控制。
2. 奖励要求真实足部正接触力，分清脚触球、摔倒撞球与无接触初始滚动。GPU 采样奖励不能替代 CPU 每 2 ms 的接触验收。
3. 保留冻结父策略及旧课程；增加的触球不能抵消稳定性或旧技能倒退。
4. 局部通过后才接回共享球队，再做角色配合、对抗和完整视频。训练日志上涨不是比赛效果上涨。
