## 找到并处理的执行问题

1. **4v4 侧向镜像未修正偏航符号。** 旧调用仅在分阶段射门控制器启用该修正，
   4v4 却关闭了那个控制器。实际轨迹中，目标方向约 +1.35 rad，机器人却向负方向转。
   现在双球门世界也启用正确的镜像偏航变换。这是运行时坐标修复，适用于默认 4v4，
   不是学习候选晋升；旧轨迹仍保留原始源码哈希，不冒充新实现结果。
2. **脚部目标会因侧向符号变化而突跳。** 新增可选的有限摆腿动作时钟，锁定本次脚、
   方向和侧向偏移，使用五次平滑插值，到期归零，不自动重复触发。
   0.18/0.30/0.50 s 的双侧离线搜索均未通过，保持默认关闭。
3. **接应点被错误拉向传球者所在水平线。** 实验配置改为保留协商的接球位置，
   不再在斜向传球准备期间把接球队员拉向球当前的横向坐标。
4. **动作意图与球权事实混淆。** 可选的预先准备模式允许指定争球者在无人持球时
   提交首次触球传球/射门计划；球权仍记为 LOOSE。只有经过角色权限、队友接应确认、
   站位和方向门限的请求才进入运动选项，成功仍由后续真实接触判定。
5. **网络切入状态不连续。** 增加参考位移对齐与当前观测历史初始化实验开关。
   这只改变网络输入记忆，不修改机器人或球的物理状态。实战未证明优于原参考，
   特别是提前到第 205 帧的组合出现跌倒，不能采用。

## 真正复用与训练了什么

复用现有 RoboNaldo ONNX 踢球网络，为红蓝双方开放相同的实验接入路径，
蓝方使用对面的球门，不只是取消蓝方禁用条件。真实网络在五种世界朝向/平移下
通过输入输出等变性检查：原参考最大误差约 2.38e-6，观测初始化实验约 9.83e-7。
这只是网络坐标契约测试，不是物理成功证明。

随后在完整八机器人 MuJoCo 回合中实际调用该网络，记录到了网络执行期间的脚球接触。
一些组合身体门限通过但机器人相互碰撞，另一些组合出现单个机器人跌倒；
审计器分别记录这些失败，不将它们混称为同一种“失稳”。

本轮进行的是有界离线动作参数搜索、执行链修复与预训练网络复用。
**没有新训练 PPO/actor-critic 权重，没有训练新的端到端小脑。**
在坐标错误与交接错误没有排除前，扩大随机训练量无法证明任务能力增长。

`--pass-reference-distance` 是实验性的神经运动条件校准：沿意图方向使用较远的
网络参考点，物理接球者和成绩标准不变。该校准没有通过，不启用为默认行为。

## 复现入口

使用项目兼容虚拟环境及 Core PYTHONPATH，设置 `ROSCLAW_G1_ASSET_ROOT`。
同一 `--output` 不可覆盖；每次试验自动运行 primary/replay 并保存轨迹。

```bash
python -m rosclaw_soccer.training.active_team_probe \
  --asset-root "$ROSCLAW_G1_ASSET_ROOT" --output /external/new-run \
  --active --four-vs-four --duration 20 \
  --bilateral-kick-options --anticipatory-contact --arrival-radius .05
```

蓝方对照追加 `--blue-kickoff`。可选参数有 `--kick-observation-warmstart`、
`--kick-entry-frame`、`--pass-swing-amplitude`、`--forward-receiver-lane`。
这些都是开发试验开关，未晋升任何学习策略。

## 后续不能跳过的工作

提交前检查：Ruff lint、本轮变更 Python 文件格式、mypy（397 文件）、compileall 通过。
带 G1 资产的全量测试日志保存在 `s214-review/pytest-final-v2.log`；仍有 11 项历史外部
证据相关失败，不宣称全量全绿。新增课程阵型测试另行通过。

- 传球者神经动作在自由站立/跑动状态切入后，必须可靠脚部触球，不能用身体碰球补数。
- 接球位置、动作执行持续时间和高层意图的有效期需要一致，而不能互相打断。
- 首先保留可执行且稳定的动作教师，再训练条件残差或连续 actor；不以跑动量奖励替代传球。
- 回到未用于调参的原始阵型、斜向接应和红蓝对抗复测后，才讨论整体提升与宣传视频。
