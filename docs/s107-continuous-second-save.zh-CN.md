# S107：同一连续世界中的第二次真实扑救

## 结论

S107 首次把 S106 的“扑救后横移 probe”升级为同一 MuJoCo 世界、同一物理足球、同一门将的第二次真实高球扑救：

```text
传球 → G1 高球射门 → 第一次手套扑救
     → 神经恢复 → 双脚准备态
     → 二次来球 → 第二次真实手套碰撞并扑出
     → 再次恢复到连续 1 秒 ready
```

全程不重置仿真时钟，不写入机器人或足球的 `qpos/qvel`，不 teleport，也没有替换足球。候选链执行两次并获得完全相同的结果和 trajectory digest；无二次威胁的父链与候选链在第一次扑救前的物理前缀完全一致。

正式结论为 `PROMOTED_SIM_ONLY_CONTINUOUS_SECOND_SAVE_CURRICULUM`。

必须明确：第二次来球当前由 **SIM_ONLY 有界球发射器**产生，不是第二台 G1 踢出的球。它是验证连续感知、恢复、重新决策和第二次身体接触的课程脚手架，不能作为“双前锋实战”宣传。第二台 G1 真正完成二次射门是 S108 的下一项任务。

## 1. 为什么不能直接复用旧视频脚本

以前的多次扑救展示可能由不同 rollout 拼接，或者在镜头外重新放置球和机器人。这可以展示单次技能，却不能证明：

- 第一次扑救留下的动量是否真的被恢复；
- 门将是否能从第一次事件退出并识别第二次威胁；
- 第二次扑救是否使用同一身体连续状态；
- 第一次失败或疲劳是否会影响第二次动作；
- 连续链能否确定性重放。

S107 因此把“禁止 reset/teleport”从文字承诺变成 telemetry 门禁：在 rearm 与 launch 两个事件点检查足球位置、门将骨盆、29 个关节和 20 ms 控制时钟的连续性，并把发射器每一帧的真实外力写入轨迹。

## 2. 二次威胁的物理实现

### 2.1 只有恢复完成才允许 rearm

第一次手套接触后，S105/S106 神经恢复 actor 继续只输出有界的世界坐标深度、横向和偏航命令，底层关节仍由冻结 locomotion policy 控制。只有 live state 同时满足：

- 骨盆高度至少 `0.70 m`；
- 躯干 upright projection 至少 `0.90`；
- 根部线速度不高于 `0.25 m/s`；
- 根部角速度不高于 `0.50 rad/s`；
- 双脚都与地面接触；

才会在 `16.4 s` 进入第二威胁准备态。rearm 只清空因果观察历史、接触 latch、reach/dive 临时记忆和上一帧 residual，不触碰物理状态。

### 2.2 发射器不是 teleport

在 `17.0 s`，系统根据足球当时的真实位置和速度，计算到达球门前目标点所需的弹道速度，然后连续 `0.08 s` 施加有界外力。正式轨迹观测到：

- 发力帧数：`4` 个 50 Hz 控制帧；
- 峰值外力：`59.917 N`，低于 `80 N` 上限；
- 发力后球速增加：`9.934 m/s`；
- launch 点足球位置步长：`0.014444 m`，不存在位置跳变；
- rearm 点足球位置步长：`0.014764 m`；
- rearm 点门将位置步长：`0.000173 m`；
- rearm 点关节最大步长：`0.000289 rad`；
- 控制周期最大误差：`1.11e-14 s`。

开发中曾出现一个真实缺陷：统一球网模型在每个 2 ms 子步清空足球外力，导致日志显示“已发射”，但物理积分没有收到发射力。S107 将发射力改为在球网响应之后叠加，并用“球速实际增长”门禁防止这种假阳性。

### 2.3 第二个因果 flight epoch

仅在 `16.4 s` 清空观察历史仍不够：第一次扑救后滚动的旧球可能在发射前被误识别为新威胁。严格考试曾因此拒绝一个视觉上已经二扑成功的候选。

修复后，在 `17.0 s` 真实发力起点再次只清空观察历史。新 flight epoch 在 `17.02 s` 由可见球历史自主检测，之后才出现门将 reaction；没有使用未来轨迹、发射器目标或 shooter phase。这保证第二次动作由第二次来球触发，而不是沿用第一次动作的计时脚本。

## 3. 从失败边界学到的腕部安全改进

在第二次高球上，冲拳力存在清晰边界：

| 二次冲拳设置 | 结果 | 安全性 |
|---|---|---|
| `80 N` + 侧向卸力 | 门将稳定，但球仍入网 | 无关节越界 |
| `85–90 N` + 侧向卸力 | 球被扑出 | 左腕被碰撞被动推过限位 |

最大越界集中在 `left_wrist_pitch_joint`，发生于二扑后约 `0.2 s`，幅度为 `0.03978 rad`；腿部和恢复网络都不是根因。

原物理腕限位只提前 `0.04 rad` 激活，晚于已配置的 `0.08 rad` 预测关节保护。S107 将腕部物理约束 margin 与预测保护对齐，并把求解时间常数缩短到 `3 ms`。修复后同一 `85 N` 候选既完成扑救，也不再越过任何机械范围。这个修复没有放宽限位，也没有在碰撞后修改关节位置。

## 5. 严格考试门禁

正式 exam 同时要求：

1. 第一次动态腾空手套扑救仍通过；
2. 父链和候选链第一次扑救前缀 digest 完全一致；
3. rearm 只在实时恢复状态合格后发生；
4. 发射器有多帧真实力和实际球速增长；
5. launch 点没有球或机器人位置跳变；
6. 新 flight epoch 在 launch 后由因果球历史产生；
7. 第二次身体接触属于真实 anatomical glove collision geom；
8. 接触 surface distance 位于碰撞可信范围；
9. 第二次接触高度至少 `1.20 m`；
10. 足球未越门线，且门将无关节/力矩违规；
11. 第二次扑救后重新保持连续 1 秒 ready；
12. 候选严格重放的 result 和全轨迹 digest 完全相同。

没有一个门禁依赖视频像素，`pixels_used_for_scoring=false`。

## 7. 对 ROSClaw 通用自进化架构的意义

S107 提炼的不是“守门员第二扑脚本”，而是一种通用连续任务协议：

```text
event A
  → learned recovery under a frozen foundation policy
  → measured readiness predicate
  → causal memory rearm
  → event B in the same physical world
  → second task success
  → recovery and readiness again
  → prefix-preserving + strict-replay promotion
```

它可迁移到机械臂连续抓取、移动机器人连续避障、无人机阵风后重新接管等场景。相较于每个 episode 自动 reset 的训练，连续协议会暴露真正的状态债务：第一次动作留下的速度、姿态、接触和控制器记忆都必须被第二个任务承受。

这也是 ROSClaw “成长”需要的关键能力：失败不只记录单次 reward，而是记录失败如何损害后续任务；恢复不只意味着没摔倒，而是重新获得完成下一个任务的能力。

## 8. 诚实边界与 S108

S107 仍有三个明确边界：

1. 正式晋升只覆盖 `left-inner` 一条连续课程，不代表多球位统计成功率；
2. 二次来球来自仿真球发射器，不是前锋 G1 的脚部碰撞；
3. 当前冲拳/卸力仍是有界任务空间控制与冻结策略组合，不是在线 actor-critic 在比赛中直接更新关节力矩。

S108 应依次完成：

1. 把发射器替换成第二台 G1 的真实脚球碰撞，保持同样的 no-reset exam；
2. 扩展左右内角、外角和不同高度，至少形成四球路连续组合；
3. 将 S107 成功与失败轨迹加入 multi-threat replay，训练“第一次动作对第二次成功率”的 credit assignment；
4. 学习第二威胁的冲拳方向和力度，但继续经过关节/力矩 safety projection；
5. 只有在物理成功率、严格重放、留出球路和稳定性都通过后，才替换当前课程脚手架。

S107 继续保持 `SIM_ONLY`、non-commercial，不授权 ROS/DDS、真机或直接关节力矩在线更新。
