# S1870–S1910：真实高球触球、落地学习与滚地进球复核

## 结论先行

本轮尚未得到“真正阻止进球 + 全链路身体恢复”的合格宣传片。
已经发生约 1.775 m 高的真实左手套触球；也训练出了能在局部失败状态
恢复平衡的反馈参数。但是组合验证揭示了数值敏感性、局部训练向实战
迁移失败，以及旧评分漏记滚地进球的问题。所有这些失败均保留，没有
把局部通过、手套触球、旧 `goalkeeper_save_observed` 当成最终成功。

这是一轮 SIM_ONLY 的模型反馈参数学习（CEM），不是新增神经网络 PPO、
在线 actor-critic 或自主 4v4 的完成证明。优化后的初始站姿和门将初始
横向位置都是显式实验条件，不代表学会了自主跑位。

## 1. 从空跳到真实三人场景

- S1870：把落地学习参数提前用于举臂过渡，4 个案例全部在起跳前失败。
- S1872：隔离参数适用阶段，4 个 16 秒“准备—举臂—小跳—恢复”案例
  均通过本阶段检查。骨盆最高增加约 35.7–51.1 mm，腾空约 96–154 ms。
- S1874-v3：保留传球和射门策略、真实球及手套尺寸，扫描 4 个来球观测
  触发阈值。均有手套接触，但均出现后续关节违规。case-01 的球在
  11 秒时已远离球门，门将却未恢复。
- S1876：把正常运行和独立重放的记录分开。所有 10 个主要物理轨迹
  文件逐数组不变；两次运行的门将原生记录和事件记录完全一致。
- S1878：尝试在落地接触出现后提前接管，4 个案例仍未解决完整任务。

没有通过放大手套、改变球/机器人根部状态、隐藏力或修改电机限额来
制造扑救。现有预测关节保护一直保留。

## 2. 从真实失败恢复学习

S1880 保存了真实扑出后、8.05 秒时的完整 MuJoCo integration state、
编译模型和后续原生控制。S1882 从该检查点重放 1,475 个原生步，全部
位置/速度逐值一致，最大差异为 0；该原始续段的外加广义力和体力均为 0。

检查点主要哈希：

- 模型：`093b87af3bf59ae0570764ea8a0f08d1e558f9cb0375bedfd797f32a7079903d`
- 状态：`6e4b84a7419f6e3145eef9a091e6283045d75a8f37ced709943696da824377e0`
- 原生续段：`8d8cb8e01156c5718ecf484e9d41432034028b12cb29b44295eb442115ebc598`

局部学习时，其他两名球员使用冻结的原生控制记录，仅门将反馈变化。
这能缩短失败复现成本，但不是完整的闭环球队执行；候选必须回到原来的
传球、射门、门将共同运行中复验。候选产生新的球网接触时，也不能靠
原始续段没有外力这一事实替代完整场景的球网响应。

重要差异是触球后保护参数会切换：空跳使用的标准保护为
0.08 rad / 0.16 s / kp=140 / kd=12；实战冲击后为
0.10 rad / 0.20 s / kp=200 / kd=20，电机执行上限为硬限额的 85%。
本轮按实战设置学习，没有调松保护。重建旧控制的最大误差仅
`5.684341886080802e-14` Nm。

这里的次数是开发评估次数，不是独立比赛成功率。S1904 的微扰为检查点
左髋俯仰速度的 ±1e-6、±1e-9 和 0；它们只是数值敏感性筛查，不是
真实扰动或场景泛化的充分证明。完整场景仍然能推翻微扰复查的乐观结论。

MuJoCo 官方说明固定求解迭代次数、将容差设为 0 可改善有限差分的
一致性。本轮仅在离线识别诊断里尝试这些设置，正式回放模型未因此修改。
参考：[mjd_transitionFD 官方文档](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html#mjd-transitionfd)。

## 4. 必须纠正的滚地进球漏判

S1906 case-01 的旧字段报告 `goalkeeper_save_observed=true`，但实际上
球在约 9.960 秒完整越过门线，随后继续向网内滚动。原因是球心因软接触
略低于半径，严格几何谓词把这个滚地球排除在门口之外。

两个实测帧（时间 / 球心 XYZ）已经转成不依赖外部文件的回归测试：

```text
9.939999999999989  [7.6047904534368, -2.9420692710808036, 0.10979241975521103]
9.959999999999996  [7.609931494963847, -2.935807768516753, 0.10980616491369734]
```

球半径为 0.10981691073340778 m，门线 x=7.5 m，因此整球前向越线的
球心平面为 x=7.609816910733408 m。该案例必须算丢球，不能用于证明
门将成功，更不能挑选它生成成功字幕。

新增 `physics/goal_entry.py`：

- 检查所有前向整球越线，不只记录第一次球心到达目标平面；
- 显式采用现有几何谓词允许的至多 1 mm 地面接触容差，报告中绑定容差；
- 门柱、横梁和射门目标精度不扩大；
- 记录球半径、球门几何和实际采样间隔，50 Hz 轨迹使用分段线性插值；
- 非有限值、数值溢出、乱序、缺失越线前缀、超时步记录均拒绝；
- 只输出观察证据，不把“本段未观察到进球”直接等同为扑救成功。

没有静默修改历史 `result.json`，也没有改动旧谓词的默认严格行为。
追加审计 `s1910-whole-ball-score-audit-v2/result.json` 明确否决旧成功字段。
其观察器哈希为
`2e6e9be4c890a5fe5f01ebb2de390888b0fdeae7511d53ad84a55dcc0ccb1000`。
后续候选和媒体选择必须读取这个额外证据层，不能只读取旧 save 字段。

## 5. 工程与后续边界

新增观察器属于 Soccer 的足球物理评分模块，不把门将参数或场景条件
塞回 ROSClaw Core。可推广的工程经验是：检查点可精确复现、学习阶段
限定参数生效范围、微扰复查、真实闭环回归，以及独立评分否决旧成功字段。

本次新增与相关几何/支撑/姿态测试共 59 个通过；新增观察器 Ruff、格式
及 mypy 检查通过。这不是全仓全部通过的声明：上一次 S1828 全仓仍有
11 个已存在的外部证据绑定失败，见前序报告。

原始模型、检查点、训练样本、失败轨迹和图像在外部 evidence 根目录，
不进入 Git。S1890 的四格图仅用于内部失稳诊断，不是宣传成片。
参考机器人/运动资产仍受原项目许可证约束，没有因此获得商业授权。

下一步必须把恢复与真实阻止进球一起训练和复查，并延长观察直到二次球
风险消退；仅改善终态站姿、碰到高球或者换一个旧评分字段都不算突破。
