# 球感知、输入迁移与身份绑定接触奖励

完整时长 Stage I 的 PPO 产生左脚局部进步，但右脚和开发集球交互
退化，不晋升、不继续堆同类动作跟踪预算。现在引入独立的新接口，
不是把原 168D 模型证书贴到新输入上。

## 输入与参数迁移

actor 从 168D 扩为 177D：原 velocity98（原归一化不变）+原
reference70（torso 几何语义不变）+当前 ball/goal9。后三组各三维：

- `(ball_position_world - pelvis_position_world)`，在当前骨盆基底表达，m；
- `(ball_linear_velocity_world - pelvis_linear_velocity_world)`，同基底表达，m/s；
- `(target_position_world - pelvis_position_world)`，同基底表达，m。

第二项是世界相对速度向量的旋转，不是旋转坐标系中位置坐标的时间
导数。球与骨盆速度直接读实际 free-joint qvel，避免扰动后的派生
cvel 滞后。目标坐标显式加入世界实例 origin，不把局部场地坐标
与世界位置相减。原生 NumPy/MuJoCo FK 独立重建全部新通道。

父模型来自已保留基础运动、但尚未足球晋升的 200 轮 PPO 候选。
actor 第一层由 512×168 扩为 512×177，新增九列为零；旧权重、
归一化和 Gaussian 状态保留。critic 从 295 扩为 304，新增九列
同样为零，新增 normalizer 均值 0、方差/标准差 1，保留旧维统计。
数学上初始输出与父模型相同，实际浮点差异须测量，门为 1e-5。
新感知权重可以学习，不能把“新输入已连接”称为学会球感知。
架构发生变化，禁止续用旧 Adam。RSL actor/critic 必须在新优化器
构造之前完成迁移，并验证优化器确实持有新参数。旧 1,200 行实测
速度技能回放补零后缀变为 177D，保存 reference_features=79。

## 触球身份与奖励

参考项目 `soccer_ball_pos` 通常逐步更新，只有 fixed-ball 模式会
冻结；先前把它笼统称为“初始球位”不准确，已修正。仍需解决的是：
最近脚的几何距离不能代替实际碰撞身份。

新增两个独立传感器：ball BODY →left/right ankle_roll_link BODY，
编译后核验 obj/ref 类型和 ID；每个用 maxforce、单槽、十子步历史。
每控制周期将历史按真实先后顺序整理为 `[世界,10,左/右]` 力幅值。
以 >10 N 的首次物理子步决定脚身份；两脚同一最早子步触球视为
歧义，不能获得正奖励。错误脚先触球后再碰正确脚，不补发首次
正确脚奖励。每个 episode 一次正触球奖励；显式 reset 才能重新获得。
正确脚事件后五控制周期内才有球速与朝目标三维方向的奖励。
飞来本来就快的球、无接触的近邻脚不应凭空获得踢球奖励。

训练权重暂定：意图脚接近度 +1（仅 shaping，不是接触标签）、
首次正确脚接触 +50、错误/歧义首次接触 -10、方向 +30、球速 +10。
anchor 位置跟踪权重置零，其余原 Stage I 奖励保持。没有使用参考
项目基于近邻脚归因的接触奖励。当前是 SIM ground-truth 球状态，
不是已经实现视觉感知；依然输出 29D 位置目标+原生 PD，不是力矩策略。

## 物理资格检验：运行前声明

先不训练，严格区分传感器校准夹具与球员表现：

1. 八世界校准：前六个交替左右脚，球放在原 foot4 capsule 端点外
   20 mm 穿入处；最后两个球远离身体。机器人在 fixture 初态抬高
   0.5 m，避免球与地面干扰。只在积分前设置初态，后续十个 2 ms
   子步不重写状态；原生 PD 保持初始关节角。80 GPU 世界步及
   80 原生物理步。它不是站立或踢球成功证据。
2. 核验 compiled sensor 的左右脚绑定；原生传感器幅值与逐接触
   `mj_contactForce` 最大幅值差≤1e-5 N。CPU/GPU >10 N 触球
   侧标签都须与夹具相符，力数组容差 atol=2 N、rtol=5%；十步
   qpos/qvel 混合单位最大差≤1e-3/0.02。失败不放宽门、不删数据。
3. 独立重新 reset，然后在原八个 TRAIN 源上使用迁移 NN 跑完整
   首轮动作，seed1601、每源最多 300 控制，最多 24,000 GPU
   世界子步。逐帧原生 FK 重建当前 ball/goal9，误差≤1e-5；
   同帧父/新 NN 输出差≤1e-5。两网络每控制各八行推理。
   保存首轮掩码与失败，不将 reset 后轨迹混入首轮。
4. 全部原增益、惯量、碰撞形状与动作 codec 保持，并与旧编译身体
   profile 比较；新增传感器意味着新 MJB 哈希，不能沿用旧文件身份。
   安全读回新检查点，零优化器更新。通过只允许后续新 ABI 学习实验，
   不证明新球技、原生长程迁移、高球、进球精度或多智能体比赛。

原始轨迹、模型、回执保存在外部证据目录。每次源码/参数修复都
使用新的冻结版本与未使用的输出目录，保留前次失败和实际计数。

开发预检时，对旧编译身体 home 姿态的 3 mm 胶囊端点夹具做过
一次原生 `mj_forward`（零物理积分步），接触峰值仅 2.447 N，不足
以校准保持不变的 >10 N 信号。因此正式冻结之前把**校准夹具**
穿入量声明为 20 mm，不降低 10 N 识别门，也不修改球员任务或
用这类夹具宣传踢球。此前 3 mm 是未执行资格实验的开发草案。

## 首次实际资格结果与下一项学习

源码 `b273527b` 的实际校准通过：80 GPU 世界步及 80 原生步，
六个左右脚正例与两个负例的标签全部相符。原生传感器与直接
`mj_contactForce` 幅值最大误差 0；CPU/GPU 最大力差 1.216 N，
在预声明容差内。十步最大 qpos/qvel 混合单位差为
6.12e-7 /2.60e-4。未放宽任何执行门。

重新 reset 后实际运行八个 TRAIN 完整首轮，23,120 GPU 世界步、
两网络共 4,624 行实际推理、2,312 次独立原生 FK。八个首轮均
到参考末尾，球感知九通道重建最大误差 2.384e-6，GPU 上新/父
网络输出差为 0。身体 profile 与旧模型相同；新增传感器使编译
模型哈希变为 `1a4a007e40583bb635e087414e397f9cc13c3073fc5ec22b98e42d763f815cb9`。
新初始化检查点哈希
`ff2161a4618b172dc8457b54450beb2f391848aa9478a8bc6f8f955cde88f08e`。
资格回执 SHA256：
`a6928a3660504f404e12ce2efab530ab7b2b86f507b9445097d19358f1b774dc`。
独立回读核验了全部输入哈希、模型/检查点以及原始校准数组。

八段原动作中仅一个首轮取得实际正确脚正奖励，说明奖励并没有因
所有机器人“看起来在踢”就普遍发放。它仍不是新策略学习成绩，
新九列权重尚为零，资格阶段零优化器更新。轨迹中的力历史在
终止重置后读取，终止控制帧的该字段可能已清零；不能用它重建
终止前接触。奖励在 reset 之前计算，缓存的奖励事件与该字段要
分开解释。后续终态接触分析须补足 pre-reset capture，不混用。

下一项固定 32 世界、seed2601、2 次 PPO iteration，每轮 24 控制，
共 15,360 世界物理子步、1,536 个控制样本、40 PPO +2 回放
=42 次优化器更新。新 actor/critic 在 Adam 创建前迁移；Adam
初始状态必须为空，绝不复制父 Adam。actor 新九列必须实际变化，
critic 必须变化，固定 98D 归一化不变，回放两次/512 行。
完整新架构、优化器计数与安全读回均落盘。它是新足球奖励链路的
学习 smoke，不是已经学会踢球；之后仍需完整时长、未训练情境、
基础运动保留和真实脚—球接触的独立物理评估。

该新 PPO smoke 已实际完成：15,360 世界子步、1,536 新控制样本、
42 attempted/completed 优化器 step。actor/critic 各四层权重与偏置
均改变，新增球感知九列范数从 0 到 0.0129742；原 98D 归一化
固定，回放 2 次/512 行、79 维补零后缀，安全检查点回读通过。
全部输入哈希已独立复核。回执 SHA256
`3216deaab4185bf00616fdac96273ea8eec6cae7f36510c43b6a0922e1a96ec2`，
检查点 `ball-aware-update2.pt` SHA256
`87e2603c95a2086e6cefda2678ef6dba86769ab021903d2195fcfccdab49e972`。
这证明新的球感知梯度和真实交互学习发生，不证明球技改善。

下一原生保留检验使用明确的新接口：`zero79` 或 `declared79`，
177D 检查点必须声明 ball-aware ABI，不能用默认 168D 会话悄悄
载入。`declared79` 分别验证 70D 参考和 9D 当前感知后才拼接，
不能拿 69+10 伪装成相同长度。错误帧/输入维持 fault latch。
零后缀保留使用相同身体参数的原编译模型，两个初态×静止/前进，
四例各两次完整独立重跑，共 24,000 原生步、2,400 神经调用，
全部沿用旧高度/直立/速度响应/停止漂移门；报告使用独立的新 ABI
标识，不继承旧 ONNX 或 168D 模型的通过结论。该检验不测试球感知
情境中的足球效果，后续仍需非零感知的完整配对球场评估。

原生新接口保留检验已实际通过：4/4，24,000 原生步、2,400 次
神经推理，完整独立重跑一致。两个前进案例速度误差约
0.03595/0.04693 m/s（仍在 0.08 门内，但比父模型稍差），停止
漂移约 1.684/1.681 cm，所有最低 upright≥0.9957。
回执 SHA256
`2004b3ecfd3fa53ac147ad4a13069b8a7618c53e475d2d33a5617e20bd3f31c3`。
这只证明新检查点在零参考/零球感知后缀下保留了被测试的基础运动，
不能据此声明带球情境更稳定或足球已经改善。

当前实现相关测试共 189 项通过（35 条 Torch JIT 弃用告警），
全仓 Ruff check 和四个相关模块的 mypy 通过；未将这些测试扩称
为全项目全量通过。最初新原生接口测试因 YAML 默认排序破坏了
原策略要求的 observation 项顺序而失败，测试夹具改为保留顺序，
没有放松运行时原策略 codec 校验。所有原始实验与失败输出保留。

## 终态记录修复与非零感知配对评估预声明

新增只读捕获：在每次物理控制开始清空临时记录，仅在 `step` 内
触发自动 reset 时，于底层 reset 之前复制终止世界的 qpos/qvel、
实际脚部十子步力历史、关节目标、最后子步执行器力与参考结束标志。
取结果时以这些副本替换已重置世界，保存 terminal_capture_mask；
普通显式 reset 不伪装成终止经历。捕获不写入物理状态、不增加 RNG
抽样。终态与未终止世界可混合、重复读取不改动原缓存。

这改变了用于资格验收的 backend 源码哈希，故重新冻结并在新的
输出目录进行相同资格检验，不热改旧源码，不重写此前文件。
前次校准夹具的十个子步没有 reset，其已验证结论依然保留。

新非零球感知配对 DEV：007/010 各 32 个既定扰动初态，seed1501/
1502，父/两轮后网络各完整首轮，最多 384,000 GPU 世界子步。
actor 使用实际 177D 输入，奖励和身体使用同一新 backend；不训练。
仅旧回执漏记协议字段时，从哈希绑定的安全检查点读取明确的
pelvis/+1，不回退 torso/0。回执与检查点字段冲突直接拒绝。
两臂初始物理状态及观测逐数组相同。额外记录每帧外生目标世界坐标，
以便原生闭环重建感知，而非猜测目标位置或读取未来物理状态。
指定脚触球及首次脚身份按实际 >10 N 子步力计算，球速是接触后
控制末采样的最大值，不宣称为该脚单独冲量归因。终末球位置只读
真实 pre-reset 状态，不把 reset 跳变算进位移。

新终态捕获版本的资格复核**失败**，不能掩盖：仍执行了 80 GPU
世界步和 80 原生步，左右脚/负例标签一致、身体 qpos/qvel 误差
约 6.08e-7/2.60e-4，但 GPU 力历史出现约 137 N 的孤立值，最大
力差 136.709 N，超过原门限。原生传感器与直接碰撞力差仍为 0。
此前同一夹具的一次通过不能证明 GPU 传感器路径在不同分配/调度
状态下始终可靠。失败的完整状态与计数保留；不放宽力阈值，不
在此问题解决前扩大 GPU 足球奖励训练。此前 GPU 触球标签暂不
作为晋升依据；独立原生物理记录与真实模型权重变化不因此消失。

非零感知 DEV 已完成，两臂均 64/64 到参考末尾。007 关节误差
0.18498→0.18478 rad、XY 0.42466→0.42188 m；010 关节误差
0.19141→0.19137 rad、XY 0.37042→0.37313 m。GPU 指定脚曾
触球 11→12/64，指定脚先触球 11→11/64；这些接触计数受上述
读数风险影响，不宣称技能提升。终态记录与配对初态检查已执行。

独立原生检验另行预声明：使用该 DEV 的两个固定 world0，初始/
最终神经模型分别完整重跑两次。读取相同的外生目标世界坐标与
参考计划，但每步从当前原生球/骨盆状态重建新九维感知；不复用
GPU 接触读数、未来物理状态或 GPU 动作。仍最多 24,000 原生步、
2,400 次推理。实际左右脚身份和力由原生 `mj_contactForce` 获取，
当前新接口的触球门严格为 >10 N，不混用旧 1 N 报告。没有后续
GPU 推动，因此是 nominal 研究而非长程 CPU/GPU 一致性。

已下载官方 MuJoCo Warp 源码至外部参考目录，对比版本与接触传感器
实现，尚未将孤立尖峰归因于某个已证实的上游缺陷；首先做有界
图捕获/非图捕获及原始接触缓冲区诊断，不盲目升级或热改旧环境。
