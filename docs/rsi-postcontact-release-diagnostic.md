# Measured post-contact release authority (SIM_ONLY)

This is an action-authority diagnostic, **not a trained cerebellum or qualified
teacher**. The preceding local perturbation pilot introduced an unsafe
regression. Its initial-contact proxy can be correct inside 80ms while missing
prolonged foot contact, subsequent ball deceleration and later knee contact.
Do not distill that rejected teacher or modify its archived score/results.

The new question is whether a bounded foot action *after measured contact* can
improve the complete outcome on one already consumed, safe failed context.
The previous baseline/corrected local pair is closed and byte-authenticated;
the containing campaign need not be finished to diagnose that closed pair.
This never accesses Fresh or authorizes training/promotion.

## Design

- Authenticate all six original source bindings, the original mean/model
  assets and the closed local pair1 (original binding0).
- Keep the original policy seed, body/world, course, Foundation, navigation,
  IK, RNN, H300 and post-contact60 outcome unchanged.
- Execute the existing 13 named Jacobian actions and one repeated baseline:
  **14 full physical executions, one physical context**, not 14 independent
  scenarios. Bound: 42,000 native substeps and 4,200 executed control periods,
  zero forecasts and optimizer updates. Constructor/qualification inference
  is separate from the executed-control count.
- Wait for a completed foot-contact force bin. At the next current-body frame,
  select the measured contacting foot and derive the predeclared named offset
  from its current Jacobian. No source contact frame or future trajectory is
  passed to the actor. Apply at most three 20ms periods, clipping against the
  unchanged hard actuator limits. Never retrigger; observed nonfoot contact or
  low pelvis cancels the remaining lease permanently.
- Every trial recomputes its own future Foundation, planner refreshes, IK and
  RNN from its changed body. Do not play recorded future joint targets.
- Preserve the complete raw trajectory and terminal outcome of every trial,
  including failures, unsafe results, censoring and unavailable/aliased action
  bases. Verify causal trigger/side, full actual-versus-requested torque
  attribution, source prefix before effective correction and both whole zero
  controls. Report requested-but-saturated actions as no actual authority.

## Entry points

Use a clean immutable checkout and a new external output directory:

```bash
python scripts/rsi_postcontact_release_authority.py --config /external/config.json --preflight
python scripts/rsi_postcontact_release_authority.py --config /external/config.json
```

The configuration profile is `postcontact-release-native14-diagnostic-v1`.
It reuses the original feedback binding fields and additionally pins
`local_root`, `local_declaration_file_hash`, `local_pair_file_hash` and the exact
action-name list. The preflight verifies actual inputs before model allocation.
Keep at least 56GiB available for the original full mean constructor. Do not
launch another own full-model constructor concurrently.

`CausalImpactReplay.release_action_name` defaults to `None` and cannot be mixed
with either existing impact-controller mode. New traces have a distinct
`postcontact_release_` namespace, never fake early-impact fields. Source files
used by active or queued studies remain immutable.

## Interpretation

A successful action on this single failure supports expanding the release
mechanism across public perturbations and retention. It is not a general
teacher, neural learning gain, or team-football result. If all bounded actions
fail, preserve that negative result and reconsider action authority or the
underlying motion/reference semantics rather than doing another identical BC
fit. In either case the larger goal remains independently verified continuous
multi-agent football, not this diagnostic alone.

# Independent physical readback

`scripts/rsi_replay_postcontact_authority.py` requires a closed successful
producer unit, the complete file hash, a clean frozen reader commit and an
unused output directory. It admits all fourteen ordered raw traces before
integrating any body. It rechecks the whole original input hash chain, raw
M0 labels, the original motor/receipt identity, both full zero controls, all
pre-intervention body/neural fields, measured-contact triggering and actual
clipped-PD torque attribution. The declared named torque is independently
rebuilt using the current recorded pose's Jacobian, not trusted by name alone.

`RecordedEarlyEpisode.verify_postcontact_release` consumes the actual distinct
postcontact fields, never fabricated early-impact fields. It reintegrates all
3,000 substeps per body using recorded targets and its own state. Its
42,000-step fourteen-body output is **one physical context**, not fourteen
independent situations, and is not independent neural/search qualification,
learning, or teacher admission. Physical tolerances, H300, M0 and world remain
unchanged. Partial failures preserve actual step counts and the last state;
there is no automatic retry or overwrite.

## Fixed-action transfer before learning

`scripts/rsi_postcontact_release_transfer.py` preregisters `forward_minus`
across **all** twelve consumed public local contexts followed by all six
original retention bindings. This is an explicitly consumed development test,
not a held-out success rate. It reuses eighteen original-control baselines
after byte authentication and raw outcome relabeling. The candidate executes
eighteen new full current-body H300 rollouts (54,000 native steps, 5,400
control Foundation pairs, no forecasts or optimizer updates). There are nine
distinct courses in three source clusters, not eighteen independent worlds.

The action is selected from the single-context authority diagnostic, then
frozen for the entire campaign. It is not selected per case after observing
outcomes. Original neural weights, policy identity/seed, gains, physical world,
heading binding, IK release, outcome contract and H300/post60 remain unchanged.
The body must finish each rollout even for ordinary failure, censoring or an
observed safety veto; the release actuator cancels on observed unsafe state.
Contract/numerical errors preserve partial data and terminate without retry.

The entry requires the closed local24 raw readback and the full independent
postcontact14 physical evidence. It reports rescues, regressions and added
unsafe outcomes separately for local transfer and retention. Local promise
requires a positive net gain, no added local unsafe outcomes and no retention
regression or added unsafe outcome. Even that result does **not** automatically
qualify a teacher or authorize training: robust causal selection and separate
validation remain necessary. A negative result is an explicit next learning
problem, not grounds to discard difficult conditions or relax M0.

## Distinct current-body exit-selection experiment

The separate `postcontact-exit-proxy-transfer18-v1` profile in the same transfer
entry selects from a current-pose Jacobian bank, rather than replaying one
fixed action. It requires `action_name=CURRENT_BODY_EXIT_PROXY`, an explicit
boolean exit mode and at most fourteen forecasts per episode. The total
forecast budget is 10,080 actual steps in addition to 54,000 native steps.
This is still consumed public development plus retention, never Fresh.

`PostContactExitController` only triggers after its own completed foot-force
observation. It samples the contacting leg once, predicts each named60ms
action plus20ms washout using three freshly recomputed Foundation/IK/RNN
updates, and compares an independently repeated zero branch. A trigger too
late or across a planner refresh remains zero; it cannot extend its horizon,
delay to a favorable future event or retry another bank. Observed nonfoot
contact or pelvis below the existing floor permanently cancels the action.

`postcontact_exit_score` keeps the old strict forecast-array checks but not the
old initial-contact score/feasibility. It evaluates terminal80ms ball velocity,
remaining foot contact during the final20ms, backward robot-on-ball impulse,
and the original action regularizer. Fixed research weights are: speed target
1.2m/s with squared shortfall, lateral allowance0.25 times positive forward
speed with squared excess,0.2 times squared terminal contact fraction,0.1
times squared backward impulse, plus the old3e-4 normalized action cost.
These are **proxy parameters**, not changes to M0 success or safety thresholds.
A second predicted impact is not required: after actual touch, cleanly leaving
the ball alone can be the right action. Any predicted nonfoot contact or low
pelvis rejects that branch. If every branch is rejected, zero is an explicit
fallback, **not** a claim of predicted safety.

`CausalImpactReplay` enables this profile only with its distinct evidence
directory and an exact boolean, mutually exclusive with all old impact and
fixed-release modes. Default behavior remains unchanged. Every raw candidate
body, three target/neural updates and its score are fsynced before executing
current native substeps. Actual control uses the distinct `postcontact_exit_`
namespace, not renamed early-action captures. Even successful short forecasts
do not prove later-body stability: the complete H300 M0 and retention test
remains mandatory, followed by separate raw/physics/search verification before
any teacher or learning admission.

`scripts/rsi_read_postcontact_transfer.py` checks the entire closed eighteen-row
campaign, including all failures and retention conditions. It independently
rederives the original public perturbation plan and all baseline identities,
relabels raw full-H300 outcomes and checks prefix/control attribution. For the
exit profile it rebuilds the current-pose named Jacobian bank, reads all300
preaction decisions per case, verifies all raw three-update forecasts and
exit scores, independently reranks the bank, verifies the repeated zero and
compares selected80ms controls/contact bins/body boundaries and neural bits
against the executed trajectory. Observed safety cancellation is explicitly a
partial alignment, never a successful full80ms alignment claim. This shares
the strict old forecast-array/alignment arithmetic, but consumes the actual
distinct exit captures and score; no early-action arrays are fabricated. It
does not advance physics, recompute the neural network or qualify a teacher.

`scripts/rsi_replay_postcontact_transfer_physics.py` consumes that whole18 raw
readback only after both real units close successfully and its exact file hash
matches. It reintegrates all eighteen recorded bodies (54,000 new steps) from
their declared courses and source-bound PD/world, checking all body, ball,
torque and contact fields with the existing tolerance. Fixed release and
adaptive exit retain distinct physical entry methods and namespaces. Exit
search counters must describe a single bounded no-replan bank after a measured
foot contact; they are explicitly **recorded counters, not reexecuted search**.
The physics method still consumes recorded neural targets, so neither this
check nor a passing raw proxy grants independent NN/search or teacher status.

## Full-H300 offline action bank for subsequent learning

The new `postcontact-full-h300-bank252-v1` entry
(`scripts/rsi_postcontact_full_bank.py`) declares all eighteen consumed
contexts times thirteen named actions plus repeated zero. It reuses the
fourteen already executed and physically verified authority trials from
context1; the remaining238 bodies are new, for at most714,000 native steps
and71,400 control Foundation pairs, zero forecasts or optimizer updates.
The full252-comparison matrix is still eighteen contexts/nine courses from
three clusters, **not**252 independent situations. Previously tested actions
elsewhere are repetitions, not new independent data.

Each new action is fixed by name before its rollout, triggered by its own
completed measured contact, and followed by its own complete Foundation,
IK, residual and planner feedback. Full source baselines and each independently
executed repeated zero must retain original array bits and M0 outcomes. The
existing one-context authority trajectories must pass exact source/policy,
raw control, outcome and independent-physics admission before reuse. There
are no source future targets or future contact frames in any new actor.

This dataset measures the actual full-horizon consequences of every candidate
action, including unsafe failure and legitimate late-contact censoring. It
avoids mistaking a favorable short proxy for a successful full body. Offline
labels prefer baseline when it already passes; otherwise they choose among
observed safe passing actions by lateral/forward ratio, normalized torque
norm, then stable index. If none pass, baseline is an explicitly unsuccessful
fallback. The source trial for every label stays inspectable.

This is **offline simulated-outcome supervision**, not a runtime actor that
knows the future, and not an automatically qualified teacher. Runtime future
outcome inputs remain forbidden; all teacher/training/promotion flags remain
false. A later learner must use only the state available before the action,
pass separately declared development/retention tests and undergo independent
verification. No claim of new trained muscles or online RL follows merely
from completing this bank. The CLI has a new frozen declaration, unused
output, explicit deadline/native budget, no retries and a56GiB admission floor
before the sole new full-mean constructor. Partial data/state and actual
attempt counts are preserved on contract or numerical failure.

The current80ms proxy search is not a real-time controller: on its first two
G1 cases, decision-frame file timestamps span270.48/271.88s for each560-step
bank; complete6s simulated episodes take297.62/296.45s wall time. These are
unrandomized filesystem-timestamp observations, not profiler measurements or
a speedup claim. The full-horizon bank is intended to obtain richer offline
action/value supervision without repeatedly paying short-branch copy/check
costs. Any learned low-latency replacement must still be measured and tested;
the present slow oracle is not ready to control a live football match.

### Whole-bank readback and learning observation boundary

`scripts/rsi_read_postcontact_full_bank.py` reads only a successfully closed
whole252 bank. It checks all238 new/14 reused executions, all raw native
tensors, M0 labels, actual torque attribution and original prefixes; rebuilds
each current-pose Jacobian bank; and independently rederives the offline
action ranking. Each of the eighteen contexts stays in the exported matrix,
including those with no eligible post-touch trigger, unsafe outcomes and
unobserved late ball quality. The output remains explicitly
`candidate_supervision_not_admitted`, with training/teacher flags false.

`postcontact_learning_observation` supplies121 current-state inputs: the
existing112 measured body/ball/current-target features, six **completed past**
contact forces transformed by `log1p(force)/log(1001)`, the measured contact
side as two indicators, and the remaining own task-clock fraction. It contains
no source case id, future event or outcome. The same pre-action input must
match across all fourteen interventions in a context. Ball state is simulator
ground truth: this is not a claim of deployable vision or pure proprioception.

The candidate export retains all thirteen actual torque vectors, availability,
pass/safety/quality-observed labels, original dense rewards and measured
post-touch recovery proxies. Dense reward is **not** a substitute for passing
M0; recovery proxies are **not** certification of naturalness or balance.
This is dataset preparation, not neural optimization. Independent body/NN
verification, scoped teacher admission, three-seed learning and retention
remain separate steps. The neural runtime must never receive the offline
future-outcome table as its observation.
