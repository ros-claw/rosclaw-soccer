# S39：80% 门将目标复盘与可恢复侧扑基础

日期：2026-08-16
边界：全部为 `SIM_ONLY`，未向真实机器人发送控制命令。

## 结论

80% 目标尚未达到，任何本轮策略都没有晋升。

在更难的 `match` 双球分布上，修复 CPU/GPU 预判教师语义后，S38 稳定候选的
CPU MuJoCo 64 回合成绩为首次扑救 34.38%、二次来球扑救 35.94%、连续二扑
3.13%、零跌倒。相对修复前，二次来球从 34.38% 小幅提高 1.56 个百分点，峰值
角速度从 2.68 降到 2.25 rad/s；但恢复率从 20.31% 降到 17.19%，且两项绝对
扑救率远低于 80%，因此终考仍返回 `REJECTED_BY_CPU_MUJOCO_EXAM`。

## 本轮查明的三个事实

1. 把首次预判窗口从 0.70 秒延长到 1.60 秒，只把 32 回合首扑推到 50.0%、
   二扑 43.75%，峰值角速度却达到 3.81 rad/s，仍不安全。准备时间不是唯一瓶颈。
2. 全身教师门控为 30%/50%/70% 时，首扑最高出现 59.38%，但跌倒率分别为
   21.88%/62.50%/43.75%，峰值角速度为 9.40--11.70 rad/s。扩大旧教师权限
   不能形成合格门将。
3. 球离开后延长旧教师动作同样失败。30% 教师加入落地锁存后跌倒率从 21.88%
   升到 43.75%，说明旧教师没有学到连续任务中的落地恢复；“多执行一会儿”
   不是完整的恢复技能。

## 工程改进

### CPU/GPU 因果预判一致性

CPU 回放以前会计算带噪射门意图对应的教师输入，但教师混合仍被
`shot_index > 0` 硬关断。现在 CPU 与 GPU 都在公开 cue 可见时允许相同的有界
预判教师混合；cue 丢失时仍关闭。64 回合复考验证该修复没有造成跌倒或角速度
越界。

### 显式恢复锁存实验开关

新增 checkpoint 绑定的教师恢复 hold/decay 参数，避免任何未来恢复教师在触球后
被单步切断。当前官方教师在该设置下物理结果更差，因此开关默认关闭，失败结果
保留为负证据，不能进入候选。

### 数据驱动侧扑 atlas

将本地固定提交的 Humanoid-Goalkeeper `leftjump.pt` 和 `rightjump.pt` 安全加载为
G1 DDS 29 自由度、50 Hz 的训练 atlas：

- 强制 `torch.load(weights_only=True)`；
- 校验源码提交、许可证、关节映射和两个动作文件的 SHA-256；
- 原始 21 自由度按明确映射进入 29 自由度，未覆盖的腰/腕保持官方 ready 姿态；
- 左右动作分别得到 423 帧/8.44 秒和 333 帧/6.64 秒；
- atlas 哈希为
  `sha256:60eca1a154a6e250e3e01913dddb6641ecfee4d553b98a2760bfc74cc09f62c5`；
- 受上游 CC BY-NC-SA 4.0 约束，只可作为非商业、训练期、`SIM_ONLY` 参考。

### 可控侧扑安全状态机

新增环境所有、而非 actor 自报的阶段：`READY → TAKEOFF → FLIGHT → LANDING →
RECOVERY → COMPLETE`。它只接受远角且球已激活的侧扑请求，并同时约束：

- 侧扑期间最低骨盆、最低直立投影；
- 最大根部线速度/角速度；
- 最大 option 持续时间；
- 允许的保护性落地接触与禁止的危险身体接触；
- 新一球到来前必须完成稳定保持，否则立即 `FAILED`；
- 完成后可停留在当前位置再次起扑，不要求机械回中。

这不是放宽全局跌倒标准。普通站立仍执行原安全门，只有状态机接受并仍处于受控
包络内的短暂侧扑阶段才获得姿态例外。
