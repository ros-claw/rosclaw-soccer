# 持续执行与实测切换试验：2026-10-26

目标仍是有完整证据的自主连续球队比赛，而不是更多资格检查或更好看的剪辑。
本阶段没有新增神经网络权重、没有通过整队考试，也没有宣称射门成功率提高。

## Agent loop 的真实边界

需要两个循环，不能混为一谈：

1. 实验循环：声明有限预算、冻结代码、运行仿真、保存原始输出、独立复核、决定下一实验。
2. Agent 循环：宿主继续调用模型，让模型读取结果、修改实现、检查、推进下一阶段。

`rsi_watch_research_loop.py` 是第一类任务的只读观察器，不会调用模型。
它已有测试保证：观察心跳、指针更新不能清除空闲计时，不能伪装为科研进展。
不能把启动 systemd timer 写成“保证 Agent 永不停机”。

每次阶段结束，外部检查点应记录：精确源码提交、实验状态、输出与哈希、真实进程、
成功/失败结论、停止的搜索家族以及下一项具体动作。重启后先对账，不重复分配已关闭的实验。
无收益则改变有证据支持的假设，不无限追加 seed、训练轮数或候选幅度。

本次运行发现根分区满，宿主 `get_goal` 返回数据库 disk I/O error。
这意味着宿主自动续轮的健康状态**未能确认**；不是仿真成功，也不是允许修改宿主数据库的理由。
实验检查点继续保存到独立证据盘。恢复宿主状态前，不能承诺无人干预的无限连续运行。

## 本轮实现

- `SynergyForecastKickPlayer.plan_entry()`：先完成原有有限预测选择，尚不发出实际 NN 动作。
  重复调用不重跑搜索；异常使适配器失败，不能下次绕过搜索直接执行。
- 所有相关 teacher、memory、实际目标候选与嵌套 NN 预测使用绝对物理回合时钟。
  私有世界的已消耗计数仍从零起算，不能据此重置 H300 截止时间。
- `retire_unexecuted_entry()`：仅允许健康、当前边界、零 proposal/commit、无 pending、
  所有权一致的 SIM 技能退出。旧适配器保持终态，不能清除失败、丢弃已发出的目标或重置物理状态。
  此操作不切 PD、不推进仿真，也不自动建立新技能。
- `rsi_probe_walk_kick_switch.py`：在同一个真实测量边界预测三种切换时机，
  相对原入场延迟 0/6/12 控制周期。预算只允许一个原始实际回合 3600 原生步和最多
  4050 预测原生步。必须保留原实际轨迹与零延迟预测的逐数组一致性。

这些预测不是实际执行的延迟切换，也不是持续学习成绩。预测窗口只能标记局部可行性，
不能替代完整 H300 实测、扰动课程、未见样本或独立审计。

## 下一步接受条件

先检查有限三分支是否提供有意义的新动作空间。若有，再让实际控制器按选择继续原速度 NN，
随后以五帧新实测历史进入踢球。保留旧 teacher 已通过的分支，实际回放验证救回失败与零退步。
只有多状态和扰动 teacher 合格，才开展 DAgger/学生与有预算的 RL；不能以更多机制测试
代替球员和球队能力增长。
