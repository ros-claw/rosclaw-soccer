# S458–S488：传球精度、成功记忆与接球泛化

截至 2026-09-10，第一脚传球已有可测量改善，但没有合格的完整 4v4
比赛成果。本阶段未发布宣传视频，未晋升实验策略。全部为 SIM_ONLY。

## 已确认的进展

- S458 使用球实际穿过目标平面的误差训练，不再仅用发射方向代替精度。
  名义开发场景误差约从 0.42 m 降到 0.04 m；实际八机器人现场第一脚
  前向速度为 1.225263 m/s，8 个身体安全、机器人间碰撞为 0。
  但是独立 CPU 新扰动考试中 g16 为 8/32 次精度通过，g32 只有 4/32；
  不能用最佳开发画面宣布整体晋升。
- S467 将 136/3 接球导航头与冻结的 133/29 肢体策略分开。导航看上一帧
  foundation target，肢体看本帧 target，只推进一次原有 LSTM。
  零导航头的实际现场回归中，185 个运动数组逐项完全一致。
- S479 从 S461、S464、S465 保留了 6 条严格成功的随机探索轨迹，共 505
  个动作样本。S481 将其中当前来球场景的一条在独立 CPU 仿真中复现：
  真实脚触球、无非脚触球、身体稳定，触球后及结束前的控球窗口均通过。
  这里只在开始恢复一次状态，之后没有加球力或重置。
- S483-v2 把这条轨迹的后 60 帧学进 133/29 神经网络。1000、5000、10000
  步检查点均在该原始成功状态下以确定性闭环推理通过，不是播放动作数组。
  前 40 帧仍由冻结的 S364 接近策略执行，不能称为无阶段切换的完整小脑。
- 新公共模块 `training.success_distillation` 对旧成功动作做独立监督更新，
  不伪造 PPO 的新策略似然。只更新 actor，保护 critic/noise，验证输入，
  自己拥有 Adam 并计数实际执行的 optimizer.step。S488 用该公共模块
  重做 1000 步，所有模型参数与上述成功检查点逐项完全相同，最大误差 0。

## 不能省略的失败与限制

| 实验 | 实际结果 | 结论 |
| --- | --- | --- |
| S459、S461、S462、S464、S465 接球 PPO | 各自确定性开发考试均无稳定接球通过；探索中有少量成功 | 奖励提高不等于策略学会 |
| S467 导航 PPO，32 次更新 | 确定性控球仍 0/64 | 新架构已跑通，效果未突破 |
| S469–S472 导航权重搜索 | 无严格控球成功 | 不能以接近距离代替接球 |
| S473 零接球残差 | 球末速约 0.502 m/s，但有 6 次非脚接触样本 | 球变慢不是有效控球 |
| S475 从零输出头训练，32 次更新 | 未获得合格接球 | 单纯重置输出头无效 |
| S478 一脚定向转传，16 次更新 | 最终确定性 0/64 | 独立技能，不把边线反弹算转传 |
| S480 混合 6 条成功的蒸馏 | 拟合误差下降，原成功状态闭环失败 | 多来源动作混合可能互相干扰 |
| S484，S483-1000 新扰动 | 成功初态附近父策略 0/32，新策略 1/32；名义来球附近 0/32 | 训练状态复现不是泛化 |
| S476，S483-1000 实际八机器人 | 全体安全、0 碰撞；中场脚触球后球末速 1.118 m/s | 尚未控住，不能继续算有效协作 |
| S485 成功初始化 PPO，16 次更新 | 开发通过 5/64→6/64，名义来球组始终 0/16 | 局部成功尚未转移 |
| S486 合成观测噪声蒸馏 | 成功附近及名义来球新扰动均 0/32 | 合成标签不等于新增成功经验 |
| S487 神经网络相位列旋转筛选 | 部分成功初态通过，名义初态没有通过 | 单独调时序仍不足 |

S484 的 32 次考试采用固定新种子 48401：球平面位置 ±0.015 m、平面速度
±0.03 m/s、关节初始角 ±0.002 rad。它们只是同一身体上下文附近的局部
扰动，不是跨场景泛化。观察多个候选后，这批数据已属于开发比较集，不能
继续称作未见过的最终考试。

## 证据与工程核验

大文件留在 `/home/dell/rosclaw_soccer_evidence/`，脚本主要在
`/code/rosclaw/phase8_evidence/`，目录名对应各实验编号。原始权重、轨迹、
日志和失败候选不进入 Git。S476 新现场执行将 7 个实际使用的适配器源码
归档到每个案例的 `source/`，并绑定哈希，避免后续编辑覆盖复现依据。

S464、S465、S475、S478 的逐轮权重/rollout 哈希及 Core plasticity 审计
通过；首个 GPU 优化更新重放最大参数误差均为 0，分别实际执行
330、464、247、608 个优化步。非脚接触后没有继续记正奖励或活跃学习样本。
这些是训练数据和更新核验，不是足球成绩证明。

公共蒸馏模块新增 13 个测试；与导航、接球适配器联合测试为 36 passed。
全量 pytest 为 1813 passed、29 skipped、11 failed：仍是此前已记录的
11 个历史证据/当前绑定测试失败，没有将其隐藏为全绿。Ruff 全仓通过，
mypy 全部 447 个源文件通过，compileall 通过。S488 的 1000 步参数精确
重放进一步绑定了公共训练实现和实际被考试的模型。

S483-v1 有一次脚本错误：循环执行 1001 次，手写审计步数却填了 10000。
已在原证据目录写入 `INVALIDATED.md`，保留原件并禁止使用该审计。
全新 S483-v2 改为对每次真实 optimizer.step 计数并断言总数，重新执行
10000 步；公共蒸馏模块进一步统一了这一职责。

S479 的物理轨迹哈希是在提取记忆时建立的；原训练行没有单独绑定该物理
归档。因此不能声称有从原始运行开始就独立验证的物理文件哈希链。S481 的
独立 CPU 复现补充了物理可复现性，但不能追溯替代缺失的原始绑定。

本方法受 [Self-Imitation Learning（ICML 2018）](https://proceedings.mlr.press/v80/oh18b.html)
启发，但当前只实现成功样本监督蒸馏，不是完整复现其 off-policy actor-critic
算法，也不是把离线样本混入 on-policy PPO。

## 下一条验收链

优先让同一个策略学习接近、触球、卸力、控球的完整过程，再扩展实际来球
位置/速度分布。候选必须依次经过：训练状态复现、新扰动、不同身体时刻、
八机器人原位执行、第二次传球及射门。安全、触球、控球、协作和比赛质量
分别记账；不以粗粒度 `result.passed` 或“所有机器人都在动”代替比赛成功。
