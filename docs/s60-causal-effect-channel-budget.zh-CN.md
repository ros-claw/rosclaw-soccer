# S60 因果效应通道预算：新域突破与冻结旧域否决

日期：2026-08-22
边界：`SIM_ONLY`、4×RTX A6000、MuJoCo MJX；无 ROS/DDS、厂商 SDK 或硬件命令

## 结论先行

S60 首次证明：恢复小脑的 Stability–Plasticity 不能只用一个全局增益解决，必须把有限纠正权威分配给不同身体通道。基于失败状态动作—效应 Jacobian 与冻结历史正常域干扰率，v4 将较多权威留给踝/腰，将肩腕权威进一步压低。它在新 192 状态开发考场同时通过故障恢复、正常成本、逐方向、稳定和有限性五门：故障成本改善 `1.192696%`，正常成本相对改善约 `0.005693%`。

但完全冻结、未参与选择的旧 96 状态考场否决了它。旧故障恢复仍改善 `1.151712%`，旧正常路线成本却退化 `2.157631%`，方向门失败。因此 v4 只是一个有价值的 `SIM_ONLY` 开发候选，不是跨域 champion，不进入 CPU MuJoCo truth exam，不制作成果视频，不具有部署或硬件权限。

本轮最重要的工程结论不是“找到一组补丁参数”，而是得到下一代通用 rosclaw growth 能力的明确接口：静态通道预算可以解决局部 Stability–Plasticity，但跨历史域需要受静态预算上界约束的、状态条件化的向量 veto，并且必须从候选自己产生的闭环正常轨迹学习。

## 问题与假设

S59 v12 在新 192 状态开发门中表现良好，但冻结旧 96 正常路线的首个方向指标超出绝对容差 `0.000371743`。此前策略只有一个全局输出增益；它无法表达“踝部纠正对失衡有益，但肩腕在正常动作中更容易形成干扰”这种身体结构差异。

S60 的假设是：

1. 失败状态 teacher corpus 中的 `action_effect_jacobian` 提供局部因果符号；
2. 候选在当前失败训练源上的动作幅度，表示可塑性需求；
3. 候选在冻结历史正常训练源上的动作幅度，表示抗遗忘干扰风险；
4. 左右镜像关节必须共享预算，避免单侧统计误差制造新不对称；
5. 新预算只能保留或降低来源模型权威，不能凭借选择器扩大 actuator authority；
6. 当前失败 holdout 和冻结旧域 holdout 均不得参与预算选择。

## 工程实现

### 1. 通道效应预算

`derive_corrective_effect_budget_gain()` 接收：

- 当前失败训练源的 4×29 动作—效应 Jacobian；
- 当前失败训练源的神经纠正输出；
- 冻结历史正常训练源的神经纠正输出；
- 来源模型的逐通道上限；
- G1 左右镜像关节对；
- 最小/最大保留比例。

对每个通道先计算加权局部效应贡献，再用“历史正常 RMS / 当前失败 RMS”形成干扰率。局部贡献有害的镜像组或单通道进入受限集合；风险越高，保留比例越接近下限。最终强制：

```text
0 <= derived_gain[j] <= source_gain[j] <= 1
derived_gain[left] == derived_gain[right]  （镜像受限组）
```

该方法是任务无关的预算原语；G1 的关节镜像表位于 OpenTrack 适配层，核心算法不依赖足球、G1 或某个固定场景。

### 2. 防泄漏与谱系绑定

预算只读取当前 168 个失败训练源和冻结旧域 72 个正常训练源。当前 24 个 holdout 与旧域 24 个 holdout 均不参与选择。报告保存：

- 两侧训练源数量；
- 两组预测内容哈希；
- 来源/冻结报告哈希、文件哈希与语料哈希；
- 受限关节、镜像组、历史风险、逐通道保留比例和最终增益；
- `frozen_holdout_consumed_for_selection=false`；
- `authority_monotonicity=DERIVED_GAIN_CAN_ONLY_RETAIN_OR_REDUCE_SOURCE_GAIN`。

### 3. fail-closed 证据验证

验证器不只检查 JSON 自身哈希，还重新打开模型归档并检查：

- `derived_gain` 与归档 `output_gain` 在 float32 规范下逐元素完全一致；
- 数组形状、有限性、范围和来源单调性；
- 选择分割、训练数量与预测内容哈希格式；
- `SIM_ONLY`、无部署、无晋级、无硬件授权边界。

开发过程中发现元数据在 float64 中计算、模型以 float32 归档，最大规范化差异约 `2.8e-8`。验证器已改为按真实归档 dtype 规范化后位级比较；这不是放宽容差，篡改 `derived_gain` 的测试仍 fail-closed。

## 如何通俗理解

可以把神经小脑想成一支 29 人的肌肉协作队。原来所有成员只有一个总音量旋钮：声音太小，机器人救不回失衡；声音太大，正常动作又被打扰。

S60 给每组肌肉分配不同音量。新场景中，脚踝和腰更像真正负责救平衡的主力，肩腕更像容易“帮倒忙”的成员。把音量从肩腕搬到踝腰后，新 192 场景第一次同时做到“该救时有效、正常时安静”。

但旧 96 场景说明同一份固定分工仍不够：有些身体状态下，脚踝/腰的动作也会通过 600 步闭环逐渐把机器人带离正常路线。下一步不是再改一张固定音量表，而是让小脑根据本体状态和短期历史，实时决定每组肌肉本次能说多大声；同时任何实时决定都不能超过 S60 的静态安全上限。

## 下一阶段：闭环状态条件向量 veto

静态比例搜索到 v4 为止。下一阶段应实现以下闭环，而不是继续扫描 gain：

1. 用 v4 在当前训练源与旧域训练源各运行完整 600 步闭环正常路线；
2. 保存候选实际访问的本体历史、primary confidence、lease 状态、逐通道动作与效应，不再只保存父策略的 20 个稀疏帧；
3. 在训练源内挖掘连续误触发窗口，holdout 全程密封；
4. 学习 29 维状态条件 veto `v(o_t, h_t)`，并强制 `0 <= v <= 1`、左右镜像约束、时间 slew 与有限 lease；
5. 实际输出满足 `gain_dynamic = gain_v4 * v`，因此动态模型只能减少 v4 权威，不能扩大硬件能力；
6. 联合使用当前失败训练源、当前闭环正常训练源、旧域正常训练源和可恢复 replay，解决 Stability–Plasticity；
7. 在密封的新 192 和冻结旧 96 两个考场顺序复考，禁止根据旧 holdout 结果回调；
8. 增加多次严格复跑/多 seed 稳健门，处理 600 步 GPU 动力学中的混沌放大；
9. 两域全部通过后，才实现并运行独立 CPU MuJoCo truth exam；CPU 通过后才接回传球—射门—扑救完整链路与对照视频。
