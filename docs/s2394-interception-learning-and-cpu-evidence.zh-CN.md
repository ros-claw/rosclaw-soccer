# S2394：接球学习、失败回放与模块化

## 当前结论

尚未获得合格的连续 4v4 比赛，也没有新的合格连续比赛宣传片。
本阶段的正向结果是单机器人接球：在 56 个开发验证条件中，学习得到的
控制器选择器通过 20 个，零导航基线通过 0 个；全部 112 个逻辑案例
保持原身体安全条件，逐案例双重 CPU 物理执行完全一致（224 次执行）。
这不是端到端关节策略的突破，也不是 4v4 泛化证明。它是冻结神经网络
步行基础策略上，通过实测脚位置进行有界平面拦截、再学习选择控制参数的结果。

## 为什么不继续盲目增加 PPO 训练

S2336、S2338、S2346、S2358 累计 96 代、6144 个训练课程、1,075,200
个控制帧、4202 次优化更新，仍未得到困难条件下可资格化的均值策略。
独立审计重建了训练奖励、样本和优化更新，算法执行正确不等于技能学会。

S2358 使用同初态四次尝试的组内比较和二值成功奖励，16 代后，CPU
原示范条件接球从行为克隆候选的 4/13 退化至 1/13，困难训练条件仍为
0/8（S2378）。未替换冠军，未激活该候选。

接触诊断发现实际的对侧小腿碰球，而非仅仅是鞋碰撞体标注错误。例如
S2384 条件 1，左脚在 0.536 秒出现 59.50 N 正向接触，随后右小腿在
0.794 秒出现 42.97 N 正向接触。不能通过扩大脚的分类或删去非脚接触
规则来制造接球成功。

## 学习路径与验证

1. S2382 在 CPU 上搜索 32 个平面控制器、8 个已知条件，每个重复执行
   两次，共 512 次物理执行。单一参数最好 2/8；参数集合覆盖 6/8。
2. S2388 从经过原物理评分复查的六个成功条件选择标签，训练
   3→32→32→32 的 MLP，1000 次 Adam 更新。输入是初始球距、横向位置、
   来球速度；输出是有限控制器编号。两次拟合权重完全一致。
3. 更新由 Core 的 begin_update/finish_update 约束，冻结步行模型哈希，
   不修改身体或运动权限。未授予策略晋升。
4. S2390 在原八条件及每条件六个新邻域扰动上进行成对 CPU 验证。
   新扰动为位置 ±5 mm、速度 ±5%。学习选择器原条件 6/8、新扰动
   14/48；基线分别 0/8、0/48。超出支持域时拒绝选用，拒绝仍计失败，
   不是从分母删除。

这些是开发验证，不是私有盲测。六个训练样本的拟合准确率不能作为
泛化率；20/56 也不足以宣称稳定掌握接球。输入目前仅验证朝向 π 的
单角色课程，尚未验证另一朝向、双方角色和实际共享世界。

## 可复用实现

新增 `skills/planar_interception.py`：纯数值目标拦截提议，明确传入目标
位置、目标速度、末端位置、上次提议及配置。不读写仿真、不操作电机，
不宣称接球成功。配置和快照拒绝非有限值、非法形状、混合设备及越界历史。
世界坐标提议有显式速度和每次调用变化上限；这不是实际身体速度或
物理安全保证，调用方仍负责时钟、坐标转换、原生运动限制及执行防护。

S2394 把已验证的六个成功案例替换为公共模块后，所有记录数组与原
S2382 轨迹逐字节相同，双次执行也一致（12 次物理执行）。这才是
模块化迁移证据，不是仅导入成功。

测试：新增 18 项通过；全量 4137 passed、18 skipped、11 failed。
11 项均为此前已存在的 S78–S114 历史外部证据测试失败，未宣称全量绿灯。
新模块 lint、格式及定向类型检查通过；仓库历史格式问题未批量改写。

## 后续失败课程及边界

S2392 原版横向偏移搜索被严格重放断言阻止。检查发现第二次执行漏传
横向偏移，比较了不同控制器。单独相同参数三次物理执行完全一致。
另存 v2 修正参数传递，并在重放失败时先保存双方轨迹，未放宽一致性
要求。原版失败日志保留。v2 完成 128 次执行并全部严格重放一致；
64 个逻辑案例均满足身体安全条件，仅条件 3 的一个参数通过接球，
条件 7 仍未通过。新经验尚未证明能由学习选择器可靠选择和推广。

下一步要覆盖未通过条件，同时保留当前成功条件回归，然后进行共享
世界真实接球→后继动作验证。不能用独立重置课程拼接替代连续比赛。
