# S286–S291：身体学习接回自主球队，而不是七人站着陪练

## 本阶段实质进展

新的全身残差 actor 已通过共享球队接口，接入八个独立角色 cell 的同一场
MuJoCo 仿真。红、蓝两侧分别完成自主射门意图、带速度交接、神经网络动作、
实际脚触球和对方后卫阻挡。逐物理步证据证实了连续强射门。

这不是比赛已完成：后卫多次发出传球意图，但尚没有对应的连续有效脚传球；
射门在对方后卫处被挡住，也没有完成要求的高质量进球/门将扑救配合。
`IndependentTeamWorldResult.passed` 只表示现有角色活动、安全等基础门通过，
不能解释成高水平足球或球队冠军。没有晋升策略，没有发布宣传视频。

## 真正接回球队时发现了什么

S287 把公共 `G1FrozenBallMotor` 接入同一比赛时钟，两名前锋分别持有模型实例
和教师历史，其他角色继续自主决策和运动。结果球没有动：前锋提出了 330 个
控制帧的射门意图，但所有移动交接都被拒绝。

追踪真实状态发现，旧射门移动目标要求在球后 0.72 米处站稳；新身体模型的
交接窗口需要距球 0.50–0.68 米且前向速度大于 0.1 m/s。前锋到达约 0.65 米
时已几乎停住。问题是两个控制接口的假设不一致，不是“再多转几轮 PPO”
就能自动解决。

新增可选 `motor_approach_standoff_m`，仅对显式接入模型的前锋、无持球者且
已有射门意图的移动目标生效。试验值 0.35 米，使运动控制在到达站立目标
之前进入实际交接窗口。世界中的机器人和球没有被平移或重置。默认不启用，
保留历史默认配置哈希；原有预触球意图功能直接复用，没有另造战术开关。

S289 实际接通了动作，但参考 28 导致后续队友贴近并发生身体碰撞，完整比赛
安全门失败。该失败保留，不能只剪出触球的瞬间。随后重新接回既有全角色
速度避让，以及同一世界中的门将伸手控制。没有改成允许碰撞来通过安全门。

## 候选试验与逐物理步核验

S290 在实际自主八人世界中筛选六条参考，使用新 S286024 身体。不同参考
产生了真实不同结果：18/19/20/27 通过基础活动和安全门，28 有身体碰撞，
29 没有踢到球。参考 27 的全场峰值球速约 3.83 m/s，后卫确实挡住了球。
这是一个开发场景的候选筛选，不是六场独立测试或选择器学习成绩。

S291 使用参考 27，对称地检查红、蓝两侧；每侧都是实际八人角色决策与
同一个球，不是其他七人维持零速。两侧结果：

- 全部角色达到现有活动门，全部身体稳定，无机器人间接触，无模型接口故障。
- 前锋动作对应 2000 个连续物理样本；首次脚触球在交接后约 0.754 秒。
- 交接至触球的最低有符号前向速度约 0.253 m/s，没有停下来再踢。
- 首次脚触球后 200 ms 内的干净目标方向峰值球速约 3.685 m/s。
- 后续非脚接触在交接后约 1.178 秒，来自对方后卫，并不抹掉此前真实脚冲量。
- 蓝、红互换是对称性核验，不把它们当成两个独立分布上的成功率。

传球/扑救意图计数不等于实际动作完成。虽然本场产生 49 次传球意图和 3 次
扑救意图，实际传接球链和门将扑救仍需继续训练与验证。

## 公共工程接口

`skills/team/motor_option.py` 把每球员的只读观测、29 关节目标/增益提案以及
可选的物理步证据消费者分开。共享世界保留实际物理步、关节限制、PD 和
85% 硬力矩上限，不把 MuJoCo model/data 或硬件接口交给提案器。

同一对象不能被两名球员共用；模型合同绑定到结果。与旧踢球选项/近球残差
冲突的覆盖所有权会被拒绝。无效提案锁定该模型并回到原有运动控制，不能
自动重试后算成功；物理证据消费者或接触力失效会在下一 2 ms 步之前移除
覆盖。故障名单进入结果与哈希，故障场不能通过 `passed`。

S287/S289 的显式故障注入都验证了只调用一次失败提案，后续使用原控制。
最初结果序列化遗漏了新增模型字段，已在 S289 修复并增加结果哈希测试；
此前原始结果保留。默认配置哈希的新增字段回归也已修复，保留原固定哈希断言。

证据保存在外部 `s286-*`、`s288-*`、`s287-*`、`s289-*`、`s290-*`、`s291-*`
目录，源码、脚本、权重、轨迹和物理证据均有内容绑定。原始数据不进入 Git。

下一步重点是将后卫的传球意图转化为实际可重复的传球，再让接应者与门将
完成连续任务；不再把单人射门进步当作球队整体已经进步。
