# S58：扩容纠偏课程、门控 DAgger 与稳定性–可塑性闭环

日期：2026-08-21

状态：`SIM_ONLY / 6 CANDIDATES REJECTED / NOT_DEPLOYABLE`

## 结论先行

S58 确实加大了训练，但没有把“训练更久”误当作“已经学会”。失败状态从 96 个扩展到 192 个完全独立状态，监督蒸馏从 1500 步提高到 6000 步，4 张 A6000 实际参与教师搜索、学生训练、on-policy 数据采集和父子策略物理对照。扩容后的教师在 192/192 个状态上找到有限且满足保留约束的短时纠偏，教师中位成本改善为 `12.0876%`。

学生端仍没有产生可保留候选。六个候选给出了清楚而可复现的结构性结论：

1. 全关节高可塑学生能在未见失败状态改善 `2.3410%`，但正常路线成本回退 `32.0441%`；
2. 稀疏 DAgger 能让正常成本改善 `1.3083%`，但困难改善只剩 `0.4457%`，且方向和稳定硬门失败；
3. 逐帧置信门能保住 `2.4812%` 困难收益，却仍让正常成本回退 `8.1415%`；
4. 提高静态门阈值并不能解决问题；
5. 门控 on-policy DAgger 几乎收住正常路线，正常回退为 `1.0560%`，只比 `1%` 硬门多 `0.0560 pp`，但困难收益变成 `-0.2865%`；
6. 使用这些 on-policy 负样本重训门后，离线留出上的困难/正常平均开度达到 `0.6689 / 0.0153`，物理闭环中却仍出现正反馈：困难集刚好通过 `+1.0404%`，正常路线回退 `14.4493%`。

因此，本轮最重要的结论不是“再加步数”，而是：单帧静态门即使离线分类很好，也无法控制一次误开以后由自身动作引起的状态漂移。S59 必须升级为带内部状态、开门保持、退场和 slew 约束的时序门控小脑，并扩展跨路线失败库；继续围绕同一路线扫 gain 或 threshold 已经没有证据价值。

所有候选均为 `student_development_retained=false`、`deployment_candidate=false`、`promotion_eligible=false`，没有真实机器人权限，也没有进入 CPU MuJoCo 晋升复考。

| 教师搜索 | 4 GPU CEM | 4 GPU CEM，192/192 接受 |

新增状态使用随机种子 5475，从控制步 `200/300/399/400/500/599` 各采 32 个。新旧银行不仅文件不同，而且按“完整状态行 + 控制步”计算的精确指纹重叠为 0。这样能证明训练规模扩大来自新源，而不是把旧 96 行复制两次。

这里仍有明确边界：192 个新状态来自同一 route group 和同一 snapshot 家族，只证明时间窗内的源独立，不证明跨动作、跨路线或跨任务泛化。

## 新增的 ROSClaw 通用能力

### 1. 课程扩容证据契约

`recovery_corrective_scale.py` 新增可复用的规模阶段契约：

- 对新旧失败银行做精确行指纹、唯一性和交叉重叠检查；
- 强制每个失败时间窗达到最低独立样本数；
- 绑定随机种子、路线、父策略、教师、快照和文件哈希；
- 权限上限固定为 `SIM_ONLY`；
- 支持把通过的新候选放回旧冻结银行复考，但新双考未通过时禁止进入该阶段。

这不是 G1 足球专用逻辑；任何采用“失败状态银行 → 教师 → 学生 → 冻结回归”的 ROSClaw Growth 任务都可复用。

### 2. 冻结旧银行物理复考

新增 `evaluate_opentrack_recovery_corrective_student_frozen_bank`。它会在旧银行的精确留出初态上重建父策略和候选，重新运行困难/正常两套动力学考场，而不是复用新银行的数字。报告同时绑定候选和冻结基准的报告/模型/语料哈希。由于本轮没有候选通过新银行双考，这条路径正确地没有被执行。

### 3. 平滑保守介入门

新增 `calibrate_corrective_confidence_gate`：在不增加关节权限、不修改纠偏网络的前提下，对已有置信 logit 做阈值和温度校准，低置信区域平滑趋近静默，高置信区域才逐步开放。OOD 潜变量包络保持原样，包络外仍强制零输出。

校准工具本身工作正确，但实验说明“逐帧开度”缺少时序语义。一次误开可以改变下一帧状态，使下一帧置信度进一步升高，最终形成闭环正反馈。这个反例决定了下一阶段的结构方向。

### 4. 门控 on-policy DAgger

S58 让被拒的门控候选实际跑正常路线，采集它自己诱发的漂移状态；每条路线混合 10 个父策略状态和 10 个候选访问状态，全部标注为零纠偏，再做 6000 步平衡蒸馏。被拒候选仅作为 `SIM_ONLY` 反例采集器，来源报告哈希和 `student_development_retained=false` 均写入新证据。

### 5. 长考性能工程

原实现要么把 600 步一次性编译成巨大 XLA 图，要么每一步回到主机调度。S58 改为 10 步 JAX scan 块：

- 正常父策略轨迹采集；
- 候选访问轨迹采集；
- 父/子独立物理考试；
- 冻结银行考试。

训练也按 100 步 scan 块执行，在保留完整 loss trace 的同时减少 6000 次 Python 调度。两次旧实现编译试验在尚未产生证据时主动终止；没有删除或伪造报告。

### 6. 证据验证加固

教师验证器原先要求重算后的浮点摘要逐位相同；相同语料在 SVD 中出现约 `1e-16` 的最后一位差异会被误拒。现改为：结构与离散字段严格相等，有限浮点摘要使用 `1e-12` 绝对容差。测试覆盖 `nextafter` 最后一位变化。

规模验证器同时校验 overlap count、fraction 和训练唯一数之间的一致性；允许配置声明的非零上限，但默认 S58 仍要求精确零重叠。

## 为什么本轮没有视频

本轮研究的是恢复小脑的纠偏介入，不是视觉编排。六个学生都没有同时通过困难和正常双考，尤其最终候选会在正常路线造成明显的横向/稳定漂移。把某条短片裁成“看起来成功”会掩盖 24 初态 × 600 步的失败，与 ROSClaw 的证据闭环相冲突。因此没有制作宣传视频，也没有把任何模型接到足球控制链。

## S59 实施建议

1. **时序门控小脑**：用小型 GRU/TCN 读取本体历史，显式输出 `OPEN/HOLD/EXIT`，加入最短保持、退出冷却和 gate slew；状态必须进入证据和复现契约。
2. **门控边界 DAgger**：采集误开、过早关闭、反复开关三类序列，不能再只把每帧当独立二分类样本。
3. **序列级安全损失**：直接优化 20–80 步累计方向、稳定和动作 slew，而不是只拟合教师瞬时增量。
4. **跨路线失败银行**：下一批 192/384 状态必须来自新的 route group、snapshot 和扰动族；当前 192 银行转为冻结回归，不再调参。
5. **双头或专家结构**：把“是否救援”和“如何救援”分开训练，门只授予有限时域的纠偏租约，执行头在租约内仍受动作/功率/稳定约束。
6. **父策略正常基线缓存**：绑定完整初态和版本哈希，减少每个候选重复计算父路线，同时保持候选物理 rollout 真实运行。
7. **晋升顺序不变**：新跨路线双考 → S58 192 冻结回归 → 旧 96 冻结回归 → CPU MuJoCo 真值复考 → 足球恢复链视频。任一失败即停止。
