# S38：机动门将与 80% 扑救目标阶段报告

日期：2026-08-16
边界：仅仿真（`SIM_ONLY`），未向真实机器人发送控制命令。

## 1. 目标与结论

本阶段目标不是让门将机械回到球门中心，而是让其能够根据自身位置、横向速度和下一扑阶段持续机动；同时以首次扑救率和二次来球扑救率均不低于 80% 作为绝对门槛。

结论：新的分层控制、因果预判和速度护栏显著恢复了机动时的稳定性，但 80% 目标尚未达到。最新四卡保守候选在更难 `match` 分布的 CPU MuJoCo 64 回合中，将冻结基线的首次/二次扑救率从 21.88% / 21.88% 提高到 34.38% / 34.38%，零跌倒，最低骨盆 0.725 m，峰值角速度 2.680 rad/s。它只因两项 80% 绝对门槛被拒绝，没有晋升、没有替换既有 champion。此前更激进候选虽能把 GPU 二扑推到约 52%，但因角速度或 CPU 尾部跌倒被拒绝。

## 2. 本阶段开发内容

### 2.1 非强制回中的动态站位

- 恢复阶段不再生成固定回中命令。
- 以 `当前位置 + 预测时间 × 横向速度` 形成动态捕获点。
- 仅当预测捕获点即将越出球门边界且动作继续向外时，才投影为向内动作。
- 因此门将可以停留在有利区域、沿原运动方向刹车或继续准备二扑，而不是每次被中心点拉回。

### 2.2 解耦三个控制责任

原适配器用同一个标量同时控制横移和全身教师，稳定脚步与扑救动作互相干扰。本阶段拆为：

1. 通道 0：冻结小脑上的横向脚步；
2. 通道 1：冻结全身扑救 option 的门控；
3. 其余通道：带幅度、速率、角速度和关节保护的腰/手臂残差。

这使在线 actor-critic 可以学习“何时横移、何时启用扑救动作、伸手多少”，而不会直接获得任意腿部或电机力矩权限。

### 2.3 Stability–Plasticity 分阶段解冻

- 阶段 A：`residual_plasticity_scale=0`，只训练脚步和 option 门控。
- 阶段 B：腿部教师权重降为 0，腰部教师权重 0.2，上肢教师权重 1.0；上肢残差仅解冻 25%。
- 每个阶段都把具体权重写入 checkpoint 配置，CPU 考试和视频回放按相同配置重建，旧 checkpoint 缺省为旧语义，避免静默改变历史证据。

消融显示，教师大幅接管腿部时会有 75%–100% 的回合跌倒；稳定小脑继续控制腿部、教师只提供上肢动作时可保持零跌倒。

### 2.4 腰部反向角动量补偿

上肢快速伸展会把躯干峰值角速度推到 4 rad/s 以上。本阶段加入只在角速度保护区内激活的腰部 roll/pitch 反向补偿，并由 checkpoint 显式绑定开关。单卡验证中峰值角速度由 4.31 rad/s 降至 2.38 rad/s。

### 2.5 80% 绝对门禁

CPU 最终考试新增：

- `minimum_first_save_rate`；
- `minimum_second_attempt_save_rate`。

本阶段两项均设置为 0.80。即使候选相对父策略有改善，只要没有达到绝对值，也必须返回 `REJECTED_BY_CPU_MUJOCO_EXAM`。

### 2.6 因果射门意图与非回中威胁跟踪

第二球原本在恢复窗口内完全不可观测，策略既不知道下一球方向，也就不可能有意义地“不要回中”。本阶段新增可选 77 维观测合同：在起脚前和两次射门之间增加落点 belief 的横向误差、高度误差和置信度。它有 0.16 m 横向噪声、0.12 m 高度噪声和 12% 随机丢失，且只在射手本应能暴露动作意图的窗口出现；球飞行后仍只用球位置/速度估算截点。旧 74 维 checkpoint 通过插入三列零权重精确迁移，原输出逐元素保持一致。

有 cue 时，门将可以向下一威胁点占位；cue 丢失时继续保持当前位置的动态捕获点；只有预测将越出门框时才由边界保护投影回场内。该机制没有读取模拟器中的未来轨迹。

### 2.7 预判式上肢预置

进一步复盘发现，旧控制器在球离脚前会硬清零全部上肢动作，高角和远角只能在不足一秒的飞行中临时甩手。现在增加 checkpoint 绑定的预判式上肢开关：仅当带噪 cue 可见时允许手臂缓慢预置，腰、腿和全身教师仍锁定；cue 丢失立即退回 ready 语义。课程学习为第一球起脚前和两球间窗口生成任务空间双臂监督，并允许威胁跟踪使用完整的已限定横移幅度，而普通恢复仍使用较小幅度。这是 Stability–Plasticity 的新解冻层，不会静默改变旧候选行为。

### 2.8 比赛合同、到点制动与教师预热

- 新增 `match` 难度：相对 `standard` 使用更宽的横向范围、更高/更低的落点、更近的发球点和更短的飞行时间；同时提供 0.70 秒带噪摆腿意图。没有 causal cue 时该合同拒绝构造，因此“反应难度”和“球速/落点难度”不会混为一谈。
- 横移教师不再使用固定 0.55 秒恢复 horizon，而是由公开 elapsed-time 特征计算距下一次起脚的时间，早期平滑移动、临近起脚再加速，降低提前冲过目标后的反复横跳。
- 新增 checkpoint 绑定的横向速度护栏：超过 0.55 m/s 后逐步削弱同向加速，达到 0.85 m/s 时生成有限反向制动；反向刹车和向场内动作始终保留。
- 新增意图驱动的教师预热：只在 cue 有效时，将 belief 转成外部守门教师可理解的虚拟来球提示，使其可以在起脚前准备；真实球飞出后立即切回真实球观测。该提示不含未来真实轨迹，且 cue 丢失时关闭。

### 3.4 机动性—稳定性参数扫描

在 `match` 分布上对冻结策略做因果可达性扫描，得到以下边界：

| 设置 | 首次 | 二次来球 | 跌倒 | 峰值角速度 |
|---|---:|---:|---:|---:|
| 保守脚步 + 12% 上肢 + 教师 30% | 56.25% | 53.13% | 0% | 3.36 rad/s |
| 下肢教师 5%、腰 20%、教师 30% | 56.25% | 53.13% | 0% | 3.30 rad/s |
| 上肢残差直接放大到 80% | 43.75% | 10.94% | 59.38% | 12.74 rad/s |

分桶诊断显示，0.70 秒预判时第一球中心区域约 57.5%，但远角为 0%，触球时根部与远角平均仍差 0.67 m；第二球有 1.35 秒预判，远角达到 52.17%，全程零跌倒。当前 80% 的首要阻塞不是是否回中，而是第一球远角到达时间与高球手臂工作空间。放大电机权限会破坏第二扑和稳定性，因此被否决。

## 4. 对当前瓶颈的判断

1. **仅靠站立横移和安全伸手的覆盖上限不足。** `match` 因果上界扫描约为首次 56%、二次 53%；把上肢残差直接放到 80%反而造成 59% 跌倒。
2. **第一球和第二球的准备时间不对称。** 第一球 0.70 秒时远角仍为 0%，第二球 1.35 秒时远角可达 52%；需要把射手真实 run-up 纳入场景，而不是让 actor 从固定时钟猜起脚。
3. **高球工作空间不足。** 当前单点线性 Jacobian 任务空间教师在大幅高/远角动作上精度不足；增加幅度只会放大角动量，必须使用非线性多锚点 IK、双臂/腿部反作用协同或可恢复侧扑 option。
4. **大幅扑救策略没有恢复能力。** 外部教师原任务常在扑救后结束；在连续二扑任务中，大幅接管腿部虽能扩大覆盖，却无法重新站稳。
5. **GPU 与 CPU 存在尾部动力学差异。** 平均指标一致并不足以保证安全，必须保留 CPU MuJoCo 最终门。

## 5. 下一阶段建议

下一阶段不应继续简单增大残差，而应增加三个模块：

1. **真实射手感知接入**：用射手 run-up、支撑脚和摆腿状态替换当前显式 belief 仿真器，同时保留同等噪声/丢失测试。禁止直接把未来目标坐标作为特权输入。
2. **非线性多锚点上肢 IK**：离线生成中心/高低/左右工作空间 atlas，再蒸馏进 actor，避免单点 Jacobian 在大动作区失真。
3. **可恢复侧扑 option**：使用“起扑—触球—吸收冲量—侧步/翻滚恢复—重新就绪”的完整动作片段和阶段 critic；考试需要区分受控侧扑与失控摔倒，并要求在二次来球前重新获得稳定支撑。

只有把远角可达性和扑后恢复一起解决，才有可能在更快、更高、更偏的射门分布上把 80%变成可信统计结果。
