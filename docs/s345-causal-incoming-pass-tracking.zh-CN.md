# S345：蓝队出现可重复、安全、纯脚触球的带球—传接球链

结论：在原有八机器人共享世界中，蓝队把一次原本漏接的真实回传接到了。
这是局部链路进步，不是合格 4v4 比赛，更不是两边均已完成全链路。

## 实施

`PassHandoff.can_track_incoming_ball` 从真实源球员脚触球与当前球朝接收者的
速度判断是否可以提前跟踪。它不激活租约、不转移控球、不宣称完成接球。
默认关闭的接收优先配置启用后，来源仍有接触记忆控球标签时也可跟踪来球。
另加默认关闭的 `receive_lateral_braking`：近球刹住纵向追球，但保留有限横向
补位。速度、加速度、关节与避碰约束均保持原值。

## 八组对照及重复

提前跟踪开/关 × 横向补位开/关 × 红/蓝，共八次 20 秒 CPU 八体实验；
组合候选红蓝各再独立重复一次，共十次。本阶段没有新增权重训练。

| 蓝队条件 | 身体安全 | 机器人间接触计数 | 真实接球 | 全局纯脚控球 |
|---|---|---:|---|---|
| 两项关闭 | 是 | 0 | 否 | 是 |
| 只横向补位 | 是 | 0 | 否 | 是 |
| 只提前跟踪 | 否 | 159 | 是 | 是 |
| 两项组合 | 是 | 0 | 是 | 是 |

组合候选精确复现：蓝前锋在 8.10 秒传出，接收跟踪记录从 8.12 秒出现，
蓝中场在 9.08 秒真实脚触球。定向球速约 2.021 m/s。现有比赛评估记录到
带球、传球和跑动事件；还没有合格射门、扑救、双方争球等完整比赛证据。
中场随后提出回传意图，但没有新的实际脚触球，不能算连续往返传球。

## 红队结果不能混报

红队也重复保持身体安全、零机器人碰撞；但 4.78 秒传出的球较慢，
8.44、8.64 秒先碰到中场的非脚身体部位，8.66 秒才有中场脚触球。
原三秒诊断窗口没有确认接球；六秒比赛窗口虽记录到 PASS 事件，
全局纯脚控制门控仍失败。因此不把红队这一条称为合格传接球。
没有放宽时间窗口、删除非脚触球或调整判分来制造成功。

## 验证

相关测试 55 passed、2 skipped；完整测试 1546 passed、29 skipped、11 failed
（49.60 秒）。11 项仍为既有外部历史证据绑定失败。ruff 通过，mypy 433 文件通过。
默认配置的固定哈希保留不变。所有候选仍为 SIM_ONLY，未替换全局冠军。
