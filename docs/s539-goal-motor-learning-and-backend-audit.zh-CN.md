# S539 起：目标条件关节学习、CUDA 扩展与失败复盘

日期：2026-09-11。全部为 SIM_ONLY，没有真实机器人操作。

## 结论先行

这轮确实训练了神经网络关节残差 actor-critic，也实际使用 A6000 跑了
128 世界 CUDA 物理训练；不是仅调整展示脚本。但尚未获得合格的接球—转身—
出球策略，不能宣称球技提升。未替换现役模型，未制作冒充新成果的宣传视频。

截至 S553，完成 88 次真实 rollout/update、1,876 个优化步骤：
CPU 五组共 72 次更新、845 步；CUDA 一组 16 次更新、1,031 步。
这里的“步”是优化器 minibatch step，不是物理步，也不是独立足球比赛。

## 公共代码与工程边界

`build_handoff_actor_critic(action_size=29)` 在既有 143/3 导航学习器之外，
新增显式 **143/29 关节残差学习合同**。输入含本体状态、29 维上次关节残差、
导航历史预留位和七维球/出球目标特征，输出 29 维原始关节残差与 critic。
公共 PPO 更新器仅增加该显式形状；默认配置和现有合同保持不变。

本轮导航由独立固定控制器提供，因此运动观测可以使用当步基础步态目标，
三个导航历史预留位为零。导航学习变体仍须使用上一步基础目标，避免本次
动作污染本次观测。动作继续经过原有关节残差包络、PD 与力矩限制；它不是
直接输出力矩的端到端策略，也没有获得硬件权限。

actor 与 critic 均实际更新，基础步态网络冻结。S539–541 只在第 80 帧后
学习，S542/S548 改为从接球技能入口开始学习。C15/24 接球偏置在 S542 起
作为采样后的确定性动作变换，不能偷偷改变保存的策略似然。

这些是足球学习接口与实验，保留在 Soccer 下游仓库；没有向 Core 的通用
Growth/SimForge 塞入 G1 特例。本轮也没有新增已验证的全队自我进化能力。

## 训练与严格验收

| 实验 | 设置 | 优化步 | 开始→最终持续控球 | 出球姿态 |
|---|---|---:|---:|---:|
| S539 | 143/29，后半段学习，低探索 | 48 | 8/32→8/32 | 全部 0 |
| S540 | 学习率从 2e-5 降为 1e-6 | 192 | 8/32→8/32 | 全部 0 |
| S541 | 增大动作探索，学习率 2e-5 | 180 | 8/32→8/32 | 全部 0 |
| S542 | 从入口联合学习，增加球在身体前方的奖励 | 305 | 8/32→0/32 | 全部 0 |
| S548 | 128 CUDA 世界，从入口联合学习 | 1,031 | 20/128→0/128 | 全部 0 |

上述 CPU 的 32 世界是同一身体状态的四种扰动各重复八次；CUDA 的 128
世界是四扰动各重复 32 次，不能当成 128 个独立场景。训练另加新球位、球速
扰动，但身体初态仍有限。所有上述开发评估的身体安全均通过，不代表控球或
比赛通过。S539 首次更新 KL 约 2.39；S540 降学习率后约 0.0147，却没有
换来任务进步，说明修正优化步长不能替代动作分布与任务设计。

持续控球门要求：合法脚触球、无非脚触球、入球速度/飞行时限合格、身体及
边界合格；首次触球后 0.3 秒起一直到结束，球速不超过 0.5m/s、最近脚踝
距离不超过 0.35m。出球姿态还要求末尾十控制帧朝向误差不超过 0.6rad，
球在身体前后轴坐标不低于 -0.03m，横向偏差不超过 0.3m。没有放松这些
阈值来制造进步。CUDA 各代连独立的姿态尾窗也全部失败，并非仅被控球门卡住。

S548 第一次更新的开发控球一度到 32/128。随后用原生 CPU 对 g0/g1 做
**32 个新配对球扰动**验收（S549）：两者都只有 1/32 持续控球，姿态均为
0，身体均为 32/32 安全。候选球仍在场内为 30/32，基线 31/32。
因此拒绝候选晋升，而不是挑开发曲线峰值发布。

S542 的首次真实 CPU 更新、S548 的首次真实 GPU 更新均独立精确重放，
所有参数最大差为 0。保存了模型、Adam、真实 rollout、CPU RNG；GPU 还
保存/恢复 CUDA RNG。checkpoint 使用 `weights_only=True` 读取。
这证明更新可复现，不证明模型变强。早期结果里的 `prefix_motor_frozen_verified`
在 S542 表示未使用的参考 actor 权重未变，不能理解为执行中的前半段不变。

## 后端差异：不能把仿真版本变化当成学习进步

| 实验 | 物理后端 / MuJoCo | 同一基线持续控球 |
|---|---|---:|
| S539 基线 | CPU / 3.12，Torch 2.13，NumPy 2.3.5 | 8/32 |
| S543 | CUDA / 3.10，Torch 2.11，NumPy 2.4.4 | 3/32 |
| S544 | CPU / 3.10，Torch 2.11，NumPy 2.4.4 | 0/32 |
| S546 | CPU / 3.12，Torch 2.11，NumPy 2.4.4 | 8/32 |
| S547 | CUDA / 3.12，Torch 2.11，NumPy 2.4.4 | 4/32 |

S544→S546 只切换 MuJoCo 包路径，不更改 Torch/NumPy，说明物理版本足以
改变严格控球标签。用显式加载隔离已有 3.12 包，没有覆盖安装环境。CUDA
后端完成兼容性和逐自由度阻尼资格检查，但 S547 与 CPU 仍有四个控球假阴性，
无假阳性，标签一致 28/32。样本单一且大量重复，不能据此宣布全面等价。
因此 GPU 仅用于候选生成，原生 CPU 保留独立验收。

NVML 仍报驱动/库不匹配；Torch CUDA 实际计算成功，四张 A6000 可见。
本轮训练实际只使用物理 GPU 3，不能宣称完成四卡训练。

## 动作问题的因果排查

1. **接住不等于能传出去。** 唯一控球基线的球最终在身体后侧，前后坐标
   约 -0.264m、横向约 -0.433m。CUDA 各代终态平均前后坐标也仍为负。
   最近脚距离合格可能对应别扭的后侧截停，不是自然的出球站位。
2. **入口确有角速度峰值，但不是新回放独有。** 原始八体轨迹在 320→321
   帧也出现约 0.278→2.086rad/s 的根部偏航角速度变化。镜像状态未在此
   切换。S550 用八组 PD 目标入口限速做配对试验，未明显减小峰值，严限速
   反而破坏身体稳定；没有采用该补丁。
3. **不能归咎于避让器。** S551 对保存的前控制状态重建投影：四扰动分别
   有 20/117、14/118、0/118、15/118 个触球后控制帧被改写，最大改变量
   约 0.0263m/s，全部可行。唯一持续控球的第三个案例完全未被改写。
   这不支持“避让迫使它后退是主要原因”，也不支持移除避让保护。
4. **加大命令可改善朝向，但会丢球。** S552 扫描八组有界靠球/转身参数，
   保留 0.7m/s、0.8rad/s 上限与投影。基线 1/4 控球；七组加强方案均
   0/4，所有姿态 0。部分朝向误差从约 1.1rad 降至约 0.36rad，但不等于
   动作整体成功。八组身体安全合计 29/32。

## 复现与验证

### S553：扩展实测入口后的进一步失败

另完成八次 CPU 更新、120 个优化步，使用原始同一次传球的第
300/305/310/320 帧四个实测身体、速度、基础步态 LSTM 与动作历史状态。
每状态四扰动各重复两次，共 32 世界。它们是相关的时间切片，不是四场
独立比赛。每次开始新的残差技能，保留基础 recurrent 状态；确认入口前
没有原始 12 维残差动作。没有在回合中改写球或机器人状态。

每回合扩展到 180 控制帧，维持传球后 3 秒绝对飞行期限。更正：1.5 秒
相对首次触球条件只用于搜索排序的 eligible，而不是 controlled 计数的
独立硬门；此前将二者混写。与 160 帧实验不是完全相同
的考题，不能直接比较比例。开始/最终持续控球和姿态均为 0/32，身体
安全从 10/32 降至 6/32；早期第 300、305 帧入口始终未通过身体安全。
首次 PPO 更新仍可精确重放，参数差为 0。拒绝该模型。

这进一步暴露技能入口范围窄与长时维持薄弱的问题，但不能仅凭该试验
归因于数据分布：技能入口时刻、相位重启与延长的考试窗口同时不同。
下一次须把这些因素分开做配对消融，再决定课程与模仿数据如何构建。
