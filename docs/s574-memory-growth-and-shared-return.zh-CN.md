### S584：前锋开始争取自由球，但接球后仍丢球

7.9秒合法进入该实验接球流程，8.448秒右脚真实接触球，峰值约53.9N；不是手工改变球速度。但接球动作100帧用尽时球已侧向离开，无法衔接原射门门限，50次射门尝试都被姿态/速度门限拒绝。记录中的 `finisher-reception-completed` 仅代表控制时域结束，**不代表接球成功**。

整体仍 `safe=false, passed=false`。不能以射门意图数上升替代射门完成，也不能为拍视频放宽准入门限。

## 进一步的球队级失败归因

S593的机器人间碰撞集中在8.10–8.46秒，双方是红方前锋与蓝方中场，而不是正在控球的蓝方前锋。现有控球确认器在任意机器人碰撞时都会中断待确认窗口；这段碰撞恰好覆盖蓝方前锋首次脚触球，后续没有新的脚触球事件，不能重新获得待确认状态。因此离线严格控球通过，但运行时未持续确认为控球者。不能人为授予控球权来掩盖差异。

S596检验对两名前锋使用相同的近身导航边界：其他身体进入1.4米时，让尚未进入活动踢球/接球的SONIC导航单向让位，继续使用本来就在观测真实运动的循环平衡底座。结果反而变差，碰撞计数269、射门意图0，没有发生后继前锋接球，**拒绝采用**。不能把有历史状态等同于两个运动控制器能安全直接切换。

S597尝试0.6秒连续过渡，但初始化发现红方旧提供器没有可选readiness接口，实验未进入有效仿真。S599保留旧提供器的默认可选接口语义，只在过渡期间显式阻止新运动承诺，碰撞计数降为11，但蓝方中场倒下，整队未通过。另一个S598对照不切换控制器，保留SONIC历史，只让原有避让约束更早生效，机器人间碰撞降为0，但中场右踝俯仰超过关节下界约0.0259rad（最低骨盆0.662m、最大倾斜0.291rad），不能笼统写成它也摔倒了。整队仍未通过。二者都是分析式边界试验，不是新学出的技能，没有放宽原碰撞与安全失败判据。

## 工程加固与尚未采用的方向

`local_action_memory` 增加读取阶段修正值、归一化尺度有限性检查，避免Inf被tanh饱和隐藏，或尺度损坏产生表面正常输出。新增Inf/NaN用例。

`rendezvous_target` 是有边界的恒速接应预测基线，只给目标建议，不执行、不授予动作权限。回看S582，用过去0.2秒速度预测实际前锋位置误差0.506m，反而大于静态目标的0.442m；没有激活为冠军。运动员的意图与后续导航变化不能可靠地由瞬时速度外推，后续应绑定接应意图、空间目标与时间窗口。

训练机制仍在Soccer孵化，不冒称已成为Core正式通用能力。当前优先补齐：实际自由球获取后的可控姿态、接球到下一运动的条件转换、接应目标时空承诺，再训练多身体竞争。不是继续堆同一个固定目标的PPO轮数。
