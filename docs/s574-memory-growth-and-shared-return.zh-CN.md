## 八机器人共享世界：链路断在哪里

### S582：球到点，队友不在点上

将130经验记忆接入蓝方中场，其他角色、物理碰撞、力矩与场地守卫保留。球在7.198秒被中场实际脚触碰并转传；8.782秒到固定目标的最近误差为0.0546米。但前锋已移离约0.4米，随后球被红方后卫身体挡住。

八个身体的各自姿态/关节/力矩检查均安全，不是中场自己倒了；但共享世界仍有145个机器人间接触计数，整体 `safe=false, passed=false`。几何落点精确不等于队友接球，更不等于合法完成传球协议。

原始S580运行期间发生源码变更，收尾源码哈希校验失败，未成为有效绑定证据。冻结源码重跑S582后校验通过，与S580保存轨迹逐项qpos/qvel一致。保留两次结果，明确区分。

### S584：前锋开始争取自由球，但接球后仍丢球

发现原前锋接球模块只接受有接球约定的来球。中场转传后，前锋被战术层选为自由球追逐者，却没有启用接球小脑。实验复用既有前锋接球策略，仅在前一运动释放、无活动射门、被选为追球者、球无主且实际接近、安全身体条件下启用，不伪造传球约定、接球租约或控球权。

7.9秒合法进入该实验接球流程，8.448秒右脚真实接触球，峰值约53.9N；不是手工改变球速度。但接球动作100帧用尽时球已侧向离开，无法衔接原射门门限，50次射门尝试都被姿态/速度门限拒绝。记录中的 `finisher-reception-completed` 仅代表控制时域结束，**不代表接球成功**。

整体仍 `safe=false, passed=false`。不能以射门意图数上升替代射门完成，也不能为拍视频放宽准入门限。

### S587：仅换新记忆，检查真实共享迁移

完成同一八身体环境的配对探针：只将130经验替换为284条训练经验，不添加提前量偏置、不重新调导航。前锋仍在第395帧进入接球，真实脚触球峰值约62.7N；但整体仍未通过，机器人间接触计数187（S584为145），没有证明球队改善，不替换整队冠军。隔离环境成绩上升并没有自动转化为整队效果。

## S588之后：直接学习实际前锋失败上下文

从S584提取前锋第395帧的完整身体、球、底层LSTM、上一动作与反射模式。新建显式配置的训练脚本，不再依赖多层字符串生成来声明新实验参数。

首先使用原始导航命令做物理桥接复现（仅复现使用记录命令，不算闭环学习）：连续100控制帧的qpos最大误差2.05e-6、qvel最大误差1.05e-4，达到预设复现容差。身体安全且脚触球，但严格控球成功为0，与真实链路失败一致。

## 进一步的球队级失败归因

S593的机器人间碰撞集中在8.10–8.46秒，双方是红方前锋与蓝方中场，而不是正在控球的蓝方前锋。现有控球确认器在任意机器人碰撞时都会中断待确认窗口；这段碰撞恰好覆盖蓝方前锋首次脚触球，后续没有新的脚触球事件，不能重新获得待确认状态。因此离线严格控球通过，但运行时未持续确认为控球者。不能人为授予控球权来掩盖差异。

S596正在检验对两名前锋使用相同的近身导航边界：其他身体进入1.4米时，让尚未进入活动踢球/接球的SONIC导航单向让位，继续使用本来就在观测真实运动的循环平衡底座，不重启任何运动历史。这是分析式模块切换规则，不是新学出的技能；所有原碰撞和安全失败判据保留。最终必须重查整队物理轨迹，不能提前认定能消除碰撞。

## 工程加固与尚未采用的方向

`local_action_memory` 增加读取阶段修正值、归一化尺度有限性检查，避免Inf被tanh饱和隐藏，或尺度损坏产生表面正常输出。新增Inf/NaN用例。

`rendezvous_target` 是有边界的恒速接应预测基线，只给目标建议，不执行、不授予动作权限。回看S582，用过去0.2秒速度预测实际前锋位置误差0.506m，反而大于静态目标的0.442m；没有激活为冠军。运动员的意图与后续导航变化不能可靠地由瞬时速度外推，后续应绑定接应意图、空间目标与时间窗口。

训练机制仍在Soccer孵化，不冒称已成为Core正式通用能力。当前优先补齐：实际自由球获取后的可控姿态、接球到下一运动的条件转换、接应目标时空承诺，再训练多身体竞争。不是继续堆同一个固定目标的PPO轮数。
