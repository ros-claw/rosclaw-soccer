# S298–S303：保留旧技能、接球域诊断与连续跑动

## 结论

本阶段没有得到可以替换现有模型的 4v4 冠军。普通 PPO 和加入行为锚点的 PPO
都在实际 MuJoCo 复测中退步，因此两个训练候选均拒绝采用。代码中的训练能力
可以合并，实验权重不能因此获得晋升。所有实验仅限 SIM_ONLY。

## 做了什么

- S298：从已有 S231 generation 2 继续更新八个独立角色的 actor/critic，
  四轮、每轮八个实际共享世界课程。射门全身模型 S286、SONIC 和参考库冻结，
  通过 ROSClaw Core plasticity lease 记录每次允许改变的角色及冻结组件。
- S299：记录实际接球过程中的身体与球状态，不修改运行中的物理状态。
  已接球前锋经常球在身后、身体向后运动，不属于现有连续前进射门模型的入域。
- S300、S301：分别用四个实际接球后状态、四个接球前状态初始化隔离研究世界，
  各筛选 30 个已有动作参考。每组 120 个实例均未获得合格射门；接球后组
  甚至没有脚球接触。离线用接球时刻选择样本，不是运行时可使用的未来信息。
- S302：加入不可变的旧策略行为锚点，在旧成功轨迹的有效角色观测上计算
  KL(reference || current)，与 PPO 联合优化。锚点内容、掩码、源哈希、系数
  全部绑定到更新上下文；旧权重作为冻结组件进入 Core 审计。
- S303：单 G1 使用冻结 SONIC 神经规划器每 0.4 秒重规划未来参考，完成连续
  转向测试。只改变参考，不重置身体、策略历史或球的状态。这不是新的 RL 模型。

## 实测结果

| 考试 | 父模型 | 训练候选 | 判定 |
| --- | --- | --- | --- |
| S298，16 个课程身体安全 | 16/16 | 15/16 | 退步 |
| S298，合格传球数 | 1 | 0 | 拒绝采用 |
| S302，20 个课程身体安全 | 19/20 | 18/20 | 退步 |
| S302，全程合规触球课程 | 10/20 | 7/20 | 退步 |
| S302，合格传球数 | 2 | 0 | 拒绝采用 |
| S302，诊断接球事件数 | 3 | 2 | 未改善 |
| S302，完整比赛通过数 | 0 | 0 | 尚无完整突破 |

S298 每个父/候选课程各运行两次，共 64 次物理运行。S302 有 16 个新偏移课程
和 4 个训练内回放课程，父/候选各两次，共 80 次。不能把回放当成额外独立样本，
也不能将这批开发考试称作独立盲测。S302 新偏移子集安全数双方均为 15/16；
增加回放课程后才得到表中的 20 个课程结果，不能与 S298 的 16 个课程直接横比。

S302 首次更新另做同一批 on-policy 数据消融：无锚点路径逐权重复现 S298
的真实更新；加入锚点后，七个有样本角色的旧观测 KL 从约 0.0035–0.0081
降到约 0.0000098–0.0000441。但物理考试仍退步，说明局部输出接近不足以保证
长时间闭环保留。蓝方门将没有锚点样本，其 KL=0 不是完美保留的证据。
S298 与 S302 主训练采用不同探索种子，不是单一变量对照实验。

S303 八秒三路点测试，四个模型/速度组合均满足本实验身体安全阈值。
v1.1、0.7 m/s 指令完成两个中间路点，最终距离 0.264 m，平均水平速度
0.672 m/s；1.2 m/s 指令最终距离反而为 0.956 m。不能据此直接提高共享
世界速度限值，更不能把单机器人导航称作自然的 4v4 比赛。

## 工程边界与验证

行为锚点是 Soccer 训练器的可选参数；默认无锚点更新路径保持不变。数据复制为
不可写底层数组，拒绝非有限输入、整数溢出、错误掩码和冻结身份冲突。锚点
不会自动放宽晋升门。Adam 仍按每次更新创建，不是持续保留优化器状态的声明。

本阶段全量测试：1409 passed、29 skipped、11 failed。11 个失败属于已有
S78/S79/S80/S94/S104/S105/S107/S108/S113/S114 外部证据与当前源码绑定测试，
并未修改或隐藏。全仓 ruff check、430 个源文件 mypy 通过；修改文件格式通过。
全仓格式检查仍有 69 个既有文件与当前格式器不一致，未进行无关批量重写。

S302 考试追加回放时发生文件名碰撞，原始 64 次结果保留；恢复脚本核验现有
策略、源树、场景和轨迹哈希后，以独立 rehearsal 名称补跑其余 16 次。

## 后续路径

1. 连续导航接入必须使用共享世界已经避碰的速度指令，不能绕过队友间距约束。
2. 先验证导航到接球/射门的控制权交接，再扩大跑动速度与角色规模。
3. 接球后近球、球在身后和转身触球需要自己的数据与动作域，不扩大旧前冲射门
   模型的入域来伪造覆盖。
4. 训练输出接近旧策略只是中间指标；实际传接球、身体安全及完整比赛仍是门槛。

本地完整证据位于外部 evidence root 下的 `s298-retained-team-ppo-v1`、
`s299-actual-received-state-capture-v1`、`s300-received-close-ball-reference-screen-v1`、
`s301-pre-reception-reference-screen-v1`、`s302-behavior-anchored-team-ppo-v1` 和
`s303-streaming-sonic-navigation-v1`。原始轨迹、权重不进入 Git。
S302 的 `examination.json`、`retention.json`、`ablation-first-update.json`
分别记录物理考试、拒绝判定与同数据消融。

规划生命周期参考 [官方 SONIC localmotion_kplanner.hpp](https://github.com/NVlabs/GR00T-WholeBodyControl/blob/main/gear_sonic_deploy/src/g1/g1_deploy_onnx_ref/include/localmotion_kplanner.hpp)。
